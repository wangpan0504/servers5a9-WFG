# 开发记忆

## 2026-10-10：商城购买单功能

- 目标：接入商城购买请求的解析、点券扣除、PVF 商品校验、奖励发放、成功/失败 ACK 与背包刷新。
- 范围：本次只处理普通商城商品和可解析的附赠奖励；名称装扮、契约、礼包开启与溢出邮件另行拆分。
- 状态 owner：选中角色的 `InventorySnapshot`；账号点券保存在 `AccountWallet`，通过既有 `CurrencyService.Spend` 规划。
- 事务边界：先规划点券扣除，再由统一 `InventoryRewardGrantService` 规划所有奖励；成功后由 `Session.MutateInventory` 一次提交，发送 ACK 和投影刷新。
- 容器规则：奖励继续使用 `ItemSlotBoundService`，装备、装扮、宠物、勋章和普通物品按物品类型进入对应栏位。
- 拒绝规则：未知商品、无效价格/数量、未支持的特殊商品区段、奖励模板缺失、点券不足或背包空间不足均不提交扣费。
- 验证：Debug 构建通过；完整资源自测已执行，商城专项断言通过。完整自测随后命中基线中的堆叠期限断言失败，与本次改动无关。
- 下一步：按独立 MR 继续实现礼包/契约开启和名称装扮使用闭环，并补充对应客户端包序证据。

## 2026-10-11：副本推荐等级通关幸运星

- 目标：修复自身等级推荐地图通关后不增加幸运星；资格覆盖所有角色、职业、副本资源和场景，不绑定测试角色或固定地图编号。
- 关键发现：当前正式结算统一经过 `GameSession.SettleFormalDungeon` → `CharacterRepository.CommitDungeonSettlement`；账号幸运星位于 `account_wallets.rental_points`，租赁面板由 S2C988 `EQUIPMENT_RENTAL_LIST` 投影。
- 实现：新增 `DungeonLuckyStarPolicy`，按副本 `minimum required level` 与 `basis level` 和角色等级 ±5 区间重叠判定；结算事务内用账号钱包 revision/CAS 增加 1，按 PVF 租赁目录上限封顶；重复结算只读已有余额，不重复增加；成功后发送 S2C988 刷新。
- 修改文件：`Game/Dungeons/DungeonLuckyStarPolicy.cs`、`Game/Session/GameSession.Settlement.cs`、`Persistence/CharacterRepository.Settlement.cs`、`Network/Handlers/DungeonSettlementHandler.cs`、`Infrastructure/ServerRuntime.cs`、相关接口/回归测试及租赁/副本文档。
- 验证：`dotnet build ServerS5A9.sln -c Debug --nologo` 通过；`dotnet run --project Server/DfoServer -c Debug --no-build -- --selftest-core` 通过，含 6 条资格与上限断言；完整 `--selftest` 使用的 PVF 与现金商城资源不匹配，在既有 `CashShopTests.Run` 第100行 `Sequence contains no elements` 终止，非本改动根因。
- 未验证：匹配客户端实机副本全场景/全职业包序、运行包部署；完整资源自测需使用对应 PVF。
- 回归步骤：运行 `--selftest-core`；有匹配资源时运行 `--selftest`，再用任意合法角色进入其等级区间地图通关，检查数据库 `account_wallets.rental_points` 与客户端 S2C988 面板余额，重复结算确认只增加一次。
