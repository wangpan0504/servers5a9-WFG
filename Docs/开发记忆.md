# 开发记忆

## 2026-10-10：商城购买单功能

- 目标：接入商城购买请求的解析、点券扣除、PVF 商品校验、奖励发放、成功/失败 ACK 与背包刷新。
- 范围：本次只处理普通商城商品和可解析的附赠奖励；名称装扮、契约、礼包开启与溢出邮件另行拆分。
- 状态 owner：选中角色的 `InventorySnapshot`；账号点券保存在 `AccountWallet`，通过既有 `CurrencyService.Spend` 规划。
- 事务边界：先规划点券扣除，再由统一 `InventoryRewardGrantService` 规划所有奖励；成功后由 `Session.MutateInventory` 一次提交，发送 ACK 和投影刷新。
- 容器规则：奖励继续使用 `ItemSlotBoundService`，装备、装扮、宠物、勋章和普通物品按物品类型进入对应栏位。
- 拒绝规则：未知商品、无效价格/数量、未支持的特殊商品区段、奖励模板缺失、点券不足或背包空间不足均不提交扣费。
- 验证：Debug 构建通过；完整资源自测已执行，商城专项断言通过。完整自测随后命中基线中的堆叠期限断言失败，与本次改动无关。
- 下一步：按独立 MR 继续实现礼包/契约开启和名称装扮使用闭环，并补充对应客户端包序证据。
