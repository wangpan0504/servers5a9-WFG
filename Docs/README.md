## 文档归属与修改规则

| 层 | 唯一负责的内容 | 修改时机 |
|---|---|---|
| README / 本索引 | 项目入口、导航与阅读选择 | 新增主题、移动入口或构建入口变化 |
| AGENTS / CONTRIBUTING | agent 工作边界 / 协作与验证流程 | 工作规则本身变化 |
| 规范 | 跨模块依赖、owner、事务、生命周期及扩展约束 | 公共规则变化，不跟随每个功能重复更新 |
| 模块 | 当前业务行为、状态归属、持久化、限制、测试入口与验收边界 | 功能行为或状态模型变化，通常只改所属一篇 |
| 协议 / 资源 | 匹配版本的字节合同、包序、消费者证据 / PVF 定义 | 对应字段、包序、证据或资源解释变化 |
| 开发 | 启动、命令及服务端工具 | 运维入口或工具变化 |

一般功能改动维护 **1 篇模块文档**；涉及字节合同再维护 **1 篇对应协议文档**。这是默认维护范围，不是文件数量上限：确实改变多个模块或公共规则时仍需同步其唯一来源。纯内部整理而行为不变时，不机械追加文档。正文相互链接，不复制同一状态表、schema 版本、字段表或测试命令。

例如：移动/堆叠规则改动只改背包文档；ACK 字段变化另改物品协议；新增配置项才改环境说明；普通功能修复不更新项目 README、索引或公共规范。跨模块引用使用链接，允许一句说明关联，但不复制完整合同。

正式文档只保留当前事实、必要原因/背景、验证边界与足够复核的字段证据。任务范围、认领、依赖、公共方案、交接和验收结果按[协作流程](../CONTRIBUTING.md#任务和分支)保存在 Issue/PR；逐次试验、原始日志、会话笔记、现场 PID 和运行资产保存在开发者本地、仓库之外。源码不设“实施状态”或“开发记忆”汇总页，也不复制一份任务看板。提炼出的最终行为归入上述唯一来源，不能要求读者寻找本地笔记或聊天记录。

新增文档应有独立维护责任；一个模块尚可清楚说明时不继续拆小页。代码、匹配客户端及实测优先于文档；冲突时修正所属正文，不追加一段相反结论。执行[仓库检查](../Tools/Check-Repository.ps1)确认链接与可移植性，文档迁移还需检查标题锚点及工具说明中的引用。
