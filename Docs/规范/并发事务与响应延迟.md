# 并发、事务与响应延迟

本页约束所有模块的请求处理、占用锁、持久化、批量计算、定时任务与消息交付。按本次修改选择对应场景；分层、现有锁和生命周期见[服务端架构](服务端架构.md)，资产业务见[物品扩展](物品扩展.md)，当前功能与wire以[模块索引](../README.md)为准。正文描述应遵守的行为及原因，不是开发记录；尚未接入的商城、战斗、组队等场景在接入时执行这些要求，不能据此宣称功能或优化已完成。

## 锁与道具占用

- 明确每把锁保护的状态、粒度、顺序和释放者。`AccountOwners` 使用短注册表锁与每账号锁；`Lease.Execute` 会阻塞本账号后续工作和接管。跨账号嵌套锁以及在 Execute 中获取新 owner 被拒绝；成员锁/发送锁不得反向取得账号锁。不同账号仍竞争 SQLite writer、成员索引和共享资源，不能把账号锁独立等同于无等待。新增锁或改变顺序须连同接管、存储、发送和清理证明一致性。
- 临时道具占用属于特定会话generation、角色/选角epoch及实例UID；需要数量或报价时同时冻结其版本与完整快照。槽号可复用，不能单靠槽号判定仍是原道具。最终提交前重验所有权、数量、完整属性和持久化revision，任何等待结束后再次核对。
- 临时占用在成功、拒绝、取消、异常、换角、断线及接管时由原owner释放，使用 `finally` 或同等明确的生命周期收尾。旧回调只释放自己的占用，不能按账号名找到新会话并清掉新占用。临时占用与持久安全锁/排序锁是不同状态，清理临时操作不得解除玩家设置的锁；单角色业务没有需求时不预建占用框架。
- 多角色业务预先确定唯一参与者、固定锁序及取消边界，不在持锁后动态扩充参与者或乱序获取另一角色锁。费用、资产和资格需原子变化时使用同一外层事务，逐角色提交不等于原子提交。
- 锁内仅保留必要校验、状态变更及当前同步提交。PVF解析、目录扫描、批量随机规划和大集合构造放在启动阶段或锁外；不在锁内等待网络、外部脚本、另一后台任务或可反向等待本锁的队列。不能用 `Task.Run` 包住整个持锁回调来声称消除阻塞。
- 锁外规划使用不可变输入，不修改在线对象或发放资产；重新进入原lease后验证原角色、epoch、资产及业务资格。GM修改、换角和接管可能发生在规划期间。冲突时拒绝或按明确业务合同恢复，不自动重抽、再次扣费或让旧计划覆盖新状态。

## 事务与数据库等待

一次业务只有一个事务owner。扣款、实例/detail、钱包、任务/成长进度、限购、奖励资格和receipt属于该业务时共同提交，提交成功后才更新在线快照并回复成功。失败恢复本次精确变更；不以全背包重载覆盖其他未提交状态，不提前清dirty，不以“稍后保存”兑现成功。

已有连接/事务必须沿调用链传递；内层保存或资源解释只能参与原事务，不另开连接写入、不再次申请写入准入、不内部Commit或Rollback。SQLite允许同一文件一个writer：外层已持有writer时，内层独立事务会等待自身直到超时，还会堵住其他账号。仅仅读取职业、携带上限或钱包时也需审计默认 `BeginTransaction` 是否申请写锁；使用纯SELECT或明确的只读快照，不能在读取里隐式建行、补默认值或保存。

引入写入准入前检查完整调用链中的连接、事务、独立保存、任务参与者和角色锁，定义统一锁序、容量、等待截止时间、取消及失败反馈。已有外层事务不得二次准入。准入超时只约束该段等待，SQLite外部writer、业务计算、发送仍需单独度量，不能当作请求总超时。禁止靠加大busy timeout掩盖自锁，或重跑整个随机/扣费回调处理竞争。

零变化与只读操作仍检查租约及业务资格，但不申请无用writer、不复制整个背包、不标dirty、不重写相同耐久或保存别人的dirty。业务“接受”与“实际变化”分开，合法零变化按协议响应，不能为了省事务改变成功语义。已有独立保存入口也纳入竞争审计；只优化某个公共提交器不能证明其他路径互不阻塞。

通用后台落库不是默认优化方向。确需引入时先定义不可变版本、合并规则、队列字节/数量上限、背压、故障恢复、提交结果不明的处理及停服排空；旧批次不得覆盖新值，不重试已提交奖励。换角/接管交接先完成被确认的修改再释放owner；禁止持角色锁等待完成路径也需要同一把锁的批次。不能借后台队列提前确认原本要求同步持久化的业务。

## 场景约束与原因

| 场景 | 必须保持的行为与需要排除的阻塞 |
|---|---|
| 背包移动、穿脱、仓库存取、整理 | 统一完整实例、UID、锁和原子提交；空移动/零变化免无用写入。连续存取属于核心请求，不能因其他账号的低频功能持writer而排队数秒 |
| NPC商店、商城、礼包展开 | 商品与资源目录共享复用；扣款、全部奖励和资格在同一事务。礼包解析若需要角色信息，读取传入快照或复用现成事务，不能再开写事务查询职业；检查其他账号同时存取/刷图 |
| 开箱、抽奖、合成、批量奖励 | 复杂度和分配量不得直接随不受约束的请求数量增长。能按数学上等价的分布聚合时保留原权重、重复池、每行数量和随机语义；逐实例属性仅在实际容量可容纳后生成。不得截断数量、改成均值、过滤奖池或额外限制合法批量来制造性能改善 |
| 奖励容量预检、掉落候选 | 复用容器索引和有界枚举，不为每次击杀或发放建立覆盖全部可能空槽的巨大集合。稳定目录在监听前按需预热，只读复用；预热不能生成掉落、消费随机数或为每角色复制整份PVF |
| 连续击杀、整房死亡突发、掉落与拾取 | 以权威死亡结果及必要掉落通知收齐为响应边界，不能只计首个包或单次handler。覆盖多只怪同批到达、重复死亡、普通/金币拾取及真实任务掉落；保持掉落UID、归属、数量、去重与失败反馈 |
| 满级经验、荣誉/成长、升级与奖励 | 这些写入可能处于击杀响应之前，归入核心路径预算；不能以“等级不变”推断没有数据库工作。等级、满级奖励和任务组合分别核对，禁止让诊断日志为了统计而加载全部满级角色 |
| 技能材料扣除、耐久 | 同连接顺序处理时，扣材料卡住会推迟后面的死亡包；同时审计前置消耗和后续响应。耐久未变化仍验证当前装备和lease，但不写库/重载；实际消耗、耐久变化与失败语义保持原合同 |
| 任务接受、完成、进度、自动掉落 | 沿原事务owner保存，复验activation/版本和事件去重；保留局部回滚与receipt。空任务范围/无推进不启事务，非空范围不能免保存。合法进度版本变化按业务核对，不因同activation版本更新一概拒绝 |
| 每日挑战、列表查询、金币携带上限 | 纯查询不因“确保存在”取得writer；缺省值与建行分开。外部writer占用真实文件库时仍验证只读与无变化路径，不能只用内存库证明无锁竞争 |
| 组队进图、队员先到/迟到/重复选图 | 队长驱动准入、共享实例和扣票，成员保留自身run/结算状态。合法成员通知按当前冻结名单和场景识别，不重复扣票、建实例、消费连图授权或补发入场包；错误身份和过期授权仍拒绝 |
| 城镇同屏、公共队伍列表、好友/公会资料 | 慢接收者只能影响自己的投递，不让创建/离队/进退图等待所有socket。公共发现列表可合并到最新内容，队内必要通知、本人ACK和奖励结果不得套用丢弃策略；详见下一节 |
| 登录/选角的大包、换区及回城 | 保持必需包序、完整字段和ready边界；大包发送慢需区分排队、构帧、抓包和socket。不得减少必要字段、提前宣布ready或截断正在写出的帧以降低耗时 |
| 宠物饱食度/期限、定时保存、在线清理 | 时钟和周期任务有明确注册、停止、切角与owner边界，只处理实际到期或变化项；不逐tick全库扫描、无变化保存或每实例创建无界任务。旧epoch不得复活已移除的道具、角色或发布缓存 |

这些规则约束实现方式，不能增加与当前业务和匹配资源不符的使用地点、物品类别、快捷栏、职业、品质或数量限制。

## 请求顺序与消息交付

每连接保持协议要求的请求顺序。等待前一请求提交和必要回复造成的后续排队属于本请求体验的一部分，不能并行乱序处理同角色指令来掩盖等待。事务锁释放后再网络await；发送工厂/guard只读当前内存投影和身份，不能在发送锁内SQL、等待角色锁、网络I/O或变更业务。

可合并的公共列表/外观刷新使用现有Runtime与每连接发送机制：重复意图只推进待更新版本，每接收者只保留有界最新状态，不每次创建任务或保存全部历史包。未就绪、换区、入队、换角、替换连接及关闭时核对可见性和epoch；业务owner完成转换及必要本人包后才能发布ready。不能只因状态字节相同就忽略实例/场景变化。

列表删除以**上次成功发送**的条目为基线；构造、入队、失败、取消不算送达。同ID的成员、队长或设置变化也需更新，不能仅按ID去重。切区需要保留足够旧基线清除残留，装载重置按模块协议处理。这里只指服务端写入完成，不代表客户端业务确认。发送中途场景变化不截断帧，超时只关闭对应连接；失败保留必要待更新意图，由后续变化/ready触发，不无限重试或新增轮询线程。

当前城镇同屏的可靠队列、移动合并及上限见[城镇同屏](../模块/城镇同屏.md)。其他发现列表接入时复用适用机制，不凭本规范预建平行广播框架。慢连接验证必须确实观测发送阻塞，单纯让客户端不读一次小包不足以证明socket被堵住。

## 延迟目标和测量

以下为验收目标，**不是当前版本已达到的性能或容量承诺**。核心包含连续仓库存取、死亡/掉落通知、拾取以及直接阻塞它们的内部保存/任务。低频预算只适用于不拖慢其他玩家核心操作的交互；特殊场景须在测量前定义预算，不能事后放宽掩盖异常。

| 正常预热负载 | 目标 |
|---|---|
| 1/3个独立活跃账号的核心请求 | P95 ≤ 50ms，P99 ≤ 100ms |
| 10/20个独立活跃账号的核心请求 | P95 ≤ 100ms，P99 ≤ 250ms；数据库竞争造成的单次 ≥1s 停顿必须定位 |
| 低频交互及正常公共列表更新 | 500ms内完成；不能持共享锁或writer拖慢其他账号 |
| 吞吐与公平性 | 有效请求无系统失败/超时，稳态完成率至少为计划速率99%，欠账不持续增长；总体与每账号分别检查，无角色饥饿 |

报告源码/产物标识、配置、PVF/schema、数据库初始状态、硬件与抓包模式。同条件比较，Release用于正式性能测量，Debug用于功能验证；冷启动/首次操作单列保留，不删掉慢样本。连续存取可用每角色2次/秒，另列5次/秒突发；独立账号并发与同账号顺序换角是不同用例，不把同账号多开作为前提。

使用单调时钟记录计划发送→完整必要响应、实际发送→完整必要响应两种口径及P50/P95/P99/最大值、≥100/250/1000ms次数。固定计划发送率，保留发送欠账、失败/超时与未完成样本；闭环等待响应后才发送会隐藏服务变慢造成的排队。报告样本数，少量短测不能当稳定P99或线上容量。

归因分开记录接收队列、handler/规划、锁等待与持有、写入准入、连接/BEGIN等待、SQL保存、COMMIT/恢复、发送队列、构帧/抓包和socket。SQLite等待常发生在BEGIN而非COMMIT；低频业务的持锁时间、同连接队列和跨账号writer竞争需一起看。仅有socket等待不能直接归因于带宽或用户网络。

慢日志应有阈值和有界限流，正常热路径不额外拼逐包字符串、同步刷盘、查库或枚举全角色。限流后的缺失日志不证明没有阻塞，suppressed不属于下一条打印的角色；已读批次queued时间不是完整请求队列或网络RTT。全量分位数使用测试计时或有界聚合，不能从抽样慢日志推算，不为采样保留无界请求列表。

## 验证与停止边界

- 首先使用独立真实文件库做聚焦复现：长规划期间另一账号仍可操作，事务内连接不自锁，零变化/纯读不申请writer，旧generation/epoch、GM更新、revision冲突及SQL中途失败不产生成功或半份资产。多角色锁顺序、双方回滚及去重按实际业务验证。
- 受控注入100ms、250ms、1s的writer等待、发送阻塞及取消，单列故障轮次，不套用正常时延门槛；验证等待有界、恢复后可继续、慢连接不拖健康接收者。两账号混合商城与满级击杀/材料扣除能暴露单业务成功测试遗漏的阻塞链。
- 核心回归覆盖真实TCP完整帧和必要通知，核对在线内存、独立读库、重连与重启；包含任务/无任务、普通/满级、单人/组队和整房突发中本次受影响的组合。不要以纯背包基准代替战斗，或用少量玩家不卡顿代替并发证据。
- 资源测试与构建串行；声明进程树内存、时间和进程数预算，运行前检查系统可用物理内存及提交余量，越界终止本轮并定位。复用只读PVF，控制fixture进程与stdout缓冲，检查退出后回收；不得并行重复加载整份资源、无上限加压或在资源不足后连续重试。测试详细要求见[贡献指南](../../CONTRIBUTING.md#验证)。
- 只有当前改动或未决证据需要时才做性能长测，默认预热2分钟、正式5分钟的一轮主要负载；其余人数/成对短测按问题选择，不机械重复全矩阵。停止输入后检查欠账排空和可解释的存活内存，短观察不能声称无长期泄漏。
- 在核心体验与低频预算已满足、正确性已证实时停止扩大优化；不为完成阶段表引入后台保存、额外缓存或全局调度框架。编译、自测、协议、性能测量和客户端实机分别报告，未执行的项目保留明确边界。
