# 剑影95实验角色

本入口为独立开发账号准备Lv95男鬼剑、剑影二觉、地图/主线任务完成及StoryDigest已接受等级。它是离线测试工具，不改变普通 C2S5 的 Lv1、job0–15 [创建规则](../模块/角色.md)，不代表已实现转职、任务领奖或成长业务。

## 1. 当前数据合同

准备工具按[开发环境](环境与配置.md)读取固定目录下的 PVF，生成任务与初始技能，不从其他版本或其他玩家复制进度。

| 字段 | 当前值 / 合同 |
| --- | --- |
| 名字 | 参数指定；示例“剑影”以CP936编码为`BD A3 D3 B0`，DSTR字节长度4 |
| job / grow_type | job0；grow=25 hex，即低4位职业索引5、觉醒2；匹配CHR名称剑影 / 夜刀神 / 夜见罗刹 |
| level / accepted_story_level | 95 / 95，均持久化 |
| 初始技能 | 合并CHR初始、剑影转职与觉醒声明15项，两树同一列表；初始技能179等级7，其他声明等级保留 |
| 完成任务 | 最终去重942项；下述资源范围及前置递归决定，不伪造已不在quest.lst的条目 |
| 出生及返回 | 房间38/1、450/234；初始返回艾尔文38/0、622/196。后续按当前最后地区规则更新 |

当前Player仍下发匹配男鬼剑CHR初始89B属性块，没有按Lv95生成战斗成长值；没有自动学习所有Lv95技能、装备或道具。已有角色的等级、觉醒、任务和技能可以用[开发 GM](GM.md)写入存档，那不是在线升级或转职。

## 2. 任务生成范围

[CharacterPreparation.Load](../../Server/DfoServer/Development/CharacterPreparation.cs)读取匹配PVF的2636项n_quest/quest.lst：

- 全部epic主线915项。
- 全部town need quest/need quest or、completed quest阶段条件，地图/import的quest condition以及dock open questindex condition：49项有效引用，其中39项属于主线，另10项为10100、2670、6928、8664、8665、8672、6170、8703、8709、2941。
- 剑影转职/两次觉醒11项：5151、5153、5154、5155、5156、5161、5162、5163、5164、5165、5166。
- 递归补齐仍在quest.lst中的pre required quest，包括8663、8702；最终942项。其他职业的觉醒成就不作为地图开放任务批量完成。

失效地图引用2656、5591、5595、5597、6359、6367、8605、8914、14395只记录为ObsoleteMapReferences，不伪造完成。可选活动地图gate_dnfaos缺少资源时记录MissingMaps。地图权限用持久化的真实完成集合判断；Lv95本身不绕过路线、任务或阶段限制，见[全城镇通行](../模块/城镇.md)。

## 4. 准备、审计和回退

先按[开发环境](环境与配置.md)完成构建、固定目录资源准备和一次运行库初始化。服务端与离线工具共同独占程序目录下的 `Data/server.lock`；准备前通过精确实例停止服务，不能绕过锁写运行库。以下在仓库根执行，尖括号参数须替换为实际输入，审计目录必须尚不存在：

```powershell
powershell.exe -ExecutionPolicy Bypass -File Tools/Start-Server.ps1 -Action Stop
dotnet Server/DfoServer/bin/Debug/net10.0/DfoServer.dll --prepare-jianying 剑影 "<新审计目录>"
```

执行[OfflineCharacterPreparation](../../Server/DfoServer/Development/OfflineCharacterPreparation.cs)时：

1. 解析 PVF，校验名字、任务/技能和新审计目录，要求 game.db 已存在。
2. 用SQLite Backup API生成game-before.db并做integrity_check，再写intent.json。
3. schema检查/迁移由Repository独立事务处理；新角色、职业等级、完成任务和技能在创建的同一事务中写入，重名/满槽/SQL失败整体拒绝或回滚该创建事务。
4. 提交后回读角色及全部任务/技能，核对成功写committed.json。slot和id由当前数据库分配，文档不固定其值。

如果提交后回读/写审计失败，创建事务可能已经完成；先查数据库和intent/备份，再决定恢复或继续，不能仅凭committed.json缺失宣告未提交或换名重复准备。已有审计目录禁止原地覆盖重跑。

职业、等级、剧情、完成任务、技能、进行中主线槽及条件编码随[完整数据库基线](数据库.md)建立。离线准备按本工具规则写入新角色进度；移动只更新位置/返回点/revision，不丢失上述进度。仓库内不包含开发者的角色库或审计产物。

回退先停止精确服务实例，保存当前一致性备份，核对要恢复的game-before.db完整性，再恢复匹配数据库及兼容代码版本；不要直接覆盖运行中的WAL数据库。数据库备份和客户端/PVF由开发者自行保管，不作为文档阅读依赖。

## 5. 验证与后续开发

[CharacterPreparationTests](../../Server/DfoServer/SelfTests/CharacterPreparationTests.cs)覆盖当前基线建库、CP936字节长度、任务/技能范围、唯一名、技能写入失败完整回滚、重开库、普通角色保留、移动不丢进度和Builder布局。[NpcTravelSpawnTests](../../Server/DfoServer/SelfTests/NpcTravelSpawnTests.cs)额外覆盖出生/重登不改任务与技能。

```powershell
dotnet run --project Server/DfoServer -- --selftest
dotnet run --project Server/DfoServer -- --selftest-tcp
```

隔离TCP从普通建角、停服准备、备份回读到重新启动和CP936名册/选角逐帧验证，使用独立数据库，不操作实际角色资产。职业/觉醒形状、任务开放和CG抑制仍需匹配客户端确认；不能将数据库或socket通过当作这些画面均已验收。

后续实现通用转职、升级或任务流程时，应增加正常请求、费用/进度事务、失败恢复与投影，而不是扩大离线准备工具覆盖真实业务；当前在线学习入口见[技能学习](../模块/技能学习.md)。新PVF或职业索引改变时重新确认任务/CHR与客户端字段，不只调整grow常量。
