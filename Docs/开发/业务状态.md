# 用户业务状态

`UserState`为服务端粗业务分类，`SessionPhase`保留现有细阶段，正式副本另有`SinglePlayerDungeonPhase`。`GameSession.Mode`从本连接只读频道类型推导Normal/Pvp，认证绑定频道后即确定，不等待建房或开战，也不另存可写模式。上述分类不进入网络包或数据库，不复制ARAD的`MODULE_TYPE`或旧端数值。不会切换客户端上下文的普通查询和资产操作不额外改变user状态。

## 当前入口

- `GameSession.GetState()`在原账号owner内，由Selected、Ready、选图上下文及当前Run计算粗状态，不维护第二份可写在线状态。
- `CheckState(UserStateRequirement)`检查最低生命周期资格；`CheckState(UserState)`检查已实现的精确玩法。
- 内部`SetState(SessionPhase)`核对转换边和目标上下文一致性后写入唯一阶段；目标不属于副本阶段时移除[运行态缓存](../模块/运行态缓存.md)中的正式副本槽位，Loading、战斗和结算之间不失效。不提供任意状态网络接口或GM强制切换。

| 粗状态 | 所需上下文 | 最低资格 |
|---|---|---|
| CharacterSelect | 未选角色、未就绪、没有选图或Run | Owner |
| EnteringWorld | 已安装Selected，入城初始化尚未完成 | CharacterSelected |
| Town | Ready、Selected有效，无选图或Run | WorldReady |
| PvpTown | Ready、Selected有效，当前频道为PvP，无房间、选图或Run | WorldReady；保留城镇移动与切图发布 |
| DungeonSelect | Ready并持有当前选图身份，无Run | WorldReady |
| Dungeon | 当前正式Run已安装，细阶段与Run同为加载、战斗或结算 | DungeonContext |
| TutorialDungeon | 正式训练Run；由本人持久训练资格、当前PVF和实例身份共同确定 | WorldReady与DungeonContext；细阶段仍区分加载、战斗和结算 |
| PvpRoom / PvpBattle | 决斗场房间与房间内战斗；由当前频道的房间会话安装，本人离开房间后回PvpTown | WorldReady；细阶段与准入见[决斗场](../模块/决斗场.md) |
| 战场、塔、桌游及祭坛 | 仅定义未来状态；当前没有对应已实现上下文 | 不通过门禁 |

认证后即有账号会话，未选角色仍可查询状态。选择、入城完成、选图、入场、加载、过房、结算、回城和退出在各自原提交或上下文安装后调用SetState。任务回放保留上游现有选择流程，也经同一入口推进。旧generation不能读取或发布新会话状态；旧连接收尾只清理自身。

频道模式采用ARAD `03EF95B0`确认的类型4/5/7/8/9/10/13/14/20/24/31/34/35/41；这不是对上述频道全部玩法的开放许可，各模式仍沿自身准入表。PvP连接未选角仍为CharacterSelect，初始化为EnteringWorld，进入城镇后为PvpTown；进入真实房间才为PvpRoom，正式开战才为PvpBattle。退房恢复PvpTown，返回选角不清除本连接模式，切换频道由目标连接的频道身份重新决定模式。

旧端提供的是相同分层而非相同枚举：`df_game_r`的Area::insert_user保持城镇state3，GameWorld::goto_pvp在入房后设6，PvP_Room::start_pvp设7，end_pvp_result恢复6。频道补正独立于该房间状态，不能把“在PvP频道”当成“已经进入对战”。

允许回选角收尾；城镇与决斗场房间可互相出入；城镇可到选图或加载，选图可回城或到加载，加载可到战斗、结算或回城，战斗可到加载、结算或回城，结算可到加载或回城。合法同阶段行为保持阶段。重复MarkReady不能把已进入选图或副本的会话覆盖为Town；失败不提前宣布新状态。

## 分派与客户端边界

命令注册可声明Owner、CharacterSelected、WorldReady或DungeonContext，默认仍为Owner。不满足时沿原Unhandled处理，不调用业务、不伪造成功或其他版本错误码。最低门禁不替代模块原有phase、资源、实例、epoch、revision及资产校验，不把商店、技能或任务统一限制为城镇。

状态边界以本版ARAD实际消费为依据：ACK4建立选角入城过程，完整入城投影完成后才MarkReady；选图由15/27建立选择上下文；28/29发布正式加载，37/30/本人3完成加载；通关及结果页保留同一Run，回城24后解除实例。这里不改变这些包体或包序，只同步管理服务端上下文。客户端MODULE名称不是服务端状态设置的充分依据。

无资源`UserStateTests`覆盖粗状态、完整转换矩阵、未实现拒绝、迟到就绪、选图回城及旧owner收尾。测试入口沿用现有`--selftest-core`；副本、任务回放和角色画面仍按所属功能定向测试及实机验收。
