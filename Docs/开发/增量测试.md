# 增量测试与跨工作树收据

本流程用于开发期减少重复验证，不替代完整验收，也不改变服务端程序集边界。严格入口和最终检查范围仍以[贡献指南](../../CONTRIBUTING.md#验证)为准。缓存结果不是一次新执行，组通过也不保证所有条件场景都执行。

## 平台支持与未完成边界

**本轮新 Run 执行链限定 Linux，首个可缓存 profile 进一步限定 Linux x64；其他 Linux CPU 架构只可 fresh 执行。不能据此告诉 Windows/macOS 用户其本机多工作树自动缓存或新进程治理已可用。** Windows/macOS 继续使用既有严格构建与自测入口；计划结果不是该平台执行验收。

Windows 私有 JobObject 监督器及显式验收入口 `Tools/Test-WindowsTestSupervisor.ps1` 已实现，但尚无 Windows 原生执行证据，正式 Run 仍限定 Linux。验收入口要求 Windows 10 / Server 2016+、PowerShell 7 和64位原生 Python 3.8+；锁竞争、取消/崩溃时点、宿主嵌套 Job、硬件架构/仿真组合与跨工作树仍须分别验证，不能用纯合同测试替代。macOS 的安全后代生命周期尚未实现，见 [macOS任务生命周期](macOS任务生命周期.md)，不能沿用 Linux 采样或进程治理结论。

当前不包含通用跨变更依赖图、全部TCP组自动缓存、动态RAM调度、自动挑选最优分片、拆分测试程序集或完整原生客户端验收。真实命中及耗时变化必须由相同来源的运行证据证明，不由工具存在推定。

## 隔离与复用边界

- 每个工作树独立源码、`bin/obj`、SQLite、端口和可变 fixture；不得把另一个工作树的活进程或构建输出作为自己的执行现场。
- 允许共享的对象是按内容寻址、经过校验且不可变的输入与结果，不是跨工作树共享可变数据库或角色。
- 精确源码内容相同只是必要条件；实际程序集、输入、工具与测试合同、配置和环境也须匹配。首期不依据“只改一个文件”自行推导无影响；跨变更依赖无法证明时按影响范围重新执行。
- 原失败、中断、跳过和未知覆盖保留独立归属。恢复后只续跑未完成或已失效的部分，不能把多段混合源码的结果写成一次连续全量通过。

## 可选开发入口

`Tools/Test-Development.ps1` 默认 `-Action Plan -Mode Dev`，不启动构建或测试。开发期先明确选组，再决定执行；没有显式组不会擅自运行全套。

```powershell
# 只计划，不启动重型任务
pwsh -NoProfile -File Tools/Test-Development.ps1 -Action Plan -Mode Dev `
  -Groups chat-rate-rules -Store <同账号共享结果库> -UseCache

# 执行构建和明确选择的组；其他范围为not-run
pwsh -NoProfile -File Tools/Test-Development.ps1 -Action Run -Mode Dev `
  -Groups chat-rate-rules -Store <同账号共享结果库> `
  -BudgetDirectory <同主机统一预算目录> -UseCache

# 真实资源组需提供匹配PVF；未审计profile不因UseCache命中
pwsh -NoProfile -File Tools/Test-Development.ps1 -Action Run -Mode Dev `
  -Groups clear-avatar -PvfPath <匹配Script.pvf> `
  -Store <同账号共享结果库> -BudgetDirectory <同主机统一预算目录>
```

`-BuildProfile Default|CloudLowMemory` 显式区分编译预算：Default 只限制编译器为 CPU1；CloudLowMemory 另给编译子进程配置堆上限 `0xA0000000` 与 ConserveMemory=5。这些值仅进入 CscEnvironment，不传播给测试运行时；实际配置进入缓存键，不能把不同配置结果互换。每阶段当前上限1800秒、流式日志上限16MiB；超限记失败，不是业务问题已修复。

参数 `-Repository` 默认脚本所在仓库，`-Configuration` 默认Debug（可Release），`-Store`必需。每次运行日志、收据和 fixture 现场单独保存在 Store 下 runs；Dev 构建复用本工作树 `build/development/<configuration>/<设置键>`，受该目录独占锁保护，不与其他工作树共享可变产物或数据库。内容、产物或中断标记要求重建时不能仅凭时间戳跳过；未知构建输入拒绝增量，回到原严格入口。源码、程序集或输入运行中变化不得记成功；显式跳项仍保留部分覆盖。

**Full不是完整TCP。** `-Mode Full -Action Run`委托原 `Tools/Check-Development.ps1` 严格入口：无PVF为基础/core，有PVF为完整core/资源；TCP仍另列未运行。它不是“全项目验收通过”的快捷键。完整TCP仍按[贡献指南](../../CONTRIBUTING.md#检查范围)另行安排。

## 显式完整执行计划

`-Mode Complete` 与兼容的 `Full` 不同：必须提供匹配 `-PvfPath`，在同一个重型许可内串行执行严格 `Check-Development.ps1`（仓库、构建、架构、PvfLib、core 和资源），随后执行无选组参数的默认 TCP。默认 TCP 由运行程序集的 `DefaultGroupNames` 决定，**不包含 `TargetedOnly` 集合，不能称为所有注册组全跑**。可选 `-Groups` 另增加一个明确的定向阶段，不自动推断已包含或核销。其他定向组与原生客户端仍列为 not-run。

```powershell
# 先生成范围，Plan 不启动构建、服务或重型任务
pwsh -NoProfile -File Tools/Test-Development.ps1 -Mode Complete -Action Plan `
  -PvfPath <匹配Script.pvf> -Store <结果库>

# 完整严格入口 + 默认 TCP；可按本次需求用 Groups 增补定向组
pwsh -NoProfile -File Tools/Test-Development.ps1 -Mode Complete -Action Run `
  -PvfPath <匹配Script.pvf> -Store <结果库> `
  -BudgetDirectory <同主机统一预算目录> -CompleteStageTimeoutSeconds 21600
```

Complete 不接受 UseCache、InputDescriptor 或 Record。每个完整阶段的超时默认 21600 秒，可显式设为 1..86400 秒；不是默认 1800 秒的开发选组限制，也不是整轮共用一个倒计时。TCP 固定 `DFO_TCP_PARALLEL=1`，清除继承的分片子模式；额外定向阶段仅在默认 TCP 成功退出后启动。继承 core worker manifest 时在启动前拒绝，不能把 worker 早退当完整 core 执行。

现场 `complete-plan.json` 先记录所有阶段 not-run，执行时变为 running，成功退出为 executed，失败/中断为 failed-or-interrupted，后续保持 not-run；未知后代终态仍由外层监督器保留预算隔离。整轮 executed 只表示所列进程均完成且退出成功，Coverage 仍为 not-established；必须查看原始日志、TCP 组收据和显式 skips，不能变成所有条件覆盖 complete 或新缓存证据。输入源码/程序集前后变化拒绝成功；PVF 只观察路径、长度与更新时间，不计算整份哈希，元数据一致不是不可变输入闭包证明。外部样本与其他条件资源仍按原入口单列验收。

### 同轮重复阶段的安全边界

当前**不自动核销** `database-schema`。核对调用链可见 `SelfTestRunner.RunCoreAsync` 与 TCP 注册包装都直接调用无参数的 `DatabaseSchemaTests.Run()`，TCP 包装不使用 options、root 或 resources，主要夹具由方法自行创建。但同方法并不足以证明两次执行等价：

- core 入口可先进入 `LukeRewardRestartTests.TryRunWorkerAsync` 并提前返回；现有 core 总体退出码不是 schema 方法已经执行完成的独立收据。
- `DatabaseSchemaTests.IncountNumbering` 读取可变外部 `DFO_MIGRATION_SAMPLE_DB`，未配置时直接跳过真实旧库样本分支；不能把合成夹具成功替代真实样本验收。路径或环境字符串相同不等于数据库快照相同。
- core 与 TCP 的进程上下文、前序测试及 native SQLite 状态不同；现有 schema TCP 覆盖仍为 unknown，不能从 PASS 文本推导 complete。

因此保留两个入口、所有断言及实际执行；Complete 的 Deduplication 明确为 disabled-unproven-equivalence，不声称已省下 schema 复跑耗时。以后启用精确同轮核销前，必须增加真正到达并完成方法的细粒度收据，审计所有条件分支，固定完整输入/产物/环境与外部样本快照，明确进程上下文等价；仅在同轮证明成立时标为 covered-by 并指向原执行证据，不伪造 executed 或 Passed，不跨未知上下文复用。

## 保守优先测试建议（仅计划）

`pwsh -NoProfile -File Tools/Select-AffectedTests.ps1 -ConservativePlan -Base <明确提交或ref>` 是既有选组入口的显式模式；不改变旧默认行为。它只输出JSON，不构建、不执行测试、不访问结果缓存，也不自动跳过严格Complete。不能与`-Run`、`-Full`、`-Paths`、`-NoCache`或排除未提交改动组合；缺失/无法解析base返回blocked，不默猜master，不把读取失败写成空改动。

计划固定实际base/head commit与tree，比较两者（不是悄悄换成merge-base），总是包括staged、unstaged和untracked。index用只读`ls-files --stage -z`记录身份，状态与改动用NUL分隔；前后检查HEAD/index/status、工作区摘要和base引用。工作区摘要仅覆盖tracked及非ignored内容，ignored文件只列路径，外部输入、生成器和构建依赖仍未证明；这不是受控不可变快照，也不能发现中途改后改回。读取失败或可见漂移保持blocked，不能据此复用旧计划。

`PriorityGroups`只表示已审核调用关系下的优先检查方向：展示分测试/算法对应`equipment-power-rules`，帧CRC测试/算法对应`frame-crc-rules`，聊天限流算法/所属测试对应`chat-rate-rules`；实际消费者还包括core及收据合同。新内容即使落在这些路径，也未获得传递依赖等价证明；共享、反射、生成器、注册、构建、依赖或未知变更仍要求严格范围，注册指纹变动不输出旧组建议。文档也可能包含命令/配置合同或被生成器读取，首版不按扩展名豁免。

所有输出均为`Execution=not-run`、`StrictRequired=true`、`ProofOfOmission=false`；没有可证明省略项。agent可据透明理由先做相关轻量检查，再按任务与预算安排严格验收；缺PVF/平台条件保持未完成，不能将优先组通过说成全量通过。本模式当前价值是可追溯的顺序和保守回退，不是已实现自动安全缩范围或节省全量运行。

### 注册清单的审核与程序集一致性

计划与续跑使用钉住完整注册入口文本的审核清单；新增组不自动继承缓存资格。修改指纹前逐项审阅组声明、默认/定向/普查分类、别名与执行选择逻辑，再将真实程序集的 `--selftest-tcp-list-json` 导出与源码核对。不能只改指纹让旧计划通过。

```powershell
dotnet <实际DfoServer.dll> --selftest-tcp-list-json > <registry.json>
pwsh -NoProfile -File Tools/Compare-DevelopmentRegistry.ps1 -Repository <源码根> `
  -RegistryFile <registry.json> -Runner <实际DfoServer.dll>
```

导出入口不加载资源、不创建数据库；核对工具本身只读文件，不启动程序集。工具比较实际 DLL 摘要、所有有序组及分类、分范围数组和别名，并拒绝重复 JSON 字段、漂移或无效输入。`consistent` 仅说明给定清单与已审核源码一致，不能认证清单来源、证明程序集对应全部源码、证明测试覆盖或授权缓存/省略；仍须固定构建和输入收据。任何后续注册变化继续拒绝旧审核结果。

恢复注册表可读性不等于恢复缓存：完整代码闭包、实际 SDK/环境/产物和原执行收据仍须独立匹配。代码闭包指纹变化继续 fresh，不借清单一致性更新代码白名单或核销失败/未知组。

## 首期缓存范围

`-UseCache`是显式opt-in，仅允许无PVF、单组选中的已审核profile；默认仍fresh，不按名称相似或历史Passed批量放行。三个入口只在TargetedOnly，Default不扩大；原core调用与断言保持不变。

| 单组 | profile | 审核边界 |
|---|---|---|
| `chat-rate-rules` | `chat-rate-rules-v1` | 原39条ChatRateLimiter规则；固定FakeClock显式步进，不是聊天TCP |
| `equipment-power-rules` | `equipment-power-rules-v1` | 完整49条EquipmentPowerScoreTests.RunCore；合成常量、decimal边界、Ordinal排序，无SQL/时钟/随机，不是实际角色资源验收 |
| `frame-crc-rules` | `frame-crc-rules-v1` | 完整574条FrameCrcTests.Run，含18条封闭MemoryStream短读；固定Random(20261007)和调用顺序，算法由实际runtime身份约束，不是真实网络 |

Program→ServerApplication的TCP分支在资源与SQL装配前返回。默认ServerOptions不读外部配置；TcpTestResources只构造Lazy，本组不取Value；选单组避免前序污染，TestCheck按组前后差值。驱动GUID、收据时间及耗时是观测，不是规则输入；工具固定私有shard/receipts，完整代码、实际工具链/native、配置和环境进入身份。

FrameCrc保留原90秒CancelAfter与全部18条短读：1/3/11字节分片只比较精确输出和流位置。TimePolicy为`deterministic-with-watchdog`，守卫不是时间判据；不等待超时、不吞取消。超时/失败/中断不能装complete，历史命中也不证明当前主机满足90秒预算。固定时钟/随机输入须逐组审核；真实调度、网络、取消回调或断连故障本身为判据的测试仍fresh，NativeFrame混合调用真实发送泵，不能一并放开。不得仅凭CancelAfter、Random或await关键词判纯或非纯。

设置快照实际依赖SQLite与计时文件，数据库/PVF闭包尚未证明，继续fresh。规则小组潜在收益主要是同输入免重复构建，不能推断74分钟全套缓存或已实测提速。profile包含BuildMetadata.SourceRevisionId，跨工作树命中须同提交、同完整内容与环境；dirty内容仍入key，不按HEAD掩盖改动。源码或断言变化须重审pin，不能只更新常量；缓存不成立时显式Dev仍可实跑。

Plan输出 `State`（run/cached/blocked）、Reason和Scope；有可验证profile才附InputKey及闭包原因。cached必须来自精确匹配的完整成功不可变结果，不重新解释skip或旧unknown。Plan不执行；Run才获取预算并执行必要构建/选组，命中时也应明确原收据来源。保留严格入口，不默认开启缓存。`-CacheWaitSeconds` 默认600秒，有界等待同 key 的持有者，获得锁后重新核验输入和原收据，超时为 blocked/退出码2。`-ForceFresh` 仅用于 UseCache 的已审单组 profile 同 key 重验，不清空稳定构建产物，不代表其他组获得缓存资格。

可见输入采集 `Tools/Capture-DevelopmentInputs.ps1` 仍接受Repository、ArtifactDirectory、ToolchainDirectory、单Group、Configuration、可选PvfPath及OutputPath。它要求标准 `artifacts-path/bin/DfoServer/<configuration>` 的真实完整产物，产生 `observed-inputs-v1` 描述，而非全部系统native/真实时间依赖已证明的证据。此观测通道Plan/Record不自动授权生产缓存；不能手改complete标志强迫命中。

观测通道 `-Action Record -InputDescriptor ...` 另需执行前 `-BeforeManifest`、实际 `-Receipt`、`-Runner`，仍必须通过闭包和覆盖校验。原始配置、环境摘要、绝对路径和本地收据不提交Git；不得把日志中的PASS文本当作合法缓存记录。

## 只读慢测试成本盘点

Agent 排查耗时时，先复用已终态的收据和阶段监督记录，不为取样重跑整服或资源测试。当前仅声明Linux运行支持；Windows缺少所需 `O_NOFOLLOW` 时拒绝，macOS未验收。Linux 下用 `Tools/Inspect-DevelopmentCosts.py` 显式列出本轮文件；不默认扫描目录、读取 fixture 内容或解释控制台 PASS。

```bash
python3 Tools/Inspect-DevelopmentCosts.py \
  --receipt <本轮组收据.json> --expected-group chat-rate-rules \
  --stage repository <repository.log.json> \
  --stage build <build.log.json> --stage selected <selected.log.json>
# 可重复 --receipt / --expected-group / --stage；构建测量另用：
python3 Tools/Inspect-DevelopmentCosts.py --build-measurement <measurement.json>
python3 Tools/Tests/TestDevelopmentCosts.py
```

只读取 TCP `SchemaVersion=2`、子进程监督 `schema=1`、Measure-DevelopmentBuild `Schema=1` 三种已有结构，验证相关字段、类型、终态和数值；这不是内容签名或输入闭包重验证。显式提供预期组才能列出缺失；调用者所选文件不自动证明同一次运行。每次最多256文件、单文件4MiB、合计16MiB，拒绝重复JSON键、过深JSON、非有限/负数指标、链接路径及读取中可见变化。只输出组名、固定角色/阶段、数值和输入编号，不回显路径、环境、日志正文或异常消息。调用前应固定输入，目录/文件读取仍不构成事务快照。

输出按实际 `ElapsedMs` 排最慢组，列出fixture启动次数/耗时、资源加载和多次启动待调查项。相同组的完整相同收据副本只计一次；不同收据发生冲突则该组成本未知，不用新绿掩盖旧红。失败、中断和running收据的准备字段默认0视为unknown；partial/unknown覆盖不能显示为完整通过。没有预期组时覆盖范围未知；退出0只表示观测解析完成，不是测试或缓存验收，证据缺失/冲突/异常退出2。

**时间不能直接相加。** 并行组总和不是墙钟；fixture与资源成本已包含在组耗时中，可能相互包含。supervisor起止给出包括监督/退出收尾的UTC跨度，不等于命令日志内的MSBuild时间；build不是纯Csc，Measure的Restore/EvaluationProbe/BuildNoRestore也不是编译器/分析器/复制拆分。未做binlog分析时该拆分为unknown。当前不导入CLI总计时或无run绑定的startup JSONL，验证工具开销与startup buckets始终明确unknown，不按相邻日志猜测、不做差估算节省。`timings.json` 仅为跨轮分片历史权重，无本轮完整身份，不接受为当前收据。重复启动观测不证明可以共享活进程/准备结果；输出始终保留复用安全未证明、预计节省未知。

## TCP 结构化执行收据

TCP 仍沿用原命令入口与退出语义；新增组收据独立保存在 `build/tcp-receipts/<RunId>/<Group>.json`，不与可清理的 fixture 现场混同。可用 `DFO_TEST_RECEIPTS_DIR` 指定收据目录。

SchemaVersion 2 记录：

| 字段 | 含义 |
|---|---|
| `Execution` | `executed` 表示本组实际执行；不是缓存命中 |
| `Status` | `running`、`passed`、`failed`、`interrupted`；未终态不能当作通过 |
| `Scope` / `Group` | `group` 覆盖单位及实际组名 |
| `Coverage` | `complete`、`partial`、`unknown`，与执行是否成功分别判断 |
| `Passed` | 保留旧兼容字段；单独为 true 不足以复用 |
| `Skips` | 明确跳项的 code/reason；部分执行不能隐藏 |
| `StartedUtc` / `CompletedUtc` | 实际起止；running 时 CompletedUtc 为 null，不是文件修改时间 |
| `Identity` | Source、Input、Runner；Runner 由实际运行程序集计算 |
| `SelectedGroups` | 本轮注册顺序的选组集合 |
| `CacheEligible` | 缓存候选资格；仍需调用工具核验全部键、输入稳定性和结果完整性 |

硬终止可能只留下 running 或完全没有终态文件，不保证一定写出 interrupted。缺终态就是未知/未完成，不能凭进程已消失补成成功；默认组数以当前源码注册表为准，不能沿用另一基线的统计数量。

工具以 `DFO_TEST_SOURCE_KEY`、`DFO_TEST_INPUT_KEY` 传入 64 位十六进制身份，执行前后还需校验输入未变。缺身份、旧版未知字段、损坏或不完整收据不得猜测补齐并命中。

**跳项与通过分开。** 显式跳项的组可以保留 `Passed=true` 以兼容既有成功退出，但覆盖为 `partial`，`CacheEligible=false`。未完成覆盖审计的组为 `unknown`，不自动视作完整。当前完整覆盖登记仅限已审计的 `chat-rate-rules`、`equipment-power-rules`、`frame-crc-rules`、`clear-avatar`、`aura-action` 和 `quest-hell-challenge` 入口；即使在该集合内，发生条件跳项仍不是 complete。其他组需逐项迁移，不能因为历史有 PASS 就批量开启缓存。

首期缓存仅接受单组 `SelectedGroups == [Group]` 的匹配收据。多组仍可通过原 CLI 正常执行，但其结果不在首期缓存接纳范围内；不能将缓存拒绝解释成测试不能运行。远古两入口虽已记录显式跳项，未发生跳项时仍保持 unknown，不能因此推定已完成覆盖审计。

## 协作式重型预算

`Tools/TestResourceBudget.psm1` 提供 `Enter-TestResourceBudget` / `Exit-TestResourceBudget`，用于接入脚本主动遵守的本机预算；模块存在不表示所有旧入口或外部进程已自动受控。

- 默认同主机、同账号所有工作树共享一个重型 permit。`DFO_TEST_MAX_HEAVY_JOBS` 可指定 1..64，但必须统一配置；同一预算目录已有容量与请求不一致时拒绝，不各自忽略限制。
- 默认目录为账号根的 `.s5a9-test-budget/<机器名>`。可通过 `DFO_TEST_BUDGET_DIRECTORY` 指定本机统一绝对目录；账号根不可写时所有工作树应设置同一个可写目录，不能每个工作树各用一份预算。
- 等待默认上限600秒，超时拒绝启动。文件独占句柄与 owner token/PID/进程启动时间用于所有权核对；崩溃留下的非空未知记录须先人工核实。不得删锁、按TTL抢占或仅凭PID不存在自动接管，更不能终止不属于本任务的进程。
- 一个 permit 不允许内部再并行多个重型分片；同进程嵌套 Enter 拒绝，Exit 必须持原对象 token。释放前必须确认本任务所有重型子进程已结束，异常也走正常收尾。Linux helper 使用 subreaper/pidfd 核对自有后代，异常只停止已核实属于本任务的 children；收尾5秒后仍不能证明退出则保留租约并隔离，不以未知状态报成功。
- Linux supervisor 在终态收据旁写入 `<receipt>.live/` 独占目录：启动前、启动后及目标间隔原子发布不可变序号身份检查点（最多256份、每份64KiB，每份至多128个已观测后代；仅诊断截断，不改变实际回收）。目标周期为 `max(1秒, timeout/240)`（扫描与I/O可能延迟，并非墙钟硬时限），默认1800秒超时对应7.5秒；达到上限显式失败并由原 supervisor 收尾，包含本轮 executionId、调用规格摘要、supervisor/父进程/root/已观测后代的 PID namespace 身份。路径须新鲜且目录无链接；目录同时为独占运行 claim，失败竞争者不得发布终态。发布经 dirfd 锚定并同步文件及目录，不覆盖任何已有序号；写入失败进入原 supervisor 的异常清理，不继续无检查点执行。不保存原始命令或环境。live 始终为 `unknown`、`terminalProof=false`，即使另有成功终态收据也不改写为通过；SIGKILL 可能留下过期或不完整 live，其存在、缺失、时间或 PID 不证明进程退出。只有本轮终态收据的原 subreaper 回收证明可用于正常归还预算；旧 namespace 不可见、缺终态或未知锁仍须保留隔离，不能凭新检查点自动清除。

- 这是同主机协作式固定并发预算，不是动态RAM调度、跨容器/网络文件系统锁或对恶意进程的安全边界。跨账号必须由操作者配置同一本地目录和正常权限；未配置时不能宣称全机所有账号统一限额。
- 预算 permit 本身不依据内存测量进行动态准入。监督器另有只读观测：Linux 收据 `memory.sampledPeakRssBytes` 是自有后代树 VmRSS 总和的离散采样最大值，目标间隔100毫秒、排除监督器；漏读整轮跳过，无有效样本为 null/unknown，有样本仍是 partial-sampled。短命进程和间隔峰值可能漏测，共享页可能按进程重复计入，不能称瞬时峰值、private bytes、累计分配或硬内存限制。Windows 的 `peakJobCommitBytes` 来自 Job commit 计数，不是 RSS，且原生未验。观测不改变并发许可、结果或未知后代隔离规则；Linux 验证不能替代 Windows/macOS 文件锁验收。

## 结果库与稳定产物容量

`Tools/Inspect-DevelopmentStorage.ps1 -Store <结果库> -Repositories <工作树路径数组>` 只读列出共享 Store 与显式列出的各工作树 `build/development`；不自动查找其他工作树。Store 按 runs、records、locks、other 分组，稳定产物单列。文件数与逻辑字节按路径累计，不是物理磁盘使用量；硬链接和重叠根可能重复计数。根缺失为 absent/零，不会创建目录。目录链接、reparse point、不可读/特殊文件、损坏或超过 1 MiB 的 Store JSON，以及超过默认 100000 条目的扫描均报 unknown，不追随链接；可用 MaxEntries 显式调整观测上限。JSON 可解析不证明收据有效，结果复用仍走原完整校验。

可给清单传 `-MaxBytes` / `-MaxFiles` 检查阈值；真正执行通过 `Test-Development.ps1 -Action Run -StorageMaxBytes <逻辑字节上限> -StorageMaxFiles <文件数上限>` 接入。0 表示该项未启用；默认两项关闭，不增加扫描开销。启用时，任何 unknown 或任一已启用阈值达到/超过即返回 blocked（退出码2），在 profile 查询、缓存锁、创建 run 或构建前拒绝；不因选择 UseCache 而绕过。当前 Run 只扫描所指定 Store 和本工作树，不替其他工作树预留空间。

这只是非原子的执行前准入，不是硬磁盘 quota、空间预留或运行中限制：已有任务/并行写入、等待预算后的增长和单次新任务都可能使运行后超限。应为峰值增长留余量，必要时用操作者配置的文件系统配额；清单不能证明磁盘可用空间。锁只计数，活动状态始终 unknown，不试占锁、不根据时间/PID推断闲置；扫描也不是针对恶意并发换链的安全边界。原生 Windows/macOS 尚未验收。

Store 与产物由运行操作者负责生命周期，当前没有自动淘汰或 TTL 删除。人工保留/归档必须先确认相关执行、后代和写入者全部终止，并保存可追溯完整证据链：runs 的原始日志/收据、records 的成功与失败记录、started/completed、invalidations 不可选择性清除，不得只删红证据而使旧绿复活。锁和未知终态不得为了腾空间删除或重置。需要退役结果库时由操作者显式切换到新的空 Store，并完整保留旧库为只读归档；新库是 cache miss，不导入挑选后的旧绿。稳定产物只属于原工作树，人工处置前还须确认其 execution.lock/未知终态已按原规则核实；不能凭清单把产物判为可删。上述人工操作需单独授权，工具不执行。既有 `build/tcp-tests` 清理合同不扩展到这些目录。

## 计时解释

组 `ElapsedMs` 包含整段执行，不是纯断言 CPU 时间。fixture 启动时间和顶层共享资源 Lazy 计时包含在其中，且可能重叠；资源指标不覆盖所有内部惰性读取，不能把相减余数都归为业务计算。组末 RSS/PrivateBytes 是快照，不是进程树峰值；累计分配不是同时占用。不能把不同时间的父子峰值直接相加当作真实峰值。

## 构建测量（不拆程序集）

`Tools/Measure-DevelopmentBuild.ps1` 默认只生成计划。Cold 使用全新独立 `build/measure/<子目录>`，不会清理 OS/NuGet 缓存；WarmUnchanged 复用其成功基线。WarmChangedTest 只接受专用 `build/measure/<实验>/executor` Git 工作树及同目录的独立 `baseline` / `changed` 冻结 Git 源码，通过 `-BaselineSnapshotPath` / `-ChangedSnapshotPath` 指定。两个冻结源必须只差一个已存在的 `-ChangedTestFile`（SelfTests C# 文件）；执行树与 changed、此前成功基线输入与 baseline 必须逐文件一致。先在 executor 对 baseline 内容完成 Cold（可再测 WarmUnchanged），再由调用者只替换指定测试文件为 changed 内容，在同一私有产物目录测 WarmChangedTest；工具自身不修改任何源码。冻结源不参与构建，不共享可变 bin/obj。各阶段前后重新核对源码和两个快照；这不是操作系统不可变快照，调用者仍应冻结输入。任何额外源码/工具/SDK/环境或产物变化都会拒绝可比较结果，不允许修改活动开发树制造实验。

每段保留 binlog 与 MSBuild PerformanceSummary；Csc 包含分析器执行，无法据此分离分析器时间，目标与任务时间可能重叠，不能相加。产物记录内容哈希与 UTC 写入时间，并列出相对成功基线的变化，帮助区别依赖复用和重新生成；时间戳不代替源码/产物身份。阶段耗时不包含工具扫描/哈希开销，不代表完整入口总耗时。未实际执行的场景不能声称已有提速证据。

输入扫描每次仍检查文件及全部祖先，并流式读取完整内容；不缓存目录安全判断、mtime 或摘要。文件系统调用替代逐层 PowerShell provider 调用，读前后拒绝可见的链接、长度、时间戳或属性变化。前后观测不能证明文件系统事务快照，也不能排除观察间发生并恢复的替换；调用者冻结输入的要求不变。输入扫描耗时与编译阶段分开报告。

`EntryElapsedMs` 从脚本主体开始计到最终收据序列化前，包含输入核验、预算等待及全部阶段，不含 PowerShell 启动或最终收据写入。`InputSnapshotChecks` 记录完整输入扫描的尝试、完成、失败、已哈希文件次数及累计耗时；重复核验同文件也重复计数，不是唯一文件数。它不含另行产物扫描和时间戳读取，不与阶段相加充当外层总墙钟。已建立测量现场后的失败也记录这些数值；建现场前的参数/输入拒绝仍可能没有收据，不能当作耗时为零。

Warm 复用还要求先前产物和未改源码的 UTC 写入时间一致（收据使用 UTC ticks 避免 JSON 日期自动转换）；指定 changed 文件必须晚于基线产物而不在未来。仅 touch、旧时间戳覆盖都不能作为可靠增量测量。它不依据 DLL 内容哈希推断 Csc 是否执行，必须同时核对 PerformanceSummary/binlog 的执行或跳过事实。三个步骤复用正式 `Invoke-DevelopmentChild`，由原 Linux subreaper 在 `waitpid` 返回 ECHILD 后确认后代收束；未知终态保留 permit。阶段耗时包含监督器启动、输出排空与读取收据，不是纯 dotnet 时间。

只有负责人明确批准测量窗口后才考虑 `-Execute -ApprovedWindow ... -InputsComplete`。参数本身不代替授权，InputsComplete也不是自动依赖证明。当前执行采样只验证Linux，其他平台只生成计划。模块自身申请预算，不再外层重复占permit造成嵌套等待；同源/工具/环境前后不一致不得记录可比较结果。

阶段分Restore、求值探测和BuildNoRestore，后者不等于纯编译器时间；应从binlog检查Csc/CoreCompile与跳过原因。编译器CPU配置仅作用Csc环境，不扩散到测试运行时。源码程序集不拆分、不禁分析器，日志/binlog可能包含本机路径或配置，不直接发布。

## 交付要求

报告当前源码与产物身份、实际执行/复用、覆盖边界、失败与未运行项。完整验收前按原入口补齐所需完整 core/资源/TCP；自动化通过不等于 Windows 原生客户端验收。部署、合并、清理及停止其他实例仍按各自授权，不因采用本流程扩大权限。

## 保守断点续跑

`Tools/Resume-DevelopmentTests.ps1 -Store <结果库> -ReceiptDirectory <单轮独立逐组收据目录>` 默认只计划当前源码的默认TCP组；`-Scope Targeted|Survey|All` 分别选择额外定向、资源普查或全部登记组，也可 `-Scope Explicit -Groups <实际组名>`。组表从当前源码读取，不硬编码历史组数；首版钉住已审核注册入口文件指纹，该文件变化须重新审核，不能按不完整C#文本解析静默漏组，未审核时使用原CLI完整入口；不接受别名，普查不会混为默认全量。

`-Run` 重新采集并核对计划，再把剩余组交给 `Test-Development.ps1 -Action Run -Mode Dev`；不自行再申请重型许可。Configuration、BuildProfile、PvfPath、BudgetDirectory 传递给现有入口；平台限制不因续跑而解除。空剩余组只表示该选择范围由已验原执行覆盖，不是新实跑。

当前只有无PVF的 `chat-rate-rules`、`equipment-power-rules` 与 `frame-crc-rules` 已审计输入闭包可逐组独立核销，且须传 `-Runner <实际DfoServer.dll>`，核对其整个运行包、实际源码/环境输入、Store不可变成功记录及独立逐组收据。命令不接受手填源码/输入hash、PASS文本或已编辑计划作为证明。没有实际Runner、闭包不明或多数旧组coverage为unknown时仍列remaining，不能承诺现阶段通用大套件都可跳过。

Schema2完整、无skip、执行/产物/输入一致只是必要条件；同组存在任何失败、partial、running、中断或不同身份记录均保守重跑并保留风险，旧绿不覆盖它们。损坏/过大/链接收据拒绝计划，不能静默当没有失败。请指向单轮逐组目录，不能把数据库、一般日志或整个结果库当逐组目录。默认/定向/普查、covered/remaining及原收据路径各自列出，计划本身不是全量通过。

`dotnet <实际DfoServer.dll> --selftest-tcp-list-json` 从运行程序集的同一注册表导出默认、定向、普查及别名，保持实际执行顺序，在配置/资源/SQL装配前返回。它必须单独使用，不接受运行参数；输出仅是registration-only，不是执行或覆盖证明。Runner身份不明的宿主返回null，不能假借旁置DLL；工具仍须独立核实际产物与构建来源。此命令为后续计划器提供正式注册接口，不授权导入手写JSON跳过测试；当前保守脚本仍使用已审核源码入口指纹。

## 迁移测试的轮内空库准备实验

`DFO_SCHEMA_RELEASED_TEMPLATE=1` 仅为 `DatabaseSchemaTests.Run` 的已发布版本迁移循环开启本次调用私有的关闭空库模板。未设置或其他值仍逐版从零建库。模板不跨轮、不接受外部库、不共享可写连接；复制前检查 SQLite sidecar，目标不得已存在，复制后仍正常构造仓储校验。创建时核对当前版本、基线、完整性、外键、WAL 和全部非元数据表为空；fresh 等价、副本隔离、已有目标拒绝、业务种子/错误版本/源与目标 sidecar 拒绝合同随实验模式执行。

开关只减少各旧版本夹具最初的当前空库准备；版本范围仍为 `1..CurrentVersion-1`，原 rewind、预条件、真实迁移、拒绝、回滚和重开断言不省略。新库、失败清理、并发初始化及外部旧库样本路径仍 fresh；这不是数据库测试结果缓存，也不改变 core/TCP 收据资格。所有私有对象随原 `Run` 临时目录清理。

`[schema-released-preparation]` 输出实际模式、完成版本数，以及 setup、prepare、rewind、migration_checks 的毫秒数。setup 包含模板构造和准备合同检查；prepare 包含复制（若启用）与正常仓储构造；migration_checks 包含循环内迁移、拒绝和重开。循环之后的三种链回滚不计入这些分段，仍属于整组耗时；日志输出不能证明整组终态。收益必须用同一冻结源码/包的 fresh 与实验模式对照，计入 setup、复制及校验成本。未经同条件验收不默认开启，不把准备复用报告为测试跳过。
