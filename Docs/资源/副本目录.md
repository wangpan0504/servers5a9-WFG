# 副本目录与迷宫资源解析

本功能读取匹配 S5A9 x86 的 PVF，为副本准入与地图初始化提供资源数据。选图请求、正式玩法与诊断入口的当前状态见[副本模块](../模块/副本.md)，包体与响应顺序见[副本协议](../协议/副本.md)。资源解析通过不表示角色已经解锁副本、能够进入地图、完成战斗或发放奖励。

## 检查入口与身份

按[开发环境](../开发/环境与配置.md)将匹配 PVF 放入固定目录，从仓库根目录执行：

```powershell
dotnet build ServerS5A9.sln -c Debug --nologo
dotnet Server/DfoServer/bin/Debug/net10.0/DfoServer.dll --inspect-dungeon 3
```

检查命令为 `--inspect-dungeon` 和一个非负整数索引，运行参数须放在命令之前；缺失、溢出、负数、错位或混用其他开关在读取资源前以退出码 2 拒绝。副本索引属于 `dungeon/dungeon.lst`，不是世界地图、地图或客户端名册索引。索引是否存在由实际目录判断。

[ServerApplication](../../Server/DfoServer/Application/ServerApplication.cs)校验启动参数，从程序目录的 `Data/Pvf/Script.pvf` 读取资源，输出 JSON 后返回。检查入口位于城镇与角色加载、角色库初始化、`server.lock`、Repository 及监听之前，可在服务使用同一角色库时只读检查资源。地址、端口参数仍须有效。

资源按内容解析。源码不携带实际 PVF 或导出的客户端资源。

## 安徒恩正式团本与备用索引

[DungeonCatalog](../../Server/DfoServer/GameWorld/Dungeons/DungeonCatalog.cs)只从`dungeon/dungeon.lst`和`map/map.lst`建立生产目录。`dungeon/tutorial/dungeon.lst`中的路径仍相对`dungeon/`根；`tutorial/`是列表所在目录，不是DGN路径前缀。备用表仅供[安徒恩资源检查](../../Server/DfoServer/GameWorld/Raids/RaidResources.cs)读取引用，不会合并进生产目录，也不会从MAP文件名、`[dungeon]`归属或DGN编号生成数字MAP登记。

匹配资源的备用表明确登记210–216、218–224共14项：第一阶段为Close_Blacksmoke、Close_Blacksmoke2、Strongleg_High、Strongleg_Lower、Strongleg_High2、Strongleg_Lower2、Fleet_Fire；第二阶段为EnergyCut、BlackVolcano、AntonHeart及Hatchery1–4。对应DGN均存在于`dungeon/anton/phase1/`或`phase2/`。这些ID均缺正式`dungeon.lst`登记，DGN显式引用的72个不同MAP数字也均缺正式`map.lst`登记。脚本存在不等于数字索引可加载。

正式Runtime通过`AntonRaidMapPaths`显式注入73项有证MAP登记，普通主目录不改写。除DGN直接引用的72项外，原始编号表在`Gloria-GK-406/DNF-JP-86-Server`提交`1cff7218ddff1570dcd48eb07b779283ee7c6542`的`Document/abyss-research-20261007/evidence/upstream-pvf-map-lst.txt`明确登记`19206 → 219_BlackVolcano/19206(6,0)S.map`；当前PVF该MAP声明`[dungeon]219`、`[type][normal]`、`[greed]BB BB`。`phase2/blackvolcano.dgn`的起点为`(0,1)`，greed为BB，该格没有显式map行。团本目录复用既有`DungeonMapPool`按真实归属、种类和greed补入19206，坐标保持DGN的`(0,1)`，不使用文件名中的`(6,0)`推断迷宫坐标。未提供显式增量表时不反扫文件名生成编号，未知或冲突登记仍拒绝。

## 分块地图声明

同一普通maze允许多个完整闭合的`[map specification]`块，但不同块的坐标必须互不重叠；按源顺序累积供原地图解析器处理，`RawSections`继续保留原始块。依据为匹配客户端`0409C8CE..0409CC6A`逐格写入同一maze，而非在块入口清空全部格子。块内原有同种覆盖、普通/Boss独立候选及剧情阶段合同保持不变；跨块同格、空块、未闭合块、越界坐标和重复size/start/boss等其它布局字段继续拒绝。

遗忘之地4000的两个不重叠块共86格可解析；解析通过不授予特殊入口或普通拓扑资格，仍需实际准入规则和玩法地图合同。

maze内`[clear condition]`的`[limit time]`由匹配客户端`04080543..0408055E`识别为条件类型5，两个整数分别由`04080647/040806A5`写入条件`+4/+8`。解析器只确认两个原始值，不证明初始时长、延长上限或活动时长政策；不能与DGN顶层同名标签混用，后者在`040AA578..040AA58B`只读取一个整数到定义`+0xD98`。正式限时通知与结束消费者见[副本协议](../协议/副本.md#限时通知603)。

## 祭坛波次资源

[MapAltarWaves](../../Tools/PvfLib/Models/MapAltarWaves.cs)读取成对的`[blood monster]`/`[blood phase time]`及`[ultimate monster]`/`[ultimate phase time]`，由`DungeonRoomCatalog.AltarWaves`保留。怪物行是十整数；阶段行按`int/int/int/float/int/int`读取，极限祭坛额外的A至E标签映射为1至5。普通地图没有该声明时返回null。重复、未闭合、混合类型、嵌套条件、截断行、错误类型和越界怪物引用均拒绝，不静默截掉后半段。未恢复的整数保持原序，`RawFactor`不直接充当服务端属性或奖励倍率。

格式依据为匹配V31客户端（SHA256 `7560188d4bac4a33690fe3b37069f365885f7f57e14cee868b64103852f28471`）的04277964及04277B50解析分支。真实17030地图有20个怪物声明、20个阶段行、七轮和A/B选择；无尽祭坛七个当前候选各有五轮，阶段行数可以不同于怪物声明数。实际资源回归在`DungeonRoomCatalogTests`中覆盖这些候选。

## 3145普通怪物的掉落声明

实际地图中的模板1对应 `monster/goblin/goblin.mob`，模板2对应 `monster/goblin/goblinthrower.mob`。二者 `[item]` 块均为六个整数 `1000 50 1047 200 1004 100`，并由 `[/item]` 闭合；哥布林另有空的 `[common champion drop item]` 块。三个物品分别由 `stackable/food_strawberry.stk`、`stackable/ftcoin.stk`、`stackable/plant_lamihwaleaf.stk` 定义为野草莓、命运硬币、苎麻花叶，均有堆叠上限1000与地面图像。命运硬币是消耗品，不是角色金币余额。该事实证明存在明确的物品条目及关联参数，不能以持续零掉落替代掉落实现。

[DungeonMonsterDropCatalog](../../Server/DfoServer/GameWorld/Dungeons/DungeonMonsterDropCatalog.cs)从匹配 `monster.lst` 解析声明，共享只读结果，保留模板、路径、物品顺序、重复行和原参数。缺失块返回null、显式空块返回空集合；畸形整数对、未闭合或未知嵌套条件拒绝。重复块逐块保存，`Items`与`CommonChampionItems`分别提供首块；本服参考策略只抽取首块，不能把萨乌塔等脚本的重复声明累计为双倍权重。目录不抽奖、不分配地面对象、不发通知或写背包。资源回归见[DungeonMonsterDropCatalogTests](../../Server/DfoServer/SelfTests/DungeonMonsterDropCatalogTests.cs)。

参数50、200、100由目录原样保留；当前本服参考策略把首块正参数作为候选权重，在独立10%触发后选一件，不将它们直接当作百分比。Boss模板107000903和同房普通模板107000906没有该块，仍可按全局资源策略生成各自等级与类型的候选，不能复制哥布林显式池。通关结算与任务奖励属于独立合同。

[DungeonItemDropCatalog](../../Server/DfoServer/GameWorld/Dungeons/DungeonItemDropCatalog.cs)从共享ItemCatalog枚举正`creation rate`的普通装备、消耗品、材料及副职业材料，按Kind/grade/rarity建只读索引。装备复用导入覆盖解析；候选模板解析失败不静默删行。`Pool`保留精确类别、范围及原权重；默认策略使用`ReferencePool`，堆叠品等权、装备按脚本权重，允许明确的同类稀有度及最近较低装备grade回退。`ItemResources`按资源生命周期共享该目录，服务/测试重建不另扫全量候选。当前PVF的`(R)ItemDictionary`不使用90参考的列偏移推断生成权重。具体计算与兼容范围以[默认资源掉落规则](../模块/单人副本实例.md#普通地面掉落与拾取)为准。

[DungeonSpecialDropCatalog](../../Server/DfoServer/GameWorld/Dungeons/DungeonSpecialDropCatalog.cs)读取`etc/independent_drop.etc`的17整数记录、难度概率/次数、等级/难度条件和内联物品权重，也读取`etc/worlddrop.etc`的等级、第二列及`-1`结束的候选对。零权重及未知列表引用原值保留；业务只消费普通怪物的直接/内联分支，引用2、其他enemy type和世界第二列提供兼容统计。存在的资源格式损坏明确拒绝；缺少可选文件单独记录，不伪造列表。

## 数据与边界

房间目录保留`[special passive object]`父子结构：每个父行四个原整数与子数量，每项子类型字符串及五个原整数，原序、位置、怪物路径和非怪物机关规则均独立冻结。不为`[trap]`、`[item]`或未知子类型伪造怪物或地面掉落；未知宽度和越界数量拒绝整块。特殊父对象由客户端原地图脚本解释附属规则，解析结果本身不证明互动和奖励已支持。

普通`[passive object]`属于客户端本地创建集合，目录未列出的正ID保留全部四整数原行、`Path=null`与`UnresolvedReason=passive-object-unlisted`，不替换ID或删除位置。匹配58581的2109006955、58589的89092均确实未列入`passiveobject.lst`；客户端创建查找失败沿[已核对分支](../协议/副本.md#客户端本地被动对象缺失分支)继续后续行，因此不作为普通实例怪物/费用资格失败。负ID、畸形字段、已列入目录但缺文件、特殊父对象或怪物缺引用仍拒绝；任务专用准入保留原未解析拒绝行为。

[DungeonCatalog](../../Server/DfoServer/GameWorld/Dungeons/DungeonCatalog.cs)读取 `dungeon/dungeon.lst` 和 `map/map.lst`，按副本索引按需解析资源。最低等级、基准等级、重复的 `[maze info]`、尺寸、起点、Boss点、显式地图条目及任务关联保留各自含义；不把后一个maze覆盖前一个，也不自动选择任务变体。

`[dungeon type]`由目录统一解析为`DungeonDefinition.DungeonType`，取最后一次声明的单个type6字符串；未声明或末条格式无效时为null，未知字符串保留原值，全部原始声明仍在`RawSections`中。强袭任务资格与退图豁免共用此属性，不在各玩法中另行解码。

无参数`[no fatigue]`单独解析为`DisableFatigueConsumption`并冻结到入场计划，重复声明仍为开启。`Fatigue`指每日基础156点、黑钻扩展到188点的疲劳值；该标记使普通路线不要求剩余值大于零、首次房间加载不扣余额、不写扣点receipt且不累计应耗疲劳值，但仍要求原疲劳值owner完整。它不代表`Stamina`退图虚弱豁免，也不授予战斗道具或复活币免耗。`df_game_r`的`ImportDungeonScript`（088E5FAA）将该无值开关置位，`CDungeon::isNoFatigueDungeon`（0822B4DE）由选图准入（081C8102）和`CParty::canFatigueUp`（085A8C88）消费；本服沿既有`UsesFatigue`统一控制准入余额、实际扣点和Run应耗量，不另建疲劳值账本。

目录按下表生成`DisableGiveupPenalty`，入场时冻结到`DungeonEntryPlan`，退出时不再扫描PVF。不同标签不互斥，任一有效条件成立即免罚；同一数值型标签及`dungeon type`按后值覆盖，无值开关重复出现仍为开启，不因重复本身拒绝。该区别与`df_game_r`的`ImportDungeonScript`（088E5FAA）一致：event/ancient/blood直接写入对应字段，类型分支更新单一类型，无值tower of despair只置位。下表是本版支持清单，不表示参考二进制已包含所有95版标签。

| 声明 | 免罚值 |
|---|---|
| `[raid dungeon]`、`[risk dungeon]`、`[operation hope dungeon]`、`[event dungeon]`、`[ancient dungeon]` | 单个整数1；0不启用 |
| `[blood dungeon]` | 单个整数1或2；0不启用 |
| `[raid normal dungeon]`、`[dimension dungeon]`、`[tower of despair]`、`[enable give up]`、`[anton dungeon]`、`[no giveup panalty]` | 无参数标记 |
| `[dungeon type]` | `tower of dazzlement`、`tower of death`、`boss rush dungeon` |

单条声明的未知格式、未支持数值或其他副本类型不自行产生豁免，也不抵消其他标签的有效豁免；同名数值末条关闭后不再沿用前值。`[no giveup panalty]`通用于所有副本，不限定为职业体验；拼写沿用资源原名，匹配客户端字段及提示消费者见[退图虚弱确认](../协议/副本.md#退图虚弱确认)。普通`[no fatigue]`不授予退图免罚资格。资源豁免只用于[退图惩罚](../模块/背包与装备.md#魔王契约八项服务)，不扩大副本准入、疲劳、道具消耗或玩法支持范围。

零参数 `[Beast dungeon]` 是独立模式边界，结束前一条普通迷宫；其后尺寸、地图和Boss字段不归入普通 `Mazes`。历史资源中的该模式已经退役；保留区块边界识别和 `RawSections` 原始声明仅用于正确解析相邻普通及剧情路线，不生成可入场的专属玩法。同一普通迷宫的重复尺寸、带未知参数的模式边界及未确认的地图类型仍拒绝，不能用忽略重复字段代替作用域解析。

`[room move keep state]`与`[individual map movement]`分别解析为独立标志，仅末次声明的单个整数1为true，原始token继续保留。匹配客户端前者写入DGN+3F0（`04096509→0409CFB7`），后者写入DGN+9FA（`0409979A→040A34DA`），再由`02A36FD6`复制到副本Runtime+7B0。两者不能互相代用；资源字段识别不等于加载计数任务已经启用。

起点和Boss点允许资源声明多个坐标。缺少显式 `[map specification]` 的结构保留为不支持固定地图初始化的资源表示，不能解释成有效空地图。显式条目按本版 `map` / `boss` / `layered` 结构校验坐标和地图引用；叠层保留在独立`LayeredMaps`集合，普通拓扑只使用`map`和`boss`行，正式路线再按任务声明选择叠层终点，不把同格候选替换为普通或Boss图。未知其他类型仍拒绝；同一副本无叠层的普通maze可独立解析，不被这些任务变体阻断。

没有有序Boss剧情阶段时，同一坐标、同一种类的重复行按末行完整覆盖候选列表，不拼接为随机池。匹配ARAD的`0409C98C→0407D9B0`按坐标取格，`0409C9B9`清普通候选（格内`+4`），`0409CA2A`另清Boss候选（`+0x18`）；同格`map`和`boss`不互相覆盖，另一种类保留于`MapAlternatives`。D85任务3553的`(5,1)`仍使用92470，92467保留在只读`OverriddenMaps`和原始区块中，不参与该显式行抽签。反向地图池资格由MAP自身声明决定，不能仅因模板被任务、叠层或旧行引用就将其排除。

悲叹之塔5115的专用资源补图仅接受已核验的精确DGN声明、1×1 BB及唯一normal100247反向归属/路径/BB BB；拓扑发布一个ExitMask0房间和空Links，原始Greed不改写。显式图、任务连接、叠层、其他类型/布局或多候选保持不支持；普通BB越界仍拒绝。该资源合同不提供正式准入资格，当前EntryPlan继续明确拒绝悲叹模式，详见[副本模块](../模块/副本.md)。

普通及深渊迷宫在入场规划时由[DungeonMapPool](../../Server/DfoServer/GameWorld/Dungeons/DungeonMapPool.cs)选择起点、Boss候选并补齐缺失房间。地图通过自身`[dungeon]`归属、`[normal]`/`[boss]`/`[dummy]`类型及`[greed]`出口反向注册，不强制DGN提供`[map specification]`。选中Boss格优先使用该格的显式Boss候选，其他格优先使用显式普通候选，再按对应反向池补图；最后复验完整静态连接。深渊沿同一组格入口，避开密门占位的起终点候选，再替换密门图；不改变票据、波次或奖励规则。任务关联迷宫不从普通池猜补剧情图；缺少真实候选、越界、出口不匹配或不可达仍不发布路线。目录在锁外按需加载并共享。

`[dummy appear count]`与已注册的MAP级`[dummy]`共同生成假Boss阶段。`df_game_r`的`CDataManager::load_map_files→CDungeon::InsertMap`（0834B988）按MAP自身归属注册dummy；`SetGridPath`（082FFB30）随机选择初始目标，再按次数选择后续Boss候选，仅避免相邻阶段重复坐标。`get_candidator_map`（08308214）按当前目标区分普通与Boss候选，`choose_random_bossmap_from_dummymaps`（08307ECA）仅在目标格选择dummy。本服保留显式行完整候选至用途确定：有dummy阶段时，普通身份从同位置候选中的`[normal]`选择，dummy阶段从其中的`[dummy]`选择，缺少该类显式候选才使用反向池；普通模板全缺时借用dummy场景并由演员规划排除假Boss，不把降为精英等同于不生成。该类型筛选是本服对显式混合候选的补全，不声称旧端逐项执行了相同过滤。D51默认两次假Boss，之后选择真Boss图；阶段地图与演员在入场规划时一次冻结，不在持有账号锁的过房请求中读取PVF。阶段是同一Run内的独立地图身份，不复用旧演员key，也不改角色库结构。

匹配客户端 `04274205..0427431B`确认地图`[greed]`每项保存两个值。当前地图池只启用两个值相同的AA..PP声明及完全相等的出口掩码；不对非对称二元组推定兼容规则。原始查询继续保留尚未生成的迷宫状态，生成成功也不等于对应地图已通过实机验收。

`[greed]` 原文通过 `DungeonMaze.Greed` 保留，实际资源查询和 `--inspect-dungeon` JSON另提供[类型化GreedGrid](../../Server/DfoServer/GameWorld/Dungeons/DungeonGreedGrid.cs)。依据[门墙通路证据](../协议/副本.md)，当前只接受相同ASCII字母对 AA..PP，输出索引0..15、原文UTF16偏移和线性消费次序。受支持解析策略仅在编码边界跳过 CR、LF 和ASCII space；不使用 `char.IsWhiteSpace`、不转换小写、不抹掉一对字母中间的空白、不扩展另一Unicode表。该策略用于资源读取，不声称执行或模拟整个原生加载函数。

Width/Height保留资源声明并校验总格数等于width×height，换行只作为分隔符。未知字符、残缺字母对、格数不匹配和非法维度产生 `GreedGrid.Supported=false`、`Cells=null` 和具体 `UnsupportedReason`，原文仍保留；不发布部分格，不用AA/0补齐。一个未知Greed文本不使同一副本的其他maze整体解析失败。Greed不是单个type6字符串等尚未支持的脚本结构仍按原定义拒绝。

`DungeonMaze.StaticTopology`通过[静态连接检查](../../Server/DfoServer/GameWorld/Dungeons/DungeonStaticTopology.cs)将行主序`width*y+x`及左/右/上/下位4/1/2/8应用到资源，依据为匹配ARAD完整查询与方向消费者原码对拍。它要求非零格与显式地图一一对应、出口目标位于网格内且有地图及对侧出口、起点/Boss存在且所有房间可达。重复地图候选、缺声明、未知编码、单向或孤立结构均产生具体Unsupported原因，并置Rooms/Links为null，不发布部分连接。Rooms保留完整地图身份和ExitMask，Links每条双向连接只发布一次，集合只读。

`MapStructure=explicit`、`GreedGrid.Supported=true`和`StaticTopology.Supported=true`分别表示资源结构或静态一致性，不是正式准入、可玩性或approvedRoute。对侧出口检查是静态一致性要求，不宣称已恢复客户端全部单向/特殊传送规则。地图内动态机关、关闭门、怪物、战斗及费用仍须独立验收；资源查询不建立生产实例，不改变已有诊断进图流程。

任务关联保留原token类型与值，type5/7引用不经文本占位丢失。匹配Dungeon3的SourceOrdinal已与[NOTI28的maze索引消费者](../协议/副本.md#maze-索引)核对；资源顺序仍不提供任务、解锁或费用资格。`TryGetDesignatedDifficulty`只读取唯一、单整数且范围0..4的`[designate dungeon difficulty]`，缺失、重复或引用未知均返回未确认，不能默认补普通难度。难度准入在没有`[difficulty level]`时接受明确的指定值；另有`[difficulty]`时必须同值，未知或冲突不放行。故事块查询仍保留自己的`[difficulty size]`及任务归属；正常任务路线额外使用地下城已开放难度的规则见[副本模块](../模块/副本.md)，不把属性表档数直接作为正常任务准入上限。角色任务、解锁、组队、费用、实例生命周期与成功包序依各自业务合同接入，资源对象不提供准入成功结果。

普通路线的Boss坐标与`map`/`boss`候选种类分开解释。匹配客户端`02A17ABB`先检查当前坐标是否为Boss坐标，`02A17AC4..02A17AD3`仅在Boss候选非空时选择格内`+0x18`列表，否则`02A17AD5..02A17AE4`回退`+4`普通列表。安徒恩9595及超时空之战400000016在Boss坐标只写`map`，仍使用该行的原地图；本次领域计划的Boss投影不改归档定义或怪物品级，也不自行补空房间。

指定难度与`[difficulty]`是独立字段。`0409944D`注册`[designate dungeon difficulty]`，`040A2BFF..040A2C12`将整数写入DGN`+0x978`，`02A36D93..02A36D99`复制到实例`+0x6A8`；`029FF220`只检查它是否处于0..4。`029FF650`返回实例`+0x180`，所以`03BAC1FD/03BAC20D`读取的内部`+0x528`仍是同一字段，并将选图难度范围的两个端点设为该值；`03BAE906..03BAE91C`同样将选图参数替换成指定值。普通卢克只声明指定难度2仍能限定选择；这些静态消费者不等于客户端实机发包或进图验收。
