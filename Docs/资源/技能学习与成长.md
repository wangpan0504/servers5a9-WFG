# 技能学习与成长

本页维护 SP/TP 表、技能费用、等级门槛、前置及上限的资源读取规则。TP 表示特性技能点。普通创建的 CHR 初始技能见[角色创建](../模块/角色.md)，在线业务见[技能学习模块](../模块/技能学习.md)。Lv1 的 SP 为零，不通过赠点开启学习按钮；静态消费依据不代替实际学习、施放或升级验收。

## SP 表的加载与累计规则

资源路径为 `Etc/spTable.etc`，`028A92BD..028A92CC` 将 manager+8E8 作为输出传给 `03FB6120`。使用 `[sp table]`、`[tp table]` 两张表。

SP 标签分支 `03FB6269..03FB63E4` 先追加一个 DWORD 零，再按每对读取两次整数，仅将第二次结果顺序追加到输出+4/+8 的 vector。第一整数用于读取对结构，没有作为写索引。匹配 PVF 的第一列严格为1..200，第二列为对应等级的原值：Lv1=0，Lv2..10=30，Lv11..20=60，之后按原表分段。

实际累计函数 `028A6450(level)` 在 `028A64C9..028A64E8` 从该 vector 的 begin 取得 `begin+(level+1)`，`028A64F1..028A650D` 取得 `begin+1`，`028A6559..028A658E` 遍历半开区间并逐项相加，最终 `028A65CB` 返回累计值。迭代器 advance `01AE60D0` 的实际地址计算为 `elementPointer + argument*4`，不能把两个界限误读成等级差。

因此等级表贡献为 `sum(spTable[1..level])`，Lv1=0、Lv2=30、Lv3=60、Lv10=270、Lv11=330、Lv95=13320。此值是等级表累计贡献；当前可用 SP 还涉及学习扣点、退点及其他来源，不能直接用累计值覆盖角色余额。`028A7450` 调用累计函数并与 `02D7EAC0` 的可用数值比较；`0266FB0F..0266FB42` 在技能窗口中将该 getter 的返回与玩家虚表+41C传入的累计表结果用于比例显示。

TP分支 `03FB6424..03FB649A`建立200个DWORD槽，按每对第一整数作为索引，将第二整数写入该槽。匹配PVF声明50..100，每项1。服务端参考S4A21采用不超过当前等级的条目累加：Lv49=0、50=1、60=11、95=46；再加独立额外TP并扣feature技能费用。加载、费用和余额通知已匹配客户端，完整原版TP累计奖励调用链尚未闭合，累计发点模型应区分为参考端业务实现。

[SkillCatalog](../../Server/DfoServer/GameWorld/Characters/SkillCatalog.cs)提供SP累计、参考业务的TP累计与原始SP/TP条目，使用真实token类型及完整闭块校验。它不决定学习准入或费用，也不写角色状态。[C#测试](../../Server/DfoServer/SelfTests/SkillCatalogTests.cs)覆盖Lv1零、分段累计、越界与非法资源拒绝。

## 费用、前置与上限

技能资源重复声明学习标签时采用 external 的 `Document.Section` / `skill.parsePrerequisites` 首段读取规则：保留首次声明，不合并或覆盖后续同名段；首次声明为空也保持为空。每个需要结束标签的重复段仍须完整闭块，首次声明的字段类型、数值范围和前置整数对继续校验。该规则是参考端资源兼容行为，不从重复标签直接判定资源损坏并断开学习连接；重复分组元数据同样取首段，见下文槽位分组。

job0/skill5 `skill/swordman/hardattack.skl`的 `[purchase cost]`为15，`[required level]`为1，`[required level range]`为2，`[maximum level]`为60，`[growtype maximum level]`为六项50。实际switch `04238089`将EAX减136，上限F3，使用byte表 `04241FD4`与DWORD表 `04241F58`。沿真实表项到entry后，才在标签表flag `073CA8C8`非零分支进入下列读取；没有把标签登记附近的下一条尾跳转当作该标签消费者。

| 标签 / tagId | index byte VA / value | target DWORD VA | entry → 读取目标 | 输出 |
|---|---|---|---|---|
| purchase cost / 1A5 | 04242043 / 09 | 04241F7C | 04236216 → 04238773 | +54的加密整数vector，逐项追加 |
| required level range / 1D2 | 04242070 / 0E | 04241F90 | 04236360 → 04238CFA | +AC的加密整数scalar |
| growtype maximum level / 21C | 042420BA / 1B | 04241FC4 | 042366BA → 0423968B | +14C起6个加密整数，每槽8B |

purchase cost 使用 `03DB1170`带success读取并将每项经codec保存，再 `0049E730`追加vector；这不是已证明费用只有一个scalar。range使用 `03DB1140`读整数，按输出地址低位分派codec写入；growtype上限同样读取6次整数。这些读取只解释资源字段的存放形状；普通费用和门槛还须结合下述运行对象查询链。

附近 `02D4FB80(player)` 从技能对象+D3C/D40另一内部vector读一个数，以 `02D4EAA0(0)`为索引；再从玩家虚表+B98返回对象+0C取得另一索引，读取技能+11C起的比例，存在 `trunc0(base*(100−ratio)/100)`路径。这条用于确认窗口数值的getter仍需恢复+D3C的标签归属及玩家输入；没有因窗口涉及购买就把它直接命名为SP费用。

已恢复资源到运行技能对象及发送前准入的进一步消费链：

- `04241847..042419DB` 取 maximum level 六槽的最大值；`04241A97..04241AC9` 在费用 vector 非空且长度不足时重复最后项补尾，长度更长时不截断。
- `02D6C477..02D6C481` 将资源+54费用 vector 复制到技能对象+90。`02D49B70` 按显式索引读取，`02D4F8E0` 普通状态按 `02D4EAA0(0)` 的已学等级读取；再应用职业比例、额外减免，最后取非负值。基础15不能一概解释为最终每级SP费用。
- `02D6C495..02D6C689` 将资源+A4/+AC复制到技能对象+B8/+C0；`02D4BEB0(targetLevel)` 普通门槛为 `base+(targetLevel−1)*range`。`02D52330` 以 current+1 查询，因此鬼斩已学1级时，学习2级的普通角色门槛为Lv3；特殊状态（premium 0x1B 达人契约生效）另有减5分支，且减五先于资源类型判断，feature TP 同样适用。
- `[pre required skill]` tag1DE沿真实switch进入 `04238F32`，把技能ID/所需等级写两条vector。`02D6C9B4..02D6C9D3` 将资源+CC/+E0复制到技能对象+D0/+E4；`02D4FEE0` 逐项查询已学技能并比较等级。
- `02D52330` 先校验已学等级、职业上限及另一转职上限，再校验普通角色等级、前置及SP/TP余额。已学等级低于任一适用上限即可继续，不能把两表取min。内部out=-1/-2/-3/-4属于本地UI结果，不作为ACK29错误码。

[SkillLearningCatalog](../../Server/DfoServer/GameWorld/Characters/SkillLearningCatalog.cs)据这些资源合同提供基础点数、普通等级门槛及原始前置/上限声明，[C# 资源规则测试](../../Server/DfoServer/SelfTests/SkillLearningCatalogTests.cs)覆盖16职业各自技能目录、repeat-last、鬼斩和非法声明。缺必要字段保持unsupported；已确认的缺省等级及间隔为1、缺前置为空、fitness默认零及feature/combo默认沿匹配客户端初始化路径。普通资源费用与第二成长上限已接入，TP及其它特殊状态的当前范围见[技能学习模块](../模块/技能学习.md)。`[active]/[passive]`只限定资源字段支持形状，不证明技能运行状态属于普通分支。

## 缺失标签默认与普通费用

成功 SKL 加载在 `04235CA1` 调用 `04231B60` 重置，再消费标签。因此缺失标签的默认值必须从重置路径取证：

| 字段 | 默认及消费者 |
| --- | --- |
| required level / required level range | `04231CA3..04231D54`将resource+A4和+AC初始化为编码整数1；显式range由`04238CFA..04238D83`读取覆盖。仅缺标签采用1，显式0保留，非法声明不回退默认 |
| pre required skill | `04231E73/04231E7E` 清空 resource+CC/+E0 的 vector；缺失即空前置 |
| growtype fitness | `04232130..04232194` 初始化 resource+11C 的六个编码整数为零；显式声明由 `04239512` 读取六项 |
| feature skill type | `04234A70` 初始化 resource+5FC 为零；`0423CF5B..0423CF60` 对显式整数 test/setne，非零为 true；`02D735D2` 复制至 runtime+E88 |
| combo set | `04234ACD` 初始化 resource+67C 为零，`04234AD3` 清空 +680；显式声明消费者 `0423E10D..0423E11A` 另设标志 |

`02D52558`根据runtime+E88分支：false使用SP getter `02D4F8E0`和余额getter `02D7EAC0`；true使用TP getter `02D4FA90`和 `02D7ECC0`。普通SP计算排除feature=true与combo根；job9/10使用各自资源规则。

TP成本来自`[special purchase cost]`整数vector，按当前等级索引，补尾重复最后一项，不应用普通SP的fitness折扣。`[combo set]`闭块读取至多六个子ID，用于黑暗武士免费根的初始连招；`[command customizing]`显式0禁用指令编辑，缺省允许。技能200–211在绑定阶段映射138–149，其费用和资格仍必须有合法职业资源，不因编号映射绕过学习校验。

`[command]...[/command]`的按键为类型5字符串引用，分隔符为类型7字符串引用；引用值不是按键枚举，必须先经PVF字符串表解析。`,`表示顺序操作，`&`将前一个方向转为按住方向；类型化默认指令使用[技能协议](../协议/技能学习.md)的按键整数。允许自定义的主动技能才提供默认投影，缺失/空声明不补键，单独JUMP/ATTACK不作为可安装的field4向量；`[command key explain]`是显示文字，不用它反推实际键序列。首个同名块沿已有Section规则读取，默认投影不成为玩家的自定义存档。

`[guild skill]`、`[expert skill]`均按标签存在置位，分别表示公会技能和特性技能；当前普通SP学习与固定赠技都排除这两类。达人契约的普通超等级资格同时排除公会技能，不把该标志解释为普通技能的费用参数。

`02D4F8E0` 的资源成本为按当前已学等级索引 purchase cost，按职业成长索引取 fitness，然后计算 `trunc(base*(100-fitness)/100)`；随后减 runtime+1100 并钳制零。runtime+1100 在 `02D67E54` 初始化零，setter 为 `02D48FD0`；普通 ACK29 成功 `023609AE` 将其清零。其他状态设置入口尚未完整恢复，故 `GetOrdinaryResourceSpCost` 明确只输出资源部分，不能冒充不受角色状态影响的最终费用。当前支持 fitness 六项且每项 0..100，其他形状或范围拒绝。

`04241A97` 将 purchase cost 补尾重复至最大 maximum level 声明长度；`02D4EAA0(0)` 给当前已学等级索引。普通下一等级门槛为 `required level + currentLearnedLevel * required level range`，调用链为 `02D52330 → 02D4BEB0(current+1)`。

| job0 技能 | 普通资源结果 |
| --- | --- |
| 5 鬼斩 | base15，费用补尾至60；已学1学习2要求角色Lv3；primary growtype cap50；缺前置为空，默认 SP、fitness0、非combo |
| 46 上挑 | base20，maximum20；已学1学习2要求角色Lv4；primary growtype cap10；同样普通默认 |
| 169 后跳 | base30，maximum及primary cap1；资源缺range时采用初始化值1，已有一级仍不能继续升级 |

`02D4C470` 只给 primary growtype cap。`02D52330` 的 cap 判断允许 current 小于 primary，或小于第二成长表 runtime+1D4 的对应项，属于 OR，不取 min。第二表按六职业、每职业两个觉醒阶段解释，共12项；当前普通上限取 primary 与对应 secondary 的较大值，最后受 maximum 限制。枪剑士三份资源只声明五组，未用的第六组保持零。

协议请求、响应和字段依据见[技能学习协议](../协议/技能学习.md)，当前支持范围、事务和验证见[技能学习模块](../模块/技能学习.md)。

## 类型与普通槽位分组

`[type]`显式保留`[active]`、`[passive]`和未知状态，不能只保存“两者均支持”的布尔值。被动仍是完整已学技能，不从技能树或Player等级投影中删除。

普通槽位分配参考S4A21与external服务端的行为：主动属于组3；被动`[skill class]=4`属于组2；class0–3且`[skill fitness growtype]`整数项不超过2时属于组1，多于2时属于组0。方向缺省为空vector，class0–3的空方向属于组1；class大于4沿S4A21的分组越界规则回退组0，涵盖本版第五转职的class5。缺失class采用匹配客户端初始化值0，显式空仍保持未知。初始被动沿角色初始布局放入102起的区域，后续新学习使用资源分组；具体范围及满组行为由[技能学习模块](../模块/技能学习.md#普通学习范围)维护。

`[skill class]`为tag20B，实际switch的byte槽`042420A9=18`指向`042365F4`，flag分支进入`04239484..04239508`，读取整数并写resource+110的编码标量。加载前重置`04231EF2..04231F4B`将同一标量初始化为0，EDI零值来自`04231B8F`；不能把标签登记后的相邻`04239512`六项fitness读取误认作class消费者。参考端`skill.parseSkill`的`firstIntValue`同样对缺失class返回0。仅缺标签采用该默认，显式非法元数据不使用默认遮盖。

`[skill fitness growtype]`的项数仅参与槽位分组，与`[growtype fitness]`六项百分比费用折扣分别读取，不作为职业学习门禁。费用、前置与既有成长上限继续沿用上文合同。特殊职业初始化与固定映射规则见[技能学习模块](../模块/技能学习.md#tp与特殊职业)。

分组标签重复声明时与其它重复标签一致取首次声明：`[skill class]`和`[skill fitness growtype]`都按首段读取，后续同名段不合并、不覆盖，空首段保持为空，重复事实登记在`UnsupportedFields`仅作诊断。据此禁用分组会让极·神剑术（job0/skill239）等9个被动因分组为空而永远学不了——这些资源把`[skill fitness growtype]`写成两段，其中首段为空。主动分组仍由type确定，class4被动不依赖方向数量；首段确实为空的其他被动缺少确定分组时不分配新槽。

## 前置技能等级0

`02D4FEE0` 前置判断逐项读ID和要求等级。`02D4FF99..02D4FFAE` 调player virtual+CBC(id,0)，同冻结callee为 `02B6EEC0`。该lookup不是只查已持久化已学技能：`02B6EF3D→02D7BD10` 查职业资源，存在资源时 `02B6EF72→02D6B490` 惰性构造runtime，并经 `02B6EFBF→02D7BE50` 加载。

`02D4FFB4` 调当前等级getter `02D4EAA0(0)`，`02D50028` 比较读取等级与要求，仅小于要求失败。有效但尚未学习资源的等级0可以满足要求0；领域不能仅因 persisted bindings 缺少该ID就判前置失败。需先确认同job资源存在，并限定已支持的普通状态。无资源或非法ID不能让null指针getter假返回零；lookup返回null后的原生调用并无可依赖的安全零默认。

## 免费基线与固定等级

CHR 的 initial value/skill、growtype/skill 与累计 awakening/awakening skill 提供免费基线；编号须存在于匹配职业技能列表，废弃编号不制造资源或绑定。SP总来源为累计等级贡献加独立额外SP，已学费用只累计免费等级以上的普通SP阶数；资源百分比费用保留匹配客户端语义，不套参考端的基础费用差异。

fixed level skill 读取 interval level、add level per interval、is apply contract skillmaster。固定资格的第一成长 fitness 按相等匹配，第二成长 fitness 按当前觉醒不低于声明匹配，同时检查对应职业上限，避免将只有secondary声明的觉醒技能赠给其他转职。等级公式为 (1+(level-required)/interval)*add，适用达人时另加5/interval，受maximum钳制。

[SkillGrantCatalog](../../Server/DfoServer/GameWorld/Characters/SkillGrantCatalog.cs)解释CHR赠技，[SkillPointLedger](../../Server/DfoServer/Game/Skills/SkillPointLedger.cs)派生余额与免费等级。Catalog装配阶段预读自动赠技资源，成长事务内不解码PVF。
