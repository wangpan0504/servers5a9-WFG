# 技能学习与成长

本页维护 SP/TP 表、技能费用、等级门槛、前置及上限的资源读取规则。TP 表示特性技能点。普通创建的 CHR 初始技能见[角色创建](../模块/角色.md)，在线业务见[技能学习模块](../模块/技能学习.md)。Lv1 的 SP 为零，不通过赠点开启学习按钮；静态消费依据不代替实际学习、施放或升级验收。

## SP 表的加载与累计规则

资源路径为 `Etc/spTable.etc`，`028A92BD..028A92CC` 将 manager+8E8 作为输出传给 `03FB6120`。使用 `[sp table]`、`[tp table]` 两张表。

SP 标签分支 `03FB6269..03FB63E4` 先追加一个 DWORD 零，再按每对读取两次整数，仅将第二次结果顺序追加到输出+4/+8 的 vector。第一整数用于读取对结构，没有作为写索引。匹配 PVF 的第一列严格为1..200，第二列为对应等级的原值：Lv1=0，Lv2..10=30，Lv11..20=60，之后按原表分段。

实际累计函数 `028A6450(level)` 在 `028A64C9..028A64E8` 从该 vector 的 begin 取得 `begin+(level+1)`，`028A64F1..028A650D` 取得 `begin+1`，`028A6559..028A658E` 遍历半开区间并逐项相加，最终 `028A65CB` 返回累计值。迭代器 advance `01AE60D0` 的实际地址计算为 `elementPointer + argument*4`，不能把两个界限误读成等级差。

因此等级表贡献为 `sum(spTable[1..level])`，Lv1=0、Lv2=30、Lv3=60、Lv10=270、Lv11=330、Lv95=13320。此值是等级表累计贡献；当前可用 SP 还涉及学习扣点、退点及其他来源，不能直接用累计值覆盖角色余额。`028A7450` 调用累计函数并与 `02D7EAC0` 的可用数值比较；`0266FB0F..0266FB42` 在技能窗口中将该 getter 的返回与玩家虚表+41C传入的累计表结果用于比例显示。

TP 分支 `03FB6424..03FB649A` 建立200个 DWORD 槽，按每对第一整数作为索引，将第二整数写入该槽。匹配 PVF 声明50..100，每项1。该加载规则已确认；TP 的累计函数及特殊职业规则仍待闭合，不把原值1当作对应等级的全部可用TP。

[SkillCatalog](../../Server/DfoServer/GameWorld/Characters/SkillCatalog.cs)只提供已确认 SP 累计与原始 SP/TP 条目，使用真实 token 类型及完整闭块校验。它不决定学习准入或费用，也不写角色状态。[C# 测试](../../Server/DfoServer/SelfTests/SkillCatalogTests.cs)覆盖Lv1零、分段累计、越界与非法资源拒绝，由 `--selftest` 执行。

## 费用、前置与上限

job0/skill5 `skill/swordman/hardattack.skl`的 `[purchase cost]`为15，`[required level]`为1，`[required level range]`为2，`[maximum level]`为60，`[growtype maximum level]`为六项50。实际switch `04238089`将EAX减136，上限F3，使用byte表 `04241FD4`与DWORD表 `04241F58`。沿真实表项到entry后，才在标签表flag `073CA8C8`非零分支进入下列读取；没有把标签登记附近的下一条尾跳转当作该标签消费者。

| 标签 / tagId | index byte VA / value | target DWORD VA | entry → 读取目标 | 输出 |
|---|---|---|---|---|
| purchase cost / 1A5 | 04242043 / 09 | 04241F7C | 04236216 → 04238773 | +54的加密整数vector，逐项追加 |
| required level range / 1D2 | 04242070 / 0E | 04241F90 | 04236360 → 04238CFA | +AC的加密整数scalar |
| growtype maximum level / 21C | 042420BA / 1B | 04241FC4 | 042366BA → 0423968B | +14C起6个加密整数，每槽8B |

purchase cost 使用 `03DB1170`带success读取并将每项经codec保存，再 `0049E730`追加vector；这不是已证明费用只有一个scalar。range使用 `03DB1140`读整数，按输出地址低位分派codec写入；growtype上限同样读取6次整数。这些读取只解释资源字段的存放形状；普通费用和门槛还须结合下述运行对象查询链。

附近 `02D4FB80(player)` 从技能对象+D3C/D40另一内部vector读一个数，以 `02D4EAA0(0)`为索引；再从玩家虚表+B98返回对象+0C取得另一索引，读取技能+11C起的比例，存在 `trunc0(base*(100−ratio)/100)`路径。这条用于确认窗口数值的getter仍需恢复+D3C的标签归属及玩家输入；没有因窗口涉及购买就把它直接命名为SP费用。

已恢复资源到运行技能对象及发送前准入的进一步消费链：

- `04241847..042419DB` 取 maximum level 六槽的最大值；`04241A97..04241AC9` 在费用 vector 非空且长度不足时重复最后项补尾，长度更长时不截断。
- `02D6C477..02D6C481` 将资源+54费用 vector 复制到技能对象+90。`02D49B70` 按显式索引读取，`02D4F8E0` 普通状态按 `02D4EAA0(0)` 的已学等级读取；再应用职业比例、额外减免，最后取非负值。基础15不能一概解释为最终每级SP费用。
- `02D6C495..02D6C689` 将资源+A4/+AC复制到技能对象+B8/+C0；`02D4BEB0(targetLevel)` 普通门槛为 `base+(targetLevel−1)*range`。`02D52330` 以 current+1 查询，因此鬼斩已学1级时，学习2级的普通角色门槛为Lv3；特殊状态另有减5分支。
- `[pre required skill]` tag1DE沿真实switch进入 `04238F32`，把技能ID/所需等级写两条vector。`02D6C9B4..02D6C9D3` 将资源+CC/+E0复制到技能对象+D0/+E4；`02D4FEE0` 逐项查询已学技能并比较等级。
- `02D52330` 先校验已学等级、职业上限及另一转职上限，再校验普通角色等级、前置及SP/TP余额。已学等级低于任一适用上限即可继续，不能把两表取min。内部out=-1/-2/-3/-4属于本地UI结果，不作为ACK29错误码。

[SkillLearningCatalog](../../Server/DfoServer/GameWorld/Characters/SkillLearningCatalog.cs)据这些资源合同提供基础点数、普通等级门槛及原始前置/上限声明，[C# 资源规则测试](../../Server/DfoServer/SelfTests/SkillLearningCatalogTests.cs)覆盖16职业各自技能目录、repeat-last、鬼斩和非法声明。缺必要字段保持unsupported；缺前置为空、fitness默认零及feature/combo默认已由匹配客户端的初始化路径确认，普通资源费用已接入，TP/特殊状态及第二OR最终上限仍未闭合。`[active]/[passive]`只限定资源字段支持形状，不证明技能运行状态属于普通分支。

## 缺失标签默认与普通费用

成功 SKL 加载在 `04235CA1` 调用 `04231B60` 重置，再消费标签。因此缺失标签的默认值必须从重置路径取证：

| 字段 | 默认及消费者 |
| --- | --- |
| pre required skill | `04231E73/04231E7E` 清空 resource+CC/+E0 的 vector；缺失即空前置 |
| growtype fitness | `04232130..04232194` 初始化 resource+11C 的六个编码整数为零；显式声明由 `04239512` 读取六项 |
| feature skill type | `04234A70` 初始化 resource+5FC 为零；`0423CF5B..0423CF60` 对显式整数 test/setne，非零为 true；`02D735D2` 复制至 runtime+E88 |
| combo set | `04234ACD` 初始化 resource+67C 为零，`04234AD3` 清空 +680；显式声明消费者 `0423E10D..0423E11A` 另设标志 |

`02D52558` 根据 runtime+E88 分支：false 使用 SP getter `02D4F8E0` 和余额 getter `02D7EAC0`；true 使用 TP getter `02D4FA90` 和 `02D7ECC0`。普通 SP Catalog 排除 feature=true、combo 声明以及特殊职业 job9/10。

`02D4F8E0` 的资源成本为按当前已学等级索引 purchase cost，按职业成长索引取 fitness，然后计算 `trunc(base*(100-fitness)/100)`；随后减 runtime+1100 并钳制零。runtime+1100 在 `02D67E54` 初始化零，setter 为 `02D48FD0`；普通 ACK29 成功 `023609AE` 将其清零。其他状态设置入口尚未完整恢复，故 `GetOrdinaryResourceSpCost` 明确只输出资源部分，不能冒充不受角色状态影响的最终费用。当前支持 fitness 六项且每项 0..100，其他形状或范围拒绝。

`04241A97` 将 purchase cost 补尾重复至最大 maximum level 声明长度；`02D4EAA0(0)` 给当前已学等级索引。普通下一等级门槛为 `required level + currentLearnedLevel * required level range`，调用链为 `02D52330 → 02D4BEB0(current+1)`。

| job0 技能 | 普通资源结果 |
| --- | --- |
| 5 鬼斩 | base15，费用补尾至60；已学1学习2要求角色Lv3；primary growtype cap50；缺前置为空，默认 SP、fitness0、非combo |
| 46 上挑 | base20，maximum20；已学1学习2要求角色Lv4；primary growtype cap10；同样普通默认 |
| 169 后跳 | base30，maximum及primary cap1；资源缺 range，保留 unsupported，不猜默认进一步升级 |

`02D4C470` 只给 primary growtype cap。`02D52330` 的 cap 判断允许 current 小于 primary，或小于第二成长表 runtime+1D4 的对应项，属于 OR，不取 min。第二表资源映射和缺失默认未完整闭合；当前普通切片只在 target 不超过已声明 primary cap 时推进，不声称最终 CanLearn。

协议请求、响应和字段依据见[技能学习协议](../协议/技能学习.md)，当前支持范围、事务和验证见[技能学习模块](../模块/技能学习.md)。

## 前置技能等级0

`02D4FEE0` 前置判断逐项读ID和要求等级。`02D4FF99..02D4FFAE` 调player virtual+CBC(id,0)，同冻结callee为 `02B6EEC0`。该lookup不是只查已持久化已学技能：`02B6EF3D→02D7BD10` 查职业资源，存在资源时 `02B6EF72→02D6B490` 惰性构造runtime，并经 `02B6EFBF→02D7BE50` 加载。

`02D4FFB4` 调当前等级getter `02D4EAA0(0)`，`02D50028` 比较读取等级与要求，仅小于要求失败。有效但尚未学习资源的等级0可以满足要求0；领域不能仅因 persisted bindings 缺少该ID就判前置失败。需先确认同job资源存在，并限定已支持的普通状态。无资源或非法ID不能让null指针getter假返回零；lookup返回null后的原生调用并无可依赖的安全零默认。
