# 角色成长资源

目标为 S5A9 x86 客户端。本文只定义匹配 PVF 的累计经验边界与等级 SP 贡献，供正常成长用例查询；[普通成长计划与投影](../模块/角色成长.md)已经提供保留已消费SP的纯领域计划及完整NOTI37纯Builder。经验奖励来源、角色写库、发布包序和技能扣点分别按[业务规范](../规范/服务端架构.md)与[技能学习](技能学习与成长.md)接入。资源读取或纯计划不代表正常升级、领奖或学习已实现。

## 累计经验表的真实编码

`character/exptable.tbl` 的原始 token 总数为108：前90项是type0有符号DWORD，后18项是9对type9。每对先存高DWORD，再存低DWORD；它们是99个逻辑经验边界，不是108个经验等级，也不是缺少后段的大值时补零。

当前通用 `--pvf-text` 不输出type9，因而只看到前90个数值；成长资源必须使用 `PvfArchive.ReadTokens`。type9的DWORD payload在C#的 `int Value` 中可能为负，但组合时须按原始32位位模式解释。不能将低DWORD的负显示值当成负经验，也不能先转换成有符号32位或单精度浮点。

原生链明确支持这一顺序：

1. `040B1EEB→03DB1250`，后者通过 `03DB0C60` 读取一个64位数并从局部out返回EDX:EAX。
2. `03DB0CA9..03DB0CB5` 通过 `0437CF90` 判断当前token.Type==9，确认还剩至少两项后，`03DB0CF6`读下一token的DWORD到EDX，`03DB0D01`读当前token的DWORD到EAX。token地址计算为begin+5*index。
3. `03DB0D04..03DB0D0E` 按out、下一项、当前项压参数并调用 `04380980`。该callee把当前项写到out+4、下一项写到out+0，然后返回true。`03DB0D17`将cursor增加2，因此type9的逻辑读宽为10B。
4. type0分支 `03DB0D93..03DB0DB9` 读取一个5B token，`CDQ`把signed DWORD扩展到64位，再写out。负type0会形成负有符号值的位模式，服务端成长表拒绝它作为合法累计经验边界。
5. `040B1EF0/040B1EF2` 将EAX/EDX写入客户端内联表，按8B前进。资源没有再次累计求和。

原生type9分支只验证当前tag及剩余数量，没有再次检查下一tag。Catalog额外要求匹配资源中的高/低项都为type9，拒绝损坏或未知混合形状；不将不符合这一形状的输入默认为合法低DWORD。

冻结内联表基址为 `073B94F8`，它本身是u64数组，不能把首项0误解为null pointer。index0为0，99个逻辑资源值逐项等于该表index1..99。100及其后的冻结零槽不是新的合法经验等级。

| index / 资源累计边界 | u64值 |
|---|---:|
| 0 / 初始经验 | 0 |
| 1 | 1000 |
| 2 | 2035 |
| 3 | 3315 |
| 90 | 2021310320 |
| 91 | 2315706532 |
| 94 | 3320457250 |
| 95 | 3726597550 |
| 96 | 4140860656 |
| 97 | 4563409023 |
| 99 | 5434027680 |

后段不能截到u32：97项已经超过2^32，99项仍须完整保存为ulong。保留96..99的原始声明不表示服务端允许突破当前支持等级。

## Lv1..95查询与SP贡献

当前业务查询范围明确为Lv1..95。`040C2845..040C284B` 将level减1，以unsigned上限94检查；`040C2851/040C2858`直接按level索引读取u64，level>=2时 `040C2864/040C286B` 减前一索引，用差值作为该等级的经验跨度。这是数组与相邻边界的消费证据，不能替代正常经验奖励及最终升级事件。

[CharacterGrowthCatalog](../../Server/DfoServer/GameWorld/Characters/CharacterGrowthCatalog.cs)提供：

- `GetLevelStartExperience(level)`：索引level−1的累计值，Lv1为0、Lv2为1000、Lv3为2035。
- `GetCumulativeExperienceBoundary(level)`：索引level的累计边界，Lv1为1000、Lv2为2035、Lv3为3315。
- `GetLevelExperienceSpan(level)`：当前边界减前一边界，Lv1为1000、Lv2为1035、Lv3为1280。
- `GetSpDelta(fromLevel,toLevel)`：复用已闭合的[SP累计规则](技能学习与成长.md)，查询目标等级贡献减原等级贡献。相同等级为0，降低等级及范围外参数拒绝。
- `GetTpDelta(fromLevel,toLevel)`：按参考S4A21的累计TP模型读取匹配表，目标累计贡献减原贡献，Lv49→50为1。

Lv1 SP贡献为0；Lv1→2为30、Lv1→3为60、Lv10→11为60、Lv94→95为270。TP贡献Lv49为0、Lv50为1、Lv60为11。它们仅是等级表贡献，不包含学习费用、退点或其他来源；查询不写入角色状态。TP加载与余额消费者已匹配，累计发点模型采用参考服务端行为，不能称为原版完整奖励调用链已恢复。

Catalog解析时检查支持的token类型、type9完整对、type0非负值与严格递增，查询时检查实际表长和业务支持的等级范围。读取空表、错误类型、缺低DWORD或相等/倒退边界会失败，不以最后一项、零或经验跳级补救。
