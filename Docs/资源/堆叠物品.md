# 堆叠物品资源

普通恢复原声明由[RecoveryConsumableFile](../../Tools/PvfLib/Models/RecoveryConsumableFile.cs)保存：cool time和cooltime group保留整数，hp/mp recovery保留操作、数值、第三整数和目标字符串。完整字段名、重复/畸形及嵌套诊断供领域拒绝未知副作用，不从描述或`[waste]`参数推断药效。普通恢复的大类资格、本服冷却策略和效果验收边界归[背包模块](../模块/背包与装备.md#普通恢复药)。

## 身份和范围

目标为 S5A9 x86 客户端。运行时从程序目录下的 `Data/Pvf/Script.pvf` 读取资源。读取使用项目 [PvfArchive](../../Tools/PvfLib/PvfArchive.cs) 的原始 token，不从文本显示结果猜 token 类型。

[StackableCatalog](../../Server/DfoServer/GameWorld/Items/StackableCatalog.cs)完整加载 `stackable/stackable.lst` 的模板索引，定义按首次查询读取并缓存。索引和声明分别由 PvfLib 的 [PvfItemIndex](../../Tools/PvfLib/Models/PvfItemIndex.cs) 与 [StackableFile](../../Tools/PvfLib/Models/StackableFile.cs) 解析，Catalog 负责索引查询和缓存。资源层不持有角色资产、不写库、不决定背包槽、数量、堆叠合并、掉落、消耗或商店买卖资格。资源定义与 [CharacterItem实例](../模块/背包与装备.md)分开；资源ID0金币定义合法，不表示可以建立普通正ID物品实例。

索引数量由所加载资源决定。Catalog对空表、奇数token、非整数ID、负ID、错误路径类型、越界路径、非token脚本、缺文件和重复ID明确拒绝。索引内扩展名不是分类依据，实际存在 `.equ` 扩展的配方；文件存在且DataType为1才允许读取。反斜杠与大小写使用归档标准归一化；不存在查不到时换文件或返回空定义的默认。

## 查询接口及实际标签

`Load(pvf)` 解析并校验全索引结构；`TemplateCount`、`TemplateIds`给出全量模板范围；`Get(templateId)`返回lazy不可变定义，未知ID抛出异常。输出字段带 `Declared`，表示资源声明，不是持有数量、最终价格或准入决定。

| 实际标签 | 原始 token 形状 | 输出 |
| --- | --- | --- |
| stackable type | type6 字符串与后续 type0 整数参数 | `TypeDeclaration.Label`与只读整数`Parameters`，不猜参数枚举 |
| stack limit | 单 type0 整数 | `DeclaredStackLimit:int?` |
| price | 单 type0 整数 | `DeclaredPrice:int?` |
| need material | 物品编号、数量的整数对 | `DeclaredNeededMaterials`，商店兑换价格，不是使用成本 |
| sell price | 单 type0 整数；允许缺失 | `DeclaredSellPrice:int?`，缺失不填0或按price折算 |
| minimum level | 单 type0 整数 | `DeclaredMinimumLevel:int?`；`HasMinimumLevel`区分缺失与存在但非法 |
| item group name | 单 type6 字符串 | `DeclaredItemGroupName:string?` |
| levelup range | 单 type0 非负整数 | `DeclaredLevelUpRange:int?`；缺失、重复和畸形不默认成1 |
| cool time | 单 type0 非负整数 | `DeclaredCoolTime:int?`与`HasCoolTime`，单位和冷却行为由所属玩法解释 |
| booster info | type3块声明是否存在 | `HasBoosterInfo`；不把随机配置降为固定升级数量 |
| action type | type6动作标签与后续原序参数 | `ActionDeclaration`保存整数、浮点、字符串及未知token原值；`HasActionType`区分不存在与结构非法 |

升级券以明确`[action type]`与上述原始字段装配，不仅凭`levelup range`出现就认定升级动作；`DeclaredBoosterEtc`仅保留唯一`booster info/etc`的整数序列，含抽取次数及完整三元组，不在库内推断等级或物品。正式资格、成长和自动主线行为归[角色成长](../模块/角色成长.md#升级券)。

## 动作解析注册

[StackableActionDeclaration](../../Tools/PvfLib/Models/StackableActionDeclaration.cs)负责原始声明读取：token入口保留参数类型、原值与次序，文本入口复用同一字段模型，不用正则从字符串里提取数字。非整数参数不丢弃整个动作，也不伪装成空参数；纯整数动作提供兼容整数视图。浮点精度以原始token为准，不能从文本显示反推原始位模式。重复或缺标签的动作保持明确的结构失败。

[参数解析器注册表](../../Server/DfoServer/GameWorld/Items/StackableActionCatalog.Parsers.cs)按标签绑定参数读取函数，不绑定opcode。保留的194种匹配ARAD动作全部注册，另注册当前PVF独有的17种声明，共211种，不以已有消费业务作为解析白名单。疲劳、转职、升级、任务、宠物、外观槽、皮肤仓库、品级箱、便携锻造及增幅目录复用该表，不再各自正则截取`[action type]`。

ARAD的STK读取路径`04145C9E → 040D4F60 → 04145D30..04145D93`先解析动作名，再反复调用`03DB1170`将数值追加到物品`+0x514`的列表，**没有按动作限制参数个数**。底层`03DB05E0`接受type0/type1整数及type2浮点，浮点向零截断为int32。因此注册层统一保留数值序列，不把某个业务只支持的零参数、单参数或固定四参数误当资源语法。非有限或越界浮点、字符串及未知token保留原声明并返回参数失败，不截取可读前缀或提取字符串中的数字。

角色资格、参数个数及含义、目标、范围、附属STK字段和消费事务继续由所属模块决定。`Arguments`是既有业务的纯type0整数兼容入口；`Parse`另提供匹配客户端的数值投影，扩展解析不会自动放宽既有增幅等消费资格。以下实际变体均能解析，但不代表本服已消费支持所有变体：

| 声明 | 资源参数与业务边界 |
| --- | --- |
| `[first awaken clear]` | 存在无参、`1`、`1 1`；接入后两种，双参数标志允许客户端自我觉醒资格路径，服务端仍核真实QST及CHR；无参旧变体待核验 |
| `[second awaken clear]` | 接入`0`、`0 1`，均复用逐级职业任务与赠技事务 |

解析结果区分无声明、声明结构非法、未知标签、参数非法和解析成功，原声明始终可供诊断。解析器另记录`Arad`或`PvfOnly`来源，以及`ExistingVariants`或`Pending`消费状态；前者只表示已有明确接线的受限变体，不是整个资源族通用可用。`Pending`表示该动作的消费接线尚未登记为已确认，不能据此断言同名系统的所有独立入口都不存在。

[客户端动作映射](../../Server/DfoServer/GameWorld/Items/StackableActionCatalog.cs)另外保存匹配ARAD `040D4F60`的194种保留标签与实际返回动作号，依据为字符串表及对应分支的`mov eax, type`；退役专属动作194/195不再注册，其余原生动作号不重排。它不是参数解析器白名单，不使用字符串资源索引或其他版本包号。标签按原文区分大小写；未知编号不猜成0或相近功能。`ItemCatalog`按本次PVF名册惰性缓存STK原声明，未知ID不占缓存。

解析注册、客户端动作号与消费协议是三件事。客户端可走通用动作producer、独立请求或本地效果；`[use action packet]`及专用分发须一同核对，不能把所有标签强制改成515或44。

上述515动作由[统一入口](../../Server/DfoServer/Network/Handlers/StackableActionHandler.cs)分派，消费前核对源STK标签与请求动作号，各玩法保留参数、场景、实例、资产和事务检查。任务券及按表成长具有持久回执，重放先交原回执判断；源已耗尽不要求重新找一张券，也不重发已完成的消费ACK。49转职、39固定升级券，以及强化、增幅等既有独立请求保持各自入口，不额外注册515或改造其包体。未实现动作仍明确拒绝并记录标签和动作号；不得消耗源后返回通用成功。字节和发布规则见[物品协议](../协议/物品.md#stk-动作分发)。

资源普查沿既有全STK遍历汇总动作号、解析器来源、消费状态、成功/非法参数数量，以及参数token形状和代表模板；单独的`--selftest-tcp stackable-actions`检查该资源合同，不参与默认网络组，不在服务启动时全量扫描。结构非法的动作独立计数，例如10301547重复声明了两次`[action type]`，不为提高覆盖率猜覆盖顺序。统计不证明对应玩法已可使用。

### 仅有PVF声明的动作

下列17种标签在当前PVF中有完整整数序列，均已注册为`PvfOnly`，保留原标签/参数，不强配当前ARAD动作号。其中`[creature use item]`已沿实收CMD44接入[宠物经验道具](../模块/宠物.md#资源与成长)，消费状态为`ExistingVariants`；其余为`Pending`，缺失的是原生路径确认与对应业务，不是资源解析器。

## 字段边界

STK/EQU 的 `[need material]` 仅参与[商店兑换](../模块/背包与装备.md#npc-商店买卖与限购)计价与购买消费，不能成为使用物品时的额外扣费或拒绝门禁。`df_game_r` 的 STK/EQU 解析分别在 `089B31D3` / `08994A81` 保存材料编号与数量；`CItem::GetNeedMaterial(0850D6F4)` 的直接业务调用者是 `DisPatcher_BuyItem::get_data(081BE658)` 与 `Inter_NpcLimitBuyItemInfo::checkError(084E6ACC)`。前者按购买数量放大材料数量，`DisPatcher_BuyItem::process(081BDC7E)` 在购买成功后扣除，不在物品使用时再次收费。宠物转换组、配方、强化增幅等业务自身声明的真实材料与源道具消耗不受此规则影响。

[ExperienceConsumableFile](../../Tools/PvfLib/Models/ExperienceConsumableFile.cs)另行保留`[increase status type]`的字符串与整数、冷却组、排除职业、声明列表及重复/畸形诊断；不把`[expUp]`、`[expPercentUp]`或`[expUpByPercent]`合并为同一种标签，也不在PvfLib计算角色经验。运行时的两类经验解释、材料及使用边界见[经验消耗品](../模块/角色成长.md#经验消耗品)。

声明的0原样保留，不能替换为猜测容量。标量错误token或负值拒绝；缺失、未知长度、重复标签保留null并列入 `UnsupportedFields`。特殊模板可能重复字段，尚未恢复原生块上下文及覆盖规则，因此不采用首项/末项猜测。

`stackable type`中的 `[material]`、`[waste]`、`[recipe]`、`[coupon]`等只保留资源文字；后续参数保持原整数，不命名为背包分类、材料子类、wire type或使用方式。`item group name`同样是原始分组文字，不等于商店分类或协议值。该Catalog没有购买资格、消费方法或材料消耗量查询。
