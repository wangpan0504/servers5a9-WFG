# 史诗祈愿协议

| 方向 | opcode | 内容 |
|---|---|---|
| C2S | CMD1354 `UPDATE_WISH_ITEM` | `u8 count`，随后`count × u32 itemId` |
| S2C | NOTI1292 `WISH_ITEM_INFO` | 同上；替换客户端整份清单 |
| S2C | ACK1354 | 成功`01`；失败使用公共`00 + u16 error`前缀，当前为`00 00 00` |

所有整数为小端。清单最多五槽；0为空槽，必须保留中间空位。原生窗口正常保存固定发送五项，允许多项0；只对非零装备检查重复。count0表示空清单，任何截断、尾随字节、负编号、超过五槽或重复非空编号整体拒绝，不部分保存。列表提交成功后先发送1292再发送1354成功，不通过成功应答伪造客户端的实际清单。

匹配原生发送器`010B5510`以1字节写入数量、4字节写入每个编号。窗口`015C1050`逐个读取五个控件，`015C1117`调用该发送器；取消单槽`015BCE26`和关闭清理`015C1182`均向控件写0。注册函数`010B53A0`将1292绑定`010B5220`、1354应答绑定`010B5090`。1292接收器先清原列表再装入新项；1354应答只根据公共成功布尔选择保存成功或失败提示，不读取额外业务字段。

原生窗口`015C0620`按槽序回放至五个控件；`015C0060`从史诗图鉴结果筛选Lv70以上装备。地面物品分类`025A23E0`调用清单成员查询`010B5110`，命中返回祈愿分类3；掉落演出`025BB160`对命中列表的掉落选择演出分支10，普通史诗走原分支4。物品提示`02A41060`、`02A41160`和列表显示`02A42250`同样查询该清单。因而展示及特效由1292维护的原生状态驱动，不需要额外死亡包字段或掉率修改。

结构解析、目录资格、持久提交、会话身份与构包分别归Parser、Catalog、Store、Session和Builder。禁止用灯笼活动`WISH_LANTERNS`、流星活动`SHOOTINGSTAR_WISH_LIST_STATE`代替本合同。
