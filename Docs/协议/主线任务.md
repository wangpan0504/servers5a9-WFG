## ACK4任务槽的状态scalar：零值不是初始进行中

ACK4的30槽读器 `02341AF3..02341B35` 固定读取每槽 `quest:u16 + scalar:u32`，空quest=FFFF时跳过，非空调用 `0203C450(quest,scalar,0)`。该u32已有状态消费者，不能继续命名为“未知保留值”或固定置0。

`0203C832..0203C83D` 以任务指针和scalar调用 `02E6A7C0` 构造12B active条目；条目+0为任务指针，+4为scalar holder，+8为holder辅助存储。`0200C8D0(task,kind=0)` 按taskId查该条目并在 `0200C968..0200C9EB` 读取并返回scalar，不重新判断地图通关。不存在任务返回FFFFFFFF，不能用0表示不存在。

多个本版UI路径直接测试该返回值为0：`0105E7ED..0105E7F7`、`01459D12..01459D1F`、`027CB865..027CB86C`、`03753962..0375396C`。其完成布尔值由 `test eax,eax; sete` 得到。新角色仅有active3145、未进副本及无completed记录时，ACK4投影scalar=0仍能让客户端显示条件已完成并发C2S34；数据库没有完成位不能防止该本地显示。当前建角不自动接取任务；通用接取单地图清图时保存scalar=1；完整任务条件与领奖的验证边界见[任务模块](../模块/任务.md)。

`0417EEA0` 将scalar拆为3个9bit计数；`0417EEF0` 根据索引0/1/2取各计数：

```text

counter[1] = (scalar >> 9) & 0x1FF
counter[2] = (scalar >> 18) & 0x1FF
```

`02031CD0..02031D16` 的任务文本路径将任务资源数量减去counter来显示达成量，这是剩余计数的证据。未解释通用scalar的bits27..31，不忽略这些位后伪造其他任务状态。三计数布局不能独自证明任何任务初值；3145的单Boolean合同由下述实际资源、真实type分派和clear-map条件分支单独闭合。不能推广成所有任务初值为1。

通用完成writer`02280710`由任务helper`02021690`在`0202188E`调用，按u16写echo34、quest、reward selector、multiplier及常量FFFF尾，10B。这是已收到FFFF尾的独立来源；`02123900`中以持有域查找结果EDI写尾的是另一条UI生产者，不能把其未知域当作该样本唯一来源。

## ACK34 注册与公共失败包

金币材料使用Main槽0，其余具有已装载Main虚拟槽的钱包材料和奖励复用普通持有域：消耗仍为`type0:u8 + slot:u16 + count:u32`的7B行，奖励仍为19B行。匹配客户端 `0237716C → 029CA9D0`查找Main槽，不能套用C2S18材料type2的请求格式。ACK34中的数量是本次扣除/发放增量，NOTI14随后同步当前绝对余额；钱包不会生成普通物品UID。

方向/category/opcode 为 S2C `(1,34)`，注册指令原形：

```text
0237CE52 push 0
0237CE54 push 02376BF0
0237CE59 push 22
0237CE5B mov ecx, esi
0237CE5D call 028F8C30
```

`028F8C30` 保存 `(callback, userdata)` 二元记录；`028F8E35..028F8E3D` 分别把参数 callback 写 `[eax]`、userdata 写 `[eax+4]`。公共 ACK 路径如下：

1. `028F85F6..028F8600` 以 `03C851B0` 读取 **u8 success**。
2. success=0 时，`028F8644` 调 `0041CA50(opcode)`。该函数只对 opcode18/20 返回 true；34 返回 false，于 `028F8655` 再读 **u16 error**。success 非零时跳过 error，内部 error 初始化为0。
3. `028F8756..028F8761` 将 error、success 和 frame 传给 `028F2970`。
4. `028F29ED..028F29FC` 从注册记录取 userdata 和 callback，按 cdecl 参数 `(opcode, success, error, userdata)` 调 callback。34 的 userdata=0。
5. `02376C1E..02376C26` 检查 success，零值跳到 `023783A5`，非零值进入正文。

所以公共失败前缀精确为 `success:u8=0 + error:u16`，3B；不能用 ACK15 的错误含义解释 ACK34，也不能把所有错误码统一映射为“条件不足”。

奖励创建、字段对应和持有域写入的实际链如下：

- `023775F0 → 020BF1D0(itemId)` 返回持有域类型，再经 `023775F6 → 029089D0(type)` 取得对应 owner。`02377612 → 029CA9D0(owner,wireSlot)` 查已有对象；命中后先以对象虚表 `+5C(itemId)` 检查模板一致，再调用虚表 `+4C(amountOrValue)`。候选虚表 `055D8F64` 的 `+4C` 指向 `020C1300`；它读取对象 `+2F0` 的当前值，在 `020C1365` 加上传入参数，再调用虚表 `+40` 写回，因此该类型的已有堆叠分支需要本次增量，不能发送最终累计数量。其余类型仍须按各自虚方法核对。
