# 宝珠附魔

本文约束S5A9匹配客户端的CMD272 `ENCHANT_BY_BEAD`。普通卡片的附魔师交互、奇异宝珠、收集箱和宝珠变换券属于独立入口，不能只消费源物品后套用本合同。

## 请求与回复

请求正文固定10B，依次为 `sourceList:u8 + sourceSlot:u16 + targetList:u8 + targetSlot:u16 + opaque:u32`。`02E519E0`查找源宝珠和目标实例；`02E51BA8 → 03BDF610`写272包头，`02E51BC2/02E51BD2/02E51BE9/02E51BF6/02E51C09`分别写1/2/1/2/4B，`02E51C0E → 03BE0FF0`完成发送。末字段保留原始u32，当前不作为客户端授权、费用或可自行选择的附魔等级。

ACK272注册为 `0237C489 → 0234CF40`。成功正文为 `success:u8=1 + targetList:u8 + targetSlot:u16`；`0234CF6D/0234CF76`读取目标容器和槽位，随后按Main、Pet或本人穿戴表查找并触发目标提示。该分支不减少源宝珠数量，因此必须另发已提交源/目标的完整库存差量。失败使用公共 `success:u8=0 + error:u16`；本模块当前使用公共拒绝编号23，尚未闭合细分错误文案，不沿用其他客户端版本的单字节宝珠错误表。

## 资源与提交

[EnchantmentCatalog](../../Server/DfoServer/GameWorld/Items/EnchantmentCatalog.cs)按当前STK列表解析实际使用的宝珠及关联卡片。普通卡片宝珠资源族是 `[enchant waste] 0`及其 `[monster card id]`指向的 `[material expert job] 1`卡片；随机称号宝珠见下文。卡片 `[string data]`首项是图像，其余装备标签限定目标类型/部位；宝珠显式目标模板清单另与它共同校验。宝珠等级取自身声明的 `[enchant index]`，未声明时只使用卡片确实包含的index0；没有相应效果段、重复等级、无关联卡及已识别但未实现的额外使用时间、次数或服务器资格均不生成成功结果。

本次真实米歇尔之魄宝珠490705314映射到卡10309006，index0声明所有属性强化18，目标为项链、手镯、戒指。其收集箱说明中的攻击力12不属于装备附魔，`[event enchant waste]`也不在此入口推进收集箱。商品和目标编号只作为匹配资源代表，生产规则不限定这些编号。

[InventoryEnchantmentService](../../Server/DfoServer/Game/Inventory/Services/InventoryEnchantmentService.cs)通过原`InventoryPlan`在同一事务消费源一件并安装目标`EnchantCardId/EnchantUpgrade`。保留持久UID、强化、增幅、锻造、耐久、锁、封装、期限和其他核心字段；排序锁不阻止附魔，装备安全锁和到期源/目标拒绝。有限实例期限进入提交前提，延迟提交不能沿用已失效的规划。源码不向CHR基础89B属性块再次加入附魔属性，客户端通过真实装备核心完成派生。

成功提交后按源/目标库存差量、必要穿戴刷新与排序锁、ACK272发布；当前owner、角色、场景和实际提交快照仍由共享Session/Projection核对。SQL失败不先回复成功，重新连接读取原已提交资产，不自动重做消费。

成功消费者`0234CFDC..0234CFF4`以模式5打开结果窗，存在直接调用打开回调的分支；`03868E33 → 038659C0`按当前目标核心的卡ID和升级索引初始化描述。`03865CD5..03865D4E`根据描述条目数设置窗口尺寸，继承的重排链`0378A950 → 0378A030`同时设置确认按钮位置。后续同模板库存更新只修改目标核心，不重跑这次布局。因此ACK必须晚于新核心投影，不能依赖跨线程排队恰好让库存先到达。ACK272不读取或扣减源宝珠，源耗尽由库存差量清槽；不套用普通药剂ACK44的消费包序。

## 随机称号附魔

`[auto enchant] 0`、`[string data] [title name]`、`[random title enchant]`和非空`[bead limited usable item]`共同定义随机称号宝珠。当前从零女圣职者宝珠490703772指向奖池10015，允许称号400330167–400330170。池内每行是`序号:i32 + 技能个数:i32 + 权重:i32 + (职业字符串 + 技能号:i32 + 增加等级:i32)[技能个数]`，支持1–2项技能；职业描述效果归属，不替代源物品使用资格。服务按首个同序号完整声明建立候选，正权重参与累计抽样；缺池、截断、非法整数或权重溢出不消费。

物品行`offset97:u32`继续使用持久字段`Extension97`，低16位为奖池编号、高16位为条目序号。随机结果和扣除一颗宝珠沿原InventoryPlan同事务提交，不替换目标UID，不覆盖普通`EnchantCardId/EnchantUpgrade`。成功与失败正文、NOTI14在ACK前的包序均沿本页CMD272合同。

此节新增静态证据绑定历史EXE SHA256 `3941e531fdc62c11b38149a767acbed09f056443c5c6be21c129e6b95aeba329`的解包转储：`016EF7E0`加载`UI/AutoEnchantBead/SkillGiveWindow.xui`，`016EF9E4`设确认模式1，`02132BE0 → 02E519E0`复用272；不能与`0252BC80`的CMD970称号变更窗口混同。`027F8783/027F8786`把offset97复制到普通核心`+0xAB`，`03865C9C/03865CB0 → 04381CB0`按高、低两个u16查询随机表；`043815EA..0438169C`证明重复序号只填首次。当前匹配客户端756构建尚未完成上述局部字节等价核对，静态结论和自动化回归不能代替该版本的界面、提示和实战验收。截图没有封包，不能单凭空目标槽的公告断定服务端拒绝；白名单外称号仍由客户端或服务端拒绝。
