# 技能学习协议与字段依据

本页维护技能学习、换槽、指令与连招的字段、消费语义和边界；资源加载及费用规则见[技能学习与成长资源](../资源/技能学习与成长.md)，当前业务与事务见[技能学习模块](../模块/技能学习.md)。其中 TP 表示特性技能点。

## 请求、重复与响应

`028A1130/028A1148` 发送 C2S command29：`context:u8,count:u8,count*(id:u16,decrease:u8,magnitude:u8),mode:u8`。队列存 signed delta；decrease 为 delta<0，magnitude 为 abs(delta)，不是目标等级。普通 SP/TP 支持 context0/1、decrease0/1 和正数 magnitude，多级增减逐阶处理；普通 sender mode0 或1，特殊 `015C1D40` 分支生成3，暂不支持。不存在正文操作 nonce；相同报文可表示合法再次升级，不能按报文哈希去重。事务需按当前 revision、当前等级和费用执行，重复报文语义边界需如实报告。

ACK29 consumer `02360630` 成功体为 `01,context:u8,sp:u16,tp:u16,count:u8,items,mode:u8`。每项为 `slot:u8,id:u16,targetLevel:u8,hasExtra:u8`，hasExtra 非零再读 `extraCount:u8` 和对应字节。单项无 extra 共13字节。每项第一字节是 slot，绝非 status。失败体为 `00,error:u16`，后续不再消费字段。

匹配文字确认 0012 已掌握、0015 技能不存在、0016 SP不足、00D9 无法学习指定Lv、0007 决斗场限制。当前等级/前置业务拒绝使用 D9，精通使用0012；身份、revision与SQL错误不混入该错误域。本地 precheck 的 -1/-2/-3/-4 也不是 wire error。

## 职业互转 CMD502

匹配x86 ARAD的`04F7DC82..04F7DC87`以`1F6h`注册ACK消费者`012A1870`。`[class change]`由动作解析`040D4F60`解释为49，`028C5980`绑定本地动作`028BD2E0`；该动作检查转职/觉醒任务及源实例后打开职业窗口，不发送44，不要求先收到731。服务器仅定义过opcode并不表示已有请求处理。

普通选择窗口`012A2D90`的mode2在`012A2F05..012A2F4D`发送502：`slot:i16,targetFirstGrow:u8,confirmed:u8`，共4B，首次确认位为0。`0129D2E0`的皮肤仓库风险确认回调重复发送同一槽/目标并将末byte置1；该位不是库存类别或免费模式。固定目标动作参数的回转券走`028BFC50`，只写`slot:i16,targetFirstGrow:u8`共3B。服务端先保留是否携带确认位，再按原券是否固定目标、参数及实际源实例核对；普通券缺末byte不被放行。

ACK502成功完整正文为`01`，失败为`00,error:u16`。`012A1870`成功仅调用`01299A60`收尾和刷新技能界面，不读取新的职业字段或技能列表，所以必须在成功ACK前安装新Actor及完整19。当前发送顺序是实际Actor USERINFO2→SKILLINFO19→实际Player USERINFO2→源及材料绝对差量→必要任务刷新→ACK502，随后刷新城镇成员；这里不复用ACK34的职业字段或其它版本的503。

同一消费者及匹配字符串确认的错误包括1信息错误、3原职业、17找不到物品、19未转职、22转职任务进行中、23不可使用、30仅城镇、235未开放职业。未闭合的更细拒绝原因不猜造新映射。133分支使用dstr100007181提示皮肤仓库武器外观风险，并由上述回调发送确认位1；当前无皮肤仓库owner，不凭此回调虚构拥有或迁移该类资产。

普通券已与匹配Windows客户端实收对拍：未觉醒分支互转及保留一觉的分支互转均发送上述4B正文，确认位为0，完整Actor、19、Player、库存与任务刷新后收到正文`01`的ACK502。该实收不覆盖固定目标3B券、确认位1、皮肤仓库风险或技能实际施放。

上述地址为匹配映像VA，映像基址`00400000`。本版STK另有材料、禁转目标、可用源分支和源分支检查关闭声明；服务器行为及事务边界见[转职互换与变更书](../模块/技能学习.md#转职互换与变更书)。原码消费者核对、自动回归及客户端收发记录不替代Windows界面和施放验收。

## 普通换槽

C2S28的直接正文为`context:u8,from:u8,to:u8,contextIndex:i32,mode:u8`，固定8B；当前实收另有4B正文检查尾，完整为12B。普通现场值为context0、contextIndex=-1、mode0。Parser只接受这两种宽度，检查尾与正文分离并记录匹配状态，不作为owner或槽位资格。额外上下文及其它mode保留原值，未闭合分支不按普通布局处理。

成功ACK28完整为`01,context:u8,from:u8,to:u8`，4B。公共前缀之后匹配消费者连续读三个u8，选择context后调用槽位交换；原交换前缀交换vector的两个指针，目标空时源指针移过去，服务端保持相同持久化语义。字段之外没有原请求的contextIndex、mode或检查尾，不能回显整个实收正文。通知使用已经提交的原选角快照，过期ACK跳过，不重复执行交换。

普通失败分支不直接读取额外包字段；错误码与服务端各拒绝条件的映射仍未闭合，当前不套其它版本或学习错误域。服务端支持范围与拒绝边界见[换槽模块](../模块/技能学习.md#普通换槽)。

## 槽位与完整树

`02D82070 → 02D80160` 建立512项槽位及两个 context；`02D82490(slot,id) → 02D82380(slot,skill)` 绑定。普通缺 combo 默认标志 false；特殊 combo 标志限制 slot<6。已有槽可被覆盖，服务端应选择对应区域的空槽并持久化，升级保持已有槽。ACK byte 可直接表达0..254，但编码和binder容量不表示这些位置都适合普通界面分配。

当前客户端12格可见快捷栏的实收换槽编号为0–11，学习ACK按这些位置预填；198–203不作为新学自动填充位置。冻结代码中0–5及198–203的辅助谓词用于拖动路径中的局部分支，不能将其直接等同于完整界面映射。技能200–211的特殊映射位置为138–149。普通新分配避开特殊槽，并按[模块中的槽位规则](../模块/技能学习.md#普通学习范围)使用主动或被动区域；已初始化旧存档继续原样回放。FF在`02360863..02360958`走特殊映射，普通未匹配ID会落槽138，不能用FF代表未分配，也不能把被动放进快捷槽后期待客户端自行纠正。

NOTI19 注册 `023CCAA2 → 023B5910`，正文为 length:u32 加 protobuf；不存在压缩或把 cursor getter 当解压的依据。

| 消息 | 字段 | 形状与含义 |
| --- | --- | --- |
| outer | 1 | optional varint packet enum，构造默认19 |
| outer | 2 | repeated length-delimited tree，按顺序 context0/1 |
| tree | 1 | required varint SP |
| tree | 2 | required varint TP |
| tree | 3 | repeated length-delimited skill |
| skill | 1 | required varint slot |

outer parser `0041C650`，tree parser `0041B3C0`/IsInit`00418D00`，skill parser `00419DE0`/IsInit`00417920`。required字段必须显式存在，包括零余额。field4缺省为空指令，匹配binder逐项消费整数vector；高位按键需varint，不能将原始字节直接写成packed负载。handler `023B5CD4`实际调用binder，完整树包含持久化技能的稳定slot。ACK29自身更新点数、等级、槽位及UI，携带指令时hasExtra=1、数量和原始u8按键；不因存在指令额外追加NOTI19。

匹配Full03的实体重绑定 `02D8D830..02D8D91C`更换当前玩家并新建技能管理器；NOTI19处理后经 `02BCFF20 → 02D80470`恢复当前树，`02D8057D → 02D52900`注册技能对象已有的指令。空field4经 `02D7C250`拒绝空自定义列表而提前返回，不会显式构造或覆盖指令。当前在23/24地区绑定后、124入城完成前再次发送完整NOTI19，空存档指令使用PVF默认键序列补field4，已有指令原样保留；点数、等级、槽位及存档指令不变。该显式恢复避免依赖空字段的隐式默认注册，完整客户端隐式默认注册的失效时机仍未闭合；TCP与原码边界验证不代替Windows按键验收。

指令键为上/下/左/右=`0/1/2/3`、SKILL/JUMP/ATTACK/BUFF=`4/5/6/8`；按住四方向为`9/10/11/12`。`02D7DA92..02D7DAAF`将9..12减9并放入独立按住表，普通0..3进入顺序步骤。因此三段斩`0C 04`表示按住右方向加Z，`03 03 04`表示顺序右、右、Z，两者不能混用。Full03冻结三段斩对象包含held3/held2的镜像方向及步骤4；这属于冻结对象证据，不是当前玩家内存或完整输入循环验证。

正常升级客户端NOTI37 consumer `023C4CB0`读取绝对SP0/1、TP0/1，不自动累加表差。服务端按累计贡献计算两种点数，TP采用S4A21累计扣除行为与匹配资源表，参考范围见[角色成长资源](../资源/角色成长.md)。NOTI37完整直接布局见[经验升级通知](经验升级通知.md)，现有成长事务和发送链见[角色成长](../模块/角色成长.md)，不发送只含前缀的伪刷新。

未学习技能的前置等级 0 仍须确认同职业资源存在，不能把未知资源当零级；资源查询依据见[前置技能等级0](../资源/技能学习与成长.md#前置技能等级0)。

## C2S29 的真实发送形状

队列发送入口 `028A1130` 在 this+70/+74 的8B条目不为空时发送 category1/opcode29。`028A1148→03BDF610(29)`建立13B帧头；`03BDF6A0`写opcode到帧头。它没有额外在body中写 `echo:u16=29`。

`03BDF720` 每次追加1B，`03BDF750` 每次追加2B，最终调用 `03D640F0` 写入缓冲区。正文为little-endian：

```text
context:u8
count:u8
count × (skillId:u16, decrease:u8, magnitude:u8)
mode:u8
```

context来自本地玩家 `02B658D0`，不能命名成job。条目第一DWORD的低u16为技能ID；第二DWORD作为signed delta，小于0写decrease=1，否则0；magnitude=abs(delta)的低u8。队列长度以8B整条目计数。服务端仍需拒绝非法值及重复技能，而不是模仿截断接受所有请求。

尾mode在该入口默认0；入口参数非零时先取1，`015C1D40`返回非零时变为3。`028A1244` 调 `03BE0FF0` 提交发送。队列入口直接caller为 `028A17AA`、`028A1D71`、`028A1E51`；`028A17AA`所在路径在实际队列非空时会写玩家+71C1=1，操作发起对象与确认/取消生命周期仍需追踪。

正式客户端实收另有发送前处理追加的4B检查尾。例如单条正文 `00 01 BE 00 00 01 00` 后跟 `B8 1A 00 00`，完整11B；前7B为context0/skill190/decrease0/magnitude1/mode0，后4B与[正文MD5折叠](副本.md)独立对拍匹配。不能把检查尾当mode、技能条目或多余字节而断开合法学习连接。`SkillRequests.ParsePurchase`严格接受 `3+4*count` 或再加4B两种形状，mode仍从直接正文末端读取；带尾时提供BodyChecksum/ChecksumMatches，当前仅记录匹配状态，不当作身份签名、资源或点数资格。其他宽度继续拒绝。

独立单条入口 `0276F6F0` 生成相同正文，count=1，decrease由参数提供，magnitude为参数绝对值，mode=0或3。其直接caller `01F8F7B3`、`033DE030`、`033DE06F`。另一单条学习路径 `02D5FAE1..02D5FBEB` 写count=1、decrease=0，技能ID来自技能对象+6C的内部字段，magnitude来自caller参数。该技能ID的完整读取路径仍待核对。

## ACK29 成功、失败与客户端刷新

`CMDFUNC_ENUM_CMDPACKET_BUY_SKILL` 的实际consumer为 `02360630`。公共success参数位于caller参数+0C，错误参数u16在+10；该函数不自己读取这两个公共字段。服务端按完整 body 编码成功 `01` 或失败 `00,error:u16`，后续布局如下。

success非零直接读取的正文形状为：

```text
context:u8
sp:u16
tp:u16
count:u8
count × (
    slot:u8, skillId:u16, level:u8,
    hasExtra:u8,
    if hasExtra != 0: extraCount:u8, extraCount × extra:u8
)
mode:u8
```

context=FF在客户端处理时规范化为0，其余按signed byte转换后设当前上下文。`023606B2/023606BB`分别读两个u16；`023607A3/023607AD`经 `02D7E9F0`、`02D7EB80`写入上下文对应加密SP/TP槽。前者使用 `0643A478+8*context`，后者 `0643A488+8*context`。SP getter `02D7EAC0` 与上文累计值比较；`0235C3B0..0235C3BF`将u16增量加到 `02D7ECC0` getter再写第二槽，附近匹配字典331C明确为“增加%d点TP点数”。这与仅凭零字段猜SP不同。

每项 `023607E0..023607FF` 按1/2/1B读取，首字节是实际技能slot。普通0..254经02D82490绑定；FF进入0236085F特殊映射，未匹配ID会落默认138，不能作为status或未分配占位。完整树和稳定槽位规则见上文。

`02360B3C..02360B52`读取hasExtra；非零时 `02360BB2..02360BD6`读取extraCount及其u8条目，随后传入玩家虚表+DF8相关逻辑，保持自定义指令。`02360DA5..02360DC0`读取尾mode，mode=1/3具有额外界面路径，3另调用 `015C22F0`。函数随后刷新技能页、技能对象/玩家被动属性及窗口；这些native调用不是已经证明必须另发NOTI19或玩家快照的服务端包序。

success=0跳 `023610B6`，该分支不再调用packet reader；按错误参数提示后执行窗口恢复及相关通知。匹配dstr说明：

| 命令 | 完整直接正文 | 回复 |
| --- | --- | --- |
| C2S331 | `count:u8,count*(id:u16,length:u8,length*key:u8)` | 提交后ACK331=`01`，再发完整NOTI19 |
| C2S332 | 空正文 | 提交后ACK332=`01`，再发完整NOTI19 |

| C2S510 | `context:u8,mode:u8` | 先按声明池把将进入连招列的上排技能移出快捷栏并回放完整NOTI19（无移动则不发），再ACK510=`01`；不改动连招绑定 |

331实收示例`01 03 00 03 02 03 04`是一个技能3的三个按键，首字节不是页号；单项恢复默认实收`01 03 00 01 04`仍为331，不能将其误称为332。332的空正文与success消费来自匹配发送和ACK函数，尚无本次实收样本。331/332公共success之外不需要附加页号或错误占位。

508的尾mode来自匹配发送函数，普通值0、决斗分支2；当前只接mode0。根和子技能均为u16，计数为u8，容量上限均为6。508成功提交后只回ACK508=`01`，客户端以同opcode回包判定完成；不能再用NOTI447代替回执，否则客户端会持续重发保存请求。连招组按根的快捷栏槽位顺序保存和回放，与NOTI19绑定顺序及客户端六列一致，不能按技能ID重排。447在消费期间切换context，处理完恢复原context；pageCount不是当前技能树，不能借该通知实现切树。510的成功触发客户端自动编排，随后508提交编排结果；不由服务端推断自动排列次序。自动组合的快捷栏清理在510阶段完成：服务端按各连招根声明的子技能池，把当前上排中的候选技能移出快捷栏（优先150–197，扩展栏耗尽后退到12–137），改动过槽位时先回放完整NOTI19再回ACK510。客户端在回执之后才本地生成排列并显示，重建发生在排列显示之前，不会清空六列。自动排列的508只保存客户端提交的排列并回ACK508，不再回放技能树或补发NOTI447；手工508不改动绑定也不触发回放。508/510尚待当前客户端手动验收，业务边界见[特殊职业模块](../模块/技能学习.md#tp与特殊职业)。

## 降级、重置与达人状态
