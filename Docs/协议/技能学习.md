# 技能学习协议与字段依据

本页维护 C2S29、ACK29 与 NOTI19 的字段、消费语义和边界；资源加载及费用规则见[技能学习与成长资源](../资源/技能学习与成长.md)，当前业务与事务见[技能学习模块](../模块/技能学习.md)。其中 TP 表示特性技能点。

## 请求、重复与响应

`028A1130/028A1148` 发送 C2S command29：`context:u8,count:u8,count*(id:u16,decrease:u8,magnitude:u8),mode:u8`。队列存 signed delta；decrease 为 delta<0，magnitude 为 abs(delta)，不是目标等级。普通正向切片限定 context0/1、decrease0、magnitude1；普通 sender mode0 或1，特殊 `015C1D40` 分支生成3，暂不支持。不存在正文操作 nonce；相同报文可表示合法再次升级，不能按报文哈希去重。事务需按当前 revision、当前等级和费用执行，重复报文语义边界需如实报告。

ACK29 consumer `02360630` 成功体为 `01,context:u8,sp:u16,tp:u16,count:u8,items,mode:u8`。每项为 `slot:u8,id:u16,targetLevel:u8,hasExtra:u8`，hasExtra 非零再读 `extraCount:u8` 和对应字节。单项无 extra 共13字节。每项第一字节是 slot，绝非 status。失败体为 `00,error:u16`，后续不再消费字段。

匹配文字确认 0012 已掌握、0015 技能不存在、0016 SP不足、00D9 无法学习指定Lv、0007 决斗场限制。文字不证明 level/prerequisite/cap/revision 的所有拒绝都可映射 D9；本地 precheck 的 -1/-2/-3/-4 也不是 wire error。

## 槽位与完整树

`02D82070 → 02D80160` 建立512项槽位及两个 context；`02D82490(slot,id) → 02D82380(slot,skill)` 绑定。普通缺 combo 默认标志 false，可绑定合法空槽；特殊 combo 标志限制 slot<6。已有槽可被覆盖，服务端应选择空槽并持久化，升级保持已有槽。ACK byte 可直接表达0..254；FF 在 `02360863..02360958` 走特殊映射，普通未匹配ID会落槽138，不能用 FF 代表未分配。确定分配最低空槽0..254是普通 binder 允许的实现策略，0只有实际分配时才合法。

NOTI19 注册 `023CCAA2 → 023B5910`，正文为 length:u32 加 protobuf；不存在压缩或把 cursor getter 当解压的依据。

| 消息 | 字段 | 形状与含义 |
| --- | --- | --- |
| outer | 1 | optional varint packet enum，构造默认19 |
| outer | 2 | repeated length-delimited tree，按顺序 context0/1 |
| tree | 1 | required varint SP |
| tree | 2 | required varint TP |
| tree | 3 | repeated length-delimited skill |
| skill | 1 | required varint slot |
| skill | 2 | required varint skillId |
| skill | 3 | required varint level |
| skill | 4 | optional repeated varint extras，支持 unpacked/packed |

outer parser `0041C650`，tree parser `0041B3C0`/IsInit`00418D00`，skill parser `00419DE0`/IsInit`00417920`。required 字段必须显式存在，包括零余额；extras absent 结构合法，但特殊技能业务语义未闭合。handler `023B5CD4` 实际调用 binder，完整树应包含持久化技能的稳定 slot，不能拿空树当通用点数刷新。ACK29 成功自身更新点数、等级、槽位及 UI，未证明必须随后追加 NOTI19。

正常升级客户端 NOTI37 consumer `023C4CB0` 读取绝对 SP0/1、TP0/1，不自动累加表差。累计 SP 资源差已在 [角色成长资源](../资源/角色成长.md) 说明；TP 原始表不是余额发奖规则，正常 TP 发点仍待确认。NOTI37 的完整直接读取布局与纯 Builder 已明确，见[经验升级通知](经验升级通知.md)；合法经验来源、成长事务和发送链尚未接入，不发送只含前缀的伪刷新。

未学习技能的前置等级 0 仍须确认同职业资源存在，不能把未知资源当零级；资源查询依据见[前置技能等级0](../资源/技能学习与成长.md#前置技能等级0)。

## C2S29 的真实发送形状

队列发送入口 `028A1130` 在 this+70/+74 的8B条目不为空时发送 category1/opcode29。`028A1148→03BDF610(29)`建立13B帧头；`03BDF6A0`写opcode到帧头。它没有额外在body中写 `echo:u16=29`。

`03BDF720` 每次追加1B，`03BDF750` 每次追加2B，最终调用 `03D640F0` 写入缓冲区。正文为little-endian：

```text
context:u8
count:u8
count × (skillId:u16, decrease:u8, magnitude:u8)
mode:u8
```

context来自本地玩家 `02B658D0`，不能命名成job。条目第一DWORD的低u16为技能ID；第二DWORD作为signed delta，小于0写decrease=1，否则0；magnitude=abs(delta)的低u8。队列长度以8B整条目计数。服务端仍需拒绝非法值及重复技能，而不是模仿截断接受所有请求。

尾mode在该入口默认0；入口参数非零时先取1，`015C1D40`返回非零时变为3。`028A1244` 调 `03BE0FF0` 提交发送。队列入口直接caller为 `028A17AA`、`028A1D71`、`028A1E51`；`028A17AA`所在路径在实际队列非空时会写玩家+71C1=1，操作发起对象与确认/取消生命周期仍需追踪。

独立单条入口 `0276F6F0` 生成相同正文，count=1，decrease由参数提供，magnitude为参数绝对值，mode=0或3。其直接caller `01F8F7B3`、`033DE030`、`033DE06F`。另一单条学习路径 `02D5FAE1..02D5FBEB` 写count=1、decrease=0，技能ID来自技能对象+6C的内部字段，magnitude来自caller参数。该技能ID的完整读取路径仍待核对。

## ACK29 成功、失败与客户端刷新

`CMDFUNC_ENUM_CMDPACKET_BUY_SKILL` 的实际consumer为 `02360630`。公共success参数位于caller参数+0C，错误参数u16在+10；该函数不自己读取这两个公共字段。服务端按完整 body 编码成功 `01` 或失败 `00,error:u16`，后续布局如下。

success非零直接读取的正文形状为：

```text
context:u8
sp:u16
tp:u16
count:u8
count × (
    slot:u8, skillId:u16, level:u8,
    hasExtra:u8,
    if hasExtra != 0: extraCount:u8, extraCount × extra:u8
)
mode:u8
```

context=FF在客户端处理时规范化为0，其余按signed byte转换后设当前上下文。`023606B2/023606BB`分别读两个u16；`023607A3/023607AD`经 `02D7E9F0`、`02D7EB80`写入上下文对应加密SP/TP槽。前者使用 `0643A478+8*context`，后者 `0643A488+8*context`。SP getter `02D7EAC0` 与上文累计值比较；`0235C3B0..0235C3BF`将u16增量加到 `02D7ECC0` getter再写第二槽，附近匹配字典331C明确为“增加%d点TP点数”。这与仅凭零字段猜SP不同。

每项 `023607E0..023607FF` 按1/2/1B读取，首字节是实际技能slot。普通0..254经02D82490绑定；FF进入0236085F特殊映射，未匹配ID会落默认138，不能作为status或未分配占位。完整树和稳定槽位规则见上文。

`02360B3C..02360B52`读取hasExtra；非零时 `02360BB2..02360BD6`读取extraCount及其u8条目，随后传入玩家虚表+DF8相关逻辑。该扩展的业务语义未闭合，不把它命名成技能等级表或快捷栏。`02360DA5..02360DC0`读取尾mode，mode=1/3具有额外界面路径，3另调用 `015C22F0`。函数随后刷新技能页、技能对象/玩家被动属性及窗口；这些native调用不是已经证明必须另发NOTI19或玩家快照的服务端包序。

success=0跳 `023610B6`，该分支不再调用packet reader；按错误参数提示后执行窗口恢复及相关通知。匹配dstr说明：

| 错误u16 | 提示 | native比较点 |
|---|---|---|
| 0012 | 已精通该技能 | 023610BA |
| 0015 | 不存在的技能 | 023610DF |
| 0016 | SP点数不足 | 023610ED |
| 005B | 金币不足 | 023610FB |
| 005C | 公会Lv不足 | 02361109 |
| 00CE | 您被禁闭在赛丽亚旅馆，无法进行该操作 | 0236111C |
| 0013 | 出现错误（技能类型扩展券） | 02361129 |
| 00D9 | 无法学习指定Lv的该技能 | 0236113C |
| 0007 | 在决斗场中无法学习技能 | 02361149 |
| 00EB | 勇士对决中无法进行技能设置 | 0236115C |

这些提示映射来自本版失败consumer和同版字典；没有证明服务端每种校验错误都应采用这些码，普通不存在技能和 SP 不足的回复及同连接继续请求由服务端 TCP 回归覆盖，其他错误不据此推定。TP不足、owner过期、revision冲突的协议映射待确认。
