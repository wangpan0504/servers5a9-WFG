# 客户端设置协议

当前保存正文来自匹配客户端实际请求；回放使用相应通知，不复用保存命令作为ACK。所有整数采用小端。

| 方向 | category/opcode | 布局 |
|---|---|---|
| C2S | 1/197 `SAVE_GAME_OPTION_1` | `length:u32=204 + gameOptions:204B` |
| C2S | 1/447 `SAVE_CHARACTER_OPTION` | `length:u32=512 + characterOptions:512B` |
| S2C | 0/173 `GAME_OPTION` | `length:u32=204 + gameOptions:204B + bank0Length:u32=0 + bank1Length:u32=0` |
| S2C | 0/390 `CHARACTER_OPTION` | `length:u32=512 + characterOptions:512B` |
| S2C | 0/357 `CHARAC_INVISIBLE_FALGS` | `actorId:u16 + flags:u8` |

保存请求不含账号或角色ID，归属由当前会话确定。长度头、实际正文与匹配设置区必须全部一致；缺失、截断及多余尾部作为结构错误结束连接。账号保存原始主区；已选角时另存角色主区，只协调以下已确认的角色字段，不解析或覆盖未知槽。

下表索引均为主区中的u16槽（字节偏移为索引乘2）：

| 角色设置 | 主区槽 |
|---|---:|
| 转职/觉醒特效 | 1 |
| 技能插图特效 | 13 |
| 查看全身时装 | 55 |
| 觉醒装扮 | 74 |
| 队员技能效果透明度 | 22 |
| 角色技能效果透明度 | 68 |
| 角色伤害字体透明度 | 89 |
| 队友伤害字体透明度 | 94 |

角色512B区的u16槽46、49会分别回写主区68、13；保存和回放必须使用同一角色值，不能让390再覆盖为不同值。其余508B保留。Actor与357的显示位保留原无关bit，bit1表示转职特效显示，bit3/bit4分别表示隐藏全身时装/觉醒装扮；技能插图不映射到bit2。Actor中的bit3还会回写主区55，故Actor不能继续发送固定默认显示位。

匹配通知消费者要求主设置204B、角色选项512B；账号通知随后读取两段带长度的银行数据。当前尚未保存快捷聊天银行，回放时两段长度写0；该组合已通过设置回放与切换角色的实机验收，非空快捷聊天银行的字段另行确认。角色选项的部分应用需要本地角色上下文，因此在本人Player和城镇地区绑定完成后回放。

选角时，有完整主区来源则在本人Actor/Player之前预载一次173，使主设置singleton先完成初始化；既有23/24地区通知及可选1379之后、124入城完成之前，仍按已有数据发送173→390→357，保留依赖本地角色的应用。前后两次173的完整正文相同；无主区不发173/357，无角色选项不发390。缺少独立角色主区时以当前账号主区作为初值，旧角色有效46/49仍参与回放；没有完整主区来源不生成未知默认模板。主区u16槽90为UI大小，当前客户端保存实收0/75/100；本功能原样保存，不在服务端计算缩放比例。保存时不发送专用ACK或即时173/390回推；外观位实际变化时本人收到357，远端沿同屏Actor刷新。再次选择角色、重连及重启后从数据库读取。

当前职责、所有权、存储与验证入口见[客户端设置模块](../模块/客户端设置.md)。
