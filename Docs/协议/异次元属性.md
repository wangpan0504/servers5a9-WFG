# 异次元属性

本页记录 S5A9 的 CMD204 净化／清除与 CMD205 赋予／扭转／黄金增幅书。普通 NPC 逐级增幅及 CMD80 券属于其他入口，不由这两条请求代替。业务与事务见[背包与装备](../模块/背包与装备.md#异次元属性赋予与清除)。

## 请求与响应

CMD204 发送者 `029D7A90`：正文固定12B，`targetSlot:i16 + targetItemId:i32 + materialSlot:i16 + materialItemId:i32`。目标和材料均为 Main，快捷栏是真实 Main 槽。

CMD205 发送者 `029C8130`：固定14B，`action:u8 + targetSlot:i16 + targetItemId:i32 + materialSlot:i16 + materialItemId:i32 + selectedOption:u8`。action0赋予、1扭转、2黄金书；只有2追加 `textLength:i32 + text:bytes`。生产者先读取最多128个宽字符再按既有DSTR转换，本服接收至多256B的名称原字节；名称不参与身份、属性、费用校验，不写入新增业务日志。

所有成功回执使用同一提交结果，源数量均为扣除后的绝对剩余量；0触发原生清源槽。

| 请求 | 成功正文 |
|---|---|
| 204 | `01 + materialSlot:i16 + materialRemaining:i32 + targetSlot:i16 + amplifyType:u8 + amplifyValue:u16`，12B |
| 205 action0/1 | `01 + action:u8 + materialSlot:i16 + materialRemaining:i32 + targetSlot:i16 + amplifyType:u8 + amplifyValue:u16`，13B |
| 205 action2 | 上述13B再加最终 `upgrade:u8`，14B |

两者失败均为 `00 + error:u16`，不能复制旧参考端的单字节错误码。公共分派 `028F8644..028F865A` 读取u16；`0041CA50`仅豁免18/20，不包含204/205。

注册 `0237C6CB..0237C6EA`：204消费者为 `0235A990`，205为 `02374FE0`。二者取得库存后，在判断成功位之前调用 `029CF9D0` 弹出等待记录。204发送时压入29，205的 `029E2E70/029E3330` 压入30；不回复会残留等待并阻止后续库存操作。业务拒绝、畸形或无法解析的资源必须回复已确认的失败结构；数据库提交异常保持原连接关闭合同，不冒充成功。

205错误分支 `02375357..023753D6` 使用错误码映射：8表示目标不能被赋予、17为稍后重试、18为强化目标不允许、20为已有属性、21为缺少已净化属性、23为相同属性。204非零错误使用固定净化失败提示，不能套用205的文字含义。

## 原位更新

存档中的未识别位与客户端可见类型不同；未净化实例出站只呈现128标记和零基础值，不能原样下发带隐藏属性的0x81–0x84。统一投影及偏移依据见[物品协议](物品.md#未净化异次元属性投影)，不通过改写存档或取消客户端保护校验规避。

204成功在 `0235A9D8..0235AB5F` 回填源数量和目标属性，允许目标Type/Value为0；205在 `0237502E..0237521A` 读取动作、源余量、目标Type/Value，action2继续安装等级并打开结果窗。Type/Value对应普通123B的offset19/20；等级仍为Attr低五位。

普通成功ACK已经原位更新全部变化字段，不能再重建源或205结果窗持有的目标对象。投影仍参与原提交资格、任务材料条件和锁回放，但跳过ACK已处理的槽。黄金清除会将既有增幅等级归零，而204没有等级字段，因此仅这一情况在ACK之后沿共享1681无播报路径，先清旧目标再载入完整123B条目，不重复发送源扣除或获得播报。

## 掉落生成

df_game_r 的`CItemList::create_item`（`08511FB8`）只在创建类型1中调用资格检查及生成器，不把普通发放全部当作掉落。`checkInvestableItem`（`08234980`）要求普通装备部位、rarity非0/1、满耐久、物品使用等级至少55，再以grade减稀有度修正值比较PVF的`equip level const`。创建调用传入角色等级0，因此掉落不以当前角色等级代替装备等级。55级稀有装备的grade57减修正2已可满足55；使用等级相同但grade较低的模板仍不参与，并非统一的60级限制。本版继续按现有装备部位映射及七种rarity装配，不复制旧端六种rarity上限。

`_generateOption`（`08514F70`）先在10000域比较`amplification rate by rarity`，命中后另抽10000域，按`option data`累计权重选属性。`importAmplifyItem`（`0890A6B0`）保留相对权重并在读入时形成累计阈值；不将`amplification weight by level`当作额外生成概率。当前PVF的common/uncommon/rare/unique/epic/chronicle/legendary依次为`0/0/12/2061/2000/2000/2000`，是资源配置而非服务端固定概率，故未新增另一份全局概率开关。

`generateAmplifyItem`（`08514EBA`）将命中属性及基础值写入实例。`CEquipItem::isAmplifyPollutionItem`（`085136B6`）控制识别状态；`set_item`（`0850FD84`）从模板的pollution限制形成该标志。普通装备使用未净化位，明确禁止pollution的模板直接保存已识别属性；不是取消生成。存档与客户端可见字段的区别仍见[未净化投影](物品.md#未净化异次元属性投影)，地面及拾取不裸发0x81–0x84，不改客户端。

## 资源与业务依据

`etc/amplifyitem.etc`按实际映射区分 `purify material`、`purify only material`、`purify only cera material`、`gold purify material`、`invest option`、`reinvest option`和`random invest upgrade option`。重复的相同材料行可保留，冲突定义拒绝；不将所有含“净化”字样的STK视为同一业务。

旧端 `df_game_r` 的 `Dispatcher_PurifyItem::process`（`08218CB6`）及 `processPurifyType`（`082194B6`）只做识别或清除；`stAmplifyOption_t::identify`（`0822B3D8`）仅移除0x80位，保留掉落时已有的类型与基础值，不重新抽属性。赋予／扭转由 `082194F4`、`08234C3C`、`08234B30`处理；只作业务参考，旧端207/208不作为本版包号。

赋予和转换的基础值来自 `option data` 第三项与 `rarity weight`。`08234B30`用float32倍率、x87乘法后向零取整；本服保留原倍率位，使用double精度完成该精确乘积后截断，不先把乘积舍入回float32，也不从说明文字重建十进制倍率。黄金书等级独立按源STK的 `amplification random value` 权重抽取并覆盖原等级。

旧端未在这两条处理链检查角色是否达到消耗品最低等级，本服也不新增该门禁，或额外的源职业、技能匹配要求。角色等级只在目标装备声明 `upgradable level` 时参与目标资格判断；装备自身的等级、稀有度、满耐久及按增幅表 `disjoint/correction grade by rarity` 修正的品级限制仍保留。

原码分析、合成断言、真实TCP和客户端验收是独立证据。`--selftest-core`及`--selftest-tcp amplification-options`验证协议、资源、原子提交、拒绝后继续、末段SQL回滚、完整核心与重连恢复；UI等待解除、黄金结果窗及属性显示仍需客户端测试。
