# 强化与增幅券（S5A9 CMD80）

本阶段接入已核对参数的 `equipment reinforcement ticket` / `equipment amplify reinforcement ticket` 固定覆盖与增量券。
普通强化/增幅材料、独立保护券、幸运券、多候选随机券，以及额外资格或附加材料未闭合的资源保持拒绝，不消耗资产。
这份实现不能用于宣称 #145 全部完成；幸运券及普通高等级增幅失败政策仍需后续闭合。

## 请求与消费者

C2S category=1 / opcode=80。完整宽度为 `20 + textLength`，严格保留以下字段：

```text
mode:u8 (0强化/1增幅)
targetList:u8, targetSlot:u16, targetItemId:i32
materialSlot:i16, protectionSlot:i16
textLength:i32, targetText:bytes[textLength]
auxiliarySlot0:i16, auxiliarySlot1:i16
```

文字最大256B，保留原字节但不写日志，不用于鉴权、费用或身份校验。当前券路径仅接受三个附加槽均为 -1。
实际用户请求28B的目标为 Main21 / 模板27308，券源 Main86，文字长8，末尾两槽为 -1；文档不保存原文字。

当前x86消费者与producer来自同一 `DungeonHelper/Evidence/code.bin`，加载基址 `0x401000`：

- producer `029DE124/029DE12D` 写80头，`029DE13D/14D/15D/17B/18B/1D3` 依次写前六项。
- `029DE235 -> 03BDF8E0` 写DSTR，`029DE245/029DE255` 继续写两个u16，`029DE25A -> 03BE0FF0` 发送。
- 注册 `0237C325 -> 02373D90`。成功消费者 `02373E60..02373EFA` 读模式及固定前缀。
- `02374194..0237419A` 用绝对余量回填券；耗尽分支清源。
- `023744EA..023745B3` 将结果新等级装回装备快照；本命令未读取新的异次元Type/Value。
- `02374932/0237493E` 必读末端i16槽与i32余量，`023749A4/023749B2` 再读两个u8状态。

## 回包与发布

S2C category=1 / opcode=80。接受的事务（包括券概率失败）成功结构为27B：

```text
1:u8, mode:u8,
materialSlot:i16, materialRemaining:i32,
protectionSlot:i16=-1, protectionState:u8=0,
oldLevel:u8, result:u8 (0成功/1券失败保级), newLevel:u8,
targetList:u8, targetSlot:i16,
optionalSlot:i16=-1,
terminalSlot:i16=-1, terminalRemaining:i32=0,
tailState0:u8=0, tailState1:u8=0
```

该27B仅适用于本入口无附加消费/产物的券。消费者还有销毁及附加产物分支，不能以固定27B推广到普通强化。
正常拒绝沿公共 `0:u8 + error:u16`，目前使用23；细分错误文案仍需本版客户端验收。
SQL异常沿现有会话错误传播，不能转成成功或自动重新随机。ACK后共享背包Projection发布已提交完整核心差量；穿戴目标沿Actor/Player刷新。
即使ACK已回填源余量与等级，差量使用绝对数量和完整核心，不另做第二次消费；目标无变化的覆盖券仅发布真实源差量。

## 资源、资格与事务

券声明为 `level percent fixed|additional rawFourthParameter`。模型保留第四整数为 `RawLevelLimit`；不将字段名字本身当作语义证据。
等级1..31、概率0..100、额外字段和未知模式不能夹紧成成功；当前增量分支按第四参数限制源等级，并遵守Attr五位最大值。
固定券第四参数是否也限制源等级尚未闭合；本阶段只支持真实样本的 -1，非 -1 固定券保持Pending，不能忽略该限制后覆盖装备。
支持显式目标物品清单和 `check usable itemlevel` 两项范围。Town门禁接收village及village加seria room；仅seria room的声明保持Pending，避免扩大到所有Town。
目标按有效装备脚本的 `impossible contents` 与真实部位限制，排除称号/宠物/时装，不靠名称推断资格。

源必须是Main中的真实可堆叠实例；目标仅Main/Equipment，保留身份、位置、锁、期限及完整快照。
强化只允许无异次元属性目标；增幅只允许已识别的Type1..4且非零基础Value，未净化高位状态拒绝。
每次扣指定格一券，无普通金币费用；券概率失败保留目标，与普通增幅当前+10冲+11的破坏政策分开。

目标只改变 `Attr & 0x1F` 对应的等级，保留高三位及AmplifyType/AmplifyValue。异次元基础值不在每次升级后加上PVF等级收益。
完整核心与本版PVF交给客户端派生属性；CHR基础Player属性不重复添加装备强化/增幅收益。
源数量、目标修改、审计和角色revision复用同一个InventoryPlan外层事务；有限源/目标期限由提交前置条件重验。

已导出真实资源：

- 490705402 新春 +11券：`11 100 fixed -1`，目标等级1..95，village/seria room。
- 27308 步兵巨剑：weapon、最低等级10，用于实际用户请求与TCP完整行保留验证。
- 10007133 +10增幅券：`10 100 fixed -1`，还含 `need material 10007110 5`。该声明作用尚未核对，当前明确拒绝。

测试用合法未到期实例模拟历史券，不修改PVF绝对到期规则或正式grant行为。

编译、各层自测、TCP和独立评审由主代理统一串行执行；静态证据不代替这些运行验证或实机验收。
