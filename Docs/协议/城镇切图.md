# 城镇切图与Loading

初次入城与普通区域切换使用不同的完成通知。当前合同由[TownProjection](../../Server/DfoServer/Network/Projection/TownProjection.cs)和[TownPackets](../../Server/DfoServer/Network/Builders/TownPackets.cs)实现；包体见[角色与入城](角色与入城.md)。

## 1. 发包合同

| --- | --- | --- |
| 初次选角 | [完整条件序列](角色与入城.md#连接与角色选择)，含 Main 背包与空124 | 完整序列发送成功后MarkReady；选角出生事务须先提交 |

| 副本选择C2S15 | 零值ACK15=`01`后空列表NOTI27；非零只ACK | 仅选图界面路径。独立进图诊断的28/29、37/30与后续边界见[副本合同](副本.md)，不复用124，不改变任务/revision |

C2S36原样使用请求x/y，选角和1426按PVF解析；位置与返回点同事务、revision保护。通知不能提前于提交，也不能因客户端临时文字重复发送完整入城初始化。后续全城镇/NPC/码头/菜单均沿上述切图序列，详见[全城镇通行](../模块/城镇.md)和[NPC传送与选角出生](../模块/NPC与出生.md)。

## 2. 匹配客户端边界

## 3. 开发与验证

新增切图入口首先明确它是普通区域迁移、初次入城还是独立玩法；不能仅凭画面都出现Loading就共用完成通知。提交失败保持原Selected/位置/revision，发送失败从数据库重连恢复；不直接清客户端内部字段来掩盖未闭合的服务端包序。

已有隔离TCP回归校验初次空124和cargo13、普通进出房及1426只发23/24、入房1379；使用后续1347 ACK作为处理边界，多余124会直接违反预期序列，不通过超时“没看到包”判断。入口为[Server/DfoServer/SelfTests/Tcp/TownProtocolTcpTests.cs](../../Server/DfoServer/SelfTests/Tcp/TownProtocolTcpTests.cs)，按[业务规范](../../CONTRIBUTING.md#验证)执行。

初次入城与普通切图已有用户确认可操作；该确认不是所有地图资源加载与特殊玩法的全覆盖保证。实际联调分别观察：初次入城后能否移动、普通切图后区域/坐标是否正确、1426返回地区是否正确、临时Loading是否自然结束、C2S15失败后能否继续移动和返回。若仍持续等待，先核对请求、提交结果、category/opcode及通知顺序，再定位匹配客户端消费者。
