# 城镇切图与Loading

初次入城与普通区域切换使用不同的完成通知。当前合同由[TownProjection](../../Server/DfoServer/Network/Projection/TownProjection.cs)和[TownPackets](../../Server/DfoServer/Network/Builders/TownPackets.cs)实现；包体见[角色与入城](角色与入城.md)。

## 1. 发包合同

| 场景 | 提交后发送 | Ready / 其他限制 |
| --- | --- | --- |
| 初次选角 | [完整条件序列](角色与入城.md#连接与角色选择)，含 Main 背包与空124 | 完整序列发送成功后MarkReady；选角出生事务须先提交 |
| 普通C2S36切图 | Area23 → Transition24 → 入房可选1379 | 不先用22改旧场景actor，不重发124 |
| 房间空body1426出口 | Area23 → Transition24 | 只允许Ready房间当前owner；使用返回地区PVF门口 |
| 副本选择C2S15 | 零值ACK15=`01`后空列表NOTI27；非零只ACK | 仅选图界面路径。独立进图诊断的28/29、37/30与后续边界见[副本合同](副本.md)，不复用124，不改变任务/revision |

C2S36原样使用请求x/y，选角和1426按PVF解析；位置与返回点同事务、revision保护。通知不能提前于提交，也不能因客户端临时文字重复发送完整入城初始化。后续全城镇/NPC/码头/菜单均沿上述切图序列，详见[全城镇通行](../模块/城镇.md)和[NPC传送与选角出生](../模块/NPC与出生.md)。

## 2. 匹配客户端边界

### 药剂与光环个人传送

237请求14B：`slot:i16 itemId:i32 mode:u8 town:u8 area:u8 x:u16 y:u16 direction:u8`。当前普通药剂mode0；成功ACK为`01 slot:i16 itemId:i32`，匹配消费者0234CC40核对源槽与模板后执行药效。失败ACK为`00 error:u16`，已确认23对应拒绝。ACK之后用无获得提示的绝对库存同步，再发23/24；药剂数量不从ACK中的i32推定。

469请求为i32长度加CP936角色名。成功ACK：`01 channel:u8 characterId:i32 nameLength:i32 name:bytes level:u8 job:u8 growType:u8 serverIndex:u8`；匹配消费者027DA270核对频道身份后显示目标确认，027D7F60显示等级与职业，三字节不是城镇/区域。失败ACK为`00 error:u16`。470请求15B：`characterId:i32 npcId:i32 town:u8 area:u8 x:u16 y:u16 direction:u8`。NPC路径characterId=-1且npcId>0；玩家路径npcId=-1且characterId>0；点选城镇的个人传送两个i32都是-1，落点用后面的坐标。成功ACK为单字节01，01767510按Equipment9实际光环启动冷却；失败还读取一个i32附加字段，本服拒绝为`00 0100 00000000`。没有恢复的组队434/435不借用这份个人传送合同。

378通知为`count:u8`后重复`type:u8 remainingSeconds:i32`。个人传送type2，0239D1F0调用02B643C0时再乘1000；资源`[solo teleport] 420`和通知420都以秒表示。跨区域仍使用23/24，138只迁移已有actor的坐标，不能承担完整切图。

匹配客户端 class0/op23→023D7AD0，准备区域路径调用03B8AEC0；op24→023DF080，场景装载调用03B93DA0。op24读取town/area之前还调用028FD4B0(1)，由Game相关条件管理Loading绘制回调。因此短暂Loading文字可能来自正常资源加载；出现文字本身不能证明服务端等待未结束。

class0/op124→023E09C0，官方函数名ENTER_GAMEWORLD_COMPLETE，body为空。它清TownScene+2B8以及初次入城输入闸，并执行其他入城初始化，属于选角完成合同。不能删初次124，也不能在每次普通切图复用其全部副作用。

23的末尾状态字节涉及远程角色分支，24保留direction/state/extra三字节。两包的state均为 `1 | (character.VisibilityFlags & 2)`：保留既有bit0，bit1同步当前角色转职特效开关，其他外观位不混入此字段，extra仍为1。

匹配消费者 `02A90970` 读取位置结构+7，`02A90B5F..02A90B79` 将其中bit1交给 `02904FA0` 写转职显示记录。23适用分支与24地区绑定共用该链，固定state=1会关闭转职特效；首次入城的后续357虽可恢复显示，普通出房和回城没有该补包。因此所有场景投影必须携带当前角色显示位。本版没有把state确认成单独的Loading开关，不为了提示闪现修改其余位或额外发送124。

C2S15的入口等待是另一条状态链：失败ACK经03B87140(0)清TownScene+218。它与124清初次入城闸不同，副本入口应按自身失败收尾处理。

## 3. 开发与验证

新增切图入口首先明确它是普通区域迁移、初次入城还是独立玩法；不能仅凭画面都出现Loading就共用完成通知。提交失败保持原Selected/位置/revision，发送失败从数据库重连恢复；不直接清客户端内部字段来掩盖未闭合的服务端包序。

已有隔离TCP回归校验初次空124和cargo13、普通进出房及1426只发23/24、入房1379；使用后续1347 ACK作为处理边界，多余124会直接违反预期序列，不通过超时“没看到包”判断。入口为[Server/DfoServer/SelfTests/Tcp/TownProtocolTcpTests.cs](../../Server/DfoServer/SelfTests/Tcp/TownProtocolTcpTests.cs)，按[业务规范](../../CONTRIBUTING.md#验证)执行。

初次入城与普通切图已有用户确认可操作；该确认不是所有地图资源加载与特殊玩法的全覆盖保证。实际联调分别观察：初次入城后能否移动、普通切图后区域/坐标是否正确、1426返回地区是否正确、临时Loading是否自然结束、C2S15失败后能否继续移动和返回。若仍持续等待，先核对请求、提交结果、category/opcode及通知顺序，再定位匹配客户端消费者。
