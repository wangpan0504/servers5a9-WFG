# 角色与入城协议

本页维护角色请求、名称检查消费者、选角/退出和入城投影。帧格式见[基础协议](帧与频道.md)，当前业务与资格见[角色](../模块/角色.md)。

## 角色请求

C2S category=1，多字节整数 little-endian，DSTR 为长度加 CP936 字节；名称限 1–12 字节及可编码的常用汉字、ASCII 字母、数字和下划线。

| 3 / 0003 | `mode:u8`，实收`00`退出、`01`变更频道 | 仅接受这两个模式；结束当前角色会话，回复 `(1,3)` body=`01` 后关闭当前游戏连接并释放其owner。客户端自行执行退出或频道重连，服务端不重跑位置写入 |

### 玩家右键与公开资料

匹配客户端右键入口 `0399EE70` 对其他玩家经 `0399EE90..0399EEEC` 发送 C2S10，13B正文为 `target:u16 + mode:u8=15 + u32=0 + u16=0 + u32=0`，并在界面保存待显示目标。NOTI7 在 `023E2AA3` 注册到 `023D19D0`：先读取 `target:u16 + mode:u8 + opaque:u32`，mode15分支 `023D1D29..023D1DC0` 再读一个u16队伍字段；`FFFF` 将客户端队伍标志清零，其他值将其设为1。随后调用 `0399EF10`，按保存目标继续菜单流程。当前服务端返回9B `target:u16 + 0F + u32=0 + u16=真实队伍ID或FFFF`，仅发给查询者。ACK10成功分支不会执行菜单唤醒，不能以通用 `01` 替代NOTI7。

常规查看资料发送端 `02559789..025597B2`、`02E3AB34..02E3AB63`、`03933A58..03933A88` 使用 C2S8 `target:u16 + type:u8=3`。服务端先发送目标Actor，再发送 NOTI2/subtype3：`03 + count:u16=1 + serverIndex:u8 + channelNumber:u8 + publicHeader:9B + target:u16 + experience:u64 + statsLength:u32 + stats:89B + equipmentFlags:u8 + 装备块 + 名称装饰8B + 双技能树 + 公开尾部`。Actor与公开资料均带目标频道；不能把CMD116枚举名当作这条请求入口。

NOTI2分派 `026823EC` 读count及频道后进入 `0267CC10`。公开9B头依次为冒险团等级u32、保留u16及三个装备标志u8，分别经 `02D83080/02D83150/02D83100` 恢复装备容器bit3/4/5，不能当作网吧或黑钻身份；`0267D04C` 读完整u64经验，`0267D060` 读取长度前缀属性。`0267D0D1 → 023C3A90` 读取完整穿戴和尾部 `u32 + u8列表数`，随后 `0267BC60` 读名称装饰，`02676C60` 读active:u8及两组 `count:u8 + (skill:u16, level:u8)*count`。公开链不调用本人的 `0267BFA0`，不能插入BUFF换装登记块。

公开尾部按消费顺序为：`u8=0`；`0267A540` 的 `3*u32 + 4*u8 + count:u8 + count*u32`（当前决斗场空状态）；`0267D182` 的保留u32；`02678F60` 的 `u16 + u32 + guildName:DSTR + u8 + u8`（除真实公会名外的未确认辅助字段保留0）；`02676510` 的u32空列表；`0267A7F0` 的u8空列表；`0267B480` 的u8空状态。公开链没有本人熟练度17B头、成长胶囊和皮肤仓库尾部，不能复制整个本人Player再仅改subtype。

服务端只接已确认的mode15零辅助字段及type3查询。其他模式、资料类型与辅助字段仍保持未实现，避免误回成功；畸形的已支持包体拒绝。离线或未就绪目标不回虚构结果。在线快照、失效与只读边界见[城镇同屏](../模块/城镇同屏.md#玩家右键与公开资料)。以上地址来自匹配本地客户端静态消费链；自有TCP不能代替部署后的菜单与资料画面验收。

### 删除角色与名册行索引

匹配S5A9主模块的三个普通删除发送点 `037B0296..037B02D0`、`037B0E30..037B0E6D`、`037B10EF..037B112C` 初始化opcode6后，通过 `03BDF750` 写当前UI行索引u16，再经 `03BDF8E0 → 03C783B0 → 03BDF850` 写确认名DSTR并 `03BE0FF0` 发送。字符串转换与建角相同，长度u32是转换后的字节数，不含NUL；无立即删除标志、角色ID或其他尾部。输入确认名先与该行名称比较，服务端仍严格核对CP936、长度及实际角色姓名。

ACK6注册 `02349CC4..02349CCF → 028F8C30`，回调为 `0233DD20`。公共ACK分派先读success:u8；成功分支 `0233DD54..0233DD5E` 读额外u8，`0233DD81..0233DD8C` 再读行索引u16，所以成功body完整为 `success:u8=1 + opaqueClearFlag:u8=0 + 原rosterIndex:u16`，不能只发`01`或把末项写成角色ID。额外标志非零只触发管理对象`+8B1`清零，后续仍删除名册行；当前普通成功取0，不把它命名为立即删除资格。回调交 `03B62AD0` 执行本地vector erase，随后 `0233DEF4..0233DF05` 发送空C2S645，没有发送C2S8。服务端ACK后主动完整名册；645按选角确认业务回放账号冒险团，后续合法请求正常处理。

失败body为 `success:u8=0 + error:u16`，回调没有继续读正文。当前普通业务拒绝选已确认的中立静默收尾123，即 `00 7B 00`；共用失败处理 `03A1F780` 在 `03A1F862` 比较123并直接走 `03A1F7BB` 返回，无文本查找或弹窗，随后ACK6回调清管理对象`+380/+B2C`。该码不被命名为确认名、槽位、状态等具体原服错误；畸形正文和存储异常仍按连接错误收尾。

C2S4普通发送入口 `03B55580` 的 `03B555AE` 捕获传入vector index，`03B55634..03B5564D` 按vector count核验，再于 `03B56F81..03B56F8F` 初始化opcode4并通过 `03BDF750` 写原index；不读取行内的持久slot。USERINFO subtype2安装端 `02681B30/02681B43 → 03B67970` 清名册及详情vector，`02681BDF`读count并逐行调用`02680B80`；首u16在`02680BB5`读作旧条目查找键，但清空后的新行经 `026810B0..026810C4 → 03B75710`，再于 `03B757F9..03B7580E` 连续pushback到名册和详情vector，没有按首u16保留洞。因此名册包含持久slot0/2时，客户端行是0/1；C2S4/C2S6均须按发布顺序映射，不能直接把正文当数据库slot。

以上为匹配原码的发送/消费证据，自有TCP核对完整帧与映射；未以当前Windows客户端UI操作确认删除、弹窗和连续建角画面。请求不携带操作身份，不能证明同名同一行重建后旧删除包的永久去重。

### 选角页拖动重排

匹配客户端在选角页拖动角色行后发送 C2S `(1,295)`，正文固定8B，为两个 `u32` 名册行索引，不是持久槽位。发送端 `03B45760` 取源值 `[this+8F8]`（拖动开始时由 `03B435CC` 从当前选中绝对索引 `[8B4]` 复制），目标值由 `03B42180()+page*[0621BA70]` 计算，两者均为列表绝对索引；随后调用 `03B42550` 经两个u32写入函数 `03BDF780` 和发送 `03BE0FF0`。偶数成对拖拽分支再发一次带 `[960]` 配对偏移（0/1）的索引对。本机匹配客户端实收三帧 `01 00 00 00 00 00 00 00`（Length=8，未选角阶段）；此前服务端未注册该 opcode，`unimplemented` 日志与“拖动顺序不保存”一致。

处理只接受尚未选角的当前owner。两个值按最近一次实际发送的名册行序取 `CharacterRosterEntry`，再用两行的真实持久槽位互换；删除角色会留下槽位空洞，索引与槽位不再相等，不能把正文直接当槽位。越界索引不写库，仍回ACK并回推当前名册。仓储在同一事务内互换两个持久槽位：`UNIQUE(account,slot)` 按语句立即检查，两行直接对调会撞唯一索引，所以先把一行移到账号内一个空槽再完成互换；62格全占时使用范围内的临时负槽，仅在本次事务内临时关闭CHECK，UNIQUE仍生效。两行revision均推进，旧删除/保存快照失效；任一步失败整笔回滚并按连接错误收尾，不返回成功。

提交成功回ACK295单字节`01`，不再发送完整 `(0,2)` 名册：客户端拖动后本地行序已与本次互换一致，回推名册会让客户端清空并重建名册列表，把滚动位置复位到第一行（USERINFO subtype2 安装端 `02681B30/02681B43 → 03B67970` 先清空名册/详情 vector 再逐行重建）。服务端在ACK前安装本次回执的generation/epoch行序映射，后续C2S4按新行序选角。同索引请求不写库；越界索引不写库但同样回ACK并回推当前名册，使客户端退出本地拖动状态。已选角或其他阶段不发送响应。失败ACK正文在本版无匹配证据，不猜造。

当前证据为匹配客户端发送点反汇编（`03B45760 → 03B42550`，两参数均为列表绝对索引）、线上日志复现，以及 2026-10-19 匹配客户端实机验收：拖动后行序立即变化、点击新位置进入对应角色、退出及完全重启客户端后行序保持、拖回后恢复原序。该次验收只有两个角色且槽位连续，索引恰好等于持久槽位，无法区分两种解释；2026-10-21 在62角色账号删除中间角色（槽位30）后，客户端发送 `(30,27)`，按槽位解释时30已不存在，服务端记录 `roster-mismatch`、未做交换。修复后同一拖动按行索引映射交换正确角色，待实机复验。

### 角色名重复检查的客户端消费

绑定本页原始 EXE 与 S5A9 身份。`02349CB1..02349CC3` 注册 ACK692 → 原生回调 `0233B8F0`；公共 ACK 分派 `028F8600` 读成功标志 u8，失败时 `028F8655` 读错误码 u16。该回调的非零成功标志分支使用文本索引 `0x81A9`（“可以使用的ID”），零标志按错误码跳表选择提示。

| --- | --- | --- |
| 2 | `0233B9BA` | `0x81AA`（“发生致命错误”），调用日志路径 `03C75160`，不弹窗 |
| 20 / 24 | `0233B9F5` | `0x81AB`（“名称重复。”），经 `0233BA0E` 调用 `036DB2F0` 提示窗口 |
| 23 | `0233B9FE` | `0x0462`（“含有无法使用的特殊字符”） |
| 159 | `0233BA07` | `0x81AC`（“包含无法使用的文字”） |

文本由取串函数 `03DDC8F0` 使用的 `073D7D28` 字符串表核对，不从其他版本移植。匹配客户端 的20/24进入同一重名提示分支，服务端当前选择24，按 u16 宽度发送，body=`00 18 00`；原 `00 02 00` 进入日志分支，不能触发重名弹窗。可用名仍发 `01`。此名称检查只读数据库，不创建角色、不变更 owner/generation、角色revision、技能或任务。

## 选角和投影

### 返回选角、退出与变更频道

匹配桥接客户端实收 C2S `(1,7)` 空body，以及 C2S `(1,3)` 的 `00` / `01`。同构建主模块的原生注册为 ACK7 → `02348C70`（注册点 `02349E4E`）、ACK3 → `0233BCC0`（注册点 `02349D1A`）。公共ACK分派 `028F85F6..028F8605` 以 `03C851B0` 读1B成功标志；失败分支另读错误码，当前不猜造失败码。`028F8756..028F8761` 把标志交给 `028F2970`，后者调用对应handler。ACK7检查标志后执行返回选角清理，成功分支没有额外body读取；ACK3调用 `028FE9C0` 和退出模块，也没有额外body读取。故当前两种成功响应均为单字节`01`，不可混用通知 `(0,3)` ActorState。

返回选角不会释放账号owner，后续请求复用同一generation；没有后台角色任务需要迁移。位置和进度已经逐次事务提交，返回/退出不额外写库或增加revision。ACK7发送失败按连接错误收尾，重连从存档恢复；ACK3写完才结束连接，发送失败也不重跑业务。非法宽度、未知退出模式及旧generation关闭该连接，不发通用成功。重复ACK7后的旧移动请求因未选角而拒绝；重新选角仍走原有出生事务和完整入城序列。

同版本客户端已确认C2S7空body → ACK7 `01` 后服务端主动发送 `(0,2)` roster；客户端可能随后补发C2S8 `FF FF 02`，该首帧仅消费不重复推送，之后可在同一连接再次发送C2S4、收到完整入城序列及显示角色房间。变更频道已实收C2S3 `01` → ACK3 `01`，随后新游戏连接发送C2S4并接收入城序列；频道重连后的操作与画面实时性尚未验收。C2S3模式`00`的自然退出仍待实机确认。分类入口共用同一个服务，没有频道隔离或正式跨频道账号迁移。客户端在SELECT_CHANNEL退出收尾时的编码器兼容仍须独立验收，不通过修改ACK3正文或跳过正常退出规避；本分支不修改客户端或DLL。

### 原生换频道重连

匹配桥接客户端 job0 的 C2S5：`00 07000000 6C69636F636F6E 000000000000FF0001000000`；job15：`0F 0B000000 7169616E677A68616E7368 000000000000FF0000000000`。前者姓名7B，后者11B。job0在建角界面选择鬼泣展示后实收 `00 02000000 3131 000000000000FF0002000000`。

### 专用决斗创建与身份投影

匹配V31客户端 `03B5FC41..03B5FC78` 的C2S872为两个u32：基础job、基础grow。grow由 `03B60020..03B60095` 原样写入0–5，没有发送时追加觉醒位。专用C2S5沿普通name布局，12B尾部的tail6和tail8为相同grow；普通tail6保持FF。服务端只接受当前872许可对应的专用尾部，不能仅凭tail6声明授予身份。
