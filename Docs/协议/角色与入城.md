# 角色与入城协议

本页维护角色请求、名称检查消费者、选角/退出和入城投影。帧格式见[基础协议](帧与频道.md)，当前业务与资格见[角色](../模块/角色.md)。

## 角色请求

C2S category=1，多字节整数 little-endian，DSTR 为长度加 CP936 字节；名称限 1–12 字节及可编码的常用汉字、ASCII 字母、数字和下划线。

| opcode（十进制 / hex） | C2S body | 当前结果与边界 |
| --- | --- | --- |
| 3 / 0003 | `mode:u8`，实收`00`退出、`01`变更频道 | 仅接受这两个模式；结束当前角色会话，回复 `(1,3)` body=`01` 后关闭当前游戏连接并释放其owner。客户端自行执行退出或频道重连，服务端不重跑位置写入 |
| 7 / 0007 | 空 | 在当前owner内清Selected、Ready及角色任务缓存，回复 `(1,7)` body=`01` 后主动发送 `(0,2)` 名册；保留TCP连接及账号generation，再允许C2S4选角。客户端随后补发的C2S8只消费不重复推送，之后再次请求才刷新名册。重复请求仍回复ACK7，不重复写库 |
| 692 / 02B4 | `name:DSTR`，不允许尾部 | 选角前名称检查。S2C `(1,692)`：可用`01`，重名`00 18 00`（`flag:u8=0 + errorCode:u16=24`），触发客户端“名称重复。”弹窗并保持连接；数据库唯一约束仍是建角的最终检查 |
| 5 / 0005 | `job:u8 + name:DSTR + 12B尾` | 普通尾 `00 00 00 00 00 00 FF 00 preview:u8 00 00 00`，preview为建角界面当前分支展示索引0–5，各job通用；其余尾部字节固定。总长17+姓名字节数。展示选择不写入角色转职，创建提交后发 ACK5 → roster；基础职业初始化和失败行为见[角色](../模块/角色.md) |
| 8 / 0008 | `FF FF 02` | 新连接已主动下发roster，首次此请求仅设置rosterRequested；返回选角后若服务端已主动推送名册，则首次补帧只消费，第二次及以后补发roster |
| 4 / 0004 | `slot:u16` | 只允许尚未选角的当前owner，slot取本人数据库名册；提交出生点后进入下述入城序列 |

### 角色名重复检查的客户端消费

绑定本页原始 EXE 与 S5A9 身份。`02349CB1..02349CC3` 注册 ACK692 → 原生回调 `0233B8F0`；公共 ACK 分派 `028F8600` 读成功标志 u8，失败时 `028F8655` 读错误码 u16。该回调的非零成功标志分支使用文本索引 `0x81A9`（“可以使用的ID”），零标志按错误码跳表选择提示。

| errorCode | 原生分支 VA | 文本索引与行为 |
| --- | --- | --- |
| 2 | `0233B9BA` | `0x81AA`（“发生致命错误”），调用日志路径 `03C75160`，不弹窗 |
| 20 / 24 | `0233B9F5` | `0x81AB`（“名称重复。”），经 `0233BA0E` 调用 `036DB2F0` 提示窗口 |
| 23 | `0233B9FE` | `0x0462`（“含有无法使用的特殊字符”） |
| 159 | `0233BA07` | `0x81AC`（“包含无法使用的文字”） |

文本由取串函数 `03DDC8F0` 使用的 `073D7D28` 字符串表核对，不从其他版本移植。匹配客户端 的20/24进入同一重名提示分支，服务端当前选择24，按 u16 宽度发送，body=`00 18 00`；原 `00 02 00` 进入日志分支，不能触发重名弹窗。可用名仍发 `01`。此名称检查只读数据库，不创建角色、不变更 owner/generation、角色revision、技能或任务。

原机器码离线回放覆盖错误码0、1、2、20、23、24、159、65535，并在选定分支第一条指令前停止；未执行UI或API。分派 `0233B99B..0233B9B9`，跳表与索引 `0233BA2C..0233BADD`。C# TCP 验证重复检查、中文名、各职业名称及后续选角；弹窗画面需匹配客户端实机确认。

## 选角和投影

### 返回选角、退出与变更频道

匹配桥接客户端实收 C2S `(1,7)` 空body，以及 C2S `(1,3)` 的 `00` / `01`。同构建主模块的原生注册为 ACK7 → `02348C70`（注册点 `02349E4E`）、ACK3 → `0233BCC0`（注册点 `02349D1A`）。公共ACK分派 `028F85F6..028F8605` 以 `03C851B0` 读1B成功标志；失败分支另读错误码，当前不猜造失败码。`028F8756..028F8761` 把标志交给 `028F2970`，后者调用对应handler。ACK7检查标志后执行返回选角清理，成功分支没有额外body读取；ACK3调用 `028FE9C0` 和退出模块，也没有额外body读取。故当前两种成功响应均为单字节`01`，不可混用通知 `(0,3)` ActorState。

返回选角不会释放账号owner，后续请求复用同一generation；没有后台角色任务需要迁移。位置和进度已经逐次事务提交，返回/退出不额外写库或增加revision。ACK7发送失败按连接错误收尾，重连从存档恢复；ACK3写完才结束连接，发送失败也不重跑业务。非法宽度、未知退出模式及旧generation关闭该连接，不发通用成功。重复ACK7后的旧移动请求因未选角而拒绝；重新选角仍走原有出生事务和完整入城序列。

同版本客户端已确认C2S7空body → ACK7 `01` 后服务端主动发送 `(0,2)` roster；客户端可能随后补发C2S8 `FF FF 02`，该首帧仅消费不重复推送，之后可在同一连接再次发送C2S4、收到完整入城序列及显示角色房间。变更频道已实收C2S3 `01` → ACK3 `01`，随后新游戏连接发送C2S4并接收入城序列；频道重连后的操作与画面实时性尚未验收。C2S3模式`00`的自然退出仍待实机确认。频道目录仍是单频道开发数据，没有正式跨频道账号迁移。

### 连接与角色选择

连接建立后执行[原生预检查与 LOGIN](原生登录.md)，不校验客户端来源 IP。验证凭据并取得 owner 后发送 `(1,1)` 端点 → `(0,2)` roster。开发账号也必须验证凭据，不再使用空请求映射或 C2S171 票据扩展。会话与接管策略见[认证与会话](../模块/认证与会话.md)。

普通角色选角成功序列：

```text
(1,4) Select
→ [AcceptedStoryLevel > 0 时 (0,1382)]
→ (0,2) Actor
→ (0,2) Player
→ (0,13) Main背包
→ [CompletedQuests 非空时 (0,356)]
→ [双树绑定已初始化时 (0,19) SKILLINFO]
→ (0,13) 个人仓库初始化
→ (0,3) 城镇actor状态
→ (0,22) 初始坐标
→ (0,23) 区域
→ (0,24) 场景迁移
→ [房间且返回地区有效时 (0,1379)]
→ [有账号设置时 (0,173) GAME_OPTION]
→ [有角色选项时 (0,390) CHARACTER_OPTION]
→ [有主设置来源时 (0,357) CHARAC_INVISIBLE_FALGS]
→ (0,124) 入城完成
→ session.MarkReady()
```

当前选角统一出生共享房间。普通 Lv1 持久 `accepted_story_level=1` 且没有完成任务，含 `(0,1382)`，不含 `(0,356)`。实际帧数还取决于容器、货币、邮件等资产初始化及已保存的[客户端设置](客户端设置.md)，包序按当前投影和各模块条件判断。通知失败不回滚已提交的出生点或已创建角色；重连由数据库恢复，不能重做已经提交的资产写入。

进行中的主要任务写在 ACK4 offset 22。普通创建不自动接取任务，30槽均为空；空槽为 `FFFF` 加 0。四个任务书签保持全零。`(0,356)` 只表示已完成。3145 的单清图条件见[主线任务协议](主线任务.md)。

offset222 的消费者 `02341BCA` 读取 u8，`02341BEE` 查询城镇资源，随后 `02341E12 → 03B93DA0` 调用 `CNTownModule::setCurrentTownArea`。该字段不能写职业或角色槽位，也不能固定成某个城镇。匹配客户端把输入7/8映射到2；服务端仍发送实际出生城镇，不复刻这项客户端兼容逻辑。当前选角出生为38/1，ACK4写38，后续USER_AREA/AREA_USERS传完整区域和坐标。

误写职业15会让客户端暂时进入城镇15/区域0，并经 `03B94B74 → 02406A10` 显示消息46701（hex B66D）。此函数在城镇变化为15且区域为0时显示横幅；匹配 `dstr.dat` 的该条文字本身为 `dnf_46701`。这是初始城镇字段的消费结果，不能通过屏蔽横幅或给其他未实现请求补通用ACK处理。消息字典格式和身份见[物品交互参考](物品交互参考.md)。

Actor/Player 中未完整命名的空结构由[TownPackets](../../Server/DfoServer/Network/Builders/TownPackets.cs)逐字段保存，不得以其他版本的结构体或整块估算替换。Player的89B属性块按job取匹配CHR初始值，偏移与精度见[普通创建](../模块/角色.md)；Lv95不意味着已实现成长公式。技能树为`activeTree:u8`以及两组`count:u8 + (id:u16,level:u8)*count`，已初始化时分别投影两个context的真实等级；未初始化保留已有技能兼容列表，无技能时active=FF。完整NOTI19与学习ACK见[技能字段](技能学习.md)。

非空装备的读宽与条件分支见[物品协议](物品.md)，业务与验收见[背包与装备](../模块/背包与装备.md)。

已认证的同场景成员进入发送远端Actor2 → ActorState3 → Position22，离开使用NOTI6；不广播远端Player本人属性或任务。私人房间、PVF阶段、位置合并、视图清场及generation/epoch合同见[城镇同屏](../模块/城镇同屏.md)，当前仅通过自测和独立TCP，双Windows客户端仍待验收。

### 创建请求样本

匹配桥接客户端 job0 的 C2S5：`00 07000000 6C69636F636F6E 000000000000FF0001000000`；job15：`0F 0B000000 7169616E677A68616E7368 000000000000FF0000000000`。前者姓名7B，后者11B。job0在建角界面选择鬼泣展示后实收 `00 02000000 3131 000000000000FF0002000000`。

建角发送入口 `037AC5A0` 的普通创建分支在 `037AC764` 调用 `03B428C0`，取得建角管理对象 `+84C` 的当前展示索引，随后在 `037AC771` 经单字节写入函数 `03BDF720` 写为 `tail[8]`；后面的三个零分别写入，不能把这四字节解释为一个转职整数。界面更新在 `03B60038..03B60090` 遍历当前job的六个展示项，把命中的索引0–5写入 `+84C`。匹配男鬼剑士CHR的名称顺序为基础职业、剑魂、鬼泣、狂战士、阿修罗、剑影，因此该job的2/4分别来自鬼泣/阿修罗展示选择。普通创建的 `tail[6]=FF` 保持原形状；活动创建等其他尾部布局未接入。
