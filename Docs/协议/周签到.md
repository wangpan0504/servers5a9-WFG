# 周签到协议

目标为V31.0.24.0 x86／Direct12 Full03。业务、资源及存储见[周签到](../模块/周签到.md)。

## 请求与通知

|方向／class|opcode|正文|
|---|---:|---|
|C2S／1|1115 `EVENT_TOTAL_ATTENDANCE_CHECK_THISWEEK`|严格13B opaque，不解释为周号或客户端通关数|
|S2C／1|1115|成功`01 + result:u32`，有新邮件为0，无新奖为1；失败`00 01`|
|C2S／1|689 `EVENT_REQUEST`|严格16B：`2208:u32,0:u32,0:u32,0:u32`|
|S2C／0|1096 `EVENT_TOTAL_ATTENDANCE`|固定459B状态块|
|S2C／0|99 `MAILBOX_ALARM`|只在本次新邮件提交后发送`01 00`|

普通领取包序：1115 ACK → 有变化时1096 → 有新邮件时99。累计领取没有689 ACK，只发必要1096和99。1115错误class静默；689首DWORD不等于2208返回未处理，属于2208但长度、未知字段或class错误时静默。

1096状态正文：

|偏移|类型|意义|
|---:|---|---|
|4|u32|总签到次数|
|8|u32|累计奖励掩码，置实际阈值2／5／8对应位|
|0x19C|byte[20]|已签周号升序排列，余位补零|
|0x1B4|u32|当前周通关余额|
|0x1BC|u32|已补签次数|
|0x1C0|u32|本周已签到|
|0x1C4|u32|当前周，从1开始；过期投影为周期周数加1|
|0x1C8|u8|当前是否可签到或补签|
|0x1C9|u8|是否存在可补历史缺周且次数未满|
|0x1CA|u8|是否有累计奖励可领|

其余字节保零。关闭或过期移除108中的2208入口，保留其它普通行、active行及原扩展页面。108按原保护压缩发送，2208的active参数为12个零DWORD。

## 匹配客户端静态证据

证据来自严格读取的V31 Direct12 Full03冻结页，属于原生代码分析，不表示已操作本次客户端：

- 菜单2208入口`0261A500`打开窗口786（`0x312`）。
- `04F862B3`的回调登记指向`01B2F360`并绑定通知`0x448`（1096）；`01B2F3A1`指定原始块长度`0x1CB`（459）。
- `01B2EF03`构造命令`0x45B`（1115），`01B2EF1D`写13B原始正文；`01B2FBB0`为其应答后继，成功分支固定读4B结果。
- `01B2EF44..01B2EF90`构造689及四个DWORD：2208和三个零。

当前PVF关联窗口为`ui/event/chn_event_2019/chn_eventtotalattendance_20190117/eventtotalattendancecheckwindow.xui`，周期及累计阈值从资源读取，不能沿用其它版本的十周与3／6／9规则。
