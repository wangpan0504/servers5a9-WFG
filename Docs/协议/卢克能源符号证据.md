## ACT解析与执行：读侧直达，写侧上报

两个精确标签的注册点分别为 `04421FCD → 043F0040`（CHECK）和 `0441FD9E → 043E4120`（SET），通过同一字符串键容器绑定，不是依据相邻文本猜测。

- **CHECK**：parser写opcode `0x65`，Type0整数参数0由 `03DB1140 → 03DB05E0`读取并原样追加、复制到参数vector。执行表 `0646BBA8`在`03B1916E`注册`03B03BC0`。执行函数经`03A3E870(record,0)`取原整数，在`03B03BD9`直接调用`01DC9FC0`，随后按参数1/2比较返回值。因此所证Type0解析及已注册执行链中，资源113/114确实查询manager key113/114，不自动映射为138/139。
- **SET**：parser `043E4120`写opcode `0xF2`，执行表`0646BA54`在`03B01C25`注册`03A9DC30`。执行先经过对象virtual+26C资格门；其动态资格含义尚未命名。通过后symbol参数0保持原值，仅operation转换，经`03A9DCA1 → 01DC6180`发送CMD662的`symbol:u32,value:u32,operation:u8`。完整发送函数不调用本地setter `01DCE450`，不能假定脚本SET会立即改变本地CHECK结果。

上述参数reader、vector追加/复制链及两执行注册均已核字节；不把有限复制路径证明扩大成所有动态对象永不改写的保证。ACT链静态复核覆盖22个有界窗口、13个精确字节检查、11条rel32调用边及两个解码标签；显示链另核11个窗口、7个字节/表项检查及四个文本。均未执行原EXE。
