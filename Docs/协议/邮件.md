# 邮件协议

本页记录 S5A9 匹配客户端的邮件读写合同。枚举取自 [PacketTypes](../../Server/DfoServer/Network/Core/PacketTypes.cs)，业务和持久化见[邮件模块](../模块/邮件.md)。字符串为 `length:u32 + CP936 bytes[length]`，不含结尾零；名称和正文分别受29/511字节上限约束。

## 请求与回复

| 信令 | body |
|---|---|
| C2S94 MAILBOX_SEND | 收件人字符串、gold:u32、一行附件、正文字符串、special:u32、global:u8 |
| C2S315 MULTI_MAILBOX_SEND | 收件人字符串、gold:u32、count:u8、附件[count]、正文字符串、special:u32、global:u8 |
| 附件行 | type:u8、slot:u16、itemId:i32、count:i32，共11B；单附件全零为无附件占位 |
| C2S95 MAILBOX_EXTRACT_ITEM | count:u32、领取对象:u32[count] |
| C2S96 MAILBOX_OPEN | 空body |
| C2S134 CHANGE_LETTER_STAT | count:u32、mailId:u32[count]、action:u16；0删除、2已读、3保存 |
| C2S324 QUERY_CHARAC_INFO_MAILBOX | 收件人字符串、mode:u8 |
| ACK94/315成功 | `1:u8` |
| ACK95逐项结果 | `1:u8 + count:u32 + {mailId:u32, claimId:u32, error:u32}[count]`；整封请求展开为实际摘要行，0成功，4入包失败，10金币上限 |
| ACK96成功 | `1:u8 + notLoaded:u16` |
| ACK134成功 | `1:u8 + count:u32 + {mailId:u32, action:u16}[count]`，action为实际状态；读取已保存邮件仍回复3 |
| ACK324成功 | `1:u8 + name:string + serverMarker:u8=0 + level:u16 + job:u8 + grow:u8 + 1:u8 + 0:u8 + 0:u8` |
| 失败回复 | `0:u8 + error:u16`，成功前缀和失败解析由共同CMD分派完成 |
| NOTI98 MAILBOX_REMOVE_MAIL | count:u32、mailId:u32[count] |
| NOTI99 MAILBOX_ALARM | 正数:u16；当前在线新邮件提示写1 |

请求对象数限制为1–100；重复、零值及越过正i32范围的领取ID拒绝。邮件ID为 `1..0x3fffffff`，附件领取ID为 `0x40000000 | attachmentId`；SQL同时约束两个持久序列上限，不能把邮件合并key当作另一条无标记附件ID。

六色晶块沿相同11B附件行传递，使用 Main 源类型、虚拟槽354–359及对应3033–3037/3262模板；不是新 opcode 或另一份普通材料库存。邮件摘要仍为普通堆叠物品布局，`value`与`enchantOrCount`均保存托管数量。领取回包后以既有14通知同步账号钱包对应的虚拟槽及金币绝对余额，不发布一件假的入包晶块。超量、错误槽位或交易资格失败保留原余额，并恢复实际源槽的客户端显示。

寄送原码 `02DFFD78..02DFFE64` 经 `03BDF610` 创建CMD，字符串走 `03BDF8E0 → 03BDF850`；`03BDF720/750/780` 分别写1/2/4B。多附件分支 `02DFFDC2..02DFFDCD` 明确写u8数量，每行再单独写u8类型。`02E00A64..02E00A9A` 证明324请求字符串后还有mode字节。special/global只保留原值，非零子型未接入。

CMD注册 `0237C4AA..0237C50C` 对应324、94/315、95、96和134。ACK95 `02366352..023663F4` 先读u32数量，每次读三个u32，再交给 `02E194A0`；`02E19622..02E19647` 用第一个key在邮件容器查找，再用第二个key在邮件内部查摘要，`02E19C44..02E19C77` 删除领取摘要。第三DWORD的低u16是单项错误码，0成功，不能把后两项均写保留零。ACK134 `02369DC0..02369DF3` 每次读u32 ID和u16 action。ACK96 `0234D1F4` 只读一个u16。ACK324 `0234D0EE..0234D141` 读取名称、一字节server标记、等级及五个尾字节；名称实际缓冲区为20B，现有合法角色名最多12B。`02E021BF..02E02222` 将server标记用于服务器显示，不能误填growType。

寄送失败映射由 `02E17DFB..02E17EE4` 的真实跳表核对：3收件人不存在、7自己、10金币不足、14收件人等级金币上限、17附件校验、22空内容、23不可交易、70每日金币额度、114状态限制、214物品锁、217账号绑定、219限时、235过期。领取失败 `02E16713..02E16785` 确认4无法入包、10金币携带上限、19状态限制、21邮件不存在；保存错误22在 `02E16C36..02E16C89` 显示保存上限。读宽确认不等于全部提示语或UI验收。

## NOTI97 MAILBOX_MAIL_LIST

注册 `023E2C71 → 023E0290`。包由附件摘要和正文两个区段组成，空邮箱为完整6B全零。

```text
summaryCount:u8, append:u8
summary[summaryCount]
notLoaded:u16
detailCount:u16
detail[detailCount]
```

`append=0` 清空现有普通和保存容器，1追加；原码 `023E034D..023E0383`。按u8摘要数量及65520B包体上限同时分批，时装附加块和正文也计入字节；首次清空、后续追加，不截断附件或正文。

普通摘要的顺序如下：

```text
claimId:u32, senderId:u32, senderName:string, gold:u32
itemId:i32, hasItem:u8, value:i32, durability:u16, attr:u8
enchantOrCount:i32, enchantUpgrade:u8, amplifyType:u8, amplifyValue:u16
[仅creature type26: extra:i32, flag:u8; flag=1时再读3×i32]
rawItemCore[123]
[仅时装: sockets:RAW(30), colors:RAW(4)]
remainingSeconds:i32, mailId:u32, extra:u8
```

原码 `023E0394..023E0436` 读取普通前缀，`023E0477..023E04C2` 读取type26扩展，`023E04D5..023E04DE` 无条件复制123B核心，`023E0605..023E0647` 读取时装两段RAW，`023E07D4..023E07F5` 读取固定尾部。RAW为自身带u32长度的块。

非堆叠value保留完整实例值；时装预览value为剩余秒数，堆叠enchantOrCount写本次附件数量。金币只写同一封邮件的第一条摘要，也只随该摘要或整封领取；`02E196B5..02E1977C` 仅在收到金币摘要key时清零客户端邮件金币。无附件也写一条零核心摘要，使纯正文和领完后的邮件保持明确期限及合并key；永久/保存邮件剩余秒数为0。

整封领取按钮经`02E13980 → 02E19FD0`枚举附件摘要并构造95；图标请求另有`02E135F0`入口，不能把抓包中单个摘要ID当作整封按钮的业务定义。ACK95 的`02E194A0`按每条错误码分支：成功调用`02E0B310`清掉对应附件对象，失败保留该摘要；因此容量中断可回已提交前缀和第一条失败结果，未处理后缀不伪造成功。领取包序为 ACK95、必要105详情、实际库存差量及其他真实资产通知；不跟随清空式97。`023E0290`遇`append=0`会先清空普通和保存邮件容器，若在领取时重建，会替换打开窗口仍引用的邮件对象并丢失剩余显示；完整列表保留在打开邮箱或入城恢复时发送。

固定核心复用[物品条目](物品.md#实体字段)布局，包含Rune、随机属性和全部扩展。`023E0717 → 024B2ED0`、`023E0730 → 02291830` 是状态应用，已确认不再读取Rune/Random；不能直接套用Player包的附加读序。`028F2E40` 同样只从固定核心复制镶嵌信息，不增加读取段。

正文固定顺序为：

```text
mailId:u32, senderId:u32, senderName:string, body:string
createdUnixSeconds:i32, letterStat:u16, extra:u8
```

原码 `023E0888..023E08DF`。letterStat为1未读、2已读、3保存；正文时间是创建时间，摘要尾部才是剩余秒数。0表示删除动作，不作为列表中的正文状态。

以上是匹配冻结原码的静态读写依据与服务端独立消费测试；不声称完成客户端原函数全链回放或实机邮件面板验收。
