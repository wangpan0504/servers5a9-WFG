# 宠物蛋孵化（S5A9 CMD102）

当前入口使用CMD102 `HATCH_CREATURE`，只支持Pet页槽0..139中的已拥有宠物蛋实例。CMD173/174属于另列的命令，当前没有对应实际请求或已确认阶段，不注册、不构造成功。产物为CRE声明的道具成长宠物时，同一转换初始化mode1及亲密字段，其余UID、详情、锁及期限保持原事实；成长与进化见[宠物模块](../模块/宠物.md)。

## 请求证据与回包

C2S正文固定3B：`list:u8=7 + slot:u16LE`，合法范围使末高位必须为0。证据来自同一63022蛋、UID63的两次实际请求：位于Pet槽0时正文`070000`；客户端将它从槽0移到槽1、库存差量确认同UID及模板后，正文变为`070100`。这份合同属于双槽抓包验证；静态producer尚未定位，不能将其它容器、额外尾字段或其它孵化阶段泛化为成功。

S2C ACK102注册为`0237C54B/0237C550 → 0234D220`。该消费者通过`029089D0(7)`取得Pet容器，再由`029CF9D0`弹出待处理项。成功正文只有`success:u8=1`，不读取槽位或产物字段；失败由`0234D25F`读取公共`error:u16`，完整正文为`0:u8 + error:u16`。当前实现使用编号0表示拒绝，具体提示语义仍未确认，不称为已证中立文案或借用移动错误表。

## 资源与实例转换

[CreatureEggCatalog](../../Server/DfoServer/GameWorld/Items/CreatureEggCatalog.cs)借用当前共享PVF、装备列表和物品目录，按实际请求解析蛋及唯一产物。双方必须是`[creature] 0`、Creature/部位26；源`[sub type]1`及单一正`[output index]`指向不同模板，产物`[sub type]0`且`[creature species]`一致。缺项、重复字段、多产物、自指或不相容类型拒绝。代表资源63022为波比蛋，output63023为波比，species20；生产规则不固定这些编号。

[孵化服务](../../Server/DfoServer/Game/Inventory/Services/InventoryCreatureEggService.cs)复用原InventoryPlan，要求Pet页真实持久UID、核心Value等于UID、完整Creature详情、原源模板身份及可用资格。装备安全锁、已到期源、缺详情、成宠或不合法容器拒绝；排序锁保留。宠物模板的等级不直接当作角色使用等级，成长资格不借普通装备穿戴规则推定。

孵化保留原槽和同一UID，仅把Core.ItemId改为产物，Creature类型字段SealFlag置为目标subtype0。完整核心、详情名字、等级、经验、饱食度、Mode及附加字段均沿用原实例，不扣可堆叠数量、不生成第二个详情或新UID。PVF原蛋及产物无固有期限不代表商城实例永久；实际实例期限取CreatureDetail.ExpireTime，Core.ExpireTime保持0，并把截止秒数绑定提交前提。

源核心转换、原详情、位置、审计及角色revision通过同一外层事务保存。成功提交后按ACK102、清旧模板的Pet14、原UID的105详情、新模板完整Pet14及锁恢复发布；整个发布链由实际提交回执、owner、选角epoch、阶段及角色快照守卫。Pet13/14头为3B，条目123B，没有时装RAW附段；Marker16投影剩余秒，持久详情保存绝对期限。发送失败不重复转换，重连加载已提交状态。

## 验证边界

[纯规则与资源回归](../../Server/DfoServer/SelfTests/CreatureEggTests.cs)覆盖双槽读宽、受限容器、ACK宽度、匹配蛋/产物、同UID完整详情和期限保留、锁及重复请求、旧revision与跨到期提交。[真实TCP回归](../../Server/DfoServer/SelfTests/Tcp/CreatureEggTcpTests.cs)覆盖Pet槽0/1、完整包序、审计末段回滚、成宠及畸形请求拒绝、同UID转换、有限期限、详情逐字节保持和重连恢复。

编译、自测和TCP由统一入口执行，测试代码存在不等于已运行。双槽抓包及静态ACK消费者不代替孵化动画、图标、穿戴、客户端提示与完整宠物玩法实机验收；静态producer及CMD173/174仍保持未确认。
