# 客户端通知与未实现请求

当前已确认读宽与处理边界如下；枚举名称不能替代实际字段依据。

### 进房与离开时的客户端通知

这些 C2S 在 `03BDF610` 写完 body 后直接调用 `03BE0FF0`，发送函数不等待应答。服务端核对下表宽度后记录 `client_notice`，不改角色、不改任务。只有 120 回空名单；其余不回包。宽度对不上时仍记 `unimplemented`，不关闭连接。

| opcode | 实收与原生宽度 | 说明 |
| --- | --- | --- |
| 63 | 空。发送点 `02341E79`、`01CBC3B0` | Cera 查询。应答未闭合，不回包 |
| 120 | 空。发送点 `023426EA` | 黑名单请求。已选角时回 `(1,120)` body=`01 00` |
| 140 | `value:u32`。发送点 `02D9CA16` | 公会成员列表。已确认样本 `00 00 00 00`，不回包 |
| 441 | `count:u8 + byte[count]`。发送点 `0110B510` | 佣兵信息。样本 count=5，字节 `01 02 03 04 05` |
| 593 | 两个 u32、三个 u32，或 `type:u32 + size:u32 + byte[size]` | 状态报告。已识别类型 15 的地址字段和类型 51 的计数字节 |
| 1507 | `a:u8 b:u8 c:u16`。常量发送点 `02DAB4B4` | 进房实收 `01 00 01 00`，只按这 4 字节记录。字段与网吧奖励语义未闭合，原生名称以 PacketTypes 为准，不回包 |
| 752 | 664 字节（`0x298`）。发送点 `03C5972F` | 帧率统计。紧跟返回选角的 C2S 7 |
| 34 | 10 字节：`echo:u16=34 + quest:u16 + reward:u16 + multiplier:u16 + reserved:u16` | 完成任务。实收任务 3145、奖励槽 `FFFF`、倍数 1、保留 `FFFF`。只记录，成功 body 未闭合，不回 ACK |

其他合法请求仍记 `unimplemented` 的包。1278 宽度 0。1723 宽度 17，样本 `6E 00 00 00 00 00 00 00 02 02 00 00` 后接 5 字节。645 宽度 0，出现在选角前。枚举名是 `CHECK_USER_CONNECTION`、`PING`、`CHARAC_VIEW_HIDDEN_CHARAC_INFO`，同号通知名对不上，应答未闭合，不回包。

1427 的实收长度是 48、90 或 132，和发送点 `03C58A90` 的 `0x6185` 前缀对不上，继续记 `unimplemented`。普通建角没有发出接取 opcode 31。打开技能栏时实收 C2S 477 body `08 00 00 00`；另有 C2S 503 body `10 00 00 00`，宽度 4。发送点和读取器未闭合，继续记 `unimplemented`，不回包。`USE_SKILL`（C2S 38）在 `02BF2AB9..02BF2B5C` 写入 10 字节：`u8 + u16 + u16 + u16 + u8 + u16`，随后 `03BE0FF0` 发送。首字节来自 `02D82730` 返回对象的 `+6280`；该函数读取的全局 `0643A49C`、`0643A498` 在本记录中缺页，不能还原具体数值。该直接写入区间的字段意义尚未闭合。匹配客户端的正常战斗另有14B实收形状，当前两种宽度分别保留并记录，不回包；其他宽度仍为未实现。原码依据见[主线任务协议](主线任务.md)，实收与处理边界见下节。

## 普通单人技能使用记录

匹配 S5A9 客户端的正常3145战斗实收C2S38正文为14B。已核对样本包含 `002E00D00729000001004AADA701`、`0005007017234800010052760356` 和 `00A9000000F16D000100DD2A7E19`；不是用全零或合成请求推导出的长度。

[SkillRequests.TryParseUse](../../Server/DfoServer/Network/Parsers/SkillRequests.cs)按已知直接写宽解析偏移0的u8、1/3/5的u16、7的u8及8的u16；14B形状的末4B独立冻结，10B形状不补尾部。末4B生产者及业务含义未确认，不将其命名为校验和、伤害、对象key或资格。所有字段以偏移命名，保留原值，不扩展猜测枚举。

匹配活进程的`02BF2AB9..02BF2B5C`完整163B已再次核对，六次直接写入仍只产生10B。其后进入通用发送`03BE0FF0`，不是“写完10B就原样送入socket”的已证明合同。该路径在`03BE113A`调用发送前处理`03BFDCB0`；当前入口是映像外跳转，不能用跳转后遗留的原函数体代替实际执行。编码入口`03B1B160`也已跳到匹配客户端补丁模块的透传实现。

通用长度调整`03B1B0F0..03B1B154`（100B）按opcode对14取模选择codec，从虚表`+20`取得块宽，对当前长度向上对齐；这段代码不读取技能伤害、怪物HP或对象key。运行时跳转、长度对齐及编码三者仍须分别核验，不能仅用“实收比直接写入多4B”断言其为填充、校验和或游戏统计，也不从未执行的原函数体推导末4B意义。

[ClientNoticeHandler](../../Server/DfoServer/Network/Handlers/ClientNoticeHandler.cs)只记录完整字节，不发ACK、不改角色状态或发放奖励。技能使用请求不证明命中某一怪物或服务端HP已归零，不能据此签发正式死亡。`ClientNoticeTests`覆盖真实样本、未知尾部所有权及不支持的长度。当前架构没有旧的 `--selftest-tcp dungeon` 组，在线包序仍待接到现有 TCP 回归。
