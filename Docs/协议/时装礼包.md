# 时装礼包

适用于匹配 S5A9 的装扮自选礼盒。固定商城外包与普通礼包的既有字段见[物品交互参考](物品交互参考.md#礼包开箱)，完整物品、owner、提交及邮件规则见[背包与装备](../模块/背包与装备.md#礼包开箱)。

## 请求入口与源身份

`[booster selection]` 装扮礼盒通过 CMD160 `USE_BOOSTER_ITEM` 提交实际分类、完整奖励ID及属性选项。`[usable cera package]` 固定外包通过 CMD518 `OPEN_CERAPACKAGE` 发送源槽与选择列表；不含时装奖励的固定外包合法列表为空，含时装的固定外包选择集合必须等于 `[package data]` 中全部时装编号。

不能仅根据开包后的同槽物品判断原请求的源。例如 Main73原有490705385时，`518:49 00 00` 开启固定外包，成功回执`01 49 00`后先清该槽，再把奖励490705387放入Main73。此时源490705385与新奖励490705387虽复用位置，仍是不同实例与不同请求入口。后续490705387实际发出91B的CMD160装扮选择请求；旧的普通160解析入口因附加选项非零将其视为未实现，是这一请求的失败触发。

当前服务按真实源定义辨认入口。目录与分类读取先于角色提交规划；最终资格、源数量及消费使用规划回调中的当前角色快照。存在装扮分类但规则未闭合的源仍属于装扮入口，不回落为普通开箱。已知装扮源的短头、非法分类、未知或不完整选择返回失败，不截断为普通160，也不自动按角色职业或颜色选择。

## CMD160装扮选择

正文为`slot:i16 + count:i32 + category:u8 + subcategory:u8 + itemId:i32×N + avatarOptionCount:u8 + {itemId:i32, option:u8}×A + secondOptionCount:u8=0`，总长`10+4N+5A`。ID清单没有独立数量字段；Parser使用PVF分类的合法清单范围辨认后续选项段，并拒绝歧义或未完整闭合的正文。

生产器`027BC1DC..027BC318`写源前缀、两个分类键及ID清单；`027BC333..027BC347`写第一组选项数，`027BC3B8..027BC3D4`逐项写`id:i32 + option:u8`，`027BC3F7..027BC405`写第二计数0并发送。

实际490705387请求的源槽73、开启数1、分类0/0包含九件：401550176、401560113、401570077、401520097、401500147、401530091、401510121、401540118、401580026；对应选项字节为0、0、2、2、19、4、0、2、0，两个清单完整且选项数9，正文91B。该输入作为固定抓包回放用例保留，不用服务端默认选项或各模板最大选项代替玩家选择。

成功回执复用CMD160的`18+8R`合同：实际源物品ID、源槽、displayMode0及所有本次获得量。提交后先发布Main源变化，再发布Avatar的165B完整条目；时装核心中的value投影剩余秒，不能把持久化UID当作倒计时。失败沿用公共`success:u8=0 + error:u16`，不发获得提示或奖励差量。

完整三奖分类的原生请求可为27B：`slot:u16 + count:i32 + category:u8 + subcategory:u8 + 3×itemId:i32 + optionCount:u8 + itemId:i32 + option:u8 + trailingCount:u8`。10150804的0/0分类主编号按装扮101521039、称号100331476、材料3330排列，属性记录仅装扮一项，本次选择值2，末计数0。材料编号属于同一完整主清单；不能按装扮数量截断，也不为该源放宽长度或另造成功应答。成功回执含全部三奖，Main差量含源消耗、称号和材料实际堆数量，Avatar差量保原165B实例详情。

## PVF、完整实例与到期复验

`[booster category num]`决定分类维数与范围，`[booster selection num]`为0时必须核对所选分类的完整ID清单；正数是选择上限，不额外要求选满。分类和奖励参数来自共享PVF，只解析实际使用的依赖，不设商品白名单，不删除未实现的奖励后返回部分成功。装扮身份Recognized只由真实booster selection分类内的avatar族声明决定，与Available及PendingRule分开；普通equipment/stackable分类不属于装扮入口，上层未闭合资格也不能抹去已声明装扮族。

`[avatar]`每行四整数依次为`itemId、count:u16、type:u16、defaultAbility:u8`。原码`04148E1E..04148EAB`分别保存这四字段。type直接索引模板的期限/孔位类型：`04135EE0`先加入index0的原生7天无孔行，再按`[avatar type select]`追加每行七整数及对应孔位标签；`027C0DC7`按32B行宽索引，`027C10CA..027C10F8`取期限和孔位。默认属性是客户端预览信息，不能替代玩家实际选项。

可选属性读取模板的`[avatar select ability]`，或按`[ability case index]`读取共享`skill/abilitydatas.dat`的完整case。`04101B31..04101B53`载入共用表；case50实际包含132个声明编号、最大140且不含0，不能补造0或只保留低五位。属性写入`ItemCore.Durability`：CMD459消费者`027960F4..0279615E`读槽和属性字节并调用`02947530`更新实例core+28；NOTI13/14在`027F83B8`把wire+0B:u16读入同一字段。Attr独立保留。

两处声明都没有的部位（典型是武器装扮、部分光环，见490705439分类内的401600014）没有可选属性，客户端在该位置仍会带一项5B选项，取值0或255。它不是玩家选择，只表示未选择，服务端按0写入`Durability`，不能当作非法属性拒绝整箱，也不能把哨兵原样写进实例。该部位收到其他数值说明客户端与资源不一致，仍拒绝。有属性声明的部位不接受0或255替代显式选择。

装扮EQU含明确`[import script]`时保留Pending：此目录尚未闭合有效继承视图，不能遗漏父模板的属性或期限后回退默认值。当前定向核对的387/425/426目标导出未见该声明。

源礼盒必须满足模板禁用标记、最低等级、职业与所需技能，同时检查数量、锁和期限。发放按所选PVF行创建全部UID0完整原型，保留属性、期限、透明装扮、孔位与颜色；真实UID只在提交时分配。每次Open入口分别冻结绝对与相对期限忽略状态：`ignoreAbsoluteExpiration`只影响固定日期，`ignoreUsablePeriod`才影响所选type.Days等相对期限，默认保留相对期限；原永久物品不制造截止，源使用资格不放宽。期限政策沿用[商城/礼包期限调试](../模块/背包与装备.md#npc-商店买卖与限购)，不把调试覆盖当作PVF原义。

扣源、全部奖励、详情、位置、溢出邮件和审计参与同一外层事务。最终前置条件绑定源与所有奖励原型的最早有限期限，包括全部进入邮件的奖励；在截止时刻到达后不能提交旧规划。

## CMD518边界与验证

518正文仍为`slot:u16 + choiceCount:u8 + {id:i32, option:u8}×choiceCount`，发送点为`025162F5、0251631A、02516377、02516388`。具有完整装扮分类的源，非空装扮列表只能匹配完整且参数等价的PVF分类；共用同一套装的职业分类可匹配，数量、期限类型或默认属性冲突时拒绝。固定外包的空列表继续走固定奖励合同；含时装的固定外包在选择集合对齐全部时装编号时仍走固定入口并发放整包。装扮自选源的空列表不消耗、不自动选择。

518成功消费者`02515F40`关闭窗口603，在`02515F88`读取源槽，再通过`02515FD8..02515FE3`减一或删除源；成功`01+slot:u16`不是“仅打开选择面板”。装扮518入口允许既有邮件系统承接无法入包的全部完整原型；160保留普通选择箱的容量不足整批拒绝规则。

专属规则、资源领域与TCP回归分别验证完整选择、非法选择、使用资格、精确到期边界、真实91B请求分派、九/八/单件发放、邮件回滚、原UID领取与重登恢复。自动化回放和静态字段证据不代替客户端界面、属性效果及全部礼盒的实机验收；不能把向装扮源合成发送518空列表的拒绝测试说成实际490705387的请求。
