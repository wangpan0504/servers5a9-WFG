# 单人队伍协议

本页只记录匹配ARAD的单人创建、设置及清理合同，业务边界见[单人队伍](../模块/队伍.md)。不提供多人入队、P2P或公开目录合同。

## CMD12

037E7160与01B4B620的发送顺序为：

```text
mode:u8 titlePreset:u8
if titlePreset==0 { nameByteLength:i32 name:CP936 }
memberCode:u8 selectionId:u32 selectionCode:u8 selectionValue:u16
recruitFlag:u8 targetMode:u8 targetId:u16 extra:u8
```

无自定义名称时严格15B。实收`00 03 04 00000000 05 0000 00 00 0000 07`为创建、预置名称3、成员上限4及末尾参数7。`mode=1`用于已有队伍设置修改。名称DSTR最多63字节，对应接收侧03BE26C0→03BE25F0的64B缓冲边界。`extra`在当前发送器和模型中均存在，不按参考项目的14B正文截断或丢弃；其业务名称暂未确认。

ACK12注册回调02364B70成功分支不继续读正文，本服成功为`01`，随后必须发送完整NOTI9，不以ACK替代队伍上下文。失败使用`00 error:u16`，本轮资格拒绝码为19。

## NOTI9

023CC918附近将9注册到023B9E70。外层为`recordCount:u16 sceneValue:u16`，`sceneValue=9999`保留当前场景选择；每条记录前缀为：

```text
partyId:u16 server:u8 channel:u8 reserved:u8 kind:u8 flag:u8
```

`kind=0`为完整记录，`kind=1`只更新设置，`kind=3`删除队伍。记录必须使用实际频道身份与同一队伍键，不能误用每账号槽位或其他版本缺少flag的前缀。

0/1的设置段为`u8 titlePreset:u8 [DSTR] u8 memberCode:u8 reserved:u32 selectionCode:u8 selectionValue:u16 recruitFlag:u8 targetMode:u8 targetId:u16`，再跟四个u8、`selectionId:u32`、两个u8和`extra:u8`。037E7160把模型+116与请求selectionId比较，因此选择值应放在后部u32，不套用NoPack的前部同宽字段；前部字段当前置0。未实现的回归/活动等附加字段为0；目标设置和extra保留请求值。不能仅复制旧端的标题、上限及副本四字段。

0的成员段为`count:u8`，逐成员读取`slot:u8 uid:u16`；同本机server/channel分支再读五个u8。当前仅0号槽本人，连接就绪值为100，其他标记为0。跨server/channel会读取额外角色资料，本轮只发给本人，不进入该分支。随后是额外成员数0、八个u8的队伍尾部；队长槽为0，未接入标记为0，末字节保留targetMode。0/1最后还有一个可选附加结构选择器，本轮为0。

无自定义名称时，完整单成员0记录共56B、设置更新1记录共38B，删除3记录共11B。3不带设置或成员段，按原键清空八槽域并删除模型。CMD13为空正文，成功退队沿9/kind3收尾；本轮不发送未经完整证明的ACK13成功附加字段。失败为`00 error:u16`。

旧df_game_r的SetPartyInfo创建/更新真实队伍后发送9，LeaveParty也依靠队伍变化通知收尾，作为业务参考；其9缺少本版多项设置、标记和显式成员槽，不能直接移植。两个Go参考项目的正文和尾部也有差异，本服以当前ARAD读写器及实收请求为准。
