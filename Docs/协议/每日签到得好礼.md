# 日签到协议（活动2370）

本页对应V31.0.24.0 x86 / Direct12 Full03的活动2370，业务见[每日签到得好礼](../模块/每日签到得好礼.md)。
多字节整数均为little-endian。

## 请求与初始化

| 方向/category | opcode | 正文及用途 |
| --- | --- | --- |
| C2S/1 | 1296 `AT_DAILY_ATTENDANCE` | 空正文，领取最早一档可领累计奖励 |
| S2C/1 | 1296 | 空应答，随后在活动开启时同步实际状态；不表示未达门槛也发了奖励 |
| S2C/0 | 108 `EVENT_INFO` | 2370同时进入extra及active；active第一u32为2，其余11个u32为0 |
| S2C/0 | 1210 `INTEGRATE_EVENT_DATA` | 下面的37B状态 |
| S2C/0 | 99 `MAILBOX_ALARM` | `01 00`，仅实际创建奖励邮件后提醒 |

1296不携带日期、次数或档位；非空正文不执行领取。未就绪请求沿原Session阶段门禁拒绝。
日奖励由服务端已确认的通关事务发放，不能通过发送1296直接签到。

## 状态正文

| 偏移 | 类型 | 含义 |
| --- | --- | --- |
| 0 | u32 | 2370 |
| 4 | u8 | 模式0：后续32B；非0的160B变体未使用 |
| 5 | u32 | 累计签到次数 |
| 9/13/17 | 3×u32 | 三档累计奖励：0未达标、1可领取、2已领取 |
| 21 | u32 | 当天推荐地下城通关次数，最多2 |
| 25/29/33 | 3×u32 | 保留参考实现的3/4/5；本版窗口只直接消费前五个u32，不赋予尾部业务含义 |

入城就绪、活动开启、通关提交、累计领奖及日切后按当前已提交状态刷新。
关闭活动从整张108目录移除2370，保留持久进度。

## 客户端依据

- 菜单2370对应事件键`0x467`和窗口819（`0x333`）；`0261ADD0`打开该窗口。
- `01313C1A..01313C3D`创建CMD`0x510`并封装13B帧，未写业务正文。
  `00427D20`的附加尾选择器对1296走默认0，未追加此选择器控制的4B尾。
- `0124FFE0..01250099`读取事件u32、模式u8，模式0复制32B，非0复制160B；
  2370分支`0125060F..01250653`取前五个u32交给`01313CA0`。
- `01313E1C..01313E5D`在三档中存在状态1时启用按钮及可领奖提示；
  `01313ED0..01313EDC`在状态2时显示累计已领标记。因此不能套用参考实现相反的1/2含义。
- NOTI108的`026BE900`读取每事件12个u32；`026BF5AB..026BF5E1`将2370第一值交给窗口`01313550`保存。

以上为匹配冻结页的静态读写与分支证据；空ACK沿用已有活动调用方式，未作客户端实机确认。
