# 原生命令行登录

适用于 S5A9 匹配的 x86 客户端，是唯一登录入口。账号业务规则见[认证与会话](../模块/认证与会话.md)，帧头、CRC 和端点结构沿用[帧与频道](帧与频道.md)。字段来源为匹配主映像的原生发送与接收函数；自有 TCP 回归不等于客户端端到端验收。

## 输入与原生消费

启动对象解析函数为 `0x01FC3AE0`。`0x028EB5A0` 按 `?` 分隔并丢弃空段，`0x01FC3820` 把不足 16 项的向量补为空串。第 4、5 段分别进入对象 `+28h`、`+48h`，作为账号和凭据；账号超过 30 个 UTF-16 单元会被替换成 `invalid_id`。第 8 段站点类型写 `+8Ch`，第 6 段服务器编号写 `+88h`。账号与凭据由调用方提供。

`0x02902990` 发送时通过 `0x0232EFE0`、`0x01FC1DE0` 读取账号、凭据。`0x03BDF8E0` 将宽字符串转换为运行时码页的多字节文本，写入 u32 字节长度及内容，不带 NUL。本实现仅接受 ASCII 账号及 32 位十六进制凭据，避免码页歧义。客户端原样提交凭据，不执行 MD5；摘要须在启动前准备。

## 包序

| 顺序 | 方向/category/opcode | 内容 |
| --- | --- | --- |
| 1 | S2C/NOTI/1 `CHANNELINFO`，sequence 0 | protobuf 频道握手 |
| 2 | C2S/CMD/1562 `LOGIN_PRECHECK` | 账号 DSTR、站点 u8 |
| 3 | S2C/ACK/1562，sequence 1 | `[01]`，允许继续提交凭据，不代表已认证 |
| 4 | C2S/CMD/1 `LOGIN` | 下表完整请求 |
| 5 | S2C/ACK/1，sequence 2 | 凭据校验并取得 owner 后返回既有 Endpoint |
| 6 | S2C/NOTI/2 | 该账号的角色名册，沿既有协议继续 |

`0x02902990` 在 `0x062EF5D7==0` 时发送预检查；`0x023453D0` 的成功分支将标志置 1，再调用该函数发送 LOGIN。两个正常调用点传入空的附加参数，本实现不接受其他分支才出现的可选 16 字节块。

握手消费者为 `0x023B7870 → 0x0041B8A0`。解码后的 body 是 u32 protobuf 长度加消息；消息 field 2/varint 为 1，field 3/bytes 提供 334 字节随机兼容 key。`0x023B7B47 → 0x03B1B070` 仍会初始化 14 个 codec，依次读取 16/16/60/32/16/10/16/56/16/16/8/16/16/40 字节，因此握手必须提供完整 key。该 key 不是账号凭据，也不提供当前连接的传输保密。

消息还包含 varint field 30004=`1748`（CMD END）、30005=`1812`（NOTI END），引用当前枚举的 END 值，表示完整协议枚举的数量，不是服务端已实现 handler 的数量。`0x0041BF07/0x0041BF59` 分别写对象 `+78/+7C`，`0x023B90BA → 0x0239B280` 分别比较 `0x6D4/0x714`；缺失字段按零解释，会出现 `Different from server's cmd and noti packet count`。原机器码回放覆盖双缺失、单缺失及两项正确的四个分支。

field7/8为本连接实际分类入口的serverIndex/channelNumber；`0041B8A0`分别按tag56/64写对象`+4C/+50`，`023B7870`安装频道上下文。LOGIN端点返回同实例的独立Native监听端口及关联值；本人Actor/Player和同屏记录头仍与原分类入口身份一致，共享服务不合并客户端的频道缓存。具体目录和身份见[分类入口](帧与频道.md#分类入口与共享服务)，附加连接见[Native独立连接](帧与频道.md#native-独立连接)。

首包另有专用变换：接收入口 `0x028F8430` 对 NOTI1 进入 `0x0369FA30(body,length,0)`，绕过通用 DecodeBody。客户端逐字节执行 `ROL8(wire,6) XOR B5`；服务端对包含长度前缀的整个 body 执行逆变换 `ROR8(plain XOR B5,6)`，再组帧计算 CRC。当前服务器2的30项配置中，protobuf 长353B、body长357B，明文前九字节 `61 01 00 00 10 01 1A CE 02` 在线上为 `53 D2 D6 D6 96 D2 BE ED DE`，抓包保存后者；其他合法身份仍按标准varint确定长度。该分支与解码函数已匹配现场代码，并对全部 256 字节值完成原机器码回放。直接发送明文会破坏长度和消息，客户端无法继续登录。

## LOGIN body

| 顺序 | 宽度 | 含义及边界 |
| --- | --- | --- |
| 1 | u32 + bytes | 账号，1..30 个 ASCII 字符；必须与预检查的账号原文一致 |
| 2 | u8 | 原生状态字段，不作为认证身份 |
| 3 | u32 + bytes | 凭据，恰好 32 位十六进制字符 |
| 4 | u8 | 站点类型，不作为认证身份 |
| 5 | u32 + bytes | 原生附加数据，长度上限 128 |
| 6 | u32 + 512 bytes | 验证数据，长度必须为 512 |
| 7 | u32、u32 | 原生运行字段，当前不赋予未确认业务含义 |
| 8 | u16 | 服务器编号，由启动对象 `+88h` 截为 u16 |
| 9 | u8 + u32 × count | 原生列表 |
| 10 | u8 | 尾部标志 |

所有长度必须有完整数据，尾部不得有剩余字节。两条 DSTR 之间包含状态 u8，不能按连续两个字符串解析。当前只使用账号及凭据完成认证；其他字段作结构消费，不能声称已校验其业务或完整性含义。

## 拒绝与回归

顺序错误、截断、账号变化、凭据格式错误、错误凭据、禁用账号均关闭连接；原生错误码映射未确认，不猜测失败 ACK。取得 owner 前不发送角色数据；错误凭据不能接管同名在线账号。登录完成后同一连接再次发送预检查或 LOGIN 也关闭。

登录包和预检查不记录 body，通用收包日志同样对这些 opcode 及可能携带旧扩展的统计包脱敏。可运行 `--selftest-tcp native-login` 验证独立握手、认证、隔离、接管、重启及脱敏；启动方法见[贡献指南](../../CONTRIBUTING.md#验证)。匹配客户端已验证账号 `10000` 的原生命令行登录、原角色选角入城及协议数量提示消失；错误凭据、重复接管等拒绝场景由自有 TCP 回归覆盖，不能视为全部已完成实机验收。
