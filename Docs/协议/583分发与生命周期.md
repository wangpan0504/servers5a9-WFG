# NOTI583分发与对象生命周期证据

## 适用范围

匹配ARAD.exe的ImageBase为`0x00400000`，SHA256为`7560188d4bac4a33690fe3b37069f365885f7f57e14cee868b64103852f28471`。以下均为只读原文件字节及有限反汇编所得，不执行、仿真、注入或解包原客户端。消息读宽见[副本协议](副本.md)，ACT参数与manager命名空间见[能源符号证据](卢克能源符号证据.md)。

## 写入后的三条支路

`01DCE450..01DCE5DA`先经`01DC9FC0`取得old，再向manager的`+B8`记录写入或追加`(symbol,new)`，并在`01DCE508`写`+108=symbol`；随后按各自资格运行以下支路。

| 支路 | 静态调用链 | 已证边界 |
|---|---|---|
| 对象分发 | `01DCE50E → 02908E30(0x23)`；`023E3850`经当前strategy取得container；`01DCE57F → 03A939A0` | 资格并非仅mode23；mode2及strategy虚函数也参与。container或对象缺失可跳过事件，但此前manager新值已保存 |
| 当前wrapper回调 | `01DCE599/5A8 → 036D0EB0`，`01DCE5BD`调用virtual+14(symbol,old,new) | 不存在统一的old==new前置抑制 |
| 尾消费者 | `01DCE5CF → 015BC9A0` | 此函数在自身raid门后才比较old/new；其完整分派排除113/114/138/139，不能推广为其它支路也排除这些符号 |

因此**同值583不是已证的整体原生幂等操作**。重复通知可能再次经过对象事件或wrapper回调，但具体ACT及对象资格仍决定副作用；不能从重复调用直接断言战斗效果必然重复。本证据不修改服务端revision投影、发送去重或重连补发策略。

## 对象事件与ACT条件

`01DCE544..01DCE590`将container保存在EBX；`02C9A6F0`计算指针数量，`02C9A690`按索引读取。每项先调用virtual+1B8检查非空，再调用同一槽取得传给`03A939A0`的对象。

`03A939A0`先经`03A81DC0`资格门；controller的`+62D`决定不同回调路径。`+62D=0`时先有命名回调及内部事件`0xD2`，再由`03A939E0 → 03A90EE0`分发`0x14`。不能将其简化成无重入机会的裸getter，也不将未解码的事件码命名为资源标签。

`03A90EE0`内部仍有owner、容器、virtual+26C等提前返回门。opcode`0x65`经跳表到`03A931C8`，`03A931DF → 03B07020`查询controller的`+60`条件engine；engine表`0646BBA8`的已注册函数为`03B03BC0`，在`03B03BD9`调用manager getter。getter读取执行当时manager的当前值，并非冻结本条583写入的新值；先行回调与0xD2尚未证明不会重入，也不表示已实证重入发生。这里只证明在实际ACT记录、engine初始化及各门满足时，已有controller可以重新求值全局symbol；不证明指定角色/怪物必定收到或伤害动作必执行。

## 回调、DESTROY与未闭合生命周期

- selector1安装的`052E3F84+14 → 0130D8A0`只处理102/105/106，此支路排除113/114/138/139。wrapper非空会被复用；退出先虚回调/删除再清`+24`，非空不是新代际证明。
- `0130D8A0`收到102后不比较old/new或非零值，直接调用`01BE54B0`；后者在地下城场景创建`0xE5`结果菜单，并禁用再次挑战按钮；102非零时另禁用选择其他地下城。因此102=0也不能作为普通583状态发送。四团资源均将102定义为`[kill all character]`，快照按名称及编号匹配省略其零值。统一节奏已由服务端安全退场处理满能源，快照省略102；未使用该策略时只保留真正非零的原规则执行值。领域符号不删改，不同名的同号普通状态不据此过滤。真实清图仍由584 operation4独立通知，不能靠102零值打开菜单。
- 已核DESTROY标签解析及opcode`0x12`登记。完整执行handler依据动态类型调用C70、90、FC8、D68或284，不能统称“只标记、延迟销毁”。保护入口`03A81BA0 → 07AAE0B6`未展开或回放。
- 具体表`05794F34`的`+C70 → 02C5A350`具有报告和置`+274`路径；同表`+284 → 02A5FC90 → 036B1560 → [06444A84].virtual+48`的最终同步、排队或释放语义未证。标记前仍有同步调用，DESTROY后续也可能调用virtual+90(0)，不能由C70局部推出整个动作保留对象。
- 583循环在虚调用后继续使用原container，再读取count；两次virtual+1B8之间没有本段可见的持有或代际复验。这不是安全采样scope证明，也不能从未见retain直接宣布UAF：线程调度、重入、动态虚函数和其它所有者仍未闭合。
- container缺失时可只存新值而不分发；本setter未排队“对象稍后安装再通知”。这不证明其它路径没有补发或初始化重评估。新对象是否主动读取当前manager须另沿实际初始化链核验，不应凭此任意增加重复583。
