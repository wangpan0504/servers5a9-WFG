# CMD668 恢复序列证据

适用 S5A9 x86 匹配客户端；地址和字节以[副本协议](副本.md#攻坚队招募与查询)的既有静态记录为依据。本页整理既有材料，不代表本轮重新逆向或客户端验收。CMD668 与同号 NOTI668 REAL_ESTATE_STATE 不同（[枚举](../../Server/DfoServer/Network/Core/PacketTypes.cs)）。

## 已证：请求及回调

- 同频道路径中，NOTI835 的读取器 023CDA19 → 023AB820 读取 key:u32, unknown:u8, unknown:u16；无本地团记录且 key 高两字节匹配时，023AB9FA..023ABA1B 发送正文仅为 key:u32 的 CMD668，自动路径不使用尾部。异频道路径不是同一重入路径，尾部不能推成重入时间或阶段。[既有读宽与分支](副本.md#攻坚队招募与查询)，KB-20261026T040014-ff9e5cf444、KB-20261027T155451-6ec4308d89。
- ACK668 成功消费者 02344410 不读额外业务体，调用 0055D870；后者只在频道类型 0x3E/0x3F 调用界面刷新，Anton 0x17 和 Luke 0x20 直接返回。005007E0..00501DD4 是本地界面刷新，既有记录未发现其发包或调用 27/585/586 读取器。这只证明所记录的调用路径，不能证明其他异步通知不存在。[副本协议](副本.md#攻坚队招募与查询)、[卢克领域边界](../模块/副本.md)。
- 成功 ACK 最小公共标志 01、失败正文 00 13 00 有既有客户端/服务端合同，但成功标志不是恢复成功的充分条件。[卢克恢复边界](../模块/副本.md)、[现有处理器](../../Server/DfoServer/Network/Handlers/RaidHandler.cs)。

## 无证与实现门禁

没有成功重入抓包证明 ACK 前后通知的完整集合、顺序、条件、接收者、字段值或场景依赖；候战室、进行中房间、加载屏障、阶段切换和奖励界面是否使用同一序列均未知。没有证据证明 ACK 后立刻发送任一候选通知或客户端会在失败 ACK 后自行恢复。因此保持成功客户端恢复 UNIMPLEMENTED，不新增猜测字节或以普通进图 TCP 通过声称重入通过。

本页所在基线的 [RaidHandler](../../Server/DfoServer/Network/Handlers/RaidHandler.cs) 在开启开关后仍回失败，并不安装 owner；后续 !164 依赖分支的状态侧进展须以其实际提交为准。状态侧恢复、ACK 失败与客户端画面恢复是三个不同事实，不能互相代替。

## 用户实机取证方案

仅在用户确认的合法测试环境中由用户操作；不连接或改动未授权服务。使用匹配客户端，在能真实成功重入的参考环境保留完整双向、带时间戳和连接标识的 packet_log；妥善脱敏登录凭据、角色识别信息和密钥。服务端运行状态、频道类型、客户端版本及断线前后截图另行记录，不能将不同连接简单按时间混成一条 FIFO。

1. 两人同团同分队，在安徒恩候战室先记录团名册、队长、分队、阶段、地图状态和角色所在界面；从断线前开始抓两名角色的收发包。保留幸存者在线，不主动解散团。
2. 用户让其中一人真实断线，记录时间和断线类型；同角色重新登录、选角、进入原同频道，并记录入城、835、自动668、ACK以及此后直到团界面稳定的全部双向包。标注每个包的连接、方向、opcode、完整正文、顺序和截图，不只截取候选 opcode；同时记录幸存者看到的名册更新。
3. 分别在候战室、已进入副本的稳定房间、加载中、阶段/奖励界面重复；记录可否成功、位置与地图、阶段、加载屏障、奖励和计时显示。无法抵达的场景标记未测，不人为声称成功；比较 585/586/583/587/596/597、普通队伍及 27/28/29/37/30 是否出现及相对顺序。
4. 用相同界面做未断线普通进图对照；若有条件再做异频道、错误 key、重复重入及原实例已结束的失败对照。保留原始顺序与关键 UI 时间点，将成功及失败分开；必要时再获授权补充客户端路径分析。参考环境无法成功重入时，仅可记录失败，不能闭合成功序列。
