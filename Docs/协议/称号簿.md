# 称号簿协议

本页使用匹配x86 ARAD.exe的收发消费者；业务、资格及未实现边界见[任务系统](../模块/任务.md#称号簿与成就)。旧端与Go实现只用于取放、三计数和奖励事务业务对比，不采用它们的opcode或错误字段宽度。

## 请求及ACK

所有整数为小端。ACK成功头为u8=1，失败为u8=0及公共u16错误码；错误不是参考Go实现的u8。

| 请求 | C2S正文 | 成功ACK正文，包含头 | 失败ACK正文，包含头 |
|---|---|---|---|
| CMD412 TITLE_BOOK_PUT | `list:i32,slot:i32,itemId:i32,category:i32,index:i32`，20B | `1:u8,list:i32,slot:i32,category:i32,index:i32`，17B | `0:u8,error:u16,list:i32,category:i32`，11B |
| CMD413 TITLE_BOOK_GET | 同412 | 同412 | 同412 |
| CMD417 ACHIEVEMENT_TRIGGER | `questId:i32,delta1:u16,delta2:u16,delta3:u16`，10B | `1:u8,questId:i32,remaining1:u16,remaining2:u16,remaining3:u16`，11B | `0:u8,error:u16,questId:i32`，7B |
| CMD423 OTHER_USER_TITLE_BOOK_LIST | `characterId:u16`，2B | 由五个NOTI358返回，不新增猜测ACK | 当前只处理有效在线目标 |
| CMD821 RAID_REQ_OTHER_CHANNEL_USER_INFO，mode2 | `server:u8,characterId:u16,mode:u8=2,channel:u8`，5B | 由NOTI762返回，不新增猜测ACK | 定位不匹配或目标离线时不返回列表 |
| CMD568 SET_CLONE_TITLE | `itemId:u32`，4B；0清除 | `1:u8,itemId:u32`，5B | `0:u8,error:u16`，3B |

请求412/413的共享发送路径在`029E10D0`选择专用命令并写五个i32；ACK消费者为`0234EED0`和`0234F1A0`。成功直接操作既有容器对象；穿戴分支接受list3/17并使用本版slot13。失败读list/category以清除两个容器的等待状态。公共失败宽度由`028F85F6..028F8686`确认。1/4/6/11等取放文案入口为`0234A350`，未知错误映射不扩展。

本服只接普通背包list0和穿戴list3；list17属于另一个特殊穿戴上下文，未核验前不能简单映射成list3改变普通装备。

CMD417由`0200EB60`、`0200EE50`生成，三个通道分别写u16；本版账号成就转到CMD855，不混用。ACK入口`023673C0`读取全部三个剩余数，结束客户端命令等待。CMD423在`037A9430`的同频道他人查看路径生成；跨频道821是另一合同。

## NOTI358

`show:u8,owner:u16,category:i32,count:u32`，固定头11B。分类0–4；owner=0选择本人五类数组，非0选择他人数组。最后分类4、show=1、非零owner才进入他人称号簿窗口打开分支。

每行字段：

| 顺序 | 字段 | 宽度 |
|---|---|---|
| 1 | index | u16 |
| 2 | ItemId | i32 |
| 3 | Value | i32 |
| 4 | Attr | u8 |
| 5 | Durability | u16 |
| 6 | SealFlag | u8 |
| 7 | EnchantCardId | i32 |
| 8 | EnchantUpgrade | u8 |
| 9 | AmplifyType | u8 |
| 10 | AmplifyValue | u16 |
| 11 | RAW长度及4B扩展 | u32=4，随后4B |
| 12 | Marker16对应的构造参数 | i32 |

前十项共22B，当前行共34B。`023C3110`逐项读取，`023C32C6`通过RAW消费者读取由`03DAA690`初始化的两个u16扩展，随后独立读取i32，再构造物品并安装到指定槽。扩展效果语义尚未命名，保存与投影保留现有Core字段，不把长度或数据省略为零字节。

此列表不是123B普通物品表。完整Core仍在数据库与领域实例保留，取回普通容器后通过其完整物品差量恢复；不能只存本表能展示的字段。主物品表合同见[物品协议](物品.md)。

## 跨频道NOTI762

攻坚队右键菜单在`037A9AC1`通过821的mode2请求称号簿，`023DEA00`消费762。正文为`channel:u8,server:u8,owner:u16,show:u8=1,categoryCount:u8=5`；随后逐类发送`category:u8,count:u32`及count行上述34B物品。空分类也保留，五类全空为31B。定位头顺序与请求不同，分类宽度也不同于358；不能套用同频道列表。

目标须在线且服务器、频道与请求完全相符。服务端从目标会话的不可变角色快照读取实际库存，发送前复验请求者和目标仍有效，不持有两个账号owner，不查询或修改请求者的称号。重复查询只重新发送快照；空列表用于清理他人窗口旧数据。821的mode0详情使用独立[757合同](角色与入城.md#攻坚队跨频道角色详情)，mode3决斗信息仍未实现，不能以称号列表或通用成功代替。

## NOTI359与360

NOTI359：`count:i32`，随后count组`questId:i32,remaining1:u16,remaining2:u16,remaining3:u16`，再附固定16B，四个i32最近完成ID，不足补0。总长度`20+count*10`。入口`023AA1E0`无条件读16B；`02019A40`维护最多四个最近完成ID，不是心情状态或金币奖励。全零行恢复完成状态，非零行恢复进度，客户端按自身titlebook资源重算章节显示。

NOTI360：`questId:i32,category:i32,index:i32,itemId:i32,durability:u16`，18B。`023C34C0`把最后的u16传到物品构造函数`027F5590`的耐久参数，不能当品质种子或百分比。该包负责完成/获得反馈，但构造的其余核心有缺省值，随后以NOTI358校准实际称号。无实体映射时category/index为-1，跳过本版的有效分类分支；完成事实仍由417/359恢复，不制造其他分类索引。

## 包序与边界

称号动画568的发送入口为`015621B0`，清除入口`015621E0`；成功消费者`01561E20`读取u32并调用外观对象虚函数`+0x10`，随后发送UDP55同步。服务端提交后先回ACK568，再在选择变化时刷新本人Actor/Player及城镇同屏。Actor外观表后的首个u32由`0267DF38..0267DF4C`读取，Player与OtherPlayer装备表后的首个u32由共享消费者`023C470A..023C4729`安装到同一外观对象。名册48B尾块首u32同步保存值。字段独立于实际称号装备和惩罚计分；重复选择只确认，不重复写库或重建角色。

选角先完成角色、普通资产和邮件初始化，再发送359及五个358，最后继续城镇状态和入城完成。三计数提交后：ACK417→实际完成360→完整359→必要普通资产差量→称号簿358→必要邮件提醒。部分进度不创建称号或360。

取放成功：提交→ACK412/413→必要普通容器绝对差量→实际穿戴变化时本人Actor/Player→完整五类358。ACK需要源物品尚在客户端容器；先清源格会破坏它的移动消费者。13槽变化后，完整Actor外观表必须带入本次实际称号，随后Player恢复完整穿戴；不再发列表3条目重复创建ACK已移动的对象。只发358不能刷新本人场景外观，城镇同屏广播也不包含本人。副本及结算的Actor保留成员状态1，不发送城镇状态或入城完成。失败回正确宽度ACK并保持资产和user状态；发送失败不重做已提交奖励。

ARAD的`0234F1A0`与`0234EED0`成功分支先调用`029D0880`转移称号对象，后续角色方法受当前模块条件约束，不能将成功ACK等同于所有场景均已刷新外观。参考原服`CTitleBook::getTitle`（`086425C4`）在穿戴后另调用`CUser::send_equip`（`0865DD14`），用于核对刷新责任，不采用其旧槽号或包序。装备称号仍使用本版槽13；独立的被拉黑计分与GradeB/C/D绘制见[角色与入城](角色与入城.md#被拉黑计分与惩罚称号)。

静态消费者、独立字节读取和TCP自动化分别提供包体证据与回归；未据此声称当前Windows客户端的全部界面、词条、穿戴替换和特殊奖励已完成实机验收。
## 漩涡原生破招报告

本服扩展C2S `0x7FF1`使用固定40字节正文，十个小端u32依次为：

| 偏移 | 字段 | 约束 |
|---|---|---|
| 0 | magic | `0x31435746`，即FWC1 |
| 4 | serial | 本连接最近排出的MAI房间流水，非零 |
| 8 | dungeon | 当前正式团队地下城 |
| 12 | map | 当前地图ID |
| 16 | seed | 本房种子 |
| 20 | position | `x | y << 8`，高16位为零 |
| 24 | sequence | 非零进程内递增序号，每包仅一个事件 |
| 28 | sourceKind | 1为怪物，2为指定光幻影PO |
| 32 | sourceId | 怪物107013148/107013178，PO109035530..109035532 |
| 36 | sourceKey | 原生对象实例键，1..65535 |

没有私有ACK，原生417仍走原有回复。服务端只消费受当前正式场景约束的单次报告，完整拒绝截断、尾字节及错误身份；不能把序号差当成数量。已提交来源随后沿称号簿现有通知投影；重放只允许补消费，不重复新增来源或奖励。

客户端匹配ACT入口`03AA8FE0`、7006成功回调`03AA907E`及原生writer公共收尾`03BE170A`，三处整组核签名并回退。事件在原回调返回后采集真实源getter及对象键，保留寄存器、flags、浮点/SIMD、LastError和原SEH链。最多排队64个事件、5秒期限；仅同owner/房间/主线程发送，切场、过期或未知传输状态安全丢弃。发送器忙时等待原生收尾再次排空，不修改原生writer忙标志。未获客户端实机回执不能称自然破招通过。
