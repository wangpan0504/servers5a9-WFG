# 经验与升级通知证据

## 输入及当前能力

累计 XP 和 SP 差已经由 [角色成长资源](../资源/角色成长.md)提供；本文补充通知消费合同，不授予经验，不把资源读取或静态解码写成正常升级验收。

当前已恢复 NOTI37 自身全部直接读取：当前自身玩家路径长度为 `91 + 8*bonusCount` 字节。新对象的成长胶囊、熟练状态及决斗胜点初值已恢复。完整正文可按明确的新角色普通事件策略编码；仍不能发送25字节前缀或把存量未知状态清零。各成长来源的实际入口与实机验收范围以所属模块为准。

[普通成长计划与投影](../模块/角色成长.md)已经实现纯领域累计经验候选与完整NOTI37纯Builder。两树SP分别在已消费余额上增加等级贡献差，TP及绑定保持；通知附属状态和事件分量必须显式输入。本服正式击杀、通关和任务领奖已有生产成长事务与完整通知入口，仍需匹配客户端验收。普通Dungeon/Settlement升级采用N37→Player→技能ACK29差量，不追加Actor或完整N19；无技能改变不发技能包。Town/MapSelect保留Actor→Player→N19，职业变化也保留完整重建。结算N35位于这些升级投影之后，刷新不另发经验或修改房间死亡事实。

## direction/category/opcode 与读取入口

S2C、notification category0、opcode `0x0025`（37），仓库枚举为 `NotiPacketType.EXP`；不是名称相近的其他经验奖励 command。注册 `023CCAEB..023CCAF6` 绑定 `023C4CB0`。本版文字 `05537EE8` 为 `NOTIFUNC_ENUM_NOTIPACKET_EXP`，`05537F2C` 为 `EXP 1`。

`03C85220` 从 packet cursor 读 word，并推进2B；`03C85290` 读 DWORD并推进4B。`03BE2690` 连续调用两次 DWORD reader，第一项写out+0、第二项写out+4，故经验是 little-endian u64。`03C85300` 按明确长度复制原始字节并推进 cursor。reader 从全局 cursor 直接取值，remaining 不足走错误支路，不能依赖局部预清零来省略字段。

handler 开头要求角色 manager 与当前 player 存在。`02D82730` 优先返回 `0643A49C`，否则 `0643A498`；在 `023C5031..023C5077` 比较当前 player 是否等于 `0643A498`，非自身可提前结束。服务端对自身成长通知必须采用完整路径，不能据提前结束分支缩短正文。

## 状态更新与包序边界

`023C56F9..023C577D` 从绝对累计经验减旧经验，再减各奖励分量用于基础经验显示。`023C602C` 调用 player virtual+B9C；同冻结虚表为 `02B6E490`，将累计经验、当前等级传入，按累计表减等级起点，分别更新 player+4530/+4540/+4550 的编码经验状态。它不是“获得的经验数”字段。

等级变化在 `023C51F6` 比较并于 `023C529F..023C5307` 更新角色Data+14编码等级。随后执行等级UI、事件与装备等刷新。两树点数为绝对余额：SP在 `023C614B..023C6191` 保存context、分别设0/1、调用 `02D7E9F0`，最后恢复context；TP在 `023C6256/023C6265` 调 `02D7EC30(value,index)`。客户端不会通过这一通知自行补累计SP表差。

技能窗口刷新 `023C6273..023C62A8` 调 `028A5570` 或等级变化路径 `028A56A0`。这证明本通知自身有刷新副作用，不证明服务端必须随后发 NOTI19、Player或另一个伪成功包。合法经验来源、成长事务及其与任务/击杀/结算包的前后顺序仍须各自闭合。

业务参考df_game_r的`CUser::gain_exp_sp(0866A3FE)`发布经验，`CParty::kill_monster(085A27E8)`在成长返回后发送Player，本版保留经验→属性主链。匹配ARAD的完整19在`023B5C13→虚表+C68→02B81140`遍历原生技能并调用清理函数；技能31的`01F4B280→02BD63B0→02B29110`将角色`+35C0`的临时武器槽36清零。存活角色的升级停点确认：37和Player结束后该槽仍有效，完整19清槽后原生效果对象仍非空、active仍为1；`01F4BF30`只在效果对象为空时重建，因此普通被动重算不等于恢复蛇腹剑。仅观察`ProcPassiveSkill_%s`、绑定或效果对象存在不能证明运行状态正常。

图内升级改用匹配ACK29消费者`02360630`的实际槽位、ID、目标等级和指令差量；它不调用整树清理`02B81140`。备用树先发、主树0最后发，避免改变本服当前使用的树；零项回复仍读取context/SP/TP及末mode，按`02360630`的count0分支恢复主树而不虚构变化项。完整字节布局见[技能协议](技能学习.md)。自动回归和原码依据不代替差量发布后存活角色的攻击与被动实机验收。

## 升级券418

本版`[level up ticket]`通过C2S command418 `REQUEST_EVENT_SERVER_LEVEL_UP`，不是普通CMD44或CMD515动作。`037867A0..03786823`从原物品取得槽号和容器，`037867D3`写opcode0x1A2，随后依次写u16 slot和u8 list；正文严格3B，没有物品ID、动作参数或客户端指定的升级等级。

command注册`0237CCA6..0237CCB4 → 0235BFF0`。不要误读notification注册`023CD298 → 023A5140`：同号NOTI418是PVP延迟惩罚，与升级券无关。

成功ACK418正文固定12B：

| 偏移 | 类型 | 内容 |
|---|---|---|
| 0 | u8 | 成功1 |
| 1 | u16 | 实际消费源槽 |
| 3 | u8 | 源容器 |
| 4 | u32 | 本次补足的经验差，不是累计经验 |
| 8 | u16 | 本次等级SP贡献差，不是余额 |
| 10 | u16 | 本次等级TP贡献差，不是余额 |

`0235BFF0`成功分支依次调用word/byte/dword/word/word reader，定位源后调用`029D02C0(...,1)`消费；随后给当前玩家经验及技能点增加回包差额，并执行技能UI和pending收尾。失败由公共0+u16错误前缀进入此函数的错误分支，不附成功字段；本入口普通拒绝用99，对应dstr22269“无法使用该物品”，不借用22的预约角色专用提示。不能只回单字节1、先删源或先同步绝对点数再回增量ACK。

完整包序为ACK418→实际任务物品差量→NOTI37绝对成长→活动任务574→等级Actor/Player→按场景的技能同步→可接任务21→完成表356。城镇及职业变化使用完整19，图内普通成长只发变化技能的ACK29。ACK中已经增加经验，因此后续NOTI37仍必须写真实累计经验，不重复加一次差额。全部通知来自同一提交回执，已发布的418不因1431最终回答重放而再次发送；商店兑换材料不参与使用费用或库存同步。

主线有未答问题时，1381消费者`023D76A0`会在尚无问题上下文时调用`0200A1A0(...,2,-1)`建立原生mode2，再读取u8数量和各u32问题ID。服务端可在扣券升级前等待真实1431选择，最终同事务提交；mode2不依赖1457。1381不能用空列表冒充成功，未选择或失效问题上下文不能自动完成所有分支。

df_game_r当前参考构建的`CUser::CalLevelUpItemState(08689D74)`按等级区间计算“升至下一等级所差经验”，`SetCharacLevel(0867A95C)`同时处理等级点数和属性；这份旧端没有新版`[level up ticket]`动作，不能复制其物品白名单或包号。参考项目DNF90-source-oneclick的`level_up_consumable.go`与go-server提供较新业务参考；上述wire宽度和mode2依据匹配ARAD重新核对。自动主线范围及持久化归[角色成长](../模块/角色成长.md#固定一级升级券)。

## 经验物品CMD30

本版普通经验物品沿command30 `INCREASE_STATUS`，与command418升级券、44恢复药和冒险团账号胶囊分开。ARAD `029CD2A0`先写opcode0x1E，再调用word writer写Main槽位；C2S正文严格`slot:u16`共2B，不携带容器、物品ID、经验量或防重token。

注册`0237BE10`内的`push 0x1E → 023612D0`确定本版消费者。成功正文为`flag:u8=1 + slot:u16 + kind:u8=1 + gainedExperience:u32 + spDelta:u16 + tpDelta:u16`，总12B。`023612D0`依次读word/byte/dword/word/word，先从Main原源消费一件；kind1路径增加实际经验，并按后两项增加点数。kind不是PVF状态类型编号，不能把`[expPercentUp]`的资源枚举3直接写入回包。失败为公共`0 + error:u16`前缀，本入口普通拒绝用19，消费者执行原pending收尾，不附成功字段。

服务端先提交，再发ACK30→NOTI37完整绝对成长→实际任务条件574→按阶段的等级Actor/Player→按场景的技能同步→可接任务列表；图内普通升级采用ACK29差量，城镇采用完整19。同等级经验没有等级投影，仅在真实绑定变化时同步技能。源已由ACK消费，不再补源删除；商店兑换材料不重复扣除或同步；NOTI37写已提交累计经验和两树绝对点数，不能先发绝对值再让ACK叠加增量。副本升级不追加城镇Actor，不借经验包切换模块。

原始标签映射`040D9BF0`确认`expUp=1`、`expUpByPercent=2`、`expPercentUp=3`，三者不是同一枚举。`040C27D0`的经验区间使用64位累计边界相减，百分比整数除100；该辅助函数不替代服务端对新标签的资格核验。df_game_r `getStackableIncreaseStatusType(089AEE71)`旧构建只认识`expUp`；`CUser::increase_status(086657FC)`由实际物品读取增量，先发经验kind1消费回执并保持成长点数，旧端请求编号不用于本版wire。最终数值、事务和支持范围归[经验消耗品](../模块/角色成长.md#经验消耗品)。

## 按表成长与193动作

匹配ARAD的 `040D9BF0` 将 `[levelUpByTable]` 映射为状态类型6，`041461C2..04146255`保留后续整数向量。`040C2690`每三项原序扫描，最低和最高等级均包含，返回首个命中行的第三项；`040C2710`取目标等级起点的64位累计经验减去当前累计经验。不能把状态类型6写入CMD30的经验kind字段，后者仍为1。

`[jumping lv]` 在 `040D4F60` 的映射为动作193，其使用注册 `028C5980 → 028BA9A0`。已转职角色及job9/10直接构造CMD515：`slot:u16 + list:u8 + reserved:u32=0 + action:u32=193 + selectedGrow:u32=0 + trailing:u32=0`。普通未转职角色先打开266号转职窗口的mode5；`012A2DDC`所属点击函数的case5确认后采用同一19B正文，`selectedGrow`为选中的第一转职分支，取消不发消费请求。

ACK515成功为 `1:u8 + slot:u16 + list:u8 + action:u32=193` 共8B；`028C0AE0`成功路径按原源减一，193没有额外经验或职业尾段。失败为 `0:u8 + error:u16 + slot:u16 + list:u8 + action:u8=193` 共7B，普通资格失败用19。没有jumping动作的等级表仍沿本页CMD30路径；两条入口不能互相借用而绕过职业选择。

服务端提交后先消费ACK，再发真实NOTI37、职业Actor/属性Player、完整NOTI19及任务投影，完成表356最后恢复。主线问题1381/1431沿用升级券等待协议，最终仍回复原CMD30或515，不改成418。匹配客户端实收已确认mode5所选分支写入selectedGrow，已转职路径写0；两条路径均接收8B成功ACK并安装Lv82及实际职业。其余窗口分支与业务验收范围见[按表升级胶囊](../模块/角色成长.md#按表升级胶囊)。

## 低等级可编码范围和停止点

Lv1→2累计经验起点1000、Lv2→3起点2035；SP等级贡献分别增加30，Lv1初始贡献0。这些已由成长Catalog闭合，可用于真实成长事务输入。完整通知还必须从同事务及真实状态 owner 提供两树剩余SP/TP、决斗胜点、offset38状态、offset59/63状态，以及实际经验事件奖励分量和标志。

没有证明全体Lv50以下角色的TP余额严格为0：TP原始表仅声明50..100每项1，表加载 `03FB6424..03FB649A` 已确认，但缺少正常升级累计/发奖consumer及任务、特殊来源规则。低等级不改变已持久化TP，与“等级规则必定TP0”是不同结论。不能通过零表槽或初始余额0制造升级发点合同。
