# 物品协议

本页维护 匹配客户端 实体条目、Actor/Player 装备、CMD18/19/20、物品锁、钱包、仓库与史诗图鉴的 wire 与消费者证据。业务、持久化及验收边界见[背包与装备](../模块/背包与装备.md)；商店/修理/分解等交互合同见[物品交互参考](物品交互参考.md)。

## 普通恢复药 CMD44

当前匹配S5A9主模块的普通C2S category1/opcode44严格15B：`slot:u16 + list:u8 + opaqueCheck:u32 + sourceItemId:i32 + argument:i32`。producer `029E0695..029E078E`依次经`03BDF750/03BDF720/03BDF780`写2/1/4/4/4B，普通末字段为0。另有10B特殊入口及非零参数入口，当前不截断兼容成普通使用。

ACK44注册`0237C0B7..0237C0C2 → 02356A00`，成功完整12B为`01 + 原slot:u16 + 原list:u8 + 原opaque:u32 + 原itemId:i32`；失败同样12B为`00 + error:u16=123 + 原list:u8 + 原opaque:u32 + 原itemId:i32`。公共分派读success和失败error，成功`02356A20/02356A2B/02356A3A/02356A43`额外读2/1/4/4B，失败`02356D6F/02356D80/02356D89`额外读1/4/4B。123是本服已确认的中立静默收尾，不被命名为各项原服错误原因。

`026DFB60 → 03C7DE70`生成opaque，末段`SHR16/AND7FFF`限定0–32767且允许0，只避免当前pending映射撞号。check及itemId均为正时，成功和失败都会经`026DF9A0`核对并删除原opaque→itemId映射，后续可再次生成同值；check为0时跳过核验而继续普通消费及收尾。正值重复ACK会触发CMD436，callback不因此保证停止后继消费，失败重复也可能移除另一pending。必须回显原值，不能命名为时间戳、恢复量、数量或永久幂等ID，不盲回放成功/失败包。

成功沿`029089D0/029CA9D0`定位原源，`02356CD9..02356CE2 → 029D17A0(slot,1)`消费pending和数量，`029D1D14..029D1D3B`减1、耗尽`029D1D87 → 029CDAF0`删槽，最后`02356D55..02356D5D`清等待。失败`02356F68..02356F6A → 029CF9D0`只弹出pending。普通使用先原子提交，再发ACK，不能先用源NOTI14更新最终数量或清槽后让ACK再次减1；必要任务条件更新另按实际提交结果投影。修炼场保留成功ACK44的药效与pending收尾，再发原槽完整123B核心行的无提示NOTI1681恢复原数量，服务端不扣源、不创建新UID；最后一件也沿同一还原流程。该数量链已用V31 Direct12 Full03原生代码复核，修炼场数量保持及使用后无获得提示已获匹配客户端确认。

NOTI1681 `UPDATE_ITEM_LIST_NOT_NOTICE`注册于`023CCA48..023CCA56 → 023C08D0`；包装器先将通知标志`0620A11E`置0，传原两个参数调用NOTI14的同一解析器`023BEC30`，返回后恢复1。因此正文仍为list/count/123B完整行。获得提示函数`0292A3E0`在`0292A40E`检查此标志，0于`0292A447`直接跳`0292ABF6`清理返回。修炼场只更换这条数量还原通知，普通掉落及付费投影仍用14；原码静态证据绑定V31 Direct12 Full03。

两条本地计时链不能混同：`+C0 → 029C3570`读取`+560/+14`并写时间记录；`+BC → 029B6C60`、`+150 → 029C4320`使用`+13C`时间和`+414`组或itemId键写不同记录表。原资源cool time/group到这些字段以及clock单位完整赋值链尚未闭合。本服对当前四种恢复药采用10秒、组0/1独立的单会话策略，责任及换角/重连边界见[模块](../模块/背包与装备.md#普通恢复药)。

普通发送后`029E0ACF`仍可能调用Player `+8F8`，受保护实现和UDP24合同尚未闭合。ACK数量/收尾证据不证明服务端HP/MP恢复、失败撤销或同屏效果；服务端不伪造HP包，实际客户端回血蓝、冷却和同房间拾取分别保留验收边界。

## CMD47地面丢弃

CMD47 与城镇 protobuf CMD18 分开。匹配实收12B正文为 `x:u16,y:u16,list:u8,slot:u16,count:u32,tail:u8`，尾byte原样保留，不推定丢弃模式。成功ACK为8B：`success:u8=1,list:u8,slot:u16,removedCount:u32`；`02356FDA/02356FE6/02356FF2`逐项读取，`029D02C0`删除/减堆，因此不能填剩余量。失败为4B：`success:u8=0,error:u16,list:u8`，`023572EF`仍消费容器byte以解除源格等待。

NOTI40 普通定长正文136B：`actor:u16,x:u16,y:u16,groundKey:u32,itemEntry[123],mode:u8,ownerActor:u16`。`023C0D59/023C0D65/023C0D71`读前三项，`023C0D83`读key，`023C0D9F`读123B核心，`023C0DB4/023C0DC6`读末两项。单人使用实际角色ID和mode0，不把请求tail复制为创建mode。原码与字段绑定匹配 ARAD.exe；其他版本只参考业务，不复制包号。

成功在数据库提交后按 ACK47→NOTI40→必要库存/穿戴刷新发布；不发送怪物死亡38或经验通知。拾取沿原 CMD43/NOTI39 消费者，完整核心不重生成；业务与失败恢复见[副本地面丢弃](../模块/背包与装备.md#副本地面丢弃)。此定长通知不用于带独立时装/宠物detail的物品。

## 条目读取边界

普通标量分别按 u8、u16、u32 读取。RAW 字段为 `length:u32 + bytes[length]`，读取时同步推进游标并扣减剩余长度；长度为 0/4/8/30 时分别消费 4/8/12/34B。

NOTI13/14 的普通实体条目均复制 123 字节。服务端自测和 TCP 回归不代替客户端显示与装备属性效果验收。

这些资源足以确定普通创建的模板选择，创建角色与初始物品须同事务提交。存量角色是否补发、补发哪些实例属于独立迁移策略，不能由CHR推导；若接入补发，须有持久化标记或唯一约束，避免重启、重登或重复迁移再次赠送，并保留既有generation/revision、任务与技能。专用Lv95角色单独处理，不能在普通创建初始化或迁移中无条件套用本表。

## 容器与普通条目

当前容器编号为 Main=0、PersonalCargo=2、Equipment=3、AccountCargo=12。槽位编号、可用范围及类别规则由[背包业务文档](../模块/背包与装备.md#移动穿脱删除与整理)统一维护。

`NOTI13 Main = list:u8 + expansionSlots:u16 + count:u16 + entry[123]*count`，expansionSlots 直接发送扩展格数0/8/16/24；列出存在的实体和全部15个货币虚拟槽，按 slot 升序。`NOTI14 = list:u8 + count:u16 + entry[123]*count`，没有扩展字段。清空实体条目为目标 slot、itemId=-1，其余零。数量虚拟槽使用自己的 itemId、value=余额，零余额仍保留该 itemId，不分配实体 UID。仓库全量的专属头见下节，差量继续使用 NOTI14。

NOTI1681只在`023C08D0`临时清除`0620A11E`并复用NOTI14消费者，不能关闭STK的独立新物品图标标记。`020C5D20`在旧数量小于或等于新数量时调用`020C5840 → 020C5630`；`020C5659`仅在完整列表载入标志`062CF69C=1`时跳过实例+996的新物品标记。因此不能把相等数量的1681当作同容器移动的无动画同步。

Main读取链为 `023BDF17` 读u16、`023BDF38` 右移3位，得到0–3档；经 `02873370` 的事件10、`02873FAB → 039835B0` 保存扩展次数。`039837F0` 按该次数累加扩展负重配置。24格须编码为 `18 00`，不能编码为 `00 03`：后者表示768格，客户端解为96档并读取配置外的数据。有界原码回放覆盖0/8/16/24及错误768输入，止于右移后的 `023BDF3B`；静态链路及崩溃栈确认越界原因，不将此前缀作为整个UI验收。

未确认业务含义的字段保留 Extension 名称，不能因宽度已确认而自行启用效果。ctor `005E5CE0` 初始化123B结构，扩展 ctor `03DAAB70` 的5B顺序是 DWORD 后 byte；不是按持久 record 参数排列。时装、宠物等还可能在基础条目后读取额外资源/detail，当前不能只靠123B开启它们。

带模板期限的堆叠物品不能用 `expireTime=0` 强制永久：`027F85B1` 将条目offset56读入内部核心 `+70`，`028B3E71..028B3ECF` 再传给实例 setter `029B73D0`。setter 对 `-1` 在模板期限为正时回退到模板值，对0及正数保留实例值；期限消费者 `029B7090` 仍按模板资格启用期限分支，并用实例截止减客户端当前秒数，非正结果归零。因此商城/礼包仅在该实例实际声明的期限都被对应开关忽略时下发 `2147483647`（2038-01-19 11:14:07，UTC+8）；未忽略的相对或绝对期限照常处理，原永久物品仍为0，见[背包模块](../模块/背包与装备.md)。2099 Unix 秒超出当前有符号32位期限合同；匹配原码局部回放验证直接写入会得到0剩余秒，不把该结果称为完整UI或实机验收。

强化、附魔升级、锻造使用三个不同字段。NOTI13 的 `023BE97C..023BE989` 调用 `027F7AC0` 将123B原始条目转为内部核心：`027F82D5` 读取offset10并调用 `027EDF50`，其中 `027EE0C9` 用 `0x1F` 提取强化存入内部 `+8`，高3位另存；ACK80 `02373D90` 的成功分支在 `023744EA..0237459D` 更新同一 `+8`。offset18在 `027F834C` 存入内部 `+20`，是独立的附魔卡升级字段。offset87在 `027F860F` 以有符号byte读取并存入内部 `+78`；ACK438 `02847B60` 在 `02847F2E..02847FB6` 将锻造结果写入同一 `+78`。因此发放装备时固定强化范围为0..31、非负锻造范围为0..127，随机强化哨兵255仅留在资源定义中，不能直接写入实例。地址绑定本页匹配客户端构建，现有字段序列与条目长度不变。

品级seed由 `03FA9940` 及跳表 `03FA9994` 映射百分比：999999993→20%、999999995→80%、999999996→40%、999999998→100%、999999999→60%；当前普通创建默认999999998。该映射只证明实例seed的含义，选择礼包 `[booster equipment grade]` 数值到seed的规则仍未确认，不直接套用品级序号或稀有度。

Actor穿戴摘要后的宠物字段为 `templateId:u32 + name:DSTR(CP936) + enabled:u8`。匹配ARAD.exe SHA256=`3941E531FDC62C11B38149A767ACBED09F056443C5C6BE21C129E6B95AEBA329` 的当前运行代码中，`0267B3DD → 02E5A6B0` 将物品模板转换为宠物运行类型；`0267B425` 对末字节取反后，经 `02A8E040` 写入城镇宠物禁用位，零会令 `02CD6FA0` 跳过场景挂接和更新。该字段不能命名为deadFlag或固定写零。`0267FFBC / 026819B7 / 02BAF647 → 02B6B030` 使用声明创建或移除Player+657C实体并设置普通宠物component。Builder从Equipment槽26的真实实例和Creature.Name取值，有完整宠物详情时enabled=1，无穿戴宠物时为0/空名称/0；模板不是详情UID，空名称由客户端资源提供默认显示。105只建立UID详情映射，102只操作已经存在的穿戴实例和component，二者不能替代Actor实体声明。102的等等级分支不执行升级刷新，因此不能通过伪造更高等级触发召唤。该语义绑定上述构建，其他构建需重新确认。

## 名册与 Actor 装备摘要

## Player 普通装备

`USERINFO subtype1` 由 `023C3A90` 消费。普通条目先26B：`slot:u8 + itemId:i32 + value:i32 + attr:u8 + durability:u16 + unknown3:u8 + unknown4:u8 + unknown5:i32 + enchantCardId:i32 + enchantUpgrade:u8 + amplifyType:u8 + amplifyValue:u16`。两个资源属性当前为零，unknown5 当前投影 SealFlag；非零含义待对应封装/特殊装备流程确认。

资源 helper `028F2A30/028F2A80(mode=3)` 只对特定时装资源插入RAW30/RAW4，资源对象+500<=0B；资源enum1A还额外读u32。这些条件枚举与本版普通装备区分，不能用另一个版本的宠物编号替代。普通装备后续为：

1. Chronicle count:u8，每项 `id:i32 + job/grow/equipmentType/number:u8`，8B。
2. expireTime:i32；emblemCount:u8，每个 emblem:i32。
3. Rune:u16，由 `023C3F7C → 024B2D60` 的嵌套读包消费。
4. Random count:u8，由 `023C3F88 → 022913F0` 消费；数量零仍占1B。每项为 `type/value1/value2:u8`，交错排列。数量非零后读 `state:u8 + changedIndex:u8`；changedIndex不是FF时再读 `changeState:u8 + changedType/value1/value2:u8`。与123B结构的固定数组不同，不能省略这段或无条件补六个状态字节。
5. 上表87–96的10B尾部。
6. 五个RAW块，顺序4/8/4/5/4B，第二个与第三个之间另有一个u8。对应 `023C4064/4078/4095/40A1/40AD`；RAW数据与Core的97/101、110、114、119–122对应。

普通初始条目91B，非空 Chronicle/Emblem 每项分别加8/4B；Random非空增加3×数量，再加2或6B条件状态。整组装备后仍需 `scalar:u32 + extraCount:u8 + i32[extraCount]`，不能把这5B并入最后一件或省略。Player总长=`167 + 6×技能数 + Σ装备条目长度`；初始五件为`622 + 6×技能数`。所有字段见统一 Writer；原始读取、扩展对象宽度及 RAW 原码对拍不代表未知属性效果已完成。

必须追踪嵌套helper的读包副作用。省略Rune和Random数量会使每件少3B，普通零属性下第二个RAW长度被错读为2048，继续读取即可能在第三个RAW的memcpy越界；整体长度断言或单独RAW函数对拍不能发现这个缺口。当前C#回归按上述嵌套消费顺序检查五件初始装备及非空随机属性，不只检查Writer计算的总长。

## 移动与穿脱 CMD19

普通发送出口 `021586E9..0215883A`、`029D3826..029D3967`、`029CB13A..029CB269`、`029DA3E3..029DA71C` 使用 category1/opcode19，完整body28B：

| offset | 字段 |
|---|---|
| 0 / 1 / 3 / 7 | sourceList:u8 / sourceSlot:u16 / sourceItemId:i32 / count:i32 |
| 11 / 12 / 14 / 18 | targetList:u8 / targetSlot:u16 / targetItemId:i32 / targetCount:i32=0 |
| 22 / 26 / 27 | actor:i32（普通路径-1或本地索引0）/ flag0:u8=0 / flag1:u8=0 |

count=0整件/整堆，穿脱数量1，拆分为指定数量。服务端数量兼容规则为：普通装备一律1，堆叠的非正数或超出现有数量归一为整堆。同模板合并不截少本次数量；整件/不同模板整堆交换成功的moveCount为1。数量归一及锁策略属于业务规则，不能反过来当作客户端已实发这些边界值的证据。两侧 itemId 均为该槽的模板编号，空格为0，不是 Core.Value 的品级 seed/堆叠数量，也不是实例 UID 或请求 ID。发送端 `029DA48B..029DA4D6` 和 `029DA5C5..029DA613` 从物品资源 `+0x14` 取编号；堆叠路径同样读取资源编号，数量另行编码。

source/target 表示请求中的第一/第二格，不能直接当作物品移动方向。卸装时客户端仍将 Main 放在前、Equipment 放在后：第一格为空时，服务端从第二格取出物品放入第一格。必须先按原顺序核对两格 itemId，再解析移动方向；否则重复的穿戴请求可能被误解为卸装。两格均有物品时按兼容属性合并或整件交换，双向检查容器范围与穿戴资格；保留完整核心及 UID。

实收卸装请求：Main9为空，Equipment16为模板12400，数量1；该装备 Core.Value 为999999998，不能用于请求校验。

```text
S2C19成功: 01 00 09 00 01 00 00 00 03 10 00
```

装备从背包拖入快捷栏也会把空格放前面。实收Main21的模板18400拖至Main3时，count=0表示整件；不能因快捷栏曾只允许消耗品而拒绝。该请求及成功格式已纳入C# TCP回归，并验证重选/服务重启后的完整列表仍保留快捷栏位置：

```text

S2C19成功: 01 00 03 00 01 00 00 00 00 15 00
```

ACK注册 `0237BF54 → 02372610`。成功11B=`01 + sourceList:u8 + sourceSlot:u16 + movedCount:i32 + targetList:u8 + targetSlot:u16`；失败5B=`00 + error:u16 + sourceList:u8 + targetList:u8`，列表追加消费见`02373888`。普通移动及穿脱保留原请求顺序；Main→Equipment 消费分支 `02372E81 → 029D0880` 用两格处理穿脱，不能把卸装ACK改成反向列表顺序。可堆叠物品跨容器自动选格则回复实际移动方向和最终槽位，不能仍回显未使用的请求空格。`02372683..023726B5` 读取成功字段；任一列表为2/12时经 `02372A91 → 023734D1` 进入仓库存取分支，按ACK列表/槽位调用 `029089D0` / `02908AC0` 定位容器和物品，`02373517..0237353A` 将源槽、数量与目标槽交给转移调用。该证据确认字段用途，不代替客户端界面验收。

提交后才回成功。Main→Main的整堆移动与交换只发送ACK19；拆分/合并在ACK后发送完整Main NOTI13同步实际绝对数量，耗尽的物理源格先用NOTI14的itemId=-1清空，不在该差量中补入正数物品。完整载入后恢复全部Main锁状态。

Main与普通Equipment槽12–25的穿脱、替换在ACK19后将Main的清槽和完整写回改为NOTI1681，正文仍为`list:u8 + count:u16 + entry[123]`。返回Main的装备先用itemId=-1清除ACK已放入的对象，再写完整正数条目；服务端旧Main槽为空或两件装备同模板也不能省略清槽。`023BEC30`先查本地槽对象，已有同模板时只更新属性，空槽才调用`029CFDD0(...,1,1)`装载；`029D001F..029D0033 → 020C5840 → 020C5630`据装载标志标记图标effect。纯穿上后的Main空槽仍只发空条目。`023C08D0`临时清除`0620A11E`并调用14的同一解析器；`0292A40E/0292A447`据此跳过获得处理，包括dstr1179的获得物品文字及关联反馈。1681不设置完整载入标志`062CF69C`，不能把无获得通知解释为无图标effect。清槽后的正数条目仍携带强化、附魔、增幅、锻造、符文、随机属性状态及变换预览，不退化为ID/数量；Player继续使用本页完整嵌套读序。合法首次穿戴只可改变普通交易封装的SealFlag，不丢弃随机属性。普通穿脱仍保留模板替换、完整属性、外观和锁同步；仓库存取、特殊容器移动及真实发奖继续使用普通NOTI14。

ACK19同容器分支`02372969..0237298F`只将两格交给`029D0650`，没有传入movedCount，不能以ACK代替拆分/合并后的数量同步。NOTI13的`023BDDF0`在载入前后分别设置/清除`062CF69C`，新建条目调用`029CFDD0(...,1,0)`，不走差量的获得参数；Main载入可能保留快捷格，因此仍须显式清除耗尽源格。只有数量实际变化使用完整载入，普通整堆移动不每次重建列表。

CMD19的普通装备、装扮、勋章穿戴槽由ACK处理，不重复发列表3；宠物26及宠物装备27–29保留专属列表3差量，宠物变化先发105详情。穿脱后Town/MapSelect发本人Actor→Player；Dungeon/Settlement普通换装只发Player，真实26或幻化33实例变化时追加保留成员状态1的Actor→Player。城镇公共Actor与穿戴槽锁恢复继续使用提交快照。字段宽度和请求端点顺序保持不变。

当前普通物品校验拒绝使用 error23=`17 00`，`02373AB2 → 0x89BD` 显示“无法移动该物品”。error1在 `02373AC3` 的普通城镇分支取 `0xADB4`，显示“当前地区无法进行移动”，仅保留给会话/场景拒绝；error4取`0x5598`为“金库空间不足， 无法放入物品。”，不能当通用背包错误。文本来自匹配 dstr.dat，不将其他协议的同号错误码套入此响应。

## 丢弃 CMD18 与整理 CMD20 的 protobuf

`0041CA50` 只对18/20返回true；公共ACK分派 `028F85F6..028F8761` 因此跳过它们失败时的公共u16错误码。不能把其他CMD的 `00+error:u16` 套到这两种响应。

C2S普通丢弃与整理使用 `length:u32 + protobuf[length]`，发送链 `03BDFC70 → 03BDFA20 → 03BDF7E0`。技能材料扣除的CMD18另在消息后写 `clientState:u8`，不计入length；该状态字节原样保留，尚不作为消费资格或去重依据。S2C使用 `success:u8 + length:u32 + protobuf[length]`。字段均为protobuf tag number，不是固定偏移：

| 消息 | 本版字段 | native依据 |
|---|---|---|
| Sort请求 | 1=opcode20可选；2=list；3=page/itemKind；4=condition | ctor004142E0、serializer00414370、parser00416270、sender029D4B50 |
| Sort返回 | 1=list；2=error | ctor00414260、serializer0041D880、parser00416000、callback0234AC00 |
| Delete请求 | 1=opcode18可选；2=list；3=repeated子项；4=flag | ctor004148C0、sender02148CC5..02148EB8 |
| Delete子项 | 1=deletionType；2=slot；3=sourceValue；4=count | serializer0041DF70、parser00415C40 |
| Delete返回 | 1=list；2=repeated结果；3=error | ctor00414580、callback02364DD0 |
| Delete结果子项 | 1=slot；2=removedCount；3=type | ctor004141E0、02365089组装槽/数量，02365277交给删除路径029D3E40 |

Delete子项3与Move的模板编号字段不同：`02148D61..02148DE5` 从物品虚方法`+28`返回对象的`+18`取实例value，经内部helper写入子项`+1C`；保留品级/数量校验。普通丢弃按[业务规范](../模块/背包与装备.md)归一数量，ACK回传本次实际删除量；非正数或超额请求表示整堆时，返回被删除的整堆数量。对排序条件不适用或未知的情况回退该页默认排序。

## 排序锁与装备安全锁

以下均属于本页 S5A9 匹配输入。C2S category=1 的五个请求统一为 3B：`list:u8 + slot:u16`。发送端 `036F3A42..036F3A92` 选择装备锁三个 opcode，`036F3A9C..036F3B17` 选择两个排序锁 opcode，均通过 `03BDF720/03BDF750` 依次写列表/槽位。排序锁设置与解除是独立操作，不把重复设置解释成开关翻转。

S2C ACK category=1：公共分派先读 `flag:u8`，flag=0 再读 `error:u16`；以下均不属于 18/20 的 protobuf 例外。

| opcode | 操作与消费者 | 成功 body | 失败 body |
|---|---|---|---|
| 267 / 010B | 加装备锁，`0234E450` | `01 + list:u8 + slot:u16` | `00 + error:u16` |
| 268 / 010C | 解装备锁，`0235B620` | `01 + list:u8 + slot:u16 + remaining:i32` | `00 + error:u16 + remaining:i32` |
| 269 / 010D | 取消解锁，`0234E540` | `01 + list:u8 + slot:u16` | `00 + error:u16` |
| 713 / 02C9 | 设置排序锁，`0233DB60` | `01 + list:u8 + slot:u16` | `00 + error:u16 + reserved:u8` |
| 714 / 02CA | 解除排序锁，`0233DBC0` | `01 + list:u8 + slot:u16` | `00 + error:u16 + reserved:u8` |

排序锁成功分支直接将实例 `+0x2FA` 写为 1/0；失败在 `0233DBAE/0233DC0B` 还消费一个字节，当前填 0。装备锁和取消解锁成功写状态 1；解锁成功先写状态 2 并读取 remaining。当前立即解锁策略使用 remaining=0，紧跟 NOTI252 清除状态，不能只发解锁 ACK。业务拒绝码为 17（交易后删除称号）、19（无效目标/状态）、21（空槽）、22（无空闲锁 ID）；不能复用移动 ACK 的错误语义。

S2C category=0：

| opcode | 消费者 | body |
|---|---|---|
| 251 / 00FB `ITEM_LOCK_LIST` | `0239CA80` | `count:u16 + {list:u8 + slot:u16 + state:u8 + [remaining:i32，仅 state=2]}` |

严格原机器码回放在实际库存查询 `02908AC0` 前停止，成功 ACK 分别消费 3/7/3/3/3B 后缀；装备锁/解锁/取消的失败后缀消费 0/4/0B，排序锁失败后缀消费 1B，单项状态 1 的 NOTI251 消费 6B，NOTI252 消费 3B，cursor/remaining 一致。回放不替代库存查询或伪造客户端状态，证明的是读取宽度；界面效果仍需实机验收。

## 时装漂染 CMD498

匹配ARAD.exe的`0279AAA0`写opcode498及两个i16槽位，正文恰好4B：`MainSlot:i16LE + AvatarSlot:i16LE`；实际`4A 00 00 00`表示Main74与Avatar0，不是物品编号或独立详情UID。发送不携带颜色，服务端从该源STK的固定`[dye info]`读取并核对当前颜色表。

回调由`04F960D0..04F960E3`注册`498 → 0279AB80`。公共success为1后，`0279ABD7..0279AC70`读取目标槽u16，通过Avatar列表定位既有对象，装载`RAW4 = length:i32(4) + color1:u16 + color2:u16`并刷新颜色；成功正文合计11B。珊瑚色、目标槽0的正文为`01 00 00 04 00 00 00 01 00 00 00`，不能只发成功位或完整物品条目替代该附段。失败采用公共`00 + error:u16(0)`，当前未确认细分498错误码；回调无论成功与否都清理漂染等待窗口。

成功发布前先提交实际颜色及源扣除，然后同步源NOTI14，再发ACK498。目标不另发NOTI14：ACK会原位更新颜色并将该对象交给结果窗口，不能再重建对象打断引用。其它核心、RAW30孔位与实例期限不参与改写，重连仍由NOTI13中的完整165B条目恢复。`[enable dye]`第一项对应第一部位：客户端`02938BE0(0)`读取模板标志；STK类型和颜色表解析线索分别为`0414E368/0414E3A0`及`042A47A2`。`df_game_r Dispatcher_UseDye`仅对照城镇、固定颜色、源删除与颜色保存业务，不采用其opcode499作为本版包号。窗口、动画及实际渲染需实机验收，业务规则见[时装漂染](../模块/背包与装备.md#时装漂染)。
