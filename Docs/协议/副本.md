# 副本协议与证据边界

目标为 S5A9 x86 客户端，资源结构见[副本目录](../资源/副本目录.md)。当前C2S15已提供ACK及空NOTI27打开选图；C2S16的匹配25B普通单人请求已接正式Session；资源、owner和事务前提齐备才发送完整NOTI28/29，加载、原生统计死亡、成长、过房、Boss确认、通关经验及免费/付费翻牌已接入；奖励和会员资格沿[单人副本实例](../模块/单人副本实例.md#通关经验与翻牌奖励)的库存与持久回执合同提交。默认关闭的开发诊断可按阶段发送候选初始化通知，用于运行态取证。本文保存请求索引域、入口资源、成功通知的真实读宽及后续解析边界，不把静态分析或资源存在写成实机验收。

## 角色死亡与复活币

下表属于 S5A9 / V31.0.24.0 x86 的 Direct12 Full03 冻结客户端，数值为 little-endian 正文。external 的死亡、提交后复活通知与钱包消费流程仅作为业务参考；本版 ACK41 有额外角色 key，不能复制 external 的 `01 00` 正文。

| 方向 / opcode | 正文 | 匹配原生读取或发送依据 |
|---|---|---|
| C2S class1 / 40 `DIE_CHARACTER` | `x:u16 + y:u16`，4B；普通角色另带 `context:u16`，6B | `031AB7A8..031AB7DE` 是4B发送分支；普通角色 `02B6D4FF` 选择40，坐标后 `02B6D65B → 02B6DAFB/02B6DB02` 再写u16。现场正文 `74 00 04 01 00 00`，额外字段不推断枚举 |
| C2S class1 / 41 `USE_COIN` | `targetKey:u16`，2B | `01C27407..01C27425` 选择41，调用一次2B写器；`00427D20` 的40/41选择项都返回0，不追加通用正文检查值 |
| S2C class1 / 41 成功 | `01 + targetKey:u16 + flag:u8=0`，4B | 注册 `0233B5B6 → 02334950`；成功分支 `0233496B` 读u16、`0233497A` 读u8。公共成功字节由外层分派消费 |
| S2C class1 / 41 失败 | `00 + error:u16=1`，3B | 公共失败前缀；本版失败分支 `02334D46` 不追加正文读取 |
| S2C class0 / 32 `DIE_STATE` | `actorKey:u16 + state:u8 + flag:u8=0`，4B | 注册 `02398123 → 02386690`；`023866D4/023866E2/023866F7` 依次读取2B/1B/1B。state0为死亡、1为正常满血蓝复活；state2进入同一复活分支后将HP/MP设为各自最大值的三分之一，跳过普通扣币处理 |
| S2C class0 / 228 `REVIVAL_CHARAC_TIMEOUT` | 空正文，0B | 注册 `023CCEF7..023CCEFC → 0239C8F0`；消费者不读包体，经`0420FC90 → 025F2360(0x60)`清理神圣祝福效果 |

复活币成功包序为 ACK41 → NOTI32(state1) → NOTI14(Main槽1，itemId1，绝对余额)，余额为0时仍保留虚拟钱包行，不清空为FFFFFFFF。必要任务条件通知跟随余额。40没有通用成功ACK：普通死亡发NOTI32(state0)，有效神圣祝福在消费单次资格后发送NOTI32(state0) → NOTI32(state2)，不发41或钱包差量，也不启动死亡回城计时。这与`df_game_r`的`CParty::die_user(085A7828)`先后调用`set_charac_live(0/2)`一致；仅借用业务顺序，32正文使用本版4B而非旧端3B。单独 ACK41 不替代角色复活状态；普通资格及事务见[副本模块](../模块/副本.md#角色死亡与复活币)，祝福资格见[特殊药剂](../模块/背包与装备.md#持续效果与特殊药剂)。

药剂自身使用成功仍由ACK44启动本地效果。原生`CAlchemist::UseRevivalItem(085D1694)`设置`now+1200秒`，`TimerRevivalCharac::dispatch_sig(08638E78)`到期复验原截止后发送228；再次用药会覆盖截止。`GameWorld::out_from_dungeon(086C6A16)`清零资格。到期228不携带剩余时间、itemId或角色key，不借41扣币/应答，也不能用普通174恢复包代替。当前实现沿同一截止与实例校验发布，已消费、回城或换角后的旧通知不得影响新角色或新资格。

死亡后10秒仍未成功复活时沿既有 `NOTI24` 城镇转移正文返回，随后刷新任务；不发送ACK40或ACK42，包序参考 external 的 `dungeon_death_return.go` / `dungeon_return_town.go`。死亡窗口现场抓到的购买正文为 C2S64 的19B `00 00 01 00 00 FF 00 A4 86 01 00 00 00 00 00 00 00 00 00`，商品号100004。使用既有[商城购买响应](物品.md#商城购买响应)，成功ACK64后发送复活币槽14及点券53；购买不自动替代41复活请求，也不延长死亡计时。

## 退图虚弱确认

匹配ARAD的dstr `38254`（`956E`）为放弃副本后的虚弱警告。客户端在发送退图请求之前独立决定是否打开该确认窗，不等待ACK42，也不直接读取服务端的`DisableGiveupPenalty`。将本人Stamina百分比投影为100或在服务端跳过保存惩罚，不会自动关闭这一提示。

主入口`0263FD80`的case3在`02640886..02640891`检查本地惩罚条件，并选择该dstr。已闭合的条件包括下表；其他活动、模块状态与特殊副本仍有独立过滤，不据此声称已恢复全部退出玩法。

| 输入 | 原生消费者及含义 |
|---|---|
| 角色等级 | `02640246`读取角色Data+14的编码等级，`026402AD`要求等级至少20；不是旧版参考服的18级门槛 |
| PC房特权 | `026402CB..0264035B`读取Data+33C，非零不走该警告；`02677320`的原生名称为`CNRDUserInfoPacketHandler::readPremiumPcRoom`。黑钻外观由`02677430`写Data+344，是不同字段，主判定不以它替代PC房位 |
| 练习及副本上下文 | 练习模式和其他场景条件可清除惩罚提示条件；主入口还通过`02673060/02673790`检查副本类型，其中类型2和3分别读取当前定义的古代、异次元标记 |
| `[no giveup panalty]` | `040A5863`将原始DGN+B1C置1，`02A374FF/02A37506`复制到Runtime+AA0；`029FF650`返回Runtime+180，因此`026405C6/026405CF`读取定义+920并清除惩罚提示条件 |
| `[enable give up]` | `040ABAFF`写原始DGN+FF0，`02A37C50/02A37C57`复制到Runtime+CC2，即定义+B42。`026407FF..02640846`将它用于另一退出条件，不直接清除主惩罚条件，不能仅凭此标记推断客户端免虚弱 |

另一引用位于`0398E060`的case150：`03990206..03990232`检查当前Runtime的E74状态位；状态非零转入另一处理，否则选择同一dstr。该路径没有复用上述完整角色判定，因此某处确认窗不显示不能证明所有退出入口或服务端罚则一致。

服务端使用同一20级门槛，并通用支持`[no giveup panalty]`；原有扩展免罚词条继续按[本服退图规则](../模块/背包与装备.md#魔王契约八项服务)独立生效，不因普通类型或其他关闭标签抵消。黑钻仅写[Actor的黑钻外观位](角色与入城.md)，不再借用`PremiumPcRoom`隐藏警告：普通副本可能仍弹原生确认窗，但有效黑钻实际退图免虚弱。网吧身份由独立的[全局GM开关](../开发/GM.md)控制，同时用于服务端本次退图免罚；只有网吧位能在上述PC房分支免除警告。此实现不改客户端指令，也不通过空白dstr、伪造练习模式或副本完成状态隐藏确认窗。`[no fatigue]`仅控制Fatigue疲劳值，不代替Stamina虚弱资格；扩展清单不表示本地PVF及所有客户端退出入口具有完全相同的提示过滤，相关画面与分支仍须单独验收。

## C2S15请求与索引域

C2S15为category=1、opcode15，body恰为一个u32。发送构造器 `03BDF610`设置信令，`03BDF780`追加u32，`03BE0FF0`提交发送。非零值的已确认路径使用匹配 `dungeon/dungeon.lst` 的指定副本索引；零值是另一种入口请求路径，不能解释为选择Dungeon ID 0。请求进入Parser后保留完整u32，Session另行校验入口、角色状态及有效owner，不能把世界地图列表索引当作此字段。

界面路径在 `01E0D421` 调用 `039EC2F0` 读对象 `+754`：值为1时，`01E0D47D..01E0D499`发送0，随后调用 `03B9D9F0(0)`；值为0时，经 `01E0D50D → 039EC310` 读取同对象 `+758`，发送该值并进入 `03BB9A90` 的指定内容路径。零值路径的全部成功行为及适用入口尚未确认。

非零字段的来源已闭合到匹配列表：

| 步骤 | Main VA及作用 |
|---|---|
| 加载列表 | `0292ECD8..0292ECE7 → 04082420`传入 `Dungeon/`、`Dungeon.lst`；`040824B6..040824C2`把列表装入对象 `073B8CE0` |

## NOTI5地下城权限通知的读取边界

Class0/op5在`023980D1..023980E0`注册到`0237D320`。正常正文为`count:u16 + (dungeonId:u32,value:u8)*count`：`0237D331`读取数量，循环`0237D3B6..0237D49C`分别调用u32及u8读器，`0237D48B→022ECF00`更新客户端表。数量FFFF沿特殊提示分支把循环数量清零，不是全图开放标志。

`022ED0B0`查询同一状态及资源默认分支，选图消费者`03BA87E5..03BA880A`将返回值与选图对象`+468`的有符号值比较；该字段、资源分支和全部value的业务映射尚未闭合。当前正式流程未用该通知覆盖选图资格，不把缺少NOTI5直接认定为普通地图无法选择的原因，也不构造统一value解除任务、等级或资源门禁。

## ACK15成功与失败

Class1/op15在 `02349E73` 注册到 `02348ED0`。公共ACK分派先读取成功u8；失败另读错误u16。handler在 `02348EFD` 检查传入成功标志；非零跳到 `0234948E` epilogue，不追加包体读取，也不写入口对象 `+78`。因此成功ACK的handler部分不要求额外字段，但成功flag不能替代后续NOTI27选图通知，也不能把入口状态从 5 改成 8。

失败分支因错误码不同可能继续读取额外字段；已确认样本 `00 01 00` 沿错误1清TownScene等待状态。当前有效选图请求若资源没有合法安全返回点，使用这一已确认的错误1正文拒绝并保留原连接和选择状态；C2S15长度或会话状态不符仍抛出结构/状态错误并关闭连接。当前成功字节只表示选图入口应答，不表示副本准入或实例创建；不得将所有失败码套成同一3B。

### 当前选图应答与排队C2S16的边界

指定路径的原码顺序是 `01E0D51F → 03BE0FF0` 提交C2S15，紧接着在同一调用内准备 `-1、0、0、039EC320返回值、0FA1` 五个参数，于 `01E0D550` 调用 `03BB9A90`。对应区间为 `01E0D4F2..01E0D555`（99B）。caller没有等待应答，但callee仍可能因资格拒绝而不发送16；它证明合法前置成立时16可能在ACK15到达前排队，不证明每次15后必有16。

当前服务端行为：

- 已就绪且已选角的4B C2S15建立MapSelect及本次返回上下文，退出城镇同屏；先回ACK `01`，再发本人NOTI3 `state=1`；正文u32为0时追加42B全零NOTI27，非0不重发列表。重复请求保留原返回点，活动已占用场景时不重新开选图。匹配客户端左入口已观察到正文0，开始冒险已观察到正文3。上述应答不改变位置、revision或任务，也不创建副本实例；取消路径见[选择界面返回城镇](#选择界面返回城镇)。
- C2S15长度错误、未就绪或未选角属于结构/状态错误，关闭连接；当前并不返回失败样本 `00 01 00`。
- 默认配置下C2S16由DungeonHandler接入任务显式路线准入，实际持久角色owner/任务及资源资格成立时预留身份，再发送NOTI28/29；入场不以职业、转职或双树初始化作门禁。准入拒绝见下文完整静默ACK16合同，未知宽度仍unhandled。具体行为见副本模块，通知不等于实机验收。
- 隔离TCP验证上述包序、无虚假ACK16及后续连接行为；实际进图还需要NOTI28/29、加载完成和实例生命周期的独立验证。

入口路径 `01E0D400` 读取 `[[062EF53C]+FF9C]+754`：等于1时发送C2S15正文0；等于0时使用同对象 `+758`，随后调用 `03BB9A90`。因此仅看到正文0且没有C2S16，不能反推 `+754==1`：另一分支也可能因资格不满足而未发16。`01E0D555` 把入口对象 `+78` 写成5；状态分派 `01E0E86C/01E0E974` 的5、6分支不自行推进状态。`01FCBFF0` 在虚表 `+AC` 调用中写入状态参数，状态7路径 `01E0E720` 可请求状态8；这些原生状态不能由成功ACK替代。

### ACK16读取与恢复边界

ACK16为category=1、opcode16。成功正文为 `01`；它只确认请求应答，地图与怪物初始化仍由后续通知完成。

失败正文的已确认前缀为 `success:u8=0 + error:u16 + memberSlot:u8`。成员槽为0–7的队伍成员索引，用于部分提示中的成员名，单人使用0。

当前普通单人准入拒绝使用完整正文 **`00 09 00 00`**。错误9静默处理，并进入客户端既有的失败状态恢复；服务端保留选图与原返回上下文，让玩家继续选择或返回城镇。其他错误分支的间接读取和完整正文尚有待确认部分，不能统一套用四字节包体。完整客户端恢复效果仍待实机验收。

## 过房与怪物死亡的字段

C2S45 的已确认普通路径为 **100B**，前两 byte 是目标格 x/y；其后两个 u32、u8、u16、八个 u16、八个 u32、u16，`01DE2560` 再追加六个 u16、u32、三个 u16、u64、u32、u16，最后 u8。偏移85..92的u64不能漏计成92B请求。Parser保留未解释字段，不把这些统计值当伤害或通关资格。

普通怪物和APC的C2S39统计正文为`74 + 14 × count`字节，参与者数量为1–254；单参与者是88B，两参与者是102B。前缀为对象key:u32和上层报送上下文:u16，贡献列表与尾部布局见下文。其他发送点保留各自格式，不按此统计形状统一解析。

匹配 S5A9 客户端的定向运行代码已补齐 `02B52FE6`、`02C5AA0B` 两条生产者。公共前缀依次为 `key:u32、reporter:u16、Unknown6:u64、Unknown14:u32、Unknown18:u64、Unknown26:u32`。`02B52FE6..02B5305E`、`02C5AA0B..02C5AA70` 的原码已分别核对；后者当前直接调用包体 writer，不再依赖早期记录缺失的映像外入口。

偏移30为参与者数量u8；每行是`kind:u16、objectKey:u16、CumulativeHpDecrease:u64、PositiveHpDecreaseCount:u16`，14B。循环写宽分别在`02B533D0..02B53493`和`02C5AE02..02C5AEC3`核对；原生数量上限为254。Parser按完整长度保留贡献者原序和所有u64高位，尾部从`31 + 14 × count`开始，共43B。报送上下文独立于贡献列表；列表首项不表示最后击杀者，列表也可以只有APC贡献。

普通发送者在`02B52FD4`将Reporter初始化为`FFFF`；上层上下文为空时直接保留该值，非空时才调用`02B64480`读取上下文`+6DC8`。该分支在贡献数量和行循环之前，因此`FFFF`也可出现于包含本人或多个来源的报告。来源kind由对象虚表`+44`取得，`0211`已有实收且对应实际发布的普通monster；APC发送者另可在`02C5AD79`由虚表`+48`分支写`F111`，其值不等同于友方阵营。S5A9保留Reporter及全部kind/key来源值用于审计，不以来源类别、key、阵营、房间或本人参与设置死亡门槛。

真正当前HP setter `02AFC260`在`02AFC30A..32B`计算旧值减新输入的正64位差，调用monster虚表`+A28 → 02C4A1B0 → 02B159A0`，按归属来源累加目标实例`+3AF8`的HP降低量和`+3B30`的正降低次数。`02AFE270/02AFE160`读取它们形成参与者数据。统计发生在夹取之前，允许overkill；累计量不能命名为死亡时当前HP，也不能要求恰等于初始HP。

同一普通sender的27B统计尾由`029083A0`写入，count1形状中偏移55为`RewriteFlag:u8`、56为`SpawnLevel:u32`、60为`SpawnHpSnapshot:u64`。快照来自创建链`02A0B354..36F`调用同目标对象当前HP getter，并保存到`this+1140/+1144`；它是创建HP快照，未恢复服务端独立最大HP公式。68..81的七个u16及82/83尾byte继续按原字节保留。

`RewriteFlag`区分客户端写入前缀统计的方式。它不是服务端改写包体的开关，也不单独赋予Boss身份。服务端保留标志原值，不以其取值限制当前敌对活对象的死亡。已恢复的客户端统计字段含义如下：

|---|---|---|
| `Unknown18:u64` | 该怪物全部来源的累计HP降低量加`random % 200` | 改写中间量`V`加`random % 200` |
| `Unknown26:u32` | 该怪物全部来源的正HP降低事件次数 | `max(1, floor(V / 300))`，属于派生次数 |

客户端Boss改写链构造中间量`V = 最大HP + random % 10000`，再写入`Unknown18 = V + random % 200`及`Unknown26 = max(1, floor(V / 300))`。这些原码含义用于解释报告，服务端不检查公式相容性，也不比较总量、本人量与创建HP之间的大小关系。稳定死亡事件与经验/掉落去重由正式Run及事务账本保障，经验使用服务端生成计划等级。

末4B是通用发送前处理为opcode39追加的正文检查值，与技能包共用[MD5折叠公式](客户端通知.md#普通单人技能使用记录)，输入为此前全部正文；88B样本的检查值仍在84..87。历史88B及实收102B样本用于布局和检查值对拍，不能替代客户端验收。Parser只报告`BodyChecksum/ChecksumMatches`，不因不匹配改变诊断长度接受行为。结构解析和诊断通知不签发`ConfirmedDungeonMonsterDeath`，不提交成长或资产奖励；Unknown6/14保持未知。

匹配原码 `02395310` 的 NOTI38 零掉落普通路径读取 `key:u16, dropCount:u16=0, optionalFlag:u8=0, mode:u8=0, grade:u8=FF, extraFlag:u8=0, deathFlag:u8=0`，共9B。key=256示例为 `00 01 00 00 00 00 FF 00 00`；grade=FF跳过grade更新分支，不附ACK39、掉落或经验通知。早期原生记录含不完整的映像外前置调用，不能把其局部u16直接当作完整包证据。
