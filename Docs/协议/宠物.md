# 宠物协议

## 宠物跨界：CMD557

当前ARAD的发送器`024C6450`发送9B正文：`sourceMainSlot:u16 + targetPetSlot:u16 + mode:u8 + recipientRosterIndex:u32`。宠物为mode1，隐含目标容器7；实际样本`52 00 10 00 01 02 00 00 00`表示Main82、Pet16和原始名册第2行。`024C86C0`遍历完整名册时跳过当前角色，但保存原始行号作为选项值；不能把它转换为角色ID或持久槽位。

注册处`04F90EB0`将557绑定到`024C8250`。消费者无论成功失败都释放操作57的临时等待并关闭确认窗715。公共分派读结果标志和失败u16后，成功分支再读取四个u16和一个u8，因此本服成功ACK为10B：`1:u8 + sourceSlot:u16 + targetSlot:u16 + sourceRemaining:u16 + 0:u16 + mode1:u8`。第三个u16是源绝对剩余数量，不是本次消费量；数量为0时由原生分支删除源槽。mode1只显示结果提示，不负责清理Pet目标，故成功ACK之后还需发送Pet14清槽；不能复制其他版本“仅刷新列表、不发ACK”的实现。

失败为`0:u8 + error:u16`，已核对`7`不可转移、`17`道具不存在、`21`无法使用、`214`物品锁定；其他跨界模式保持明确拒绝，不假装成功。成功回执发布须仍属于原generation、角色和选角epoch，网络失败不重跑已提交资产操作。常规源数量由ACK同步，不重复发送源减量；超出u16显示范围时以已提交完整库存行校正，不裁掉实际资产。业务资格、邮件托管和原子保存见[宠物跨界](../模块/宠物.md#宠物跨界)。

本页绑定S5A9匹配ARAD.exe的已确认读写链。普通库存Core和详情布局仍见[物品协议](物品.md)，孵化请求仍见[宠物蛋孵化](宠物蛋孵化.md)。业务及未实现边界见[宠物模块](../模块/宠物.md)。不能用df_game_r或早期dfls的opcode、字段宽度替换本页。

`DSTR`为`byteLength:u32 + CP936字节`，不附加NUL。角色引用是`u16`，宠物UID是`i32`；两者不能混用。

105的名称由`0239F760`读取；Actor宠物名称由`0267B3B0`读取，`02CE6CF0`仅对空指针兜底，空字符串会覆盖显示名。服务端新实例保存CRE默认名（CRE空名回退EQU），按CP936完整字符限制30字节；旧装备空名补存后通过101更新。CMD100空名称恢复同一默认名，不再保存空字符串。无需改客户端或PVF。

## 经验胶囊与升级券

当前10005895的实收为CMD44、Pet=7、源槽189、参数0，正文仍是`slot:u16 + list:u8 + opaqueCheck:u32 + itemId:i32 + argument:i32`共15B。参数不含目标UID、经验或等级；服务端从当前装备槽26取得目标，按PVF的`[creature use item]`声明计算，不将未确认的1101枚举当作该道具入口，也不为这个PVF独有标签编造515动作号。

成功先回复44的完整12B，再发送NOTI102的普通模式6B绝对数据。ARAD的`02356A00`成功分支读取原源槽、容器、校验值与模板，经`029D17A0(slot,1)`消费源并清等待；`023A36B0`读入等级、模式和32位经验后更新当前装备宠物。因此不在ACK前后另发同源14重复扣除，也不借角色升级包。自动进化仍沿上述106/105/槽26差量。失败沿44现有完整12B中立收尾，不发空成功或错误命令的响应。原码核对及TCP包序验证与客户端实机验收分别报告；经验参数语义来自当前PVF，不宣称旧版df_game_r已包含这组新道具。

## 进化任务

本版QST解析`04198D4B..041991C3`把`[creature evolution]`保存为资源枚举20；该资源枚举不是wire结果模式。ACK34进化使用wire模式10，`02377B73`调用`02857F60(0)`且不读取额外字节。条件及经验公共头、寻物材料数组仍按[任务协议](主线任务.md)；模式10后不追加物品计数、宠物种类或旧版技能页。实际转换通过106、105与完整槽26差量同步。资源、存储和字节回归不证明客户端进化任务窗口已经实机验收。

## STK定向转换：CMD515 / Action64

`[action type] [change creature]`的已捕获入口是CMD515 `USE_STACKABLE_ACTION`、action64，不是CMD323。转换窗口发送器`024CC290`直接写入19B；`028687F0`的另一确认回调把目标持有域和槽传给通用发送器`028BA3F0`，使用同一布局，没有额外opcode或模板ID前缀：

| 偏移 | 类型 | 含义 |
|---|---|---|
| 0 | u16 | 进化道具源槽 |
| 2 | u8 | 源持有域 |
| 3 | u32 | 当前生产者固定写0 |
| 7 | u32 | action，当前路径为64 |
| 11 | u32 | 目标持有域；已捕获Pet=7 |
| 15 | u32 | 目标槽，不能当作UID或宠物模板ID |

目标可以是Pet背包中的非穿戴宠物；模板和UID须从当前权威槽位读取。490705419的当前资源以`[stackable action limit indexes]`限定源模板400990236，并在`[stackable action result limit indexes]`声明`0 400990451 10000`。这与CRE升级/亲密成长及QST进化是不同的业务入口，不能要求它先满足CRE进化等级或装备在槽26。

ACK515的原生消费者`028C0AE0`成功读取`success:u8=1 + sourceSlot:u16 + sourceList:u8 + action:u32`，共8B；失败在公共错误前缀后读取`sourceSlot:u16 + sourceList:u8 + action:u8`，完整正文共7B。action64沿`028BE970`默认分支消费源道具1件；`028BBFB0`的当前回调表没有action64专用读取器，已核对路径不追加目标槽、结果模板、剩余数量或宠物详情尾部。不能为了显示结果拼接旧端字段，也不能先同步源剩余量再让ACK重复扣除。

515唯一注册入口仍是[StackableActionHandler](../../Server/DfoServer/Network/Handlers/StackableActionHandler.cs)，先将64分发给[CreatureChangeService](../../Server/DfoServer/Game/Creatures/CreatureChangeService.cs)，其他任务券动作和回包保持原样。提交后先发8B成功ACK，再发Pet目标的NOTI14清槽、105完整详情、14完整123B物品行；123B包含槽号，不在其前重复写槽。源槽由ACK扣一本，不再补同一源差量；商店兑换材料不参与使用消费。不发106、Actor或Player来误改当前装备宠物。

资源解析`0414C3CF..0414C635`将限制列表保存为模板集合，结果表按`group + itemId + weight`三元组保存，并按group累加权重。10000为相对权重，不是另有失败区间的成功率；本轮仅接入已确认的第0组。固定转换的前两项为源/目标模板，宠物等级另取`[creature minimum level]`。转换窗口`024CDE40`用动作第三项选择提示样式；固定源/目标的第四项`-1`按原始永久兑换券说明执行永久转换，不用作等级或分组，其余未确认末项不猜测。已接入的原始声明及限制以[宠物模块](../模块/宠物.md)为准，自动回归不等于Windows转换窗口已实机验收。

## 转换组：CMD515 / Action107

`[creature growth]`经`040D4F60`的字符串映射返回107；`028C5980`将107关联到`028B7E60`，由参数首项选择777或778窗口，而非action108。`020F9D50`构造固定/随机请求，`020F7790`构造选择请求。共用前述19B格式，但两个参数与64的含义不同：

| 偏移 | 类型 | 含义 |
|---|---|---|
| 0、2 | u16、u8 | 实际道具源槽与Main=0 |
| 3、7 | u32、u32 | 固定0、action=107 |
| 11 | u32 | Pet背包目标槽，隐含容器7，不是模板ID或UID |
| 15 | u32 | 固定/随机为0；选择型为客户端选项下标加1 |

`020F78E0`和`020FAD50`按STK的组编号、后续类型列表、道具和源EQU依次查询；`0430C960`保留先类型后行的顺序。`0430E7C0`装载转换组；`0430C3F0`解释行首消耗和四类结果，类型3的源集合还包含全部随机结果，类型4同一列表既作为源集合又作为选择列表。`020F9AD0`不允许选中与当前源EQU相同的图标，107发送器也要求已选定有效下标，因此同属性重复提交不消费。选择窗按资源目标原序绘制图标，服务端不能排序或把1基选项当目标模板。

成功ACK107与64一样为8B，但`028BE970`对107明确返回0，客户端不消费源；失败仍为完整7B。已核对的`028BBFB0`回调表没有107专用尾部读取器，不追加成本、目标或随机结果尾字段。成功包序为ACK515→Main14实际源/材料差量→Pet14清旧模板→105详情→Pet14完整新模板；随机结果与原模板相同仍实际消费，目标零变化时不重复发送Pet通知。即使消耗30、50或100个，也只同步提交后的绝对数量，不用虚构的ACK18补扣。与64一样，不对Pet背包目标发106或装备Actor/Player刷新；业务限制及保存规则见[转换组道具](../模块/宠物.md#转换组道具)。
