# 结婚协议

业务所有权、费用及恢复规则见[结婚系统](../模块/结婚.md)。本页描述匹配S5A9客户端的已接入请求和通知；整数按小端序，名字和正文使用CP936。

## 请求与回执

部分客户端结构在网络头之外仍有13字节未解释前缀，Parser只按固定宽度跳过，不从中提取业务身份。无正文请求必须恰好为空；未知子型、长度、容器和尾字节拒绝。

| CMD | 业务 | 主要正文 |
|---|---|---|
| 1034 | 求婚、婚礼预约、解除及离婚 | 结构前缀后target:u32、operation:u8及两个子参数 |
| 1035 | 双方邀请回应 | 结构前缀后target:u32、operation:u8、reserved:u16、response:u8；ACK保留答复结构的保留字，不用原预约档位覆盖 |
| 1036 | 婚礼礼金 | context:u32、gold:u32、textBytes:u32、正文 |
| 1037 | 配偶角色卡 | 结构前缀后target:u32，0查询本人伴侣，非0查询该角色的伴侣；固定97字节卡数据，成功ACK共98字节，含配偶装备摘要 |
| 1038 | 升级戒指 | 结构前缀后itemSlot:u32、newLevel:u8 |
| 1039 | 使用心意点道具 | 结构前缀后itemSlot:u32 |
| 1040 | 发请帖 | 结构前缀后选项、目标、临时目标和目标类型 |
| 1041 | 礼堂入场 | 结构前缀后context:u32、礼堂区域:u32、flag:u8 |

| 1044 | 读留言 | 结构前缀后context:u32、mode:u8 |
| 1045 | 查询伴侣传送 | 结构前缀后context:u32、ticketSlot:u32 |
| 1046 | 确认伴侣传送 | 结构前缀后slot:u32、town/area/x/y各i32 |

| 1048 | 家具移动 | 结构前缀后两个slot结构，每个为container:u8、slot:u16、itemId:i32 |
| 1049 | 删除家具 | 结构前缀后slot:u16、itemId:i32、quantity:i32 |

| 1054–1056 | 制作、赠送、领取胶囊 | 无正文 |

共享背包容器为1，已摆放家具容器为0。1048跨容器摆放或收回时，源、目标结构的itemId都回显源家具编号，空目标也不填0；`01E3FB0F/01E3FB12`及`01E3D2E1/01E3D2E4`分别写入同一寄存器值。共享背包内部拖动`01E3B260`则写目标原物品编号，空目标为0。服务端按两种语义分别校验，摆放资格和交换、合并数量取提交前的真实共享资产，不将跨容器的编号回显误作目标占用证明。

通用婚房结果是`01 result:i32`，负值为业务拒绝；这不是未实现请求的成功占位。错误数值按各命令消费者解释，不能复用一套关系错误代替所有失败。成功1046仅`01`。1047再带close:u8；1054成功再带gauge:u32和owned:u8，1055带owned:u8，1056带taken:u8。

1048回调`01E3CFB0`的已确认错误映射如下；关系错误只用于真实资格缺失，不用于来源消失、错槽或编辑占用。该回调的容量分支使用DSTR21912，没有DSTR72839的独立分支；不能将后者编号直接当作result发送。

| 1048结果 | 本版ARAD提示 | 服务端含义 |
|---|---|---|
| -2（原生-3/-4也同提示） | 72853：没有搜索到伴侣信息 | 无有效已婚成员资格 |
| -13 | 21912：金库空间不足，无法放入物品 | 收回容量或堆叠上限不足，保留原家具 |
| -20 | 72798：您的爱人正在使用物品保管箱 | 编辑权由另一有效会话占用；未打开编辑窗口不冒用此提示 |
| -22 | 72799：该婚房装饰无法摆放在此处 | 资源摆放限制或不能成立的替换 |
| -1 | 72782：发生错误，显示操作及错误数值 | 未打开编辑窗口、来源已失效、参数不符或提交快照变化，不误报关系丢失 |

1037的target是要查看婚姻信息的角色编号，不是请求者的伴侣编号或婚姻context。原生发送器`01E512D0`将本人的编号转换为0，其他角色编号原样发送；服务端分别查询本人或目标角色所属关系，再返回其伴侣。查看他人不要求请求者自己已婚。目标越界、主体无有效关系或正文长度错误返回`00`。角色卡中的匹配字段仍使用被查询关系的context，不能写成请求的0或角色编号；`01E51AA0`据此决定是否更新本人伴侣缓存，婚姻窗口`01E36E40`使用返回的伴侣模型更新另一侧，不能再次发被查看者。

外观数组的装扮空槽0–9由[统一默认外观](../模块/角色.md#默认外观)按伴侣职业及完整growType解析；克隆装扮使用已保存的来源编号，无来源按空槽处理。未映射槽及空武器装扮写有符号`-1`，不伪造武器装扮来源；不改变库存。客户端婚礼选择窗口从成功角色卡缓存取得伴侣姓名；没有角色卡时会禁止确认。

`01E51AA0`将13个i32外观编号直接写入预览DTO；此处0不是默认哨兵。`02AB3010`仅在编号为-1时调用`02B61730`取得本职业基础或觉醒默认，后者先按`01E26BF0`查询PVF觉醒表，再回普通基础映射。只发旧ETC默认表既会漏掉没有该文件的新职业，也会用普通外观压掉觉醒外观。本人Actor创建保留的-1与角色卡不能使用不同的空槽语义。

已解析的1035业务失败回执也保留请求的目标、操作类型、保留字和回应值。消费合法邀请后若确认失败或已过期，向原发起会话发送带负结果的1001；其客户端接收器会先关闭等待窗口。错误对象或非原会话的回应不消费邀请，也不向合法发起人发布结束通知。

1045回执是`01 result:i32 channel:u16 opaque:u32 town:i32 area:i32 x:i16 y:i16`，不把opaque当作关系ID。留言正文1至255字节，禁止控制符和无效CP936；长度是编码字节数，不能使用.NET字符数。

1041成功回执为`01 0:i32`，随后发布已提交的入场礼库存差量及城镇旅行。首次入场礼无法完整放入时返回`01 -9:i32`；`01E50AF0`将该值映射到DSTR72917。原生参加婚礼入口`01E45FF0`也在发送前检查两个消耗品空格。重进时已领取的礼炮不再生成，婚礼结束的礼金回礼仍走原邮件交付。

礼炮C2S251为`itemId:i32 slot:u16`，不含旧版参考的u8容器字段。`029D6820`在`029D6941/029D6951`分别写入4和2字节；ACK回调`0235ADC0`成功后读取`slot:u16 outcome:u8`并在本地扣一件，所以成功正文必须是`01 slot:u16 outcome:u8`。NOTI219由`023A9650`读取`actorId:u16 itemId:i32 outcome:u8`，结果序号用于当前资源动画查询；服务端只对实际提交的使用发布该通知。源槽的原生扣除结果无需重复发送；奖励复用源槽或使该槽数量不同于原生扣除结果时，仍通过既有库存差量更新完整实例。

## 通知与场景

| NOTI | 内容 |
|---|---|
| 1000、1001 | 原邀请和回应；预约档位保存在邀请通知语义中 |
| 1002 | 临时婚服，固定71字节；action0入场、1离场，包含双方名字、实际礼堂及服务器 |
| 1003 | 本人婚姻信息15字节：context:u32、state:u8、reserved:u8、marriedAt:u32、lovePoints:u32、ring:u8 |
| 1005 | 关系解除原因 |
| 1007 | 预约完整信息79字节，含实际开始时间、婚礼档位与请帖余量 |
| 1008 | 请帖82字节，指向实际婚礼上下文与礼堂 |
| 1010 | 婚礼电影68字节，发给本场新人和来宾 |
| 1011 | furnitureCount:i32，逐项slot:u16、itemId:u32，随后13字节树结构 |
| 1012 | storageCount:i32，逐项slot:u16、itemId:u32、quantity:u32，末尾tail:u32 |
| 1014 | 增量家具：count:i32，逐项container:u8、itemId:u32、slot:u16、quantity:u32 |
| 1015 | 树：treeIndex:u32、expiry:u32、growth:u32、waters:u8 |
| 1016 | 远端婚姻属性14字节：actorId:u32、partnerId:u32、state:u8、ring:u8、decorationScore:u32 |
| 1017 | 树收获：count:u16，逐项itemId:u32、quantity:u32 |
| 1018 | 胶囊：gauge:u32、owned:u8、taken:u8、showNotice:u8 |
| 1019 | 胶囊进度：gauge:u32 |

本人入城先1003；已婚再1018及1011，实际婚房另1012；仍有效的预约与请帖随后恢复。家具变更先1014，再完整婚姻与家具输入，供双方客户端重算。离婚发布1005、清空1003及1011，并重放结婚任务清理结果。

NOTI2 subtype0的116字节Actor头包含`+23 state:u8`、`+24 ring:u8`；`0267FB8B..0267FBD3`将其无条件覆盖到角色Data+3E8／+3EA。`01E53840`消费1003时也写这两个角色字段，但全局婚姻上下文独立保存；Actor发0会造成“全局仍已婚，当前角色资料却变未婚”的不一致。完整Actor创建及刷新都必须取当前角色所属的有效关系状态和婚戒；解除或无关系时发0。1003会同时释放旧伴侣预览，不能作为每次装备刷新的补发手段。

1011末尾及1015共用13字节树结构。首个u32是`decoration/coupletree.etc`的`[tree] [index]`，由`[seed]`中的种子物品映射得到；不是种子STK编号。`01E41070`、`01E3D450`读取后交给`026EF4F0`，`01E3FB60`按该值查找树配置和成长动画；错误物品编号会进入客户端无效参数崩溃路径。空树发送完整13字节零值，不能只省略字段。服务端存档仍保存种子物品编号，在登录、入房与实时树通知中统一映射；资源缺失时隐藏树的显示并保留原存档，不下发未知index。

电影结束没有新增专用完成命令。客户端查询NPC20013并发送普通CMD36：目标town/area、NPC的x和y+30、Movement5、两个u16零、TargetNpc:u32零、PathKind0。服务端只对已授权礼堂身份开放这一形状，再走正式保存、23/24及临时婚服离场投影。

本版大祭司“离开礼堂”实发CMD36正文`27007508B40005000000000000000000`：目标39/0/2165/180，来源0/0，其余字段同上。该精确落点与MAP中的NPC20013摆放坐标不同，服务端兼容此请求时仍要求当前礼堂身份、目标地图实际存在NPC20013及正常地区准入；不接受任意来源、坐标、NPC或路径类型，离堂后重放也不能再次切图。

婚房资源门-101经原生分派读取缓存来源town/area，并以固定300/200、当前婚房PreviousTown/Area、Movement5、TargetNpc0、PathKind0发送CMD36。来源只能是本选角实际入场留下的缓存；不能将负号去除后解释为101自环。

原码消费者已经证明1003/1011参与本人婚戒及婚房加成重算，不能在基础Player再叠一次。远端1016在Actor创建后及关系、婚戒、布置变更时发送。装饰分逐个已摆家具条目累加模板`[need material]`所有整数对的第二项，不过滤材料编号、不乘堆叠数量、不按物品编号去重；例如10002693贡献200。解除关系后清零。未知字段不用于传递自定义经济或状态。

家具及心意点商品沿用普通购买CMD21，正文为itemId:i32、count:i32、shopId:i32、npcId:i32。心意余额来自当前关系成员；家具直接进入共享保管箱，不能另建主背包家具实体。
