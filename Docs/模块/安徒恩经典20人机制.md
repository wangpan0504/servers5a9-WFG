# 安徒恩经典20人机制

本文对照经典 PC 20 人机制稿，说明本版资源与服务端的可执行边界。机制稿的社区数值仅作需求，不作为匹配 S5A9 版本的实现证据。状态、资源装配、配置和既有奖励政策以[副本模块](副本.md#安徒恩阶段与结算执行入口)为准；字节合同以[副本协议](../协议/副本.md)为准。

## 资源到执行链

`RaidCatalog`从`etc/raid/raid.lst`定位`etc/raid/anton.etc`；`RaidResourceLoader`将脚本及独立符号表交给`RaidScriptParser`。解析器保留头字段原值、两阶段、14 个 DGN、51 对规则、41 个符号、HP、PARTY MAX 和 timer 的(kind,DGN)键，不赋予未证字段战斗语义。`RaidIssue`使未知或不完整语法拒绝装配，不能跳过错误后开战。

`AntonRaidStart`沿原团/分队、原 owner 及门票事务安装同一个`AntonRaidBattle`；`AntonRaidDungeonService`只为当前阶段 Open 图授权。`DungeonReservation`在同一 Battle 锁内预留共享 Run；安装及释放仍用原 Run 身份。117 经正式死亡提交得到的 ClearFact 才能推进，每个不同 Run 扣一次本图 HP；同队多名成员及重复117不重复扣减。这是已有本服兼容策略，不是原厂 HP 公式证明。

规则解释器支持 `[if]`、`[on change symbol]`、`[on change dungeon state]`、`[check dungeon state]`、`[check timer end]`；行为支持 `[set]`、`[set dungeon state]`、`[set timer]`、`[reset timer]`、`[reserve dungeon state]`、`[open random hatchery]` 和 `[clear phase]`。规则求值先登记随机开图待决，正式Runtime在原Battle时钟与目标代门禁内沿86兼容策略完成四选三及感染选择；显式领域夹具不自行启动这条自然时钟。`[fail phase]`、进图/进房/放弃/阶段结束触发器和`[reset sanctum object]`属于 Luke 扩展，Anton 解析器拒绝；P1 重置来自 `[1phase fail]` 符号规则，不使用 `[fail phase]`。

`ExpireTimer`对 Anton 拒绝外部到期输入。正式 Runtime 另由原`LukeRaidClocks`租约按本服秒制处理 timer/reserve，并按相同兼容政策处理阶段总限；该路径早已存在。声明单位及原厂起算链尚未闭合，不能把兼容测试通过写成原厂证明，也不据机制稿增加新计时器或改动原值。

## 1.0 团队与入场

**UNIMPLEMENTED**：每图分队额度、活动24币、复活后技能CD规则、掉线300秒踢出及当日禁入、装备特效禁用与机制稿的购票/开放日策略。`[disconn member wait time]300`只是声明；当前Anton恢复沿原存活实例和owner检查，不设猜测超时。Luke已有阶段复活策略，范围与小队共享池不同，不能直接套入。门票实际物品及既有周期政策见副本模块，不用机制稿覆盖。

复活币资源和计数合同：匹配ARAD的标签分派先将`[coin limit]`注册为`0x532`，跳表`040ADA80→040ADA2C`落到`04095AB0→0409BBC3`，读取并覆盖原DGN`+0x300`；`[character coin limit]`为`0x536`，落到`04095AF2→0409BBE1`写`+0x304`。`02A33D39/02A33D45`分别复制到完整Run`+0x2E8/+0x2EC`，嵌入DGN基址为`+0x180`，即总上限`+0x168`和个人上限`+0x16C`。`[coin info]`经`04099694→040A3015→040A302F`写原DGN`+0x9C9`，`02A36F77`复制到完整Run`+0x790`（嵌入DGN`+0x610`）；该值为1时`02616EC0/02617730`走个人计数，否则使用当前Run总数。`[risk dungeon]`写的是相邻`+0x9C8`，不能代替此标志。

正式14图未声明`[coin info]`或`[character coin limit]`，计数选择缺省0；最终`[coin limit]`均为12。舰炮先4后12，`DungeonDefinition.CoinLimit`依序使用最后同名段，畸形末段不回退旧值。controlled Anton入口保留该额度。`PartyDungeonInstance`为当前共享Run持有独立池，先在本人owner下复核原Battle/Run/成员，再原子检查`used + reserved < limit`；钱包事务成功后才提交一次计数和复活，失败释放预留。634只投影已提交总数，不泄露预留。池不持其他成员owner或共享场景gate跨钱包SQL；新共享Run建立新池，不套Luke跨Run阶段8/20额度。`etc/raid/raidrewardlimit.etc`的`[raid common coin limit]10304529 2000`及CHN的2500仍属奖励物品限制，不能充当复活币上限。

原生复活币数字倒计时由客户端消费32后启动本地时钟，默认常量9999 ms，mode6另读客户端DGN的 `[char coin limit time]`（资源 `+FE4`）。匹配客户端的14份 `dungeon/anton/` DGN均未声明该标签，资源初始化为 `-1`；mode6经 `029FFD20` 读取的分支遇 `-1` 回退10000 ms。这不证明正式Anton实际进入mode6；不需要新增秒数通知。服务端死亡提交后已有state0，用币成功后已有state1。具体消费者与时长选择见[证据地图](安徒恩经典20人机制-证据地图.md#随机图标执行槽及房内血条的消费边界)。正式用币资格按上述共享Run池处理；倒计时mode、死亡到期政策和真实界面仍须分别验证。
