# 安徒恩经典20人机制

本文对照经典 PC 20 人机制稿，说明本版资源与服务端的可执行边界。机制稿的社区数值仅作需求，不作为匹配 S5A9 版本的实现证据。状态、资源装配、配置和既有奖励政策以[副本模块](副本.md#安徒恩阶段与结算执行入口)为准；字节合同以[副本协议](../协议/副本.md)为准。

## 资源到执行链

`RaidCatalog`从`etc/raid/raid.lst`定位`etc/raid/anton.etc`；`RaidResourceLoader`将脚本及独立符号表交给`RaidScriptParser`。解析器保留头字段原值、两阶段、14 个 DGN、51 对规则、41 个符号、HP、PARTY MAX 和 timer 的(kind,DGN)键，不赋予未证字段战斗语义。`RaidIssue`使未知或不完整语法拒绝装配，不能跳过错误后开战。

`AntonRaidStart`沿原团/分队、原 owner 及门票事务安装同一个`AntonRaidBattle`；`AntonRaidDungeonService`只为当前阶段 Open 图授权。`DungeonReservation`在同一 Battle 锁内预留共享 Run；安装及释放仍用原 Run 身份。117 经正式死亡提交得到的 ClearFact 才能推进，每个不同 Run 扣一次本图 HP；同队多名成员及重复117不重复扣减。这是已有本服兼容策略，不是原厂 HP 公式证明。

规则解释器支持 `[if]`、`[on change symbol]`、`[on change dungeon state]`、`[check dungeon state]`、`[check timer end]`；行为支持 `[set]`、`[set dungeon state]`、`[set timer]`、`[reset timer]`、`[reserve dungeon state]`、`[open random hatchery]` 和 `[clear phase]`。随机开图只留下待决，不在 Runtime 选择目标。`[fail phase]`、进图/进房/放弃/阶段结束触发器和`[reset sanctum object]`属于 Luke 扩展，Anton 解析器拒绝；P1 重置来自 `[1phase fail]` 符号规则，不使用 `[fail phase]`。

`ExpireTimer`对 Anton 拒绝外部到期输入。正式 Runtime 另由原`LukeRaidClocks`租约按本服秒制处理 timer/reserve，并按相同兼容政策处理阶段总限；该路径早已存在。声明单位及原厂起算链尚未闭合，不能把兼容测试通过写成原厂证明，也不据机制稿增加新计时器或改动原值。

## 1.0 团队与入场

沿现有 20 人、5 支小队、每队最多 4 人、原成员身份、门票与候战室检查。匹配资源 P1 的216 `[PARTY MAX]` 为1，其余图为5；当前只解析保留，字段的并发消费者和释放条件未闭合，不能据此收窄合法准入。全团5个Run上限不等于实现了该字段。

**UNIMPLEMENTED**：每图分队额度、小队共享12复活币、活动24币、复活后技能CD规则、掉线300秒踢出及当日禁入、装备特效禁用与机制稿的购票/开放日策略。`[disconn member wait time]300`只是声明；当前Anton恢复沿原存活实例和owner检查，不设猜测超时。Luke已有阶段复活策略，范围与小队共享池不同，不能直接套入。门票实际物品及既有周期政策见副本模块，不用机制稿覆盖。

## 1.1 阶段状态机与完成条件

阶段0从210 Open开始；HP4归零后才执行后续开图。213/215各HP2，全部归零后脚本置`[1phase success]=1`，隐藏P1地图并`[clear phase]`。阶段资格先落库再允许领奖；全部既有牌种确认后才初始化阶段1。最终心脏阶段资格在最后通关时落库，领取与周通关次数分开。

**UNIMPLEMENTED / 版本差异**：机制稿要求舰炮、震颤A/B各至少一次，但匹配脚本完成条件只检查213与215的Clear。不能额外添加216/212/214硬门槛；这仍是经典稿的缺口。总限原值为2400/2400，已有本服秒制解释为各40分钟；原厂时基及超时演出未闭合。休息600的起算、自动换阶段及团长跳过仍UNIMPLEMENTED，不以奖励完成后的立即初始化冒充10分钟休息。

## 1.2 地图依赖

210四次后隐藏210，211 Close，212/213/214/215 Open，并保留216 Open的预留原值20。211是之后重开的黑雾目标，不能把它与开场210合并成同一资源ID。213/215各两次Clear；尚有HP时继续Open。舰炮延迟沿原值20，不改成机制稿约25。

阶段1初始218能量、219火山Open，220心脏与221–224孵化场Hide。219一次Clear后隐藏218/219/221–224，只开放HP5的220；心脏累计五个可信Run才进入最终Reward。火山关闭时还撤销来自其timer规则的旧随机孵化待决，避免迟到的显式机制输入在心脏阶段重新开场；已有孵化场240重开预留也随hide撤销。撤销与战况候选一起提交，不另建状态容器。

## 1.3 一阶段timer与重生

资源声明：211重开300、攻略480、被动符号240；212/214攻略300、重开150；216延迟开放20、攻略360、被动符号120、重开150。timer以地图键隔离、重设递增代次、reset取消旧代；reserve不等同立即Open。上述值只沿已有本服秒制运行，不将震颤重开150替换为稿件120。

211攻略到期及212/214攻略到期写`[1phase fail]`，脚本重新Open210并隐藏其余P1图；重开的图恢复声明HP并递增目标代。216超时则沿脚本重开212–215并显式写双腿HP0，不能将其概括成与黑雾/震颤完全相同的重置。

**UNIMPLEMENTED**：原厂timer单位和起算、NOTI596/597自然计时展示、超时的全团伤害/强杀、原厂失败及重开演出。保持外部Anton到期入口拒绝，不新增基于社区时长的调度。

## 1.4 跨图全局效果

**UNIMPLEMENTED**：黑雾蔓延的沉默/掉血，震颤或舰炮的全屏伤害/陨石，孵化蛋、蜘蛛与感染增益。脚本中的`[kill all character]`、烟雾及陨石创建符号仅为状态；没有对应战斗消费者，写1不表示角色已死亡或场景对象已生成。

## 1.6 孵化场

## 回归入口与验收边界

`--selftest-core`沿`RaidCreateFlowTests`覆盖解析器（含Anton拒绝FAIL PHASE）、既有共享Run预留、回滚、最后成员退出和旧Run释放隔离。`anton-raid`覆盖开战、正式入口、多分队及清图；`anton-raid-gap`覆盖票据/关闭开关/分队；`anton-raid-phase1`覆盖HP4、双腿HP2、舰炮延迟与重开、火山→心脏HP5、阶段持久资格与原领奖链；`anton-raid-phase-timer-221-224`包含真实PVF timer领域回归及两阶段总超时TCP，并验证火山关闭后旧随机待决不能打开任何孵化场。其它既有奖励/重连组见副本模块。

构建、core、真实资源领域测试、TCP和客户端实机分别成立。自动化通过不能证明自然点击、计时UI、原生AI、UDP或翻牌演出已验收；逐轮命令、结果和提交状态保存在任务交付记录，不在本文累计测试日志。
