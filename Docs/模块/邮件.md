# 邮件

邮件使用当前账号 lease、Session 的选角 epoch 和已提交角色快照。规则位于 [MailboxService](../../Server/DfoServer/Game/Mailbox/MailboxService.cs)，SQL 通过 [IMailboxStore](../../Server/DfoServer/Game/Mailbox/IMailboxStore.cs)及 [CharacterRepository.Mailbox](../../Server/DfoServer/Persistence/CharacterRepository.Mailbox.cs)执行；字节合同见[邮件协议](../协议/邮件.md)。

## 寄送

支持本服收件人查询、单附件和最多十件多附件寄送，以及纯正文、金币、附件的组合。收件人必须存在且不是发送角色；寄送和领取在已就绪的城镇会话中执行。未确认的特殊寄送及跨服字段不提交资产、不返回成功。

查询324和寄送94/315共用目标服务器索引，不是0/1模式或全局邮件开关。0表示默认本服，当前连接的实际`ServerIndex`同样按本服处理；寄送在连接边界核对后归一为0，再进入原有领域校验与事务。外服查询按暂不可查询回复原生错误2并结束等待，不在本服库中查找同名角色，也不谎报收件人不存在；外服寄送仍未接入，不误投本服或扣费。查询成功回复真实服务器索引和收件人资料，不存在使用21（该ID不存在），自己使用7，未就绪使用2（请稍后再使用），均沿正常324回调收尾；不另外伪造解锁通知。成功查询不代替寄送时的再次查找、费用、附件、归属及交易资格校验。

普通附件来自 Main、Avatar 或 Pet，按请求模板、数量、完整实例和实际槽位核对。装备数量为一，堆叠数量必须在现有量内；重复源槽整批拒绝。安全锁和排序锁均阻止寄送；过期物品与尚未到期的限时物品分别拒绝。

六色小晶块虽保存于账号钱包，仍可作为邮件中的材料寄送和领取。玩家寄送从 Main 的真实虚拟槽354–359读取，逐项核对模板、槽位、PVF交易资格和足额余额；扣钱包、邮费及新邮件在同一事务提交。附件仅在邮件中托管，不插入 `character_inventory_slots`；领取复用统一奖励分流加到收件账号钱包，原托管 UID 随领取退出，不形成第二份背包资产。失败寄送重新投影真实钱包槽，恢复客户端草稿显示。

交易规则使用匹配 PVF 的 attach type 和实例 TradeRestriction：free 可寄送，sealing/seal 必须仍封装，account 只允许同账号其他角色，trade limit 必须有剩余次数并在转出的实例中减一。未知和禁止交易类型拒绝。源堆叠的未转出部分保持原属性，不能因为发送另一部分而重复消耗它的交易次数。

手续费为固定 100 金币、每条附件 1000 金币，另加寄送金币的 5%及附件总出售价值的 5%；两部分分别向下取整。附件价值为当前出售单价乘寄送数量的合计，装备沿用耐久和90%折价后的出售价格，不使用品级字段或商城买价。常规费用不统一封顶，余额不足整笔拒绝，不自动减少寄送金额。金币、手续费、源物品扣除、新邮件、附件、每日额度、角色 revision 和资产审计在同一个 SQLite 事务中提交。

单封寄送金币不超过收件人等级对应的基础携带上限；发送角色每天最多寄送 `10000 × level²` 金币，按 UTC+8 06:00 刷新。每日记录只保留该角色当前日期的累计数，失败事务不消耗额度。费用不计入寄金币额度。

每个新的寄送请求是一次独立业务操作。已转出整件的再次请求因源实例缺失而拒绝；余额或堆叠仍足够的重复内容可以再次寄送，不能把客户端 pending、包体相同或同模板槽位视为永久幂等标识。

## 收件箱与领取

玩家邮件保留十五天。加载最早二十封普通邮件及全部保存邮件，未装载数只统计普通邮件；最多保存十封，保存后不参与邮件期限清理。列表按客户端逐行前插行为排列，纯正文和领完后的邮件也保留期限摘要及正文。

邮件 ID 与附件 ID 使用不相交的领取命名空间。客户端的整封领取按钮枚举待收附件；附件 ID 是底层请求及回执粒度，不把一次点击定义成只收一件。服务端处理实际收到的对象列表，整封邮件 ID 展开为尚未领取的全部附件，不额外扩展其他邮件或客户端未请求的附件。金币绑定第一条未领摘要，只随该摘要或整封领取一次；领取其他摘要保留金币资格。回执携带实际邮件合并 key 和领取摘要 key。全部请求先核对归属、有效期、重复及交叠；无效对象拒绝整批，不借部分成功放行伪造请求。

领取复用背包的[统一发放和材料规则](背包与装备.md)，按请求及邮件内顺序规划完整属性的堆叠合并、目标容器与空槽。空间足够则收尽本次请求；容量或金币携带上限阻止后续对象时，只形成可领取前缀的计划，回执返回实际成功项及第一条失败项，失败项和未处理后缀仍归原邮件，不分配新邮件 ID。第一项就失败时不改变资产或领取资格。正常整批只规划一次；容量失败时以有界二分查找前缀，避免逐件重新扫描完整背包。提交仍在原 lease 内复验角色快照、选角 epoch、邮件 revision、核心和详情。

整件和未合并的完整堆叠保留原 UID；部分寄送在提交时分配新 UID。附件托管期间继续使用同一物品核心和时装/宠物详情表，只脱离真实库存槽位。领取后合并进既有堆叠的附件 UID 退出托管，不形成第二份资产。领取、金币、背包、邮件状态及审计同事务提交，失败恢复原状态；发送失败不回滚已经提交的领取。

实际领取的邮件自动标为已读，领取结果与成功前缀的金币、背包及审计在同一事务提交；SQL 失败仍整体回滚该计划，不允许先成功一项后丢失回执。ACK95 由原生消费者逐项移除已领摘要并处理错误，随后只发布实际库存变化，不追加清空式 NOTI97 打断正在打开的邮件对象。重新打开邮箱或入城时才重载完整正文和剩余摘要，发布绑定原账号 generation、角色及选角 epoch。支持已读、保存、删除；有未领金币或附件的邮件不能删除。已读和保存的重复请求不写库；读取已保存邮件保持保存状态，回复实际状态。已删除的本角色邮件重复删除成功，其他角色或未知 ID 不获得删除资格。

到期清理由打开邮箱或入城恢复触发，每次最多处理二百封，记录到期资产审计并清理托管实例；所有读取和领取同时检查绝对期限，尚未清理的到期记录也不可见、不可领取。没有到期对象时不申请 writer。保存及永久系统邮件不参与此清理。

## 系统投递与发布

内部系统投递接受普通实体的完整核心与详情，支持永久邮件或明确截止时间。稳定 delivery key 在数据库中唯一；同 key 同资产重试返回原邮件，接收者或资产变化明确拒绝。此入口用于独立投递，不自动承担其他奖励来源的扣料或资格事务；礼包、碎片制作等满包溢出尚未接入。

钱包的存储方式不作为禁止正常邮件业务的理由。当前已接入3033–3037、3262六种晶块的系统投递、玩家寄送和领取；托管数量遵循钱包整数范围，不按普通物品堆叠上限裁掉。领取会先检查钱包上限，不能沿饱和加法吞掉超额附件；失败对象继续留在原邮件。账号券、灵魂、复活币和碎片的邮件入口尚未确认，保持明确拒绝，不借此改动放行。黑名单、正式交易/摆摊限制、文本审查、额外发送等级和次数限制还没有对应权威状态，未追加假限制；背包负重规则沿用当前统一发放边界。

入城在账号资产后发送邮箱列表，完成入城包仍保持原 ready 边界。在线新邮件提交后通过现有 OnlineSessionDirectory 找到接收者原 Session，再向其有界发送队列投递提醒；提醒不等待发送者的回复或收件人的 socket。未选角、其他角色、过期 generation 和选角 epoch 不接收提示。已开始写出的帧仍遵循现有[在途边界](../规范/服务端架构.md#账号-generation)。

成功回复和背包差量只使用本次提交回执；失败寄送按有效源槽投影当前库存，恢复客户端临时显示。邮件结构从 v4 连续追加，保留原角色、物品、UID 和详情；建库与升级规则见[数据库](../开发/数据库.md)。

## 验证

基础邮件协议、交易资格、真实文件库回滚/归属/期限/迁移和通知隔离接入 `--selftest-core`；实际资源用例加入完整 `--selftest`。TCP 分组为 `--selftest-tcp mailbox`，覆盖入城列表、查询、寄送、失败恢复、逐附件/批量领取、已读/保存/删除、重连和服务重启；公共调用方变更还须运行完整 TCP，见[贡献指南](../../CONTRIBUTING.md#验证)。

原码字段核对、自有测试与真实客户端界面验收分别报告。邮件排序、预览、领取提示和交互仍需匹配客户端实机确认。
