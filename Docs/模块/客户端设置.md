# 客户端设置

当前支持账号通用设置 `SAVE_GAME_OPTION_1`、角色选项 `SAVE_CHARACTER_OPTION`、账号键位 `SAVE_GAME_OPTION_2`、账号快捷聊天 `SAVE_GAME_OPTION_QUICKCHATTING`，以及聊天表情指令的保存与选角回放。

## 任务提示书签

CMD506保存当前角色最多四个任务提示编号，保留客户端顺序。数据库v175的`character_quest_notify`按角色及账号归属保存固定四槽，未使用槽为0；首次空保存不建行，同值保存不申请writer，清空会覆盖原书签。SQL失败保留旧值，旧generation不能写入，未就绪或退出角色后的迟到请求不保存。

选角ACK4沿原有四个u32字段恢复书签，缺少存档时为零；同账号换角色和其他账号互相隔离。书签只是显示偏好，不接取任务、不完成目标、不生成奖励，也不改变角色revision。保存不即时回推列表或发送未经核证的专用ACK；客户端可按实际任务可见性过滤已保存编号。真实界面恢复仍须客户端验收。

## 聊天表情

聊天表情配置与皮肤仓库的即时表情是两套业务。聊天表情名册来自 `chatemoticon/chatemoticon.lst` 及各 `.emo`，按 `EmoticonOrderList.etc` 顺序下发：`COMMON` 默认开放，`LEVEL` 检查角色等级，`WEDDING` 检查已婚状态与本角色心意点；`CASH/EVENT` 只接受资源所引物品能映射到有效账号 premium 期限的资格，不猜测未注册来源。

自定义指令按账号和表情编号保存在 `account_chat_emoticons`（数据库增量 v157），保存请求只更新提交的已注册编号；其他账号互不影响，切换同账号角色保留指令。同值保存只读，不申请 writer；整批失败回滚。选角、保存后及等级、婚姻、契约资格改变时按当前可用目录回放；资源移除或资格暂时不符合时不删除原指令。连接只保留最后已发视图，用于抑制相同通知，不另存资格。聊天正文的资格过滤与独立表情发送见[聊天](聊天.md#表情)。兼容升级只接管结构精确匹配的存档，保留原配置及玩家数据，不补造资格；未知结构拒绝升级。

最近使用的18槽按账号保存在 `account_recent_emoticons`（增量 v158），与指令和资格分开。CMD1447忽略不透明保留区，只保存完整18个编号，保留顺序、零槽及暂时不符合资格的已注册编号；同值只读，SQL失败不改变原值或回成功。选角及换频道恢复时，先发NOTI1384安装最近列表，再用411刷新界面；缺省发送18个零，避免继承上一账号历史，不填入默认表情，也不因此开放任何资格。保存时不即时回推1384，避免覆盖客户端刚使用后的新顺序。客户端第1排是婚姻表情区，第2、3排是最近使用区，不是契约解锁范围；实际显示和退出后恢复仍需匹配客户端验收。未曾保存的旧历史无法从空记录还原。

## 保存与所有权

[SettingsRequests](../../Server/DfoServer/Network/Parsers/SettingsRequests.cs)校验完整长度，[SettingsHandler](../../Server/DfoServer/Network/Handlers/SettingsHandler.cs)通过 Session 调用 [ClientSettingsService](../../Server/DfoServer/Game/Settings/ClientSettingsService.cs)，[ClientSettingsRepository](../../Server/DfoServer/Persistence/ClientSettingsRepository.cs)负责 SQL。主设置按当前账号保存，角色选项按当前选中角色保存；不从请求正文接收账号或角色 ID。

主设置为204字节，角色选项为512字节。账号主区保留完整原始请求；选中角色时，同一事务另存角色主区快照。四个角色开关（转职/觉醒特效、技能插图特效、查看全身时装、觉醒装扮）及四项透明度以角色为单位，其他主区项按账号共用。账号设置允许在选角前保存，角色选项要求已有选中角色。设置不修改角色位置、revision、任务或资产，也不因处于选图界面而改变这些业务资格。

角色主区保存时，已确认有效的512B角色槽46、49分别纠正主区68、13，避免客户端先保存角色选项、再回写旧账号值。保存仍保留完整原始角色区，包括未知槽、零值与 `FFFF`；槽48为独立光环显示开关，不映射Actor/357的显示位。独立角色主区缺失时沿用当前账号主区作为初值，同时保留旧角色已保存的46/49；后续保存建立独立快照，不伪造历史角色值。

仓储通过当前账号 lease 校验 generation，角色读写同时验证账号归属。账号与角色两段均相同时不申请写事务；账号相同而角色不同仍提交角色段。实际改变使用同一设置事务提交，SQL失败保留两段原值并结束当前连接，不补成功应答。两类请求均不发保存ACK或即时173/390回推；三项外观显示位变化时通知本人357，并沿既有同屏外观刷新更新远端。

## 回放与存储

[ClientSettingsRules](../../Server/DfoServer/Game/Settings/ClientSettingsRules.cs)从账号主区复制数据，只回填当前角色的八个槽；390中的46/49与该次173保持一致。角色槽48为 `FFFF` 时仅在回放快照中改为1（默认显示光环），显式0保持关闭，其余已保存槽不变。无角色选项存档时，沿原生512B未设置布局及槽43=0初始化，透明度46与插图49分别沿有效主区68/13，主区缺失或完整102槽全为7FFF时使用原生缺省100/1；合成角色选项不反写主区，以保留原生初始化标记；光环48显式设为1。该默认显示是服务端策略，客户端自身没有为未设置光环提供开启回退。投影不写库或授予光环资产。

[SettingsProjection](../../Server/DfoServer/Network/Projection/SettingsProjection.cs)在本人Actor、Player创建之前预载 `GAME_OPTION`→`CHARACTER_OPTION`，使第一次场景外观创建即可读取当前光环开关；普通选角在本人实体与城镇地区绑定完成后、入城完成124之前恢复设置；换频道恢复原场景时在124及最终24绑定之后恢复设置。后段保留390回放，以完成依赖本地玩家的选项应用，使用与前段同一快照；有主区存档才回放173和357，键位454按存档恢复。账号与角色均无主区存档时，实体前的173仍发送原生未设置标记，由客户端补齐原生默认，后段不重复发送缺省173或357。服务端不主动持久化初始化值；客户端自动回送的真实保存仍按原事务处理。发布绑定读取时的账号 generation、角色 ID、显示位和选角 epoch，旧角色或旧连接的结果不能发给新选择。

本人及远端Actor使用当前角色的显示位，不再写固定6。角色读取在同一读取事务中派生显示位，库存、技能、旅行和GM重新加载快照也保留这一设置事实；位置与资产提交仍不改写设置表。

数据库v6增加 `account_client_settings` 和 `character_client_settings`，v7追加 `character_game_settings` 保存角色主区快照；账号外键与角色/账号复合外键保护归属。升级只建立空表，保留已有数据，不为存量角色伪造独立主区；维护规则见[数据库](../开发/数据库.md)，字节与包序见[设置协议](../协议/客户端设置.md)。

## 账号键位

198保存原生动作、整数键值与换行文本，原样保留顺序、重复值及未分配键，不将其当作技能快捷栏。正文没有profile，按当前选角职业确定：job10缔造者使用1，其余本版职业使用0；同账号普通职业共享配置，两个profile独立，其他账号不串数据。

匹配原码的文本长度范围为1至1399B，严格拒绝尾部、NUL和畸形行；不沿用参考端8192B上限。保存不发送ACK或即时454，以免重置客户端当前键位模型；回放对应454时位于原173/390后、357前；普通选角在124前发送，换频道恢复在124及最终24之后发送。没有存档不合成空默认表。发布仍绑定原generation、角色ID、profile与选角epoch，不改变user状态或角色资产。

在已发布v25称号簿、v26训练之后以v27追加账号双profile键位表，迁移只建空表，保留已有设置、称号和训练数据，已发布历史不重排。既有主区、角色选项及独立角色快照继续保留，纯读与同字节保存不取得writer，SQL失败保留原数据。

设置核心测试覆盖账号/profile隔离、完整回放、外部writer下零变化、SQL失败、旧generation、增量及回滚，可用无资源入口 `--selftest-tcp settings-storage` 单独复验；`--selftest-tcp settings`追加198静默保存、454原生包序、普通/缔造者换角、非法尾部、重连与进程恢复。实际按键效果仍须匹配客户端验收，详细字节见[设置协议](../协议/客户端设置.md#键位原码合同)。

## 账号快捷聊天

368按银行保存客户端提交的300B原始文本，两个银行独立成行、互不覆盖，同一账号全部角色共享；服务端不解释GBK编码，也不把文本当聊天命令执行。正文必须恰好305B，银行号只能为0或1，未知银行、长度不符、截断及多余尾部均作为结构错误结束连接。首次保存才建行；相同字节重复提交不申请写事务；SQL失败保留原值并结束当前连接，不回通用成功。

在已发布v25称号簿、v26训练、v27键位和v28心情之后以v82追加 `account_quick_chat`，键为账号与银行，外键指向 `accounts`，文本列约束为300B blob；迁移只建空表，保留账号与角色设置。回放跟在173主设置后：有主区存档时前后两次173都带银行，无主区存档时实体前的原生初始化同样带银行，后段不重复发送173。缺省银行写零长度，正文与旧格式逐字节一致。

TCP回归覆盖368静默保存、两个银行隔离、同字节零变化、重新选角回放、其他账号缺省、SQL失败断线与畸形尾部；详见[设置协议](../协议/客户端设置.md)。

## 角色心情

CMD254按当前PVF `etc/emotionexpressiondata.etc`验证普通和特殊心情，保留完整u16编号。可见类型0至2为基础；类型3根据称号簿章节及角色持久`TitleSections`解锁，包括原先隐藏的活动心情；类型5要求声明的全部任务已在角色、账号或称号进度中完成。类型300的关系心情不开放手动选择，其余未知资格仍拒绝。未注册编号返回错误1，已注册但未解锁返回错误3，避免把真实存在的心情误报不存在。格式归PvfLib的[EmotionExpressionFile](../../Tools/PvfLib/Models/EmotionExpressionFile.cs)，目录归[CharacterEmotionCatalog](../../Server/DfoServer/GameWorld/Characters/CharacterEmotionCatalog.cs)，资格归[EmotionSelectionRules](../../Server/DfoServer/Game/Settings/EmotionSelectionRules.cs)；Runtime显式共享已有TitleCatalog，不新增解锁表。

仅修改当前账号所选角色的心情，不改资产、位置、revision或user细阶段；同值只读，不申请writer，失败不回成功。在已发布v25称号簿、v26训练和v27键位之后以v28追加心情字段，完整SQL将字段置于原characters列后，保持既有读取宽度。新角色及未知存量缺省0，不补特殊心情解锁；已发布历史不重排。

先提交再专用ACK。城镇及选图上下文追加本人Actor，城镇通过原同屏通道广播实际心情；本人及远端Actor均使用接收者当前频道身份；不在副本重建城镇Actor。非城镇心情仍保存并确认，在后续入城或选角时回放完整状态。发布核对原epoch、细阶段及角色引用，旧owner或旧角色结果不覆盖新上下文。匹配客户端原Actor仅写资料而未安装活实体动画，成功ACK也只改面板；显示需配套客户端在这两处调用原生动画装配器，同步资料、重建来源及当前实体。副本同伴的即时变更未新增广播，界面与动画显示仍待QA实机；资源缺图或越界帧不能由成功ACK证明正常。

[心情核心回归](../../Server/DfoServer/SelfTests/EmotionTests.cs)覆盖资源形状、u16字段、只改Actor末尾字节、角色隔离、外部writer下同值只读、SQL失败、旧generation及增量升级；[选择资格回归](../../Server/DfoServer/SelfTests/EmotionSelectionTests.cs)覆盖普通/特殊格式、全部真实资源定义及ANI存在、章节独立解锁、隐藏活动、任务全条件和拒绝边界。`--selftest-tcp emotion`核对保存/拒绝、同屏、持久章节资格回放、重新选角、连接恢复与实际SQL失败；ANI存在不代表引用的全部NPK图片帧均有效。

## 验证

[设置存储测试](../../Server/DfoServer/SelfTests/ClientSettingsStoreTests.cs)覆盖完整字节、账号与角色隔离、重复保存、旧lease、数据库失败、外部writer占用时的只读/零变化、v5升级及回滚。[协议与选择测试](../../Server/DfoServer/SelfTests/SettingsProtocolTests.cs)覆盖非法长度、构包和旧选择发布资格。

`--selftest-tcp settings` 覆盖真实注册、静默保存、本人实体创建前预载与地区绑定后回放字节一致、新账号job0至15首角色的原生初始化、UI大小槽90的0/25/50/75/100首次保存和重进回放、选角/重连/重启回放、其他资产不变及非法包和SQL失败。普通设置保存、重进角色恢复、八项角色设置隔离已通过匹配客户端验收；无主区存档的首账号初始化有原码及TCP回归，修复后的画面效果尚待匹配客户端确认。账号键位的静态原码及TCP验证不代替实机按键验收。快捷聊天保存与回放已有存储、协议及TCP回归，退出客户端重开后的实际显示仍待匹配客户端验收。

settings TCP 的 `settings.phases.json` 使用单调时钟累计阶段墙钟耗时，记录调用次数及每次耗时的最小/最大值，不保存逐调用明细。`FirstEntry/` 区分登录、建角、首次选角、保存屏障、读库检查及重进回放；`character-scope/` 区分首次会话、开关持久化/切区、重连、进程恢复后回放及同屏检查。子阶段和快照耗时包含在父阶段中，不能直接相加、当作 CPU 时间或据此跳过检查；失败也会输出 `Completed=false` 的已观测阶段。阶段计时不改变 16 职业、五档 UI、真实重启、协议包序或超时合同。
