# 客户端设置

当前支持账号通用设置 `SAVE_GAME_OPTION_1`、角色选项 `SAVE_CHARACTER_OPTION`，以及账号键位 `SAVE_GAME_OPTION_2` 的保存与选角回放。快捷聊天及聊天表情保存尚未接入，不返回占位成功。

## 保存与所有权

[SettingsRequests](../../Server/DfoServer/Network/Parsers/SettingsRequests.cs)校验完整长度，[SettingsHandler](../../Server/DfoServer/Network/Handlers/SettingsHandler.cs)通过 Session 调用 [ClientSettingsService](../../Server/DfoServer/Game/Settings/ClientSettingsService.cs)，[ClientSettingsRepository](../../Server/DfoServer/Persistence/ClientSettingsRepository.cs)负责 SQL。主设置按当前账号保存，角色选项按当前选中角色保存；不从请求正文接收账号或角色 ID。

主设置为204字节，角色选项为512字节。账号主区保留完整原始请求；选中角色时，同一事务另存角色主区快照。四个角色开关（转职/觉醒特效、技能插图特效、查看全身时装、觉醒装扮）及四项透明度以角色为单位，其他主区项按账号共用。账号设置允许在选角前保存，角色选项要求已有选中角色。设置不修改角色位置、revision、任务或资产，也不因处于选图界面而改变这些业务资格。

角色主区保存时，已确认有效的512B角色槽46、49分别纠正主区68、13，避免客户端先保存角色选项、再回写旧账号值。未知槽、零值与 `FFFF` 保留，不按其他版本猜映射；角色槽43、48也不作为外观开关。独立角色主区缺失时沿用当前账号主区作为初值，同时保留旧角色已保存的46/49；后续保存建立独立快照，不伪造历史角色值。

仓储通过当前账号 lease 校验 generation，角色读写同时验证账号归属。账号与角色两段均相同时不申请写事务；账号相同而角色不同仍提交角色段。实际改变使用同一设置事务提交，SQL失败保留两段原值并结束当前连接，不补成功应答。两类请求均不发保存ACK或即时173/390回推；三项外观显示位变化时通知本人357，并沿既有同屏外观刷新更新远端。

## 回放与存储

[ClientSettingsRules](../../Server/DfoServer/Game/Settings/ClientSettingsRules.cs)从账号主区复制数据，只回填当前角色的八个槽；390中的46/49与该次173保持一致，其他角色字节不变。[SettingsProjection](../../Server/DfoServer/Network/Projection/SettingsProjection.cs)在本人Actor、Player创建之前先发送已保存的 `GAME_OPTION`，让首次入城的UI读取已初始化主设置；普通选角在本人实体与城镇地区绑定完成后、入城完成124之前恢复设置；换频道恢复原场景时在124及最终24绑定之后恢复设置。两条路径均按已有存档发送 `GAME_OPTION`、`CHARACTER_OPTION`、键位454，有主区时再同步357。两次主设置使用同一个当前角色快照；后段回放保留依赖本地玩家的设置应用。没有相应数据来源不合成204B或512B默认模板。发布绑定读取时的账号 generation、角色 ID、显示位和选角 epoch，旧角色或旧连接的结果不能发给新选择。

本人及远端Actor使用当前角色的显示位，不再写固定6。角色读取在同一读取事务中派生显示位，库存、技能、旅行和GM重新加载快照也保留这一设置事实；位置与资产提交仍不改写设置表。

数据库v6增加 `account_client_settings` 和 `character_client_settings`，v7追加 `character_game_settings` 保存角色主区快照；账号外键与角色/账号复合外键保护归属。升级只建立空表，保留已有数据，不为存量角色伪造独立主区；维护规则见[数据库](../开发/数据库.md)，字节与包序见[设置协议](../协议/客户端设置.md)。

## 账号键位

198保存原生动作、整数键值与换行文本，原样保留顺序、重复值及未分配键，不将其当作技能快捷栏。正文没有profile，按当前选角职业确定：job10缔造者使用1，其余本版职业使用0；同账号普通职业共享配置，两个profile独立，其他账号不串数据。

匹配原码的文本长度范围为1至1399B，严格拒绝尾部、NUL和畸形行；不沿用参考端8192B上限。保存不发送ACK或即时454，以免重置客户端当前键位模型；回放对应454时位于原173/390后、357前；普通选角在124前发送，换频道恢复在124及最终24之后发送。没有存档不合成空默认表。发布仍绑定原generation、角色ID、profile与选角epoch，不改变user状态或角色资产。

在已发布v25称号簿、v26训练之后以v27追加账号双profile键位表，迁移只建空表，保留已有设置、称号和训练数据，已发布历史不重排。既有主区、角色选项及独立角色快照继续保留，纯读与同字节保存不取得writer，SQL失败保留原数据。

设置核心测试覆盖账号/profile隔离、完整回放、外部writer下零变化、SQL失败、旧generation、增量及回滚；`--selftest-tcp settings`追加198静默保存、454原生包序、普通/缔造者换角、非法尾部、重连与进程恢复。实际按键效果仍须匹配客户端验收，详细字节见[设置协议](../协议/客户端设置.md#键位原码合同)。

## 验证

[设置存储测试](../../Server/DfoServer/SelfTests/ClientSettingsStoreTests.cs)覆盖完整字节、账号与角色隔离、重复保存、旧lease、数据库失败、外部writer占用时的只读/零变化、v5升级及回滚。[协议与选择测试](../../Server/DfoServer/SelfTests/SettingsProtocolTests.cs)覆盖非法长度、构包和旧选择发布资格。

`--selftest-tcp settings` 覆盖真实注册、静默保存、本人实体创建前预载与地区绑定后回放字节一致、UI大小槽90的0/75保存回放、选角/重连/重启回放、其他资产不变及非法包和SQL失败。普通设置保存、重进角色恢复、八项角色设置隔离及首次入城UI大小即时应用已通过匹配客户端验收。账号键位的静态原码及TCP验证不代替实机按键验收；快捷聊天仍未实现。
