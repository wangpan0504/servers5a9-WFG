# 护石与符文

护石和符文的类型化资源解释由 [ItemCatalog](../../Server/DfoServer/GameWorld/Items/ItemCatalog.cs) 提供，复用同一装备、堆叠物品名册与 PVF 归档。首次查询解析，后续查询共享不可变定义。未知编号或非对应类别返回无定义，畸形声明明确失败，不补造职业、首转、技能或阵营。

## 资源与资格

- 护石按 `[equipment type] [talisman]` 识别，附加整数是资源子类型，不是客户端装备槽。`[useable growtype]` 与 `[rune skillIndex]` 分别保存首转限制和技能。缺少这两个字段的零品级、全职业占位物保留为不可装备定义，不视为任意职业的有效护石。
- 符文按 `[stackable type] [rune]` 识别，保留 `[usable first growtype]`、`[rune skillIndex]` 与 `[rune option]` 的阵营、品级。`terracotta`、`circlemage`、`guardians`、`antiquitylibrary`、`secondpact` 分别映射孔色 1 至 5；模板堆叠上限为 999。只有当前 `stackable.lst` 注册的资源进入目录，归档中的孤立文件不充当有效候选。
- 使用资格同时检查模板等级、职业和首转。GrowType 高位的觉醒状态不改变首转限制；重复、空白、越界或嵌套的关键声明拒绝，不按默认值放行。
- `etc/runesystem.etc` 的合成和随机选择重复块保留原值、原序。重锻材料与各品级数量由独立字段装配；未知品级不补造费用，商店 `[need material]` 不作为重锻附加成本。`[compound info]` 每组以族（0 符文、1 护石）与模式（0 普通合成、1 当前转职合成）开头，其后按品级给出件数、金币与升档/同档两列权重；两列之和必须为正，末档与模式 1 的升档权重为 0。`[random choose info]` 同时作为随机箱奖励表独立校验：每行首列是本职业权重（0–10000 的万分比），其后按 `品级 权重` 成对给出，品级 0–6 不重复且至少一档，总权重必须为正；重复键、越界或奇数宽度整表拒绝。

## 库存与历史兼容

内部分类为 `Talisman=11`、`Rune=14`，与资源子类型分开。客户端容器 46 共 216 格：护石背包 0–69、符文背包 70–209、已装符文 210–215。护石穿戴于装备槽 34、35，各自对应连续三个已装符文槽。自动发放按类别进入对应分页；合堆只查背包格，不能向已装符文槽增加数量。

登录兼容仅接受资源确认的历史 `Equipment→Talisman`、`Consumable→Rune`。原 Main 实例迁往对应分页，个人及账号仓库保留原容器和首份位置；超上限符文守恒拆分，第一份保留 UID，额外份在事务中分配新 UID。完整核心、锁和未知位保留。容量不足时整批延后，保留旧分类和位置并允许登录，不截断或删除资产。邮件领取及拍卖归还同样保留原快照供提交复验，输出时才归一分类。

数据库迁移只开放容器 46，不猜测物品编号或批量改写核心；资源兼容通过既有库存提交器落库。库存、邮件、仓库与拍卖的公共行为见[背包与装备](背包与装备.md)。

## 装卸与重锻

装入从符文背包取一枚真实实例，保存到 210–215。单枚移动保留 UID，堆叠拆出的一枚分配新 UID；替换时旧符文先规划返还，容量不足整笔拒绝。孔色是唯一限制：符文阵营颜色与目标孔色一致即可装入，不要求符文技能与护石技能一致，同一护石的不同孔允许多次装入同阵营同技能符文；两枚护石分别校验。错色拒绝装载，不扣材料、不改库存。普通移动请求不能代替专用符文装卸；已装符文槽也不接受普通删除、出售或锁定，资产只能经卸除整枚返还背包。

孔位绑定装备槽而不是护石实例：34、35 号槽上仍留有任一已装符文时，该护石不能卸下，也不能与背包或另一护石槽的护石互换，ACK19 回错误 23；必须先卸符文再卸护石，避免符文留在原槽错挂到另一枚护石。

护石和符文装入均检查等级、职业、首转、期限和安全锁；卸下允许返还没有父护石的孤立符文，父护石存在且锁定时拒绝。卸下、替换和重锻复用库存计划与单次事务，失败不产生部分资产变更。锁外规划后，回锁复验角色引用、选角 epoch、阶段与原始库存，再提交；成功回包只使用实际提交回执。

三孔颜色位于 `Extension114.Value` 的低 24 位；高字节、扩展 Flag、旧 `ItemCore.Rune:u16` 及 `Extension119` 保留。新实例与重锻共用服务端生成策略：五色等权、不重复抽三色。该策略不是已证明的原服概率；旧实例的重复颜色仍合法。重锻从 Main 指定材料格扣除当前资源表声明数量，同时替换护石背包目标的孔色，不额外重建实例或清除其他核心属性。

## 合成

合成按材料族（符文 0、护石 1）与模式（普通 0、当前转职 1）查 `[compound info]` 的件数与金币。材料必须全部位于容器 46 的背包格、同族同品级、未到期且未加锁；同一格重复引用按出现次数扣堆叠，无堆叠的护石因此必须用三枚独立实例。总件数必须等于资源声明值，扣料、扣费与产物在同一库存事务提交，容量不足整笔拒绝，不产生部分资产变更。

升档只在模式 0 且该行升档权重为正时判定，概率为 `升档权重 / (升档权重 + 同档权重)`：普通符文可升高级、高级可升稀有，稀有护石可升神器。末档（稀有符文、神器护石）与模式 1 的权重是 `0 / 10000`，所以当前转职合成恒产出相同品级，与客户端说明「只有普通合成有一定几率获得高稀有度」一致。

产物在对应品级池中抽取：普通合成从全部同品级定义抽取，当前转职合成只从本人等级、职业、首转可用的定义抽取，材料本身也须可用。产物可能并入已有堆叠，回执槽位按合并前后的数量差定位，不按「新出现的实例」查找。成功回执是通用成功字节后接 `目标槽:u16 + 物品编号:u32 + 升档标记:u8`，失败回通用失败加错误码，并以覆盖全部 216 格的容器 46 差量恢复显示。

合成回执在客户端只清空合成窗格并重画，不写物品容器。因此回执**之前**的容器 46 差量必须同时覆盖产物槽与本次扣减的全部材料格；只预载产物槽时，回执重画会按旧容器把材料画回背包，直到回执后的绝对差量到达才消失（表现为材料「回背包再消失」）。装载/卸除不同：源槽由客户端拖拽自行移动，ACK 清理时才归还预留数量，预载只含目标槽。

## 随机箱

`[stackable type]` 为 `` `[legacy]` 0 `` 的消耗品，若根级恰有两段完整 `[action type]` 且正文为 `` `[rune random box]` 族 档 ``，进入独立的符文/护石随机箱入口：族 0 取符文行、族 1 取护石行，档为非负整数。该声明没有物品文件内的本地奖池，候选来自 `etc/runesystem.etc` 的 `[random choose info]`；其他 `[legacy]` 声明或其他动作类型仍按未实现拒绝，CMD160 也不能消费这类物品。当前资源中同一形状的18件箱子（含 `[usable job] [all]`、部分带 `[action usable place] village`）全部由声明驱动，新增同类箱子不需要改代码。

[InventoryBoosterService.OpenLottery](../../Server/DfoServer/Game/Inventory/Services/InventoryBoosterService.cs) 对主背包源格按 CMD27 模式0消费一只。读取产物池和随机抽取前，复验源实例与模板的编号、类别以及角色等级、职业、已学技能和禁用资格，沿用普通礼包的源资格规则；资格不符不消费源、不抽取。[RuneBoxSelection](../../Server/DfoServer/Game/Inventory/Services/RuneBoxSelection.cs) 的抽取顺序固定：先掷0–9999的本职业骰，再按该行全部 `品级 权重` 的总权重掷品级，最后在该品级的候选池内等概率取一件。候选池由 [ItemCatalog](../../Server/DfoServer/GameWorld/Items/ItemCatalog.cs) 按品级给出，只含 `rune/` 堆叠模板或非占位护石装备，并按角色等级、职业、首转过滤可用性；本职业骰命中但该档没有本职业可用产物时退回全体池，不因某职业缺高档产物而固定失败。表行缺失、总权重非正或骰值越界明确拒绝，不重掷、不补默认档。本职业权重10000即恒为本职业：`chn_490014161`的`[explain]`写明「开启后，可以随机获得1个自身职业的稀有护石。」，与其族1档3的10000及2级品级一致。服务端不执行该类物品的`[cool time]`，与既有袖珍罐入口一致。`[need material]`（如10310946声明10310947×100）沿既有政策只作商店售价，不成为开箱成本；带`[weekly delete item]`的箱子（10311013、10311014）在新建实例时由`ItemExpiration.Resolve`冻结到下一个周四的UTC+8 06:00，选角时按实例`ExpireTime`清理；合并上游前已存在的零期限旧实例不重算下一周、也不写成永久上限，具体规则见[背包与装备](背包与装备.md)。

源消耗、产物发放、角色 revision 与审计在同一库存事务提交，容量按释放源格后规划。产物必须恰好落入容器46的一格（护石0–69、符文70–209）；该页满时整笔拒绝并保留源，错误4。提交成功后先回130B ACK27，再发主背包 NOTI13 全量与容器46 NOTI13 全量：客户端确认后立即读取奖励容器，只发 NOTI14 增量会留下其预置的奖励槽。ACK 的123B记录取实际提交槽位与完整核心；护石不可堆叠，记录的数量字段是实例品级值而非1。

## 整理

护石窗口的整理请求是 CMD20，分类字段是客户端页面号而不是 `ItemKind`：`18` 为符文页 70–209、`19` 为护石页 0–69，旧值 11/14 等价；其他页面号或把页面号发给 Main 一类容器直接拒绝。已装符文 210–215 绑定装备槽，不属于任何背包页，任何整理都不移动。

条件是菜单编号，`1` 为按品级：护石按稀有度、符文按资源声明品级降序（符文品级不能读模板稀有度）。其余取值（含默认项和菜单里的按组织）回页面默认，护石页按等级降序，符文页按阵营归组再按品级降序。整理只在所属页内重排，不跨页搬运；整理锁实例保持原位，其余实例从页首连续回填、页尾空槽收回。菜单编号由客户端决定，服务端把原始分类与条件写进 `sort_item` 日志，便于按实机值校正映射。

成功且确有变化时，ACK20 后先发 `1681` 清空、再发 `1681` 全量差量，最后补一次容器 46 全量 `NOTI13`：护石窗口与图鉴符文页只在容器 46 全量到达后重新装载，只发差量时页面维持旧顺序。零变化整理按协议只回 ACK，不额外补发。

## 同步与未实现边界

登录发送容器 46 全量，普通变化使用同容器差量。装载与卸除成功后补发一次**覆盖全部 216 格**的容器 46 差量（NOTI14，空槽为清空条目），不用 NOTI13 全量：NOTI13 会让客户端重建整个容器列表，不利于保留图鉴符文页的当前状态；差量就地更新槽位，同时以清空条目冲刷拖拽期间残留的槽位状态，该页无需切页即可继续拖拽。业务拒绝同样以该 216 格差量恢复，客户端状态与存档一致。护石孔中的符文（210–215）不改变外观、不进属性，装载与卸除**不再补发本人 USERINFO**：0x067B/0x067C/0x06CE 回执由客户端自行完成 210–212→装备键 34、213–215→装备键 35 的联动（0069A170/0069A4A0），而补发的 USERINFO 会走 0267C4F0→023C3A90 重灌六符文向量并触发护石面板刷新（00698B70），是图鉴符文页在按技能筛选时整页退回「所有技能」的唯一未排除触发路径。装载槽中的真实实例只持有一份，装备尾部编号向量仅是效果投影，不再创造道具。

重锻结果窗立即按回执槽位读取孔色，因此成功先投影已提交目标，再发送回执，最后发送权威差量覆盖客户端预留返还。业务拒绝发送失败回执并恢复容器显示。

合成、升档与整理已接入业务和回执；仍未验证的是回执末尾升档标记在客户端的显示效果、整理菜单的分类与条件实机值（服务端记录原始值），以及合成窗口的实机交互。邮件附件 Type 使用来源容器号，服务端接收 46 的背包格并在回执后恢复权威数量，装载槽不能直接寄送；客户端护石界面的附件选择路径尚未实机确认。装载、卸除、拒绝后的 216 格容器差量、重锻、合成、整理与登录迁移已由 TCP 回归覆盖，客户端验收仍待实机进行。
