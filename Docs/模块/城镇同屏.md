# 城镇同屏与连接发送

本模块依赖[认证与会话](认证与会话.md)，目标为匹配的 x86 客户端。已接入不同账号同频道的场景成员、Actor快照、位置广播和离场；同频道可见性和移动已通过双客户端验收，长期运行仍需验证。已接入穿脱提交后的同场景装备摘要刷新；组队、副本成员与战斗广播不由本模块管理，换装画面仍需双客户端验收。

原生登录使用实际认证的不同账号建立多人场景成员，开发账号也遵循相同规则；不能用同一账号反复接管冒充两名玩家。

## 场景身份与进入

[TownPresence](../../Server/DfoServer/Network/Projection/TownPresence.cs) 的场景键为 `服务器分组 + 频道号 + town + area + 当前PVF地图路径`，地图路径按角色已完成任务解析阶段。房间额外加入账号名，其他账号不会进入该角色的房间成员集合；共享房间资源38/1不意味着所有账号共享同一房间实例。同一城镇区域但不同频道或不同PVF地图阶段的角色也不互发快照。

actorId使用角色库的全局u16角色ID，不能使用每账号重复的slot，也不从进程ID或连接号生成。每次成员接入有独立的membership序号，连接、账号lease及membership引用共同识别本次成员身份。

分类频道共用同一在线目录和场景索引，但仅城镇同屏按频道隔离：不同频道不互发角色入场、移动、外观刷新或离场。账号owner、角色资产、公会及其他玩法仍沿原共享业务处理，不因本模块拆分存储或业务状态；端点及登录身份见[帧与频道](../协议/帧与频道.md#分类入口与共享服务)。Actor记录头采用本次成员的频道身份，同场景接收者具有相同身份，远端角色进入其本地角色表；来源角色仍按真实UID、owner和场景校验。包体只在本次同场景投递内复用，不建立跨请求或跨epoch缓存。

成员同时按连接、角色ID和场景索引。进入、移动、外观刷新和离场只枚举对应场景的接收者；最后一名成员退出时删除空场景集合。替换角色成员时按角色ID直接定位旧连接，移动或刷新不能改变当前成员的角色ID。三个索引由独立成员锁维护，旧连接的迟到清理不会删除新成员。

选角只在本人完整入城序列、NOTI124发送完成并MarkReady成功后加入成员集合。首次房间仍走原有包序，不增加额外的124。切图成功时先提交位置/返回地区和revision，再离开旧成员集合、清理本人视图、发送原有23→24→可选1379，完成后加入新场景；发送或owner失败不能撤回已提交位置。

同场景进入时，双方分别收到对方的：

```text
(0,2) subtype=0 Actor，count:u16=1
→ (0,3) count:u8=1、actorId:u16、state:u8=0
→ (0,23) actorId:u16、town:u8、area:u8、x:u16、y:u16、direction:u8、显示状态:u8
→ (0,22) actorId:u16、x:u16、y:u16、direction:u8、speed:u16=100
```

使用现有[TownPackets.Actor](../../Server/DfoServer/Network/Builders/TownPackets.cs)的固定字段、真实普通穿戴和原辅助结构；不猜改未知字段。换装由 TownPresence.Refresh 更新当前成员快照，以同一membership发送Actor更新，不通过离场/重入刷新。不发送其他玩家的Player subtype=1、本人属性、任务或技能投影给接收者。

Actor只建立角色资料缓存，不能单凭后续22坐标包创建远端城镇实体。23的远端分支要求该角色已存在且town/area与接收者当前区域一致，随后创建实体并应用位置；不会切换接收者自己的地图。新增入场23纳入原成员消息、场景epoch、可见性复核及有界字节预算；普通移动仍只发22，换装不重复入场。同屏Actor同时携带真实所属公会，沿用[公会基础投影](公会.md#4-数据与归属)。

冒险团昵称作为发送者成员的只读投影快照随Actor发布，规则见[冒险团](冒险团.md#命名与改名)。加入及昵称刷新前由原账号owner读取实际提交名称，再进入成员锁；成员锁内不读库或取得其他账号租约。普通移动与未指定新昵称的外观刷新保留该成员原昵称，昵称更新不替换membership或重复加入。共享包体仍只在本次同频道同场景的投递内复用。

位置样本：角色ID2、x633、y196、direction0、speed100的NOTI22 body为 `02 00 79 02 C4 00 00 64 00`；删除该角色的NOTI6 body为 `02 00`。这两个样本是本模块布局样本，实际角色ID从本次数据库分配，不固定为2。

原字段读宽来自匹配原生路径，成员包序来自服务端自有TCP回归；这些证据不宣称双Windows客户端已显示相同画面。远端方向保持当前持久Direction，位置广播不模拟C2S631的攻击/技能动作，动作和速度完整业务仍待恢复。

## 移动与离场

C2S35/631仍先通过Parser、Ready、PVF可走范围、当前generation和角色revision验证并提交。只有实际坐标变化才发布NOTI22；重复坐标和普通业务拒绝不产生远端位置包，也不改变此前的无ACK合同。C2S36落点仍原样保存和回送x/y，不因同屏增加裁剪或偏移。

返回选角、退出、变更频道、断线、同账号接管和切换场景都移除对应连接的旧成员。接收者只对实际发送过Actor的membership执行NOTI6；没有发送成功的进入包不得随后发送删除，避免客户端查询不存在的actor。已复用ID的新membership不会被旧离场包删除。

光环传送的379出发特效作为本次旧membership离场消息的前置帧投递，而不是依赖离场后必然失效的普通Visible广播。接收方只对已知且匹配的旧actor先播放阶段1、再发送NOTI6；单成员组队传送还在阶段1前加入阶段3准备标记。旧源owner或已改变的接收视图不播放，已知旧actor的删除仍按原规则收尾。该事件不等待其他玩家socket，因此慢接收者不阻塞传送者切图。阶段2复用普通成员广播，排在新场景Actor/状态/区域/位置之后；同频道、同阶段及房间隔离与其他城镇广播一致。原生包体及触发边界见[城镇切图](../协议/城镇切图.md#药剂与光环个人传送)。

本人切图/返回选角前，发送器先对其已知远端actor逐个发送NOTI6，再继续本人场景包或ACK。源连接已过期的排队进入/位置消息会跳过；目标视图epoch已改变的旧场景消息也会跳过。旧连接清理按连接引用执行，不移除新generation成员。

## 锁序、队列与生命周期

[AccountOwners](../../Server/DfoServer/Game/Accounts/AccountOwners.cs)分别保护各账号的业务状态和提交；TownPresence 使用独立成员锁。进入、移动和刷新先验证并持有源账号锁，再更新成员索引；精确离场只取得成员锁。[GameConnectionSender](../../Server/DfoServer/Network/Core/GameConnectionSender.cs)在这些锁内只执行非阻塞入队，锁内不得 await、发包或等待客户端。

锁序为账号锁 → 成员锁 → 发送队列锁；队列锁同时保护移动合并和字节预算。发送泵取出合并位置后释放队列锁，才检查 owner 及成员有效性。持接收账号锁检查成员时，只读取源/目标租约的单向失效状态，不获取另一账号锁；该可见性快照不能用于写库授权，写入必须使用 Lease.Execute。网络写入与发送日志在锁外。

发送失败或队列溢出通过 CancelAsync 立即设置取消状态，回调异步执行，避免持源账号/成员锁时同步进入接收账号清理。每个发送器仅创建一次取消任务，DisposeAsync 等待发送泵和该取消任务收尾；回调只做有界通知或精确清理，不等待发送泵。外部接管的断开回调在账号锁释放后执行，旧 owner 清理不能影响新连接。

每个连接只有一个发送泵，串行分配S2C sequence、构造帧及写socket，防止业务ACK与广播并发写坏帧。可靠本人消息有完成通知，原handler继续按发送完成推进状态。排队上限256项，另有2 MiB字节预算，覆盖排队、正在发送的消息及合并中的移动快照。同一远端membership的未发送位置更新合并为一项，保留最新已提交快照；替换时按新旧大小差值调整预算。必要进入/离场及本人消息不按位置丢弃；任一上限溢出或写入超时5秒结束该接收连接，不阻塞源账号或无关连接。

字节预算按保留包体及帧头计费：本人消息为包体加16B，正式远端快照计入Actor/State/Area/Position及四个帧头，离场/清场消息计18B；共享包体在每个接收连接独立计费。预算用于限制消息积压，不是精确堆上限，另有消息对象、可见成员字典及至多一个正在写出的完整帧。发送、跳过旧epoch/guard拒绝及失败清理均释放对应额度；可靠发送释放额度后才完成通知，关闭时所有等待任务结束并清空移动快照。

携带光环出发特效的离场消息另计特效包体与16B帧头，普通/升级个人共38B，单成员组队再含阶段3准备帧共58B。正常发送、旧视图/源owner失效及取消都释放同一消息的完整额度；不因绑定多帧而跳过既有队列数量、字节上限或写入超时。

同一次成员更新的公共 Actor、State、Area、Position 包体只构造一次，以 `ReadOnlyMemory<byte>` 共享给当前场景接收者；构造后的底层数据不再修改，也不跨更新复用旧内容。目标可见性检查仍各自绑定 source/target membership 和 epoch；完整帧、sequence 与 CRC 在各连接发送泵中生成。广播先固定场景接收者快照再入队，异步取消清理仍按精确连接与成员身份移除。

每次写前检查目标owner，异步写完再次检查；成员消息另检查source/target引用、源generation和目标epoch。和原发送合同一样，检查与已开始的socket写入不构成原子区间，接管仍可能与在途旧帧交叠；本模块不宣称消除了在途帧。FIFO、membership判断及后续清理保证旧消息不在新成员快照后覆盖新身份。

取消、发送失败和正常结束都会完成或失败所有可靠发送等待者，关闭发送泵、清空合并位置、移除精确成员及释放原lease。成员和视图是在线状态，不写SQLite、不跨重启恢复；角色位置仍由原Repository事务恢复。

## 验证与实机场景

[TownPresenceTests](../../Server/DfoServer/SelfTests/TownPresenceTests.cs)覆盖房间隔离、慢接收者与移动合并、可靠队列顺序、最新坐标、离场/重复清理、旧generation、未见Actor不得删除、接收者旧epoch及资源释放。在途用例先写出半个Actor帧再接管源账号，验证旧Actor按`2→6`收尾、失效State/Area/Position不发送、新membership按`2→3→23→22`进入，旧连接迟到清理后仍可发送新坐标；不以此声称消除了在途旧帧。[C# 同屏 TCP 回归](../../Server/DfoServer/SelfTests/Tcp/TownPresenceTcpTests.cs)使用两个不同认证账号、独立临时库和真实TCP，验证公共入场快照、移动、无效/重复坐标静默、切图清场、接管、重新入场、返回选角、完整包序、CRC及每连接sequence。

[场景索引测试](../../Server/DfoServer/SelfTests/TownPresenceIndexTests.cs)覆盖服务器分组和频道隔离的入场、移动、外观刷新、离场及换频道后的新成员；[分类入口TCP](../../Server/DfoServer/SelfTests/Tcp/ChannelEntryTcpTests.cs)在同一服务的不同实际入口验证不同频道不互发城镇包、换入相同频道恢复互见、换出后不再入场，同时保留共享角色库、设置回放、非gate位置和跨入口账号接管的覆盖。

```powershell
dotnet build ServerS5A9.sln -c Debug --nologo
dotnet run --project Server/DfoServer -- --selftest
dotnet run --project Server/DfoServer -- --selftest-tcp
```

实机验收使用两个不同账号登录。先确认私人房间互不可见，再分别进入同频道、同一公开PVF阶段的街道，检查双方角色、短方向键后的远端坐标与画面、进出房间、返回选角、重登和自然退出；关联同一时段的发送包及已提交revision。切到不同频道后应互不可见，回到同频道应重新入场；这部分需独立实机确认，不能把TCP通过写成画面通过。
