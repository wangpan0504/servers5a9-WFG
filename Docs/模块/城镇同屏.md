# 城镇同屏与连接发送

本模块依赖[认证与会话](认证与会话.md)，目标为匹配的 x86 客户端。已接入不同账号的场景成员、Actor快照、位置广播和离场，自测与隔离TCP通过；真实双客户端可见性、移动表现和长期运行仍待Windows验收。已接入穿脱提交后的同场景装备摘要刷新；组队、副本成员与战斗广播未接入，换装画面仍需双客户端验收。

原生登录使用实际认证的不同账号建立多人场景成员，开发账号也遵循相同规则；不能用同一账号反复接管冒充两名玩家。

## 场景身份与进入

[TownPresence](../../Server/DfoServer/Network/Projection/TownPresence.cs) 的场景键为 `town + area + 当前PVF地图路径`，地图路径按角色已完成任务解析阶段。房间额外加入账号名，其他账号不会进入该角色的房间成员集合；共享房间资源38/1不意味着所有账号共享同一房间实例。同一城镇区域但不同PVF地图阶段的角色也不互发快照。

actorId使用角色库的全局u16角色ID，不能使用每账号重复的slot，也不从进程ID或连接号生成。每次成员接入有独立的membership序号，连接、账号lease及membership引用共同识别本次成员身份。

成员同时按连接、角色ID和场景索引。进入、移动、外观刷新和离场只枚举对应场景的接收者；最后一名成员退出时删除空场景集合。替换角色成员时按角色ID直接定位旧连接，移动或刷新不能改变当前成员的角色ID。三个索引由独立成员锁维护，旧连接的迟到清理不会删除新成员。

选角只在本人完整入城序列、NOTI124发送完成并MarkReady成功后加入成员集合。首次房间仍走原有包序，不增加额外的124。切图成功时先提交位置/返回地区和revision，再离开旧成员集合、清理本人视图、发送原有23→24→可选1379，完成后加入新场景；发送或owner失败不能撤回已提交位置。

同场景进入时，双方分别收到对方的：

```text
(0,2) subtype=0 Actor，count:u16=1
→ (0,3) count:u8=1、actorId:u16、state:u8=0
→ (0,22) actorId:u16、x:u16、y:u16、direction:u8、speed:u16=100
```

使用现有[TownPackets.Actor](../../Server/DfoServer/Network/Builders/TownPackets.cs)的固定字段、真实普通穿戴和原辅助结构；不猜改未知字段。换装由 TownPresence.Refresh 更新当前成员快照，以同一membership发送Actor更新，不通过离场/重入刷新。不发送其他玩家的Player subtype=1、本人属性、任务或技能投影给接收者。

## 匹配客户端依据

| 信令/处理 | 原生路径与已确认边界 |
|---|---|
| Actor本人区分 | `0267DA20`读取Actor；`0267DA8C`读取u16 ID。`0267DC34`本人路径进入`02676E60`；`0267DC3F..0267DC9E`另按ID查询/建立远端对象。现有后部固定byte通过`0267E0A8`读取、写DTO bool，完整业务名仍待确认，保持Builder现值 |
| NOTI22 | 在`023E2AE3`注册到`023D2790`；`023D27A1/27AD/27B9`读3个u16、`023D27C7`读u8、`023D27D7`读u16，共9B |
| NOTI22远端分支 | `023D27E0`按actorId查询；`023D2870`与本人ID比较，不等时进入远端路径。`023D28D2..023D28EE`将位置、方向和速度送入远端对象方法；未建立对象的情况不能代替Actor进入快照 |
| NOTI6 | 在`023E2A63`注册到`023D1790`；`023D179F`只读一个u16，`023D1929`调用`02D93780`，按该ID查询并移除客户端actor；不是ACK6，也没有count前缀 |

位置样本：角色ID2、x633、y196、direction0、speed100的NOTI22 body为 `02 00 79 02 C4 00 00 64 00`；删除该角色的NOTI6 body为 `02 00`。这两个样本是本模块布局样本，实际角色ID从本次数据库分配，不固定为2。

原字段读宽来自匹配原生路径，成员包序来自服务端自有TCP回归；这些证据不宣称双Windows客户端已显示相同画面。远端方向保持当前持久Direction，位置广播不模拟C2S631的攻击/技能动作，动作和速度完整业务仍待恢复。

## 移动与离场

C2S35/631仍先通过Parser、Ready、PVF可走范围、当前generation和角色revision验证并提交。只有实际坐标变化才发布NOTI22；重复坐标和普通业务拒绝不产生远端位置包，也不改变此前的无ACK合同。C2S36落点仍原样保存和回送x/y，不因同屏增加裁剪或偏移。

返回选角、退出、变更频道、断线、同账号接管和切换场景都移除对应连接的旧成员。接收者只对实际发送过Actor的membership执行NOTI6；没有发送成功的进入包不得随后发送删除，避免客户端查询不存在的actor。已复用ID的新membership不会被旧离场包删除。

本人切图/返回选角前，发送器先对其已知远端actor逐个发送NOTI6，再继续本人场景包或ACK。源连接已过期的排队进入/位置消息会跳过；目标视图epoch已改变的旧场景消息也会跳过。旧连接清理按连接引用执行，不移除新generation成员。

## 锁序、队列与生命周期

[AccountOwners](../../Server/DfoServer/Game/Accounts/AccountOwners.cs)分别保护各账号的业务状态和提交；TownPresence 使用独立成员锁。进入、移动和刷新先验证并持有源账号锁，再更新成员索引；精确离场只取得成员锁。[GameConnectionSender](../../Server/DfoServer/Network/Core/GameConnectionSender.cs)在这些锁内只执行非阻塞入队，锁内不得 await、发包或等待客户端。

锁序为账号锁 → 成员锁 → 发送队列锁；队列锁同时保护移动合并和字节预算。发送泵取出合并位置后释放队列锁，才检查 owner 及成员有效性。持接收账号锁检查成员时，只读取源/目标租约的单向失效状态，不获取另一账号锁；该可见性快照不能用于写库授权，写入必须使用 Lease.Execute。网络写入与发送日志在锁外。

发送失败或队列溢出通过 CancelAsync 立即设置取消状态，回调异步执行，避免持源账号/成员锁时同步进入接收账号清理。每个发送器仅创建一次取消任务，DisposeAsync 等待发送泵和该取消任务收尾；回调只做有界通知或精确清理，不等待发送泵。外部接管的断开回调在账号锁释放后执行，旧 owner 清理不能影响新连接。

每个连接只有一个发送泵，串行分配S2C sequence、构造帧及写socket，防止业务ACK与广播并发写坏帧。可靠本人消息有完成通知，原handler继续按发送完成推进状态。排队上限256项，另有2 MiB字节预算，覆盖排队、正在发送的消息及合并中的移动快照。同一远端membership的未发送位置更新合并为一项，保留最新已提交快照；替换时按新旧大小差值调整预算。必要进入/离场及本人消息不按位置丢弃；任一上限溢出或写入超时5秒结束该接收连接，不阻塞源账号或无关连接。

字节预算按保留包体及帧头计费：本人消息为包体加16B，远端快照计入Actor/State/Position及三个帧头，离场/清场消息计18B；共享包体在每个接收连接独立计费。预算用于限制消息积压，不是精确堆上限，另有消息对象、可见成员字典及至多一个正在写出的完整帧。发送、跳过旧epoch/guard拒绝及失败清理均释放对应额度；可靠发送释放额度后才完成通知，关闭时所有等待任务结束并清空移动快照。

同一次成员更新的公共 Actor、State、Position 包体只构造一次，以 `ReadOnlyMemory<byte>` 共享给当前场景接收者；构造后的底层数据不再修改，也不跨更新复用旧内容。目标可见性检查仍各自绑定 source/target membership 和 epoch；完整帧、sequence 与 CRC 在各连接发送泵中生成。广播先固定场景接收者快照再入队，异步取消清理仍按精确连接与成员身份移除。

每次写前检查目标owner，异步写完再次检查；成员消息另检查source/target引用、源generation和目标epoch。和原发送合同一样，检查与已开始的socket写入不构成原子区间，接管仍可能与在途旧帧交叠；本模块不宣称消除了在途帧。FIFO、membership判断及后续清理保证旧消息不在新成员快照后覆盖新身份。

取消、发送失败和正常结束都会完成或失败所有可靠发送等待者，关闭发送泵、清空合并位置、移除精确成员及释放原lease。成员和视图是在线状态，不写SQLite、不跨重启恢复；角色位置仍由原Repository事务恢复。

## 验证与实机场景

[TownPresenceTests](../../Server/DfoServer/SelfTests/TownPresenceTests.cs)覆盖房间隔离、慢接收者与移动合并、可靠队列顺序、最新坐标、离场/重复清理、旧generation、未见Actor不得删除、接收者旧epoch及资源释放。在途用例先写出半个Actor帧再接管源账号，验证旧Actor按`2→6`收尾、失效State/Position不发送、新membership按`2→3→22`进入，旧连接迟到清理后仍可发送新坐标；不以此声称消除了在途旧帧。[C# 同屏 TCP 回归](../../Server/DfoServer/SelfTests/Tcp/TownPresenceTcpTests.cs)使用两个不同认证账号、独立临时库和真实TCP，验证公共入场快照、移动、无效/重复坐标静默、切图清场、接管、重新入场、返回选角、完整包序、CRC及每连接sequence。

```powershell
dotnet build ServerS5A9.sln -c Debug --nologo
dotnet run --project Server/DfoServer -- --selftest
dotnet run --project Server/DfoServer -- --selftest-tcp
```

实机验收使用两个不同账号登录。先确认私人房间互不可见，再分别进入同一公开PVF阶段的街道，检查双方角色、短方向键后的远端坐标与画面、进出房间、返回选角、重登和自然退出；关联同一时段的发送包及已提交revision。无法完成双账号实测时保留验收缺口。当前黑屏/捕获实时性问题未解决，不能把TCP通过写成上述画面通过。
