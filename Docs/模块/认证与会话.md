# 认证与游戏会话

服务端只接受客户端原生的预检查与 LOGIN 凭据登录，不提供开发免认证、启动票据或 C2S171 认证扩展。启动使用命令行，不读取 JSON 运行配置，不校验客户端来源 IP。

## 登录与账号

[LoginHandler](../../Server/DfoServer/Network/Handlers/LoginHandler.cs)先发送频道握手，处理预检查与 LOGIN，验证成功并取得账号 owner 后才发送端点和角色名册。原生字段、包序与失败边界见[原生登录协议](../协议/原生登录.md)。

登录 Handler 通过 [ILoginAuthenticator](../../Server/DfoServer/Game/Auth/ILoginAuthenticator.cs)调用 [AuthenticationService](../../Server/DfoServer/Game/Auth/AuthenticationService.cs)。认证服务负责输入规则、归一化、首次建号决策、凭据派生/验证及身份生成，通过 [IAccountCredentialStore](../../Server/DfoServer/Game/Auth/IAccountCredentialStore.cs)访问存储；Runtime 显式装配服务与 [AuthenticationRepository](../../Server/DfoServer/Persistence/AuthenticationRepository.cs)。仓储只管理 `game.db` 中 `accounts` 表的读取、唯一键插入、密码更新和禁用状态，不生成登录身份，不接收原始密码或登录摘要。

原生登录账号为 1..30 位 ASCII 字母、数字、下划线或连字符，归一为小写；凭据为 32 位十六进制摘要，归一后以随机盐和 PBKDF2-SHA256 保存，不保存原摘要。账号不存在时自动创建；并发首次登录通过数据库唯一键竞争，创建之后读取并验证持久凭据，不能把插入冲突当作认证成功。同凭据可各自验证通过，不同凭据只有持久化的那一份通过。禁用账号与错误凭据均拒绝；其他约束及存储故障向上传递，不作为重复账号忽略。

既有账号登录只读取一次凭据快照，派生和验证在数据库连接释放后执行；不为校验申请写事务或建立跨请求凭据缓存。密码更新、启用和禁用原子递增 revision。身份记录本次读取的凭据 revision，不表示持续追踪管理员后续变更，也不自动中止已经认证的在线会话。

开发账号固定为 `10000`，初始凭据是密码 `123456` 的 MD5：`e10adc3949ba59abbe56e057f20f883e`。启动时只创建缺失账号，后续启动不重置已修改的密码或禁用状态。开发账号同样走原生凭据校验，没有自动登录特例；GM 和离线角色工具的默认账号也是 `10000`。

账号表与角色、物品等数据共用 `Data/game.db`，建库和版本检查见[数据库](../开发/数据库.md)。

## 会话与退出

- [AuthenticatedIdentity](../../Server/DfoServer/Game/Auth/AuthenticationModels.cs)保存账号、认证会话 ID、有效期、客户端地址、协议版本及凭据 revision。有效期目前是身份元数据，不是在线强制踢出计时器。
- [AccountOwners](../../Server/DfoServer/Game/Accounts/AccountOwners.cs)使用精确 lease/generation 保护账号。原生登录策略固定 `ReplaceExisting`，认证成功后才替换旧连接；错误凭据不能接管原连接。旧连接不能写入或释放新 owner。内部离线 GM 占用仍使用 `Reject`，不会挤掉在线玩家。
- 业务执行、接管和释放共用该账号的锁；不同账号不共用业务锁。接管等待当前同步工作完成，再安装新代数并在锁外断开旧连接。注册表只做短操作，最后一个 owner 和等待获取者退出后回收锁条目；断开回调失败时清理调用方未取得的新租约，保留回调重入时已安装的更晚租约。锁序及 SQLite 竞争边界见[架构规范](../规范/服务端架构.md#现有锁与吞吐限制)。
- [OnlineSessionDirectory](../../Server/DfoServer/Game/Session/OnlineSessionDirectory.cs)按准确 Session 引用维护在线索引，网络与 GM 使用同一个 Session；不同已认证账号接入[城镇同屏](城镇同屏.md)。
- 返回选角保留账号 owner 和 TCP；退出发送原生 ACK 后关闭并释放资源。重新建立连接时重新执行原生登录，不发行频道续接票据。位置和资产已逐次提交，退出不重复写入。

## 验证与限制

认证成功后，LOGIN 的 Endpoint 同时返回独立 Native 连接地址和非零随机关联值。Native 传输索引只持有本次 `GameConnectionContext` 引用；账号 owner/generation、在线 Session、选角及副本状态仍由原连接拥有。首个 Native 帧在同一账号锁内核对精确注册和在线 Session，每次处理前重新核对租约；新 Native 连接替换旧连接，旧 finally 只释放自己的租约。主连接结束或被接管后，旧关联失效并取消对应 Native 读取，不能按账号名转接到新会话。取消回调失败记录 `native_disconnect_failed`，继续其它传输与主会话清理。

Native 中继只接受当前正式副本实例、同一房间及真实成员槽位；好感NPC出场另核对已清图事实、资源资格及队长身份，单人仅开放该消息和其确认记录的原生回送。其它上下文仍只保留脱敏长度诊断，不推进任务、生成掉落或返回猜测的成功 ACK。中继沿原Session和实例生命周期失效，不另存在线角色；每个Native发送队列有界，慢连接只关闭其Native传输。关联值是明文传输材料，不提供链路保密；LOGIN 回复和 Native 原始帧均不进入普通日志或抓包正文。外层与端口合同见[帧与频道](../协议/帧与频道.md#native-独立连接)。

无资源自测分别覆盖认证用例和 SQLite 存储：非法输入无存储副作用、已有账号只读、首次创建竞争、凭据校验与身份元数据、开发账号初始化、外部 writer 下读取、非重复约束故障及更新失败回滚，并保留账号与角色共用单库、基线检查和重开。独立 TCP 的 `native-login`、`authentication`、`presence` 组覆盖原生登录、错误凭据不接管、账号隔离、重启、开发账号、旧格式拒绝和同屏。执行方法见[贡献指南](../../CONTRIBUTING.md#验证)。已记录的客户端原生登录验证及未覆盖场景见[原生登录协议](../协议/原生登录.md)；双客户端画面仍待验收，自动化结果不能代替当前构建的实机验证。

认证失败的原生错误码映射尚未确认，当前拒绝时关闭连接，客户端可能显示网络中断。凭据不写普通日志；现有明文通信不提供链路保密，频道兼容 key 不改变这一点。
