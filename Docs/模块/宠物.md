# 宠物

宠物实例继续使用统一库存的UID、完整Core和`CreatureDetail`。背包中的宠物不参加成长，只有装备槽26的未到期、非蛋实例参加饱食、经验、交互和进化；宠物装备占27–29。容器、穿脱、交易限制、锁和到期清理仍由[背包与装备](背包与装备.md)负责，孵化沿用[宠物蛋协议](../协议/宠物蛋孵化.md)。

## 资源与成长

[CreatureCatalog](../../Server/DfoServer/GameWorld/Creatures/CreatureCatalog.cs)共享启动装配的PVF与装备、堆叠列表。EQU的`[creature species]`关联`creature/creature.lst`，CRE原始声明由[PvfLib解析器](../../Tools/PvfLib/Creatures/CreatureFile.cs)读取；玩法层不重新解释token，也不使用物品图鉴构造进化产物。

- 普通宠物使用`creature/exptable.tbl`累计经验阈值，等级上限取CRE的`[max level]`，不套角色等级。装备宠物饱食为0、已满级或处于道具成长模式时不获得普通通关经验。
- 经验在正式通关原事务发放，点数取原实例实际首次完成加载的房间数。普通和剧情副本都参与，回访同一房间不重复计点；训练、修炼场、职业体验及剧情回放不发放。开发无限疲劳不抹掉该计数，也不因宠物成长额外扣疲劳。怪物经验包不直接追加宠物经验。
- 已开放的CRE红、蓝、绿装备槽中，合法宠物装备的`[creature experience amount rate]`修正经验，满足其宠物等级和实例期限；合计百分比在本次基础点数上向零截断。实际依赖的装备期限也参与提交复验。
- `[selective grow creature]`是嵌套资源块。`[using exp item]`及声明的A/B/EXP物品决定道具成长，不把所有饲料都当作经验。每级次数取嵌套的`[item count for levelup]`，缺省或0为25。A增加亲密、B减少亲密，范围0–10、初值5；EXP道具按`[add EXPtype exp value]`增加成长次数，不改变亲密。实际存在的`[need material]`与源道具、宠物成长同事务消费，材料不足整笔拒绝。
- 道具成长保存独立`Mode=1`、累计成长次数及两个亲密字段，不照搬旧端DB中打包的整数。新发放实例按资源初始化；旧mode0成长宠物装备后归一到道具模式，不分配新UID。

## 饱食与功能

[Session时钟](../../Server/DfoServer/Game/Session/GameSession.Creatures.cs)绑定当前角色、选角epoch及装备UID，不保存另一份在线宠物。战斗基础每60秒减少1点，休息每360秒恢复1点；`[creature food consume rate]`叠加修正战斗消耗。采用1/36000点保存余数，常规每60秒合并持久化，换宠物、相关消耗及退出前结余；忙碌的加载或未决事务不强行写入。切角、换UID、接管后的旧时钟不能提交给新角色。

饱食降到0通知宠物离场；喂食或回城休息恢复后发送复活与饱食通知。饱食最多100，归零和封顶丢弃越界余量。

本版客户端`02CF06B0`检查低饱食、搜索feed物品并进入原生使用链，服务端不再独立定时扣另一份饲料。主动和自动使用都走CMD44；普通`[feed] 1`的`[int data]`提供持续秒数、技能集气修正和饱食恢复量。服务端先提交实际源扣除和宠物详情，再发送原生消费ACK与103，不用源库存增量重复消费。冷却窗口内完全相同请求结果存在歧义时关闭原连接，重连从实际存档恢复，不重复发送消费ACK。

技能、蓄气、动作和饲料的本地技能效果由客户端按CRE/STK执行。服务端提供真实等级、模式、装备和存活状态，不另外伪造客户端技能或伤害引擎；饲料效果不在重登时补播消费ACK。

## 交互与进化

换名卡按`[creature] 1`识别，不固定物品编号。CMD100消费原Pet源槽一张卡并保存当前装备宠物名称；名称必须能用CP936表示、少于20字节且不含控制字符，空名称保留原生恢复默认名入口。CMD101在城镇响应当前账号宠物，客户端携带的引用不能操作他人的实例。

宠物主动喊话114与脚本消息122支持当前场景类型2/3；发言者从当前会话重建，不信任请求中的角色引用。城镇通知复用原同屏索引及有界发送队列，按频道、地图和私人房间隔离；正式单人副本只回本人。私聊、跨服等聊天类型不冒充成功。

进化有三条入口：

1. 普通经验升级达到CRE`[evolution level]`且没有进化任务时自动进化。
2. 道具成长达到`[grow level]`且不要求进化任务时，按亲密度选择A/B种类；本次EXP成长道具采用声明的EXP种类。
3. 带`[creature kind]`/`[creature level]`的任务核对当前装备宠物，进度沿原任务事件推进。`[creature evolution]`奖励是目标种类，不是普通物品编号；材料、宠物转换、完成位及领奖回执在原任务事务保存。穿戴或成长只在实际宠物任务候选变化时刷新列表；CMD479主动刷新实际资格，不代替接取、完成或领奖。

已确认的宠物进化任务允许省略`[difficulty]`，按ARAD `04333710`与旧端`QuestParameterScript::getRewardWeight`的默认100%权重计算角色经验，其余经验规则仍沿统一任务策略。冻结回执保留空键表示未声明，不修改PVF或补造难度标签；显式未知键仍拒绝，也不放宽其他普通任务的缺省声明。真实2102使用32级佛尔卡斯（63001、species2），通关条件达成后原UID进化为菲尼克斯（63002、species3），并非直接发放species编号对应的物品。

STK的`[change creature]`使用CMD515/action64选择Pet背包中的成宠，与上述三种进化分开。515沿用单一分发入口，任务券动作不变；资源与随机规划在账号锁外，提交复验原owner、选角epoch、阶段、快照及期限，源书、额外材料和目标模板在同一库存事务保存。仅已Ready城镇且无活动占用时可操作；错误容器、安全锁、宠物蛋、源模板不符、期限或材料不足均拒绝。

已接入两种资源形状：动作前两参数指定源/目标、末项为`-1`的固定转换，以及`-1 -1 ... 0`配合源白名单和第0组结果表的权重转换。第三参数是客户端确认窗口样式，不用作概率；结果表保留原序及重复项，抽取前验证完整候选。未确认的非零末项、其他结果分组及穿戴目标不猜测实现。角色等级、职业、所需技能、独立`[creature minimum level]`与`[need material]`仍参与资格检查。

转换只修改原实例的ItemId，保留UID、完整Core、附魔、名字、等级、经验、饱食及原有期限，不重新发宠物或重置获得时间。490705419按资源将400990236转换为400990451；这两种EQU关联的CRE内容相同，因此保持原外观。此处不推广为任意两个外观不同的CRE都自动保留造型。成功ACK自行消费一本书，目标按清槽、详情、完整核心的顺序同步；不给背包目标发送106影响当前装备宠物。请求、ACK及消费者见[STK定向转换](../协议/宠物.md#stk定向转换cmd515--action64)。

上述CRE/QST进化的产物优先采用源EQU的精确`[output index]`。没有该对应时仅接受种类索引中唯一的成宠模板；多个同种类模板不能按编号最小值随意挑选。进化保留UID、名称、等级、经验、期限、锁及其他Core字段，只改变产物模板和相应成长模式。通知原地更新现有宠物，不重发城镇Actor打断副本实体，具体字节见[宠物协议](../协议/宠物.md)。

## 转换组道具

STK的`[action type] [creature growth]`是独立的转换组业务，不是CRE的`[selective grow creature]`喂养，也不使用action64的白名单和结果池。参数依次为界面模式、组编号及有序转换类型列表。匹配`creature/common/creaturegroup.cre`中相同组、类型、实际道具编号和源宠物的首条规则；类型顺序和行顺序均保留，不能按成本、模板编号重新排序，也不能因材料不足回退到后续类型。

| convert type | convert info的解释 |
|---|---|
| 1 固定转换 | 消耗数量、源EQU、目标EQU |
| 2 选择转换 | 消耗数量、源EQU、有序可选目标EQU；客户端提交1基选项，不能选择当前模板 |
| 3 随机转换 | 消耗数量、初始源EQU、N个目标EQU、N个权重；初始源及全部目标均可再次参与，权重总和必须为10000 |
| 4 同型号属性转换 | 消耗数量、同一型号的一组EQU；每项均可作为源，可选同一行的其他属性，不能选择当前模板或跨行改变型号 |

行首是实际道具消耗，不是宠物等级。例如2683441的首段需要30个矿石；选定源堆必须足额，不能沿丢弃归一策略少扣，也不自动合并其他堆支付。2683443使用组1中的类型1、4列表，当前实际匹配类型4，按玩家选择改变属性和颜色；2683444/2683445按类型1附加对应形态，10003716按组2的实际规则转换。目标从资源和合法选项取得，不接受客户端直接指定任意模板。

与action64共享[原UID转换用例](../../Server/DfoServer/Game/Creatures/CreatureChangeService.cs)及库存提交边界，保留完整核心、附魔、详情、期限和位置，只改变模板。仅接受Main源与Pet背包成宠；锁、到期、职业、技能、角色及宠物最低等级、额外`[need material]`继续校验。地点未声明时允许已就绪城镇或合法正式副本/结算阶段，显式仅城镇声明仍拦截图内操作。规划、资源装载和随机在账号锁外；同事务保存全部消耗与转换，旧owner、选角、阶段或快照不能提交或发布。缺失可选转换表不阻止启动，但相应请求不取得转换资格；畸形表不猜测默认规则。

该路径走CMD515/action107。客户端成功ACK不扣源，因此服务端必须在提交及ACK后同步实际源剩余量，再清理Pet旧模板、发布105详情和完整新模板。不复用action64的源差量豁免，也不发送106改变当前穿戴宠物。字节和消费者见[转换组协议](../协议/宠物.md#转换组cmd515--action107)。

## 保存与验证

没有新增库表；饱食小数及饲料记录保存在原宠物详情JSON的可选字段中，旧存档缺字段按0读取。每笔消费、升级和进化仍使用当前owner、完整库存前提和revision；提交后才发布真实UID结果。晚期SQL失败整笔回滚，通关和任务领奖回执阻止重复增加宠物经验或再做进化。

`--selftest-tcp creature-system,creature-dungeon,creature-egg,creature-change,creature-group`覆盖真实PVF资源、原生喂食与改名、道具成长、六房通关升级、进化、STK原UID转换、四类转换组、同报告重放和晚期回滚；核心覆盖转换权重/材料/完整实例、时钟旧UID/epoch/generation以及同屏通知隔离，PvfLib合成用例覆盖嵌套字段、转换组和结果表原始声明及畸形字段。515共享入口的兼容组为`quest-ticket,quest-specified-ticket,quest-awakening-ticket`。TCP及原码核对不能代替Windows实机的宠物技能、低饱食自动操作、动画、对白和任务界面验收。

封印、合成、经验书、胶囊与活动领取属于另外的宠物扩展入口；未确认的323、555、1101请求不返回通用成功，也不借旧端包体填充。
