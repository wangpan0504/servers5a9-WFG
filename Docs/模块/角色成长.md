# 普通成长计划与经验通知投影

目标为 S5A9 x86 客户端。累计经验和等级 SP 贡献来自[成长资源](../资源/角色成长.md)，S2C `(0,37)` 完整直接读取来自[经验通知证据](../协议/经验升级通知.md)。本切片只提供纯领域计划与纯 Builder，没有生产经验来源、Handler、成长仓储或通知发送路径，不代表正常升级、发点或 Windows 客户端验收通过。

## 纯领域计划

[CharacterGrowthPlan.Create](../../Server/DfoServer/Game/Characters/CharacterGrowth.cs) 接收当前 Character、明确的目标等级、目标绝对累计经验与匹配 CharacterGrowthCatalog。当前限定普通 grow0、非 job9/10、已初始化完整两树；旧角色、特殊职业和转职角色不自动重建绑定或补点。

源等级和经验必须处于同一资源区间；目标等级不得降低、经验必须增加，目标经验也必须位于对应等级的 `[GetLevelStartExperience, GetCumulativeExperienceBoundary)` 区间。支持 Lv1..95，Lv95 达到下一边界时拒绝，不猜测封顶截断或 Lv96 业务。开发 GM 的高等级零经验快照拒绝，不以这一计划修复工具数据。

同等级经验增加时 SP 贡献差为0。升一级或跨级时，分别对两树当前剩余 SP 加 `GetSpDelta(旧等级,目标等级)`，保持已消费 SP、两树不同余额、原 TP、技能等级与稳定 slot。任一树超过 u16 余额上界时整计划拒绝，不夹取点数。Lv1 XP0/SP0 至 Lv2 XP1000 时两树各加30；Lv2 当前 SP7/29 至 Lv3 XP2035 时变为37/59，不重置为累计贡献60。

计划冻结 id、revision、job、grow、源等级与完整学习前提，输出目标等级和学习候选，不修改 Character、金币、物品、任务或其他角色状态。计划创建不验证 account generation、不递增 revision、不写库，也不证明输入的经验来自合法事件。

## NOTI37 纯 Builder

[GrowthPackets.Experience](../../Server/DfoServer/Network/Builders/GrowthPackets.cs) 构造 S2C notification category0、opcode37 的 body。正文为 little-endian，完整长度为 `91 + 8*bonusCount`；count0为91B、count255为2131B。方法只排列已确认的直接读取字段，不构建帧或发送消息，不在入城或技能学习路径自动调用。

调用方必须显式提供目标等级、完整两树绝对 SP/TP 与 u64 经验，以及[附属状态和事件分量](../../Server/DfoServer/Game/Characters/CharacterExperienceNotice.cs)：

- `CharacterGrowthAuxiliaryState` 提供决斗胜点、成长胶囊 DWORD 位模式、熟练等级和熟练 u64 经验。没有默认值，不从角色 XP、等级或金币推导。胶囊客户端使用 CDQ 符号扩展，Builder 只保留输入32位位模式。
- `CharacterExperienceDisplay` 提供全部已确认显示分量、原始分支值、额外资源 ID/经验对、扣除分量及 offset75 未引用 DWORD。分支值保留 byte，不伪造完整枚举；额外记录保留顺序，数量上限255。

缺完整技能树、附属 owner 输入或事件显示输入时拒绝，不补零、不省略固定尾部。Builder 不验证经验来源、额外奖励业务或分支语义；这些资格必须在调用方领域事务前确认。新角色普通事件可以显式采用已记录的零附属初值和无额外奖励策略，不能借此覆盖存量未知状态。

## 后续事务与发布前提

生产接入须先建立可信经验事实和稳定事件身份，绑定 account generation、角色、task attempt、instance/epoch 等真实 owner。Repository 应在一个事务内重读当前等级、完整学习前提与所需附属状态，确认来源资格和重复事件，提交经验、等级、两树 SP、事件结果及 revision。当前 CommitLearning 禁止修改经验和授予 SP，不能复用它假装已接入成长事务。

当前正式实例只有内存死亡签发与清图事实合同，没有生产战斗组件、奖励额度规则或可信经验事实owner。等级经验边界不能用作杀怪或通关奖励额度。实例接受死亡会先消费内存事件，随后SQL失败不能靠重放该方法恢复奖励；正式接入须先闭合[死亡事实与提交协调](单人副本实例.md#战斗事件与结算)，再实现成长仓储及通知调用链。

附属字段当前不在 Character 或角色 schema 中，本切片没有迁移或存档默认。正常事件如依赖这些字段，须从明确 owner 提供并定义持久化/迁移边界；未知状态不清零。事务提交后才发布 Selected 和通知，发送失败不重发奖励、扣费或经验事实。完整任务、击杀、结算及经验通知包序仍须分别闭合，不因为 NOTI37 有技能刷新副作用就追加猜测的 NOTI19 或 Player。

## 验证边界

[CharacterGrowthTests](../../Server/DfoServer/SelfTests/CharacterGrowthTests.cs) 使用 C# 和匹配 PVF，覆盖 Lv1→2、Lv2→3、跨级、同等级经验增加、已消费/不同 SP 余额保留、TP和slot保持、源/目标边界、Lv95上界、余额溢出、特殊/旧状态拒绝及集合快照冻结。

[GrowthPacketsTests](../../Server/DfoServer/SelfTests/GrowthPacketsTests.cs) 独立按证据偏移解码，逐字节比较91B文档样本，验证全部非零字段、两树顺序、u64及胶囊位模式、0/2/255个额外记录、固定尾部、短包/长包/count错误和缺输入拒绝。两套测试均接入 SelfTestRunner；公共构建、自测和隔离 TCP 回归按[验证入口](../../CONTRIBUTING.md#验证)执行。

这些测试没有生产成长提交路径，因此不宣称成长事实去重、旧 generation/revision、SQL回滚、提交后发送失败或重登恢复已经由本切片验证。对应测试须随后续 Repository/Handler 接入补齐；普通升级、真实技能使用及 Windows 客户端完整包序仍待验收。
