# 普通成长计划与经验通知投影

目标为 S5A9 x86。累计经验和等级 SP 贡献来自[成长资源](../资源/角色成长.md)，S2C `(0,37)` 完整直接读取来自[经验通知证据](../协议/经验升级通知.md)。当前提供成长计划、本服击杀经验规则、原子成长仓储、会话提交发布入口和纯通知Builder；原生统计战斗解释器、正式Session/Handler及完整通知已接入。当前路线战斗与通关结算的Windows实机确认见[副本模块](副本.md)，实际跨级升级显示仍需独立验收。

当前通关经验采用同一成长计划与既有职业限制，规则来源、独立v10经验账本及免费翻牌事务边界见[通关经验与翻牌奖励](单人副本实例.md#通关经验与翻牌奖励)。

## 纯领域计划

[CharacterGrowthPlan.Create](../../Server/DfoServer/Game/Characters/CharacterGrowth.cs)接收当前Character、明确的目标等级、目标绝对累计经验与匹配CharacterGrowthCatalog。支持普通职业及转职/两级觉醒、黑暗武士job9与缔造者job10、已初始化完整两树；特殊职业允许first0的0x10/0x20觉醒阶段。旧未知来源不强行重建。

源等级和经验必须处于同一资源区间；目标等级不得降低、经验必须增加，目标经验也必须位于对应等级的 `[GetLevelStartExperience, GetCumulativeExperienceBoundary)` 区间。支持 Lv1..95。直接绝对经验候选仍须严格增长；合法奖励增量通过 AddExperience 接纳，累计经验封顶于 Lv96 门槛减1，不进入 Lv96。封顶前只到账剩余额度，已封顶时实际到账为0，仍提供同等级、同经验的有效计划供死亡、掉落、通关和任务事务提交，不额外发SP/TP或推定满级胶囊奖励。开发 GM 的高等级零经验快照拒绝，不以这一计划修复工具数据。

同等级经验增加时SP/TP贡献差均为0。升级分别对两树当前剩余余额加 `GetSpDelta`及 `GetTpDelta`；未知来源保留已消费点数和两树余额差，已知来源按目标累计贡献加额外来源减各树费用重新派生，并同步免费赠技与固定等级。已有slot、指令及有效连招保持，任一树超过u16余额上界时整计划拒绝。Lv1 XP0/SP0至Lv2 XP1000时两树各加30SP；Lv2 SP7/29至Lv3 XP2035变为37/59；Lv49升50时两树各增1TP。

计划冻结 id、revision、job、grow、源等级与完整学习前提，输出目标等级和学习候选，不修改 Character、金币、物品、任务或其他角色状态。计划创建不验证 account generation、不递增 revision、不写库，也不证明输入的经验来自合法事件。

## 任务阶段成长与经验分项

普通任务交付可按[主线阶段补足](任务.md#主线阶段补足)在同一领奖事务追加阶段经验。这是本服规则：先投影本次普通经验、有效契约、任务完成/回答、职业及TP奖励，再对已证因果前沿计算差额；不改资源原门槛、累计经验表或全服倍率。

目标T固定为来源领奖前等级之后最早的合法前沿等级，范围1..95；`阶段额 = max(0, GetLevelStartExperience(T) - 普通完成后累计经验)`。正额精确补到T级0%，不增加一整级经验，不再乘契约、批量或其它倍率。普通经验已达到目标时不降低经验，以`Satisfied`和0额claim消费资格。仍有当前工作或更早前沿时延期，单次不递归补到下一目标；来源与持久防重规则归任务模块。

[QuestCompletionPlan](../../Server/DfoServer/Game/Quests/QuestCompletionPlan.cs)冻结下列分项，存储及通知不得混用额度与实际到账：

| 字段 | 含义 |
|---|---|
| `OrdinaryExperience` | 普通任务经验，不含契约与阶段 |
| `ContractExperience` | 本次合法契约分量 |
| `ExperienceReward.Amount` | 普通任务经验与合法契约合计，保持原语义 |
| `StageExperience` | 独立阶段补差，不计作契约或组队经验 |
| `TotalRequestedExperience` | `ExperienceReward.Amount + StageExperience`，写入普通回执`experience_amount` |
| `ActualExperience` / 提交结果`GainedExperience` | 最终累计经验减交付前累计经验，封顶时可小于请求额度 |

阶段正额与普通额度合并为唯一最终`CharacterGrowthPlan`，由原累计表派生等级、两树SP/TP及赠技；职业/TP奖励按最终成长同步。最终成长、学习或总额显示范围校验失败时整笔拒绝，不截成任意阶段额；资源图资格未知只退让为普通领奖，持久证据完整性错误仍拒绝。冻结快照记录普通、契约、阶段、总请求及实际到账分项，旧无阶段回执不重写或重新计奖。

ACK34经验量使用实际总到账，NOTI37使用已提交角色的最终绝对经验和两树状态。普通0而阶段正额仍发送NOTI37；普通正额度封顶实际0时保留原通知。契约显示只按实际普通到账分配合法契约分量，阶段额不进入契约或队伍栏；其余任务资产、技能、等级与完成记录按原提交后包序发布。

## 固定一级升级券

`[action type] [level up ticket]`与`[levelup range] 1`通过[LevelUpTicketService](../../Server/DfoServer/Game/Characters/LevelUpTicketService.cs)接入。模板从`stackable/stackable.lst`查询，不按物品编号或说明文字列白名单；使用等级、职业、城镇限定和实际实例期限均保留。`[need material]`属于商店兑换价格，不作为使用成本或资格。缺省最低等级沿用物品模板，重复或畸形使用声明不降为缺省。其他动作、多级及随机升级券不借此入口处理。

一次使用补足到下一级累计经验起点，最高到Lv95，不在原经验上额外叠加整级经验；两树已用点数、额外SP/TP、绑定及自动赠技沿普通成长计划处理。不会将券经验再乘成长契约等奖励倍率。实例必须位于Main真实消耗品槽或快捷栏，已过期、安全锁、职业或等级不符时不扣券。`cool time`按毫秒执行同模板的单会话间隔，只在提交后记录，过期条目及时移除，选角失效时清空。

自动完成范围等同**升级后按一次完成主线按钮**：复用[手册无奖励范围](任务.md)，包括其前置、问题回答、账号同步标记及特殊任务物品规则。普通支线不会仅因券的历史说明而额外完成；当前等级、Lv90至94及Lv95的截止规则与手册一致。没有可跳主线不影响升级；存在问题时先用1381等待真实1431回答，未选分支不默认作答。

扣源一张、经验等级、两树技能与主线完成集共用原`CommitQuestQuickClear`事务和`Ticket`回执，不增加库表，不重复扣购买代币。问题等待期间绑定原Selected、generation、选角epoch、phase和副本身份；角色或场景变化使旧准备失效。提交前复验源期限，失败不发布部分升级；提交后精确恢复同一回执，不重复扣物或加点。CMD418没有永久请求ID，正常后续使用仍校验当前真实源，不能声称任意跨连接重复请求均具备exactly-once。

发布采用ACK418增量在前、NOTI37绝对成长在后，源不再补发删除通知；实际任务物品仍按已提交差量发布。任务投影最后用356恢复完成位，重复最终回答不再次发送已确认的418增量。协议读宽与消费者见[升级券418](../协议/经验升级通知.md#升级券418)。用户粗状态和细阶段保持当前合法场景，问题准备复用任务上下文，不伪装回城或重入副本。

[升级券规则与事务回归](../../Server/DfoServer/SelfTests/LevelUpTicketTests.cs)覆盖资源、等级边界、点数、问题选择、材料及回滚；[levelup-ticket TCP](../../Server/DfoServer/SelfTests/Tcp/LevelUpTicketTcpTests.cs)覆盖真实418/1381/1431包序、源消费、绝对成长、失败后重连及服务实例恢复。普通一级券已通过客户端实测；问题窗口与券连续使用仍需客户端独立验收。

## 按表升级胶囊

STK 的 `[increase status type] [levelUpByTable]` 读取原序的 `最低等级、最高等级、目标等级` 三元组，使用前等级匹配闭区间的第一项。目标为该等级的累计经验起点，即升级后0%，不是增加该数值的等级，也不把目标累计经验再次加到原经验上。未命中区间、目标不高于当前等级或超出本服Lv95上限时拒绝消费；模板本身的最低/最高等级、职业及 `[usable first growtype]` 仍独立约束使用资格。

[LevelUpByTableDefinition](../../Server/DfoServer/GameWorld/Items/LevelUpByTableDefinition.cs)通过真实名册解析，不使用道具ID白名单。分段样本10303200中Lv1–28升至80、Lv29–49升至81，后续使用按新等级重新选表；490704541的Lv85–94直接升至95。仅声明 `[seria room]` 时必须处于实际赛丽亚房间；与 `[village]` 同时声明表示允许普通城镇。实际源期限、安全锁和数量沿升级券规则校验。胶囊的 `[need material]` 属于商店兑换价，例如490704662的100份金秋花篮特别凭证；使用已持有胶囊时不再次扣购买代币，也不要求从特定途径获得。

带 `[action type] [jumping lv]` 时使用原生CMD515/action193。普通未转职角色须先由客户端选择本职业实际存在的分支；未选择不升级、不扣物，伪造已转职角色换职也拒绝。首次转职复用既有双树重建及CHR赠技规则，保留额外SP/TP；已经转职及黑暗武士、缔造者不改变职业。没有该动作的表道具走CMD30，不擅自为其追加转职选择。

按表成长、必要的首次转职、源消费、升级后的一次手册主线跳过共用现有 `CommitQuestQuickClear` 与 `Ticket` 回执，无库表变更。主线问题未答时保持原角色、入口、职业选择和实例上下文，答完才提交；重复最终回答不重发消费ACK。普通固定/百分比经验胶囊仍不自动跳主线。原生ACK之后发送NOTI37绝对成长、必要技能、Actor/Player与任务完成表，不重复发源删除或获得通知；用户状态不切换为新的城镇或副本。

[规则和事务回归](../../Server/DfoServer/SelfTests/LevelUpByTableTests.cs)及[按表升级TCP](../../Server/DfoServer/SelfTests/Tcp/LevelUpByTableTcpTests.cs)归入 `levelup-ticket` 的检查范围；资源与事务可单独使用 `levelup-table-rules`。匹配客户端已确认Lv55未转职角色经mode5选择漫游枪手后升至Lv82，以及已转职弹药专家使用后保持职业并升至Lv82；源只消费一件，经验为目标等级0%，两树点数与主线完成位同步。取消、主线问答、无jumping动作的CMD30及多段连续使用仍未逐项实机验收，不以自动回归代替这些窗口和显示检查。

## 经验消耗品

STK 的 `[increase status type]` 支持 `[expUp] N` 固定经验与 `[expPercentUp] P` 当前等级区间百分比，按真实 `stackable.lst` 查询，不按名称或物品编号补经验。百分比增量为 `floor(GetLevelExperienceSpan(使用前等级) * P / 100)`，不是当前累计经验或距离升级剩余经验的百分比；跨级后下一次使用重新取新等级区间。经验不额外乘契约、疲劳燃烧或组队倍率。

[ExperienceConsumableService](../../Server/DfoServer/Game/Characters/ExperienceConsumableService.cs)沿普通成长计划保留两树余额、已用点数、额外SP/TP及赠技。实际源须在Main消耗品槽或快捷栏，校验原实例、数量、锁、期限、模板适用/排除职业、等级、城镇限制、材料和冷却。冷却复用会话消耗品组，未声明组时按模板隔离，换角清空；CMD30没有token，相同槽的合法连续请求各消费一件，不按正文相同永久去重。无可到账经验时拒绝，不浪费物品。

`CommitExperienceConsumable`复用库存标准删除与原事务提交器，扣源、等级经验、两树技能、任务条件及revision共事务，不新增库表。商店兑换的`[need material]`不参与使用费用，已有代币数量不变，无代币也可使用。规划在账号锁外，提交重验generation、当前Selected、选角epoch、阶段、原副本身份和持久快照，成功后才安装在线状态。SQL失败不发成功，结果不明关闭原连接，重登读取实际提交结果，不自动重做扣物或补发增量。城镇、副本、结算沿原合法user状态；Loading和已有未决业务不借胶囊改变状态上下文。

成功按[经验物品CMD30](../协议/经验升级通知.md#经验物品cmd30)先发消费与经验增量，再同步NOTI37绝对成长、必要技能及升级投影。只更新实际变化的任务条件和可接列表，不自动完成主线；这一点与固定一级升级券不同。冒险团账号胶囊继续使用原账号账本及请求，不走STK源。

`expUpByPercent`、`expUpByTable`、异次元计算、复合动作及未核对的经验等级限制不当作上述两种效果消费；`levelUpByTable` 使用上面的独立按表成长规则。[规则与事务用例](../../Server/DfoServer/SelfTests/ExperienceConsumableTests.cs)及`experience-consumable` TCP覆盖跨级、两树、材料、SQL回滚、重放、重连和副本原场景。固定经验与10%经验胶囊已通过匹配客户端实测；材料、冷却及跨级SP/TP等组合由自动回归覆盖，未逐项实机验收。

## NOTI37 纯 Builder

[GrowthPackets.Experience](../../Server/DfoServer/Network/Builders/GrowthPackets.cs) 构造 S2C notification category0、opcode37 的 body。正文为 little-endian，完整长度为 `91 + 8*bonusCount`；count0为91B、count255为2131B。方法只排列已确认的直接读取字段，不构建帧或发送消息，不在入城或技能学习路径自动调用。

调用方必须显式提供目标等级、完整两树绝对 SP/TP 与 u64 经验，以及[附属状态和事件分量](../../Server/DfoServer/Game/Characters/CharacterExperienceNotice.cs)：

- `CharacterGrowthAuxiliaryState` 提供决斗胜点、成长胶囊 DWORD 位模式、熟练等级和熟练 u64 经验。没有默认值，不从角色 XP、等级或金币推导。胶囊客户端使用 CDQ 符号扩展，Builder 只保留输入32位位模式。
- `CharacterExperienceDisplay` 提供全部已确认显示分量、原始分支值、额外资源 ID/经验对、扣除分量及 offset75 未引用 DWORD。普通单人杀怪、通关和任务使用 Ordinary 策略，队伍及其他额外贡献为0；客户端由绝对累计经验差计算基础经验，不能把本次总额填进 offset9 的队伍奖励。分支值保留 byte，不伪造完整枚举；额外记录保留顺序，数量上限255。

缺完整技能树、附属 owner 输入或事件显示输入时拒绝，不补零、不省略固定尾部。Builder 不验证经验来源、额外奖励业务或分支语义；这些资格必须在调用方领域事务前确认。新角色普通事件可以显式采用已记录的零附属初值和无额外奖励策略，不能借此覆盖存量未知状态。

## 本服击杀经验规则

[DungeonKillExperienceCatalog](../../Server/DfoServer/GameWorld/Dungeons/DungeonKillExperienceCatalog.cs)读取匹配PVF的`monster/monsterexp.tbl`及`etc/(r)serverparameter.etc`。基础表有300行，Lv1/2/3/5对应30/60/72/95，Lv300对应64906；表外等级拒绝。五项难度倍率为1.3/2/2.5/3/4，怪物品级倍率当前只有一项1，Boss及越界品级沿用首项，不采用其他版本的Boss四倍值。副本`experience increasing point`缺失或负值时为1；`named monster`内非Boss模板再乘3。入场计划冻结副本基准等级、权重和精英名单，逐次击杀使用当前角色等级。

`monster-level-modifiers-v2`参考external的`dungeon_monster_experience.go`：先将基础表值乘权重并截为i32，再依次乘难度和品级倍率截为i32，最后乘等级差系数截为u32，各乘法采用float32。等级差为怪物实际等级减角色等级：≤−7为0.05，−6/−5/−4为0.2/0.5/0.75，−3..0为1，1..3为1.12，4..5为1，6/7/8/9为0.75/0.7/0.6/0.5，≥10为0.05。中间值和最终值越界拒绝。该参考规则不声称已恢复原服全部经验奖励。

奖励使用可信生成计划的实际等级：76125第五行`1/1/0`按副本基准5加偏移0生成Lv5；76126两行均Lv3。普通难度下，Lv1/2角色击杀Lv3得到104，Lv3角色击杀Lv3得到93，Lv3角色击杀Lv5得到137。Lv1零经验依资源顺序完成六房的28次敌对击杀累计2868并升至Lv3；友方托比没有击杀奖励。通关评分经验保持现有规则。

[DungeonKillExperiencePolicy](../../Server/DfoServer/Game/Dungeons/DungeonExperienceReward.cs)只为当前已核验的待提交死亡规划奖励，冻结规则版本、资源表路径、怪物模板、实际等级及经验增量。累计等级边界不作为奖励额度；`CharacterGrowthPlan.AddExperience`负责将明确增量转换为目标绝对经验和等级，沿用两树SP增量及全部边界校验。历史`local-monster-level-x1-v1`receipt保持原值，不重新计算或补发已提交事件。

## 成长事务与发布前提

生产接入须先建立可信经验事实和稳定事件身份，绑定 account generation、角色、task attempt、instance/epoch 等真实 owner。[CommitDungeonGrowth](../../Server/DfoServer/Persistence/CharacterRepository.Growth.cs)在当前account lease内核对原实例待提交候选、角色、怪物与资源来源；同事务重读等级和完整学习前提，提交经验、等级、两树SP、事件receipt及revision。CommitLearning禁止修改经验，SP增加仅允许携带已核算总来源的退款/同步候选；正常经验仍走独立成长事务。

当前正式实例提供内存死亡签发、提交前准备及提交后确认合同，匹配原生本地HP统计解释器也已提供，并已接入生产会话owner与Handler调用链；本服额度规则已独立实现。等级经验边界不能用作杀怪或通关奖励额度。奖励接入应使用[死亡事实与提交协调](单人副本实例.md#战斗事件与结算)的Prepare/Confirm接口，不能先调用一步Accept再提交SQL；成长仓储、receipt及会话提交发布入口已提供，正式调用绑定Session私有实例，SQL成功后才发布通知。

v8的character_dungeon_state持久保存成长胶囊与熟练等级/经验，仅正常建角明确初始化0。决斗胜点来自实际Inventory.WinPoints。旧角色无owner行保持未知，正式入口拒绝，普通城镇与资产保持；迁移不自动清零。事务提交后才发布 Selected 和通知，发送失败不重发奖励、扣费或经验事实。击杀、通关和任务经验分别沿原事务提交并发布NOTI37；任务ACK34领奖弹窗的经验量使用实际到账，封顶时显示0，仍保留正额度事件的完整成长通知。仅当成长改变实际技能绑定/等级时，在NOTI37后发送完整NOTI19同步固定技能；不追加无变化的技能或Player投影。

数据库 v3 新增`character_dungeon_growth_receipts`，不补发存量角色经验或点数。v5 将历史资源标记列改名为 `resource_source`，保留原值；新事件记录 `monster/monsterexp.tbl`，路径用于标明来源，不证明资源内容相同。receipt保存事件ID、实例、任务尝试、epoch、地图、怪物key、战斗序号、generation、规则与资源来源、增量及提交前后经验/等级和revision。v23保留回执原奖励额度，实际到账由after_experience减before_experience取得；三类经验回执允许因封顶而少于额度，仍拒绝倒退或超过额度。迁移同事务保留依赖表、rowid、外键、索引及触发器，不补发历史经验。实例击杀总额和结算页基础/评分分量使用实际到账，封顶展示0；原冻结额度继续用于来源及重放校验。事件ID、同实例怪物key和战斗序号受唯一约束；同ID不同来源、额度、规则或资源拒绝。提交后内存尚未确认时，精确重放只返回当前持久角色，不再次增加经验或SP。

Repository不消费内存死亡，也不发送通知。SQL明确回滚后，由原实例撤销准备再以同事件ID重试；结果不明时先查询持久化结果，不能生成新ID。Repository实例重新打开可读取已提交角色及receipt；会话提交入口可安装该持久结果，但正式战斗事件恢复、owner更替后的实例恢复仍未实现；生产Handler已接入当前实例。

[GameSession.CommitDungeonGrowth](../../Server/DfoServer/Game/Session/GameSession.Dungeons.cs)在原账号lease内核对Ready、选角epoch、规划时的在线快照引用、角色及原实例待提交死亡；调用`ICharacterRepository`成长合同，SQL成功后确认原死亡候选，再安装返回的实际Character。接口返回存储结果和死亡结果，不签发战斗事实、不发送包、不创建诊断奖励；正式Handler经Session原生统计入口调用它。

存储异常时在线角色与原候选保持不变，不在会话入口擅自撤销候选或换事件ID。调用方确认回滚后可按领域合同撤销，提交结果不明时以原receipt查询恢复。SQL已提交但原调用方未发布时，精确重放只安装当前持久角色并确认原候选，不再增加经验/SP。已确认候选、旧epoch、旧快照及旧账号lease拒绝。返回选角或接管后不通过此入口恢复旧实例。

## 验证边界

任务阶段成长的代表资源矩阵、自然Scene预算、Session/SQLite与TCP证据见[任务验证边界](任务.md#验证边界)。相关用例覆盖普通/契约/阶段分项、T级0%、两树成长、0额防重与通知实际总额；这不表示全Lv1–95连续主线或匹配客户端阶段升级显示已经验收。

[CharacterGrowthTests](../../Server/DfoServer/SelfTests/CharacterGrowthTests.cs) 使用 C# 和匹配 PVF，覆盖 Lv1→2、Lv2→3、跨级、同等级经验增加、已消费/不同 SP 余额保留、TP累计贡献与slot保持、源/目标边界、Lv95上界、余额溢出、非法/旧状态拒绝及集合快照冻结；特殊职业正向成长见[扩展用例](../../Server/DfoServer/SelfTests/SkillExtendedTests.cs)。

[GrowthPacketsTests](../../Server/DfoServer/SelfTests/GrowthPacketsTests.cs) 独立按证据偏移解码，逐字节比较91B文档样本，验证全部非零字段、两树顺序、u64及胶囊位模式、0/2/255个额外记录、固定尾部、短包/长包/count错误和缺输入拒绝。两套测试均接入 SelfTestRunner；公共构建、自测和隔离 TCP 回归按[验证入口](../../CONTRIBUTING.md#验证)执行。

[DungeonKillExperienceCatalogTests](../../Server/DfoServer/SelfTests/DungeonKillExperienceCatalogTests.cs)核对各档等级差、float32分步取整、真实基础表、倍率、精英与Boss区别、76125/76126实际规划等级及非法资源拒绝。[DungeonGrowthRepositoryTests](../../Server/DfoServer/SelfTests/DungeonGrowthRepositoryTests.cs)使用隔离SQLite与合成已确认死亡，覆盖Lv3奖励104从XP950升至Lv2/XP1054、两树各加30SP，事实去重、同ID篡改、旧generation/revision、同revision技能变化、真实SQL晚期回滚、原ID重试、仓储重开与v2升级当前结构。会话用例覆盖未Ready、旧选角epoch、同值但非原引用的角色快照、SQL晚期失败与原候选重试、提交后未发布的精确恢复、末次死亡清图、重复请求、重选、接管和仓储重开。正式TCP独立检查六房生成等级、逐次经验、总额2868及重复报告不加经验。用于测试跨级的其他额度明确属于fixture，不是怪物奖励声明。

这些成长用例使用合成死亡输入；正式Handler及通知失败隔离另见[单人副本实例](单人副本实例.md#验证与待接入)。实例重启恢复尚未实现，Windows客户端实际跨级升级显示仍需独立验收。
