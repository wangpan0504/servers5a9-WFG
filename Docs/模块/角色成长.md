# 普通成长计划与经验通知投影

目标为 S5A9 x86。累计经验和等级 SP 贡献来自[成长资源](../资源/角色成长.md)，S2C `(0,37)` 完整直接读取来自[经验通知证据](../协议/经验升级通知.md)。当前提供成长计划、本服击杀经验规则、原子成长仓储、会话提交发布入口和纯通知Builder；原生统计战斗解释器、正式Session/Handler及完整通知已接入。当前路线战斗与通关结算的Windows实机确认见[副本模块](副本.md)，实际跨级升级显示仍需独立验收。

当前通关经验采用同一成长计划与既有职业限制，规则来源、独立v10经验账本及免费翻牌事务边界见[通关经验与翻牌奖励](单人副本实例.md#通关经验与翻牌奖励)。

## 纯领域计划

[CharacterGrowthPlan.Create](../../Server/DfoServer/Game/Characters/CharacterGrowth.cs)接收当前Character、明确的目标等级、目标绝对累计经验与匹配CharacterGrowthCatalog。支持普通职业及转职/两级觉醒、黑暗武士job9与缔造者job10、已初始化完整两树；特殊职业允许first0的0x10/0x20觉醒阶段。旧未知来源不强行重建。

源等级和经验必须处于同一资源区间；目标等级不得降低、经验必须增加，目标经验也必须位于对应等级的 `[GetLevelStartExperience, GetCumulativeExperienceBoundary)` 区间。支持 Lv1..95，Lv95 达到下一边界时拒绝，不猜测封顶截断或 Lv96 业务。开发 GM 的高等级零经验快照拒绝，不以这一计划修复工具数据。

同等级经验增加时SP/TP贡献差均为0。升级分别对两树当前剩余余额加 `GetSpDelta`及 `GetTpDelta`；未知来源保留已消费点数和两树余额差，已知来源按目标累计贡献加额外来源减各树费用重新派生，并同步免费赠技与固定等级。已有slot、指令及有效连招保持，任一树超过u16余额上界时整计划拒绝。Lv1 XP0/SP0至Lv2 XP1000时两树各加30SP；Lv2 SP7/29至Lv3 XP2035变为37/59；Lv49升50时两树各增1TP。

计划冻结 id、revision、job、grow、源等级与完整学习前提，输出目标等级和学习候选，不修改 Character、金币、物品、任务或其他角色状态。计划创建不验证 account generation、不递增 revision、不写库，也不证明输入的经验来自合法事件。

## NOTI37 纯 Builder

[GrowthPackets.Experience](../../Server/DfoServer/Network/Builders/GrowthPackets.cs) 构造 S2C notification category0、opcode37 的 body。正文为 little-endian，完整长度为 `91 + 8*bonusCount`；count0为91B、count255为2131B。方法只排列已确认的直接读取字段，不构建帧或发送消息，不在入城或技能学习路径自动调用。

调用方必须显式提供目标等级、完整两树绝对 SP/TP 与 u64 经验，以及[附属状态和事件分量](../../Server/DfoServer/Game/Characters/CharacterExperienceNotice.cs)：

- `CharacterGrowthAuxiliaryState` 提供决斗胜点、成长胶囊 DWORD 位模式、熟练等级和熟练 u64 经验。没有默认值，不从角色 XP、等级或金币推导。胶囊客户端使用 CDQ 符号扩展，Builder 只保留输入32位位模式。
- `CharacterExperienceDisplay` 提供全部已确认显示分量、原始分支值、额外资源 ID/经验对、扣除分量及 offset75 未引用 DWORD。分支值保留 byte，不伪造完整枚举；额外记录保留顺序，数量上限255。

缺完整技能树、附属 owner 输入或事件显示输入时拒绝，不补零、不省略固定尾部。Builder 不验证经验来源、额外奖励业务或分支语义；这些资格必须在调用方领域事务前确认。新角色普通事件可以显式采用已记录的零附属初值和无额外奖励策略，不能借此覆盖存量未知状态。

## 本服击杀经验规则

[DungeonKillExperienceCatalog](../../Server/DfoServer/GameWorld/Dungeons/DungeonKillExperienceCatalog.cs)读取匹配PVF的`monster/monsterexp.tbl`及`etc/(r)serverparameter.etc`。基础表有300行，Lv1/2/3/5对应30/60/72/95，Lv300对应64906；表外等级拒绝。五项难度倍率为1.3/2/2.5/3/4，怪物品级倍率当前只有一项1，Boss及越界品级沿用首项，不采用其他版本的Boss四倍值。副本`experience increasing point`缺失或负值时为1；`named monster`内非Boss模板再乘3。入场计划冻结副本基准等级、权重和精英名单，逐次击杀使用当前角色等级。

`monster-level-modifiers-v2`参考external的`dungeon_monster_experience.go`：先将基础表值乘权重并截为i32，再依次乘难度和品级倍率截为i32，最后乘等级差系数截为u32，各乘法采用float32。等级差为怪物实际等级减角色等级：≤−7为0.05，−6/−5/−4为0.2/0.5/0.75，−3..0为1，1..3为1.12，4..5为1，6/7/8/9为0.75/0.7/0.6/0.5，≥10为0.05。中间值和最终值越界拒绝。该参考规则不声称已恢复原服全部经验奖励。

奖励使用可信生成计划的实际等级：76125第五行`1/1/0`按副本基准5加偏移0生成Lv5；76126两行均Lv3。普通难度下，Lv1/2角色击杀Lv3得到104，Lv3角色击杀Lv3得到93，Lv3角色击杀Lv5得到137。Lv1零经验依资源顺序完成六房的28次敌对击杀累计2868并升至Lv3；友方托比没有击杀奖励。通关评分经验保持现有规则。

[DungeonKillExperiencePolicy](../../Server/DfoServer/Game/Dungeons/DungeonExperienceReward.cs)只为当前已核验的待提交死亡规划奖励，冻结规则版本、资源表路径、怪物模板、实际等级及经验增量。累计等级边界不作为奖励额度；`CharacterGrowthPlan.AddExperience`负责将明确增量转换为目标绝对经验和等级，沿用两树SP增量及全部边界校验。历史`local-monster-level-x1-v1`receipt保持原值，不重新计算或补发已提交事件。

## 成长事务与发布前提

生产接入须先建立可信经验事实和稳定事件身份，绑定 account generation、角色、task attempt、instance/epoch 等真实 owner。[CommitDungeonGrowth](../../Server/DfoServer/Persistence/CharacterRepository.Growth.cs)在当前account lease内核对原实例待提交候选、角色、怪物与资源来源；同事务重读等级和完整学习前提，提交经验、等级、两树SP、事件receipt及revision。CommitLearning禁止修改经验，SP增加仅允许携带已核算总来源的退款/同步候选；正常经验仍走独立成长事务。

当前正式实例提供内存死亡签发、提交前准备及提交后确认合同，匹配原生本地HP统计解释器也已提供，并已接入生产会话owner与Handler调用链；本服额度规则已独立实现。等级经验边界不能用作杀怪或通关奖励额度。奖励接入应使用[死亡事实与提交协调](单人副本实例.md#战斗事件与结算)的Prepare/Confirm接口，不能先调用一步Accept再提交SQL；成长仓储、receipt及会话提交发布入口已提供，正式调用绑定Session私有实例，SQL成功后才发布通知。

v8的character_dungeon_state持久保存成长胶囊与熟练等级/经验，仅正常建角明确初始化0。决斗胜点来自实际Inventory.WinPoints。旧角色无owner行保持未知，正式入口拒绝，普通城镇与资产保持；迁移不自动清零。事务提交后才发布 Selected 和通知，发送失败不重发奖励、扣费或经验事实。击杀与当前通关经验已各自提交并发布NOTI37，完整任务及其他结算奖励未接入；仅当成长改变实际技能绑定/等级时，在NOTI37后发送完整NOTI19同步固定技能；不追加无变化的技能或Player投影。

数据库 v3 新增`character_dungeon_growth_receipts`，不补发存量角色经验或点数。v5 将历史资源标记列改名为 `resource_source`，保留原值；新事件记录 `monster/monsterexp.tbl`，路径用于标明来源，不证明资源内容相同。receipt保存事件ID、实例、任务尝试、epoch、地图、怪物key、战斗序号、generation、规则与资源来源、增量及提交前后经验/等级和revision。事件ID、同实例怪物key和战斗序号受唯一约束；同ID不同来源、额度、规则或资源拒绝。提交后内存尚未确认时，精确重放只返回当前持久角色，不再次增加经验或SP。

Repository不消费内存死亡，也不发送通知。SQL明确回滚后，由原实例撤销准备再以同事件ID重试；结果不明时先查询持久化结果，不能生成新ID。Repository实例重新打开可读取已提交角色及receipt；会话提交入口可安装该持久结果，但正式战斗事件恢复、owner更替后的实例恢复仍未实现；生产Handler已接入当前实例。

[GameSession.CommitDungeonGrowth](../../Server/DfoServer/Game/Session/GameSession.Dungeons.cs)在原账号lease内核对Ready、选角epoch、规划时的在线快照引用、角色及原实例待提交死亡；调用`ICharacterRepository`成长合同，SQL成功后确认原死亡候选，再安装返回的实际Character。接口返回存储结果和死亡结果，不签发战斗事实、不发送包、不创建诊断奖励；正式Handler经Session原生统计入口调用它。

存储异常时在线角色与原候选保持不变，不在会话入口擅自撤销候选或换事件ID。调用方确认回滚后可按领域合同撤销，提交结果不明时以原receipt查询恢复。SQL已提交但原调用方未发布时，精确重放只安装当前持久角色并确认原候选，不再增加经验/SP。已确认候选、旧epoch、旧快照及旧账号lease拒绝。返回选角或接管后不通过此入口恢复旧实例。

## 验证边界

[CharacterGrowthTests](../../Server/DfoServer/SelfTests/CharacterGrowthTests.cs) 使用 C# 和匹配 PVF，覆盖 Lv1→2、Lv2→3、跨级、同等级经验增加、已消费/不同 SP 余额保留、TP累计贡献与slot保持、源/目标边界、Lv95上界、余额溢出、非法/旧状态拒绝及集合快照冻结；特殊职业正向成长见[扩展用例](../../Server/DfoServer/SelfTests/SkillExtendedTests.cs)。

[GrowthPacketsTests](../../Server/DfoServer/SelfTests/GrowthPacketsTests.cs) 独立按证据偏移解码，逐字节比较91B文档样本，验证全部非零字段、两树顺序、u64及胶囊位模式、0/2/255个额外记录、固定尾部、短包/长包/count错误和缺输入拒绝。两套测试均接入 SelfTestRunner；公共构建、自测和隔离 TCP 回归按[验证入口](../../CONTRIBUTING.md#验证)执行。

[DungeonKillExperienceCatalogTests](../../Server/DfoServer/SelfTests/DungeonKillExperienceCatalogTests.cs)核对各档等级差、float32分步取整、真实基础表、倍率、精英与Boss区别、76125/76126实际规划等级及非法资源拒绝。[DungeonGrowthRepositoryTests](../../Server/DfoServer/SelfTests/DungeonGrowthRepositoryTests.cs)使用隔离SQLite与合成已确认死亡，覆盖Lv3奖励104从XP950升至Lv2/XP1054、两树各加30SP，事实去重、同ID篡改、旧generation/revision、同revision技能变化、真实SQL晚期回滚、原ID重试、仓储重开与v2升级当前结构。会话用例覆盖未Ready、旧选角epoch、同值但非原引用的角色快照、SQL晚期失败与原候选重试、提交后未发布的精确恢复、末次死亡清图、重复请求、重选、接管和仓储重开。正式TCP独立检查六房生成等级、逐次经验、总额2868及重复报告不加经验。用于测试跨级的其他额度明确属于fixture，不是怪物奖励声明。

这些成长用例使用合成死亡输入；正式Handler及通知失败隔离另见[单人副本实例](单人副本实例.md#验证与待接入)。实例重启恢复尚未实现，Windows客户端实际跨级升级显示仍需独立验收。
