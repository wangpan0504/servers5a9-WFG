# 卢克场景观察回执准备层

共同逻辑合同为 [CP_LUKE_SCENE/1](../协议/CP_LUKE_SCENE_V1.md)。这是本服自定义、仅自己角色Town对象观察的准备层，不是原ARAD协议，不是全队就绪或恢复授权。

## 实现及责任

`Game/Raids/LukeSceneReceipt.cs`只提供每连接一槽的纯状态机。默认关闭；没有Runtime实例、配置入口、能力协商、发送器或packet handler。即使局部启用，也必须明确已经协商同版本能力才可创建请求。没有选择opcode，没有借用CMD37或其它原版字段。

权威身份只从未来宿主的实际连接/owner/选角/Battle/目标场景取得，包含账号、连接ID、角色、owner generation、selection epoch、raid instance、phase与phase generation、目标Town/Area及targetRevision。字符ID0属于合法ushort值，但不代表已经验证身份；缺少身份用null表达。Town/Area的byte范围也不表示真实资源存在或允许前往。

调用方必须在现有owner与命令串行合同中取得当前事实，并在使用返回观察之前继续持相同权威边界。结构相等检查不会把客户端自报或陈旧快照变为权威。phase generation和targetRevision必须由服务端维护且不可借原native未知字段赋义；在此批尚没有生产捕获器。

## 状态边界

- Begin创建随机128bit非零小写hex ID，替代旧槽；期限1..30000ms从服务端签发单调时间算起。
- Observe仅将匹配请求改为Observed；重复幂等、不延长deadline、不产生第二次消费资格。旧ID的观察或取消不会凭旧身份清掉新ID槽；当前能力由独立SetCapability宿主事件更新，false立即清槽；旧回执方法没有能力参数，不能用旧capture撤销新槽。重新设true不能复活旧challenge。
- ConsumeObservation再次核对全部当前事实及期限，只能取走一次观察结果。它不是Ready/RestoreApproved；不调用Restore、不签发权益、不移动角色、不恢复Run、不发668。
- 身份、连接、owner、角色、raid阶段代、目标版本改变，匹配旧请求失败并撤销；过期撤销。断线永久关闭原连接对象，不能复用来开始新请求。
- 检测单调时钟较上次观测回退时锁定旧对象；不能靠UTC修正或重置issued时间延长旧期限。没有后台定时任务；最多保留一个请求，下一操作清理过期槽。

## 验证及未接线

`LukeSceneReceiptTests`是fake authoritative facts / fake clock / fake receipt的纯领域测试，接入既有core入口；覆盖默认禁用、无能力、字段bounds、身份变化、替换ID、超时、回退、断线、重复及并发一次消费。它不证明clientpatch能读取真实Town对象，更不证明完整团本或原生重返。

未来接线前仍需：合法且无编号冲突的自定义transport、显式双边能力协商、真实连接/owner事实捕获、已证客户端Town对象observer与正确线程、实际发送失败和生命周期收束、原领域Restore门禁复验。任一未证均保持不发送；不得用模拟Ready或等待固定时长替代真实观察。

共享向量镜像为 `SelfTests/Fixtures/luke-scene-contract-vectors.json`，与clientpatch的 `Tests/Extensions/LukeScene/contract-vectors.json`逐字一致。嵌入测试资源仅为跨语言合同校验，不是JSON传输入口；数字采用规范十进制字符串避免int64精度损失。共同英文合同保留原文以供双方逐字核对。
