# 每日重置与物品补给

## 服务日

[ServiceDay](../../Server/DfoServer/GameWorld/Time/ServiceDay.cs)供疲劳恢复与本页全局物品规则使用，按服务器本地时区06:00分日，06:00前属于上一服务日，不固定为UTC+8。原有商店限购、任务、礼盒、NPC好感、活动和普通物品期限等业务保留各自已有日界及时间解释，不随本页规则改变。两种日界在服务器本地时区不是UTC+8时可能不同；已有绝对期限和已冻结的物品截止不因重登重新计算。

[ServiceDayProjection](../../Server/DfoServer/Network/Projection/ServiceDayProjection.cs)为当前选角设置可取消的到点唤醒。持续在线的角色在本机06:00恢复疲劳、推进本页物品规则并保留强袭信息推送；强袭原有自然日计数与星期计算不变。在原UTC+8 06:00另推进原有任务日周期，并推送副本剩余次数、冒险团及原有权益视图；各业务仍按自己的规则计算，不把它们改为本机服务日。每日道具和NPC赠礼次数也保留既有在线投影。两种边界不要求重新登录或发请求；请求前后另作补查，覆盖休眠、时钟跳跃及操作期间暂缓的日切。到点遇到未决事务时只检查门禁，按1秒起逐步退避至30秒重试，不重放原事务。疲劳余额恢复见[普通图疲劳owner](单人副本实例.md#普通图疲劳owner)。

日切不切换user状态，不结束副本、不清理本局房间/掉落缓存、不再次扣已付房间费用。遇到资产提交结果不明、未决死亡/结算/疲劳或转场时暂缓，原操作明确结束后补查。通知绑定原账号generation、选角epoch及已提交事实；断线、换角或接管取消旧任务。服务日回拨不重复补满或倒退领取日戳。全局限次的旧日计划在跨界提交时拒绝，客户端可在新日重新请求。

## 全局物品配置

[ServerItemUsageCatalog](../../Server/DfoServer/GameWorld/Items/ServerItemUsageCatalog.cs)装载`etc/chn_server_limititemusageinfo.etc`的五类声明。缺文件时没有这些附加规则；存在但格式损坏、行宽非法或键冲突时明确拒绝资源装配，不静默放行。

| 声明 | 当前业务 |
|---|---|
| `[Limit Item Usage Info]` | 三列：类型、物品ID、上限。0/1为使用，2为购买，3使用物品键0表示普通寄信；按角色、类型和物品分别保存每日次数。费用、道具、奖励及次数同事务提交，失败不扣次数。系统投递邮件不占普通寄信额度，库存移动、出售和材料扣除不冒充道具使用 |
| `[reset item]` | 物品ID、截止时间。到达或超过配置时刻后清理当前角色各库存容器及其未领取邮件中的目标实例，包括带锁项；保留邮件文字、金币及不相关附件。该时刻不是补给有效期，已经过去的清理时间仍生效。在线定时器同时关注未来清理时刻，不只等下一次06:00 |
| `[refill item]` | 物品ID、目标数量、补给截止、可选第四列。服务日内按角色执行一次：已有首堆赋值到目标数量并保留UID、核心和原期限；缺失时经统一发放入口补给。数量0执行清理，过了补给截止则不再补给或按此行清理。满包不改走邮件，失败项保留待重试；每项独立记成功日戳，不能因其他项失败而重复补充已消耗的成功项 |
| `[account refill item]` | 行格式同角色补给，但每日资格归账号。当日首个上线且符合条件的角色领取；持续在线跨日时由当前角色领取。满包时保留该角色的领取归属，腾出空间后重试，同账号其他角色不能接走或重复领取。物品绑定与期限沿模板，不额外放宽交易范围 |
| `[charac daily item mail]` | 为符合等级和配置有效期的角色生成系统补给邮件。按角色、模板和间隔日去重，不追补每个离线历史日。邮件与日戳同一事务，晚期失败整笔回滚，重登不重发；不受背包空格影响 |

全局使用限次与物品自身的`[total usable count]`分别判断并独立记数；前者采用本机06:00，后者保留原UTC+8日界。即使两者的服务日不同，也须同时满足各自额度。

旧端`importLimitItemUsageInfo`只覆盖前三类，三列补给继续兼容。当前PVF补给第四列及每日邮件扩展缺少同版服务端原码，采用明确的本服解释：补给第四列为最低角色等级，0不附加门槛；邮件八列为物品ID、数量、间隔日、两个消息配置键、最低等级、最高等级、结束时间。等级上限0表示不限制。两个消息键保留在投递身份中，不误用为客户端dstr编号；邮件使用通用“每日补给”发件人与正文。这些是经配置推断采用的政策，不宣称已还原原服字段。类型2/3的每日购买/寄信政策同样不照搬旧端未完整接入的终身计数分支。

当前PVF的账号补给段为空，每日邮件和正数角色补给已过配置截止，因此不会自动恢复这些历史奖励。仍读取其完整声明；修改PVF启用后使用相同实现，不需要按物品ID硬编码。已有四项有效零数量角色补给仍按配置处理。

[婚戒门票补齐](结婚.md#婚房与后续玩法)复用本服务的角色日戳、库存事务和本机06:00调度，但属于独立婚姻资格业务，不伪装成PVF通用补给配置；只补差额、不裁减超量，不能改变普通`[refill item]`原有的数量赋值语义。

## 保存与通知

选角补给和清理在ACK4及首次全量资产之前提交，不能用登录后的额外刷新代替。角色状态、账号首个领取角色和每日邮件水印使用[数据库](../开发/数据库.md)中的增量结构。共享账号资格通过原账号owner复核；领取归属、补给、清理和系统邮件共用库存提交事务。在线推送副本次数时按当前角色批量只读，不逐模板重开数据库，也不装载其他角色的完整资产。同日无变化请求不申请额外writer。

库存与穿戴变化沿完整库存投影同步，新增邮件或实际清理邮件才发布邮箱提醒。匹配ARAD的NOTI290消费者`023A4EE0`读取三个DWORD：物品ID、上限、使用前次数；旧袖珍罐提示使用`max-used-1`，因此提交后次数N投影为N-1。该通知不是通用客户端额度表，不能在日切时发送任意零计数以冒充清表或触发首次使用提示。

## 验证边界

无资源自测覆盖五类声明、三/四列兼容、使用/购买/寄信额度、回拨、跨界提交、角色与账号隔离、首个领取角色、满包重试、邮件删除、重开库及晚期SQL回滚。迁移回归覆盖新建、升级、结构冲突和失败回滚；`fatigue-daily` TCP验证无新请求的城镇/副本双账号跨日通知、离线选角恢复、同房去重及继续过图。实际客户端窗口和图标仍须实机验收，自动检查不能替代。
