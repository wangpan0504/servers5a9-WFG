# 每日签到得好礼（活动2370）

## 规则与资源

活动使用本版 `event/chn_event/chn_dailyattendanceanytimeevent.evt` 及
`ui/event/chn_event_2016/160825_daily_attendance/eventdailyattendancewindow.xui`。
服务端从当前PVF读取每日奖励、数量及累计门槛，按实际格式校验，不绑定整包hash。

账号每天完成两次推荐地下城通关即自动签到，奖励邮寄给完成第二次的角色。
推荐资格复用正式结算的95推荐规则，按本人等级及本人任务路线判断，不继承队长的入场资格标记，
不从客户端领奖包增加通关次数。教程、练习、职业体验、修炼、任务重放与遗忘之地不计入。
UTC+8每天06:00切日；账号共享当天次数、累计签到和领奖事实，换角不会重置。
28次每日奖励发完后不自动循环；活动关闭保留全部历史，再开启继续。
每日两次的目标沿用已实现参考活动的规则，并由本版NOTI108数值段同步给窗口。

每日第1至7次为 `490013043×2、490013044×1、490013045×2、490013046×2、490013047×3、490013048×1、490013049×1`，
当前资源按相同顺序重复四组。累计奖励通过窗口按钮每次领取最早一档可领奖励。

## 状态和事务

日签到服务在Runtime显式装配，复用账号租约、正式结算回执、完整物品创建和系统邮件。
资源及奖励实例在账号锁外准备；正式通关的经验、revision、结算回执、当天次数、签到事实、
邮件及真实物理UID在同一SQLite事务提交。任一步失败整笔回滚，同一冻结结算可重试；
同一实例重复结算沿原回执返回，不再次签到。

累计领取在当前角色lease内重验角色revision、账号进度和活动版本，邮件与领取事实同事务。
重复领取、删除邮件或删除原收件角色不恢复资格；角色复制保留原账号事实，不复制领奖记录。
附件保留模板metadata及原期限，
期限政策沿用现有“忽略商城绝对日期/相对期限”开关；失效附件不生成领取事实。
领取后使用原[邮件](邮件.md)流程取件，不另建背包或在线状态。

v195只新增账号当天计数和永久领取事实两张表，详见[数据库](../开发/数据库.md)。
纯查询、关闭态及无奖励的累计请求不申请writer。日界复用现有ServiceDayProjection；
发布前校验generation、选角epoch、角色快照和活动版本。

## 开关与协议

未配置时默认开启，使用现有GM命令 `event on 2370` / `event off 2370`，`event auto 2370`恢复默认开启。
已有显式关闭配置继续保留，启动不会覆盖人工选择。
GM活动目录自动展示本活动的名称、规则及默认状态，不支持单独时间表或自动换期。
开关刷新完整NOTI108，保留积分商城、在线228、探险记及其它已开放活动。
请求、状态和本版消费者依据见[日签到协议](../协议/每日签到得好礼.md)。

## 验证入口与边界

`--selftest-core`包含无资源规则、完整状态包、28次每日及三档累计奖励、文件库回滚、
升级与账号接管；`--selftest-tcp daily-attendance-rules`另验当前PVF和真实通关结算事务。
`--selftest-tcp daily-attendance`覆盖实际1296分派、开关、邮件、畸形请求、重复领取、跨日及Runtime重开。
TCP累计门槛使用明确的历史签到准备，不能算作已完成七天刷图。
自动检查及冻结页静态分析不代替客户端界面、点击和取件的实机验收。
