# 单人队伍

当前只支持创建、修改仅有队长本人的队伍，以及城镇中的单人退队。不支持邀请、接受申请、加入其他玩家、踢人、队员换位、公开队伍列表或多人副本。组队光环仅能传送这个真实单成员队伍，见[城镇传送](城镇.md#6-药剂与光环个人传送)。界面中允许设置的成员上限不代表本服已接入多人：实际成员始终只有本人，占0号槽。

## 所有权与生命周期

`SingleMemberParty`由当前`GameSession`唯一持有，不建平行在线目录或数据库表。队伍键暂用队长的唯一角色ID，限定于这个单成员实现，不能作为未来共享多人队伍的ID分配方案。创建和设置修改要求已入城就绪、粗状态Town、细阶段Town，并通过原交互占用和未决任务门禁；无队伍时修改请求拒绝。创建不改变角色属性、库存、位置、revision或粗业务状态。

同内容重复请求复用队伍；已有队伍的创建窗口请求按设置更新处理，不重新分配身份或增加成员。会话内的队伍版本、选角epoch和账号generation共同保护发布，旧设置、旧清理、旧选角和旧owner不能发布到新上下文。正常城镇移动、选图及原有单人副本不另外创建成员；返回选角先清空Session上下文，并在ACK7前用原队伍键发送kind3清理客户端缓存。断线和换频道的新会话不继承旧队伍，旧连接结束仅清理自己的Session。

单人退队在城镇中清空上下文，发送同一队伍键的9/kind3删除记录；没有队伍或不满足前置状态时明确失败。不猜造尚未完整恢复的13成功正文，邀请及其他未接入口不返回通用成功。

## 发布与边界

`SoloPartyHandler`解析本版CMD12的完整15B基础布局，登记或更新Session后回复ACK12与完整NOTI9；自定义名称按CP936 DSTR保留，预置名称仅保留索引，由客户端资源显示，不硬编码中文文案。末尾新增参数和目标设置原样保存、回传，不把未知字段解释成活动资格或成员权益。完整读宽与证据见[队伍协议](../协议/队伍.md)。

当前通知仅发给本人，不登记公开队伍列表或向其他角色广播队伍。创建、修改和退队都不转移城镇场景，不重发Actor、23/24或124，不刷新装备和物品，也不绕过原副本入场、资产或任务资格。单成员组队光环请求在原Session核对队伍对象与版本后走独立434合同，队长自动同意，不创建不存在的待确认成员。只有真实多人owner、成员和确认流程接入后，才能扩展多人传送或奖励。

## 验证

[SoloPartyTests](../../Server/DfoServer/SelfTests/SoloPartyTests.cs)接入`--selftest-core`，覆盖实收请求、原生通知宽度、自定义名称、未就绪/未选角、重复、更新、退出、旧epoch/generation、清理版本和不写库；[SoloPartyTcpTests](../../Server/DfoServer/SelfTests/Tcp/SoloPartyTcpTests.cs)的`solo-party`组覆盖真实分派、ACK/9、唯一成员槽、重复更新、退队、重选和存档不变。普通副本及城镇链路继续使用原实现；客户端队伍窗口、队长标记及创建后的实际游玩仍须实机验收。
