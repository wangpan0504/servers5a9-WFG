# 随机盒与赛丽亚幸运值

## PVF 奖池规则

服务端只从运行时加载的 `Script.pvf` 解析 `[RANDOMBOX]`。每个 `[int data]` 是一个独立的一级奖池；该段前三个整数是 PVF 段头，后续按 `(物品模板 ID, 权重, 数量, 保留字段)` 四元组解析。每次开启从每个一级奖池各抽取一次，奖池内使用权重随机选择，数量按 PVF 原值汇总。不同标签前缀（普通、Samsung、Goblin）共享同一解析规则，材料从 `[sealing removal item]` 读取。

随机盒奖励与商城、普通礼包共用[期限设置](背包与装备.md)：每次开箱在入口冻结忽略绝对日期与忽略相对期限两个开关，全部基础及双倍奖励沿统一发放使用同一组规则。恢复资源期限后，抽中已过期奖励时整笔拒绝并保留源、材料和幸运值；忽略奖励模板期限也不允许使用已经过期的源盒实例。

## 赛丽亚幸运值

赛丽亚幸运盒模板为 `2682272`。幸运值是账号级持久字段，范围为 0–8；每次成功开启后递增，当前值为 8 时下一轮奖励额外复制一份并将值重置为 0。奖励和幸运值在同一背包事务提交后发布，重连从账号钱包恢复。

结果窗口使用物品列表完整条目宽度，并分别发送普通奖励与双倍奖励；虚拟货币使用虚拟槽位显示，直接生效的奖励不伪造背包行。
单开触发双倍时，基础行与复制行连续写入单开结果包；十连使用左右双列表结构。开盒提交后重发各物品容器，保证结果窗读取到最新槽位，不影响其他背包操作的增量刷新。

登录或回到城镇时，服务端以受保护的 `EVENT_INFO` 帧发布事件 2037 的最大阶段 8，并用 `BOOSTER_GAGE` 发布当前阶段乘 5 的客户端进度值；开盒提交后再次发布前后阶段，确保切场景和重连可恢复。

## 验证范围

- 解析真实运行资源中的普通盒、无材料盒和赛丽亚盒。
- 验证多一级奖池各抽一次、池内权重选择、材料消耗、单开/连开和双倍奖励结果。
- 逐行定点验证真实赛丽亚奖池的全部正权重候选及期限开关边界；`--selftest-tcp magic-box` 验证捕获的十连请求、双栏完整条目、提交后刷新和重新选角恢复。
- 验证账号幸运值持久化字段迁移与重载。
- 已用匹配客户端确认：单开双倍结果、十连奖励列表、幸运值进度初始化及提交后刷新均可被客户端正常消费；协议字段由受保护事件通知和进度通知共同组成。
