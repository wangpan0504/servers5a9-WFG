# 强者之路

当前接入2019首期的内容频道、简单与英雄挑战、两支各1至4人队伍匹配、五种干扰技能、邮件奖励、两套资源商店及角色成绩。正式流程复用现有角色、队伍、副本实例、死亡事务和邮箱，保留原4v4并允许真实1v1；客户端入口、难度切换和商店显示已有可见效果核验，完整联机、商品实际使用及部分原生字段分别保留验证边界。

## 入口与资源

[Strongway2019Catalog](../../Server/DfoServer/GameWorld/Dungeons/Strongway2019Catalog.cs)读取`etc/dpl/season/dpl.etc`，保存副本三列记录、奖励五列记录、随机地图与怪物映射、五技能和各阶段延迟。未证实用途的原始列保留原值，不直接解释为人数、难度或奖励额度。物品、地图、怪物、商店继续使用Runtime已有共享目录。

默认[频道目录](../../Server/DfoServer/Resources/channel.txt)在末尾追加编号50、`type55`的内容入口，保持原有入口与端口分配顺序。显示名绑定`etc/hardcodetexttag.etc`的`chn_channel_info_059`，频道分组使用已支持的中性`[none]`；尚未证实`[dpl_e]`的频道消费者，不据其名称猜造分组。

匹配客户端在`type55`内容频道的`65/1`场景打开原生匹配窗口13；普通挑战沿CMD15选图、CMD16正式入场。资源副本行的第三列不是最终入场难度，正式入场核对各DGN的指定难度，当前开放图使用难度2。

服务端事件312控制活动时段及其revision。入场和兑换均冻结活动前提，并在资产事务提交时再次核对，零费用入场也不能跳过该校验。该服务端开关不启用遗留窗口734的累计领奖流程。

新启动器正常连接后通过专用默认初始化入口，为尚无312配置的存档开启活动。初始化复用活动表唯一键和版本条件插入；已有手动关闭、自动或时间表均保留，多个启动器并发只提交一次。GM仍可关闭，重启及后续初始化不会重新打开；只读查询不补写配置。失败返回真实错误，启动器最多重试三次且不阻塞游戏启动。

卡西利亚斯使用原生通知639动态呈现：固定登记城镇38、地区1的已有NPC400001051，开启活动时插入，关闭时删除。当前地图缺少原活动静态NPC声明，坐标685、240、0是兼容摆放位置，不能作为原活动资源坐标的证据。包体为动作u8、ASCII字节长度u32和无末尾NUL的文本；地图段按城镇、地区排列，目标正文为`[map] 38 1 [/map]`。初始化显式恢复当前状态，既有活动投影同时处理312开关与时段，旧owner或选角不能发布过期状态。排队快照按选角代际、活动显隐和312修订去重，关闭重开即使最终显隐相同也重新投影；发送守卫使用稳定角色编号，不因同角色的合法资产快照更新丢弃NPC通知。原生按同图同NPC编号去重，地图加载会重新应用登记；删除会清掉该地图的整组动态登记，目前仅由这条单NPC路径使用，不能推广为任意多NPC独立删除接口。

## 准入与抗魔

[Strongway2019EntryPolicy](../../Server/DfoServer/Game/Strongway2019/Strongway2019Admission.cs)要求角色恰为95级、非决斗专用角色、位于内容频道的准备场景，且活动有效。

| 模式 | 副本 | 人数 | 最低抗魔 | 入口限制 |
|---|---|---|---|---|
| 简单 | 5359 | 1至4人 | 4000 | 普通挑战入口 |
| 英雄 | 5363 | 1至4人 | 5400 | 真实队伍正式入场，一人队伍沿原单人副本链 |
| 匹配 | 5360 | 每队1至4人，两队共2至8人 | 5400 | 两支真实队伍，仅接受匹配服务生成的入场资格 |

资源中的5364资格图不作为当前公开模式开放。玩家请求不包含可授予准入的抗魔数值。单人队伍必须由原队伍服务真实建立，未组队角色仍不能进入英雄或匹配；匹配缺少真实对手时继续等待，不生成替代队伍。等级、抗魔、活动、原队长、选角、owner和Ready资格继续逐人核对，不改变其他团本人数规则。

简单5359和英雄5363从城镇通过非零CMD15直接进入时，先依序发布ACK15、本人USER_STATE1和完整42字节NOTI27，建立原生选图场景后才由CMD16发布28/29。一人真实队伍沿单人链同样遵守此场景合同；已在MapSelect重复指定15只确认选择，不重开场景。场景通知不授予英雄、匹配或资格图准入。

[CharacterAntiEvil](../../Server/DfoServer/Game/Characters/CharacterAntiEvil.cs)从当前角色快照计算服务端抗魔。有效穿戴复用现有槽位、职业、等级、必需技能、装备槽解锁及契约资格；背包物品和光环、宠物外观槽11、33不重复贡献属性。有耐久上限且当前耐久为0的物品排除；装备截止秒严格早于当前秒时排除，带`[usable expired item]`的资源保留期限后的可用属性，破损过滤仍然生效。

每件装备的贡献为根基础抗魔加上强化、锻造贡献的较大值。基础声明按导入继承处理，`anti evil`覆盖、`add anti evil`追加；强化或增幅按真实等级、部位及稀有度读取资源，非零`AmplifyType`选择增幅目录，锻造只用于武器槽12。耳环使用升级资源第六列，旗帜不增加升级抗魔；称号、宠物等种类使用相同的已声明根属性。

[AntiEvilSetCatalog](../../Server/DfoServer/GameWorld/Items/AntiEvilSetCatalog.cs)读取`part set index`完整有符号成员集合，最近声明层继承、后声明整组覆盖，同组编号去重；非正编号保留但不查询套装。局部字段解析不因旧装备无关的额外关闭标签失败，每件有效穿戴可为多个正套装各贡献一件。从`etc/equipmentpartset.etc`定位套装，并叠加达到件数要求的`piece set ability`直接抗魔。当前已核实的抗魔套装为30044、30045、30046、30073、30074、30123、30125。黑洞湮灭三件首饰各516，三件套另加60，因此未强化三件总值为1608；缺件或成员失效时不会保留三件效果。

既有`ConsumableStates`中的有效Effect按原期限读取药剂抗魔平值，过期与Cooldown不计入。[AntiEvilUpgradeContribution](../../Server/DfoServer/Game/Characters/AntiEvilUpgradeContribution.cs)先合计整数平值，再乘以单精度倍率并截断；倍率算法为`1 + 各百分比之和 / 100`，不逐项连乘。当前provider只传入装备、套装及持续药剂平值，百分比来源列表为空；算法存在不表示客户端临时appendage、条件脚本或尚未绑定的成长、附魔抗魔来源已经接通。

匹配客户端的原生规则依据包括：`03FC36B3`的升级贡献单精度运算顺序、`03E58080`的强化与锻造取大值、`02953C20`的基础抗魔合入，以及`CNChangeStatus`枚举73向`6C0`倍率字段追加百分比。它们用于约束计算合同，不能代替角色面板显示或完整属性来源的实机验收。Runtime显式为准入provider装配共享物品、持续药剂、契约及套装目录。

Session在账号owner外完成首次资源计算，再回owner复验同一角色快照、选角代次、队伍人数及活动前提。提交前重新核对资格，换装、效果到期、换角或活动revision变化均不能重放旧许可。

## 正式挑战与计时

简单、英雄沿正式副本的真实地图、怪物生成、加载、推进、击杀和通关事实运行，不另建活动用的模拟战斗。资源声明`disable exp`时关闭怪物及通关经验。奖励必须来自原Run签发的终点事实，普通怪物死亡、客户端自报胜利和普通翻牌入口不能替代通关证明。

本次首期准入同时消费无参`disable drop item`，原Entry冻结禁掉落状态，不准备普通怪物掉落、显式掉落池或地面对象预留；被动物品沿原资源策略禁止。春节宝藏的潜在和个人推荐资格也排除该声明。任务条件与既有任务收集语义保持，胜负邮件奖励使用独立活动事务；禁掉落不删除真实怪物或终点事实。匹配入口仍显式共享正式掉落准备依赖，不能使用调试显式池作为未装配的默认实现。

简单5359与英雄5363读取DGN的`limit time`，当前均为3600秒。服务端采用首次真实加载后开始计时、真实通关后冻结耗时的策略；到期后拒绝继续战斗、移动和发奖。Runtime的一秒维护通过原在线目录找到同一Session，复验原Run、选角epoch及原副本实例，即使客户端不再发包也沿原返城路径退出；单人调用原正式返城，组队先零等待取得队伍及全部成员命令门，再沿原组队退场服务逐人返城，任一门忙时整队保留供下轮重试。返城投影复用NOTI3和NOTI24，不添加超时专用成功包，也不生成奖励、胜场或通关成绩。旧owner、旧选角或旧Run的回调不能退出新入口。这一服务器起点策略与已经证实的资源数值分开，原生倒计时的完整开始、到期消费者尚未闭合。

复活继续沿既有死亡及资产事务。`DungeonCatalog`解析DGN的`coin info`五档命名行，核对selector0、非负上限及行标志0；仅已通过首期准入的Entry冻结对应难度的个人上限。简单5359为12次，英雄5363及匹配5360为4次，5364不因资源声明而开放。缺少合法声明或难度时拒绝入场，不借用其他行。

selector0使用被普通复活角色的DC计数；成功花币者的E4是另一项计数，不能合并或按全队累计。服务端沿原Run记录本人普通复活次数，过房保留已用额度，各队员互相独立；达到上限时不扣币，重复复活请求不重复消费。当前保持既有本人key复活入口，跨队员代付尚未接入。

## 双队匹配与五技能

[Strongway2019MatchingService](../../Server/DfoServer/Game/Strongway2019/Strongway2019MatchingService.cs)持有原队伍票据和比赛索引。入队核对每队1至4名真实成员、队长、同频道、活动及各自准入；准入份数和声明人数必须恰好等于原队实际人数。队伍或选角身份改变后旧票据失效。未预约票据也在活动关闭或修订改变后失效，释放原队全部成员的城镇动作；重新排队必须取得新资格。活动快照在匹配门外读取，较旧观察不会撤销刚取得更高修订的票据；已预约后的最终资格仍由两队共同入场事务复验。两队配对后，全部实际成员的正式入场尝试经共同事务提交，再安装两支原队副本实例与同一比赛对象；失败不安装半场比赛，并保留可释放、重试的原配对状态。两队人数可以不同，不伪造补位成员。

CMD520的首期请求使用玩法类型14和目标5360，由既有匹配Handler唯一分流，避免与决斗场重复注册。CMD521取消及CMD522退出保留已证的3字节正文；未证实的522成功ACK不另行构造。

NOTI1492公布开始截止秒、0或1的本队阵营键及对方名单。双方分别完成`kind7,value3`和`kind7,value4`屏障后才进入比赛运行态，600秒权威比赛计时从此开始；普通挑战3600秒与该比赛预算分别管理。每个写命令也检查截止，后台维护只负责推动原队列、超时终局和返城，不代替命令门控。

[Strongway2019Competition](../../Server/DfoServer/Game/Strongway2019/Strongway2019Competition.cs)按队伍管理能量、共享冷却及技能次数。能量每秒增加1，上限100，五技能共用10秒冷却；首项整局限一次。

|---|---|---|---|
| 0 | dplitem3 | 召唤干扰怪物 | 0 |
| 1 | dplitem1 | 陨石干扰 | 30 |
| 2 | dplitem2 | 飓风干扰 | 45 |
| 3 | dplitem0 | 混乱、失明及减速 | 60 |
| 4 | dplitem4 | 替换对方下一张地图 | 100 |

CMD1525的前两项为施技阵营和类型，技能0至4的客户端第三项不作为地图、伤害或合法性依据。成功后向双方广播相同的施技阵营；前四项交匹配资源的原生地图脚本表现，服务端不根据请求伪造伤害。

换图由服务器从400596、400597、400603中选取，保存为目标队伍待应用的下一房间替换。[Strongway2019RouteService](../../Server/DfoServer/Game/Strongway2019/Strongway2019RouteService.cs)先准备真实MAP和生成行，再在原队全部Run中共同复验和应用；保留原实例、尝试、权威状态及已提交事实，不替换已加载房间或终点。加载完成后才确认该替换，成功ACK或界面提示本身不代表换图已经发生。加载和死亡进度投影也按原队实际人数收齐，单人队伍不等待不存在的队员。

怪物进度HUD的非零百分比只接受当前原队长、同一场景且身份一致的展示遥测，不用于扣血、确认击杀或裁决胜负。比赛胜负来自原Run真实清图、退出事实或权威超时；第一份终局冻结胜方、原因、耗时及收件成员。NOTI1494对比赛实际全员公布同一获胜阵营，超时无胜方；末字段保留为原值，不将其包装成已经证实的结果原因枚举。

换角、断线及原副本退场先处理胜队奖励，再清理本人匹配索引。终局投影按收件人隔离，单连接发送失败不替其他成员消费发送状态；存储异常保留原资格供重试。终局发布后按资源返城延迟沿原副本退出路径回城。

[奖励仓储](../../Server/DfoServer/Persistence/CharacterRepository.Strongway2019Completion.cs)先持久冻结真实完成事实、完整附件、原账号周期及有效成绩，再独立投递邮件。普通挑战只接受原Run确认的终点；匹配先由当前有效报告者把原胜队全部实际成员的原权威终局一起写入[共享检查点](../../Server/DfoServer/Persistence/CharacterRepository.Strongway2019MatchingCheckpoint.cs)，不要求旧Session仍在线，也不借旧owner修改角色快照。随后各收件账号在当前owner下恢复自己的成绩和奖励，Ready恢复不重建旧比赛。首次检查点失败时整队回滚，原服务保留未落盘终局供维护重试；检查点成功后的恢复不依赖旧Session或Run引用。

待交付权益占用原日周额度；恢复经过06点、周界或新入场attempt，也不改发到新周期。额度已满仍保存有效成绩，但不补发奖励。邮件、附件、奖励回执及已交付状态在同一事务提交，晚期失败不留下半封邮件或半个回执；重复完成、恢复或Ready不增加邮件和成绩。邮件通知仍复验当前owner、选角和角色，真实恢复才追加面板刷新及新邮件通知。普通结果报告在完成持久冻结及奖励提交后继续原结算菜单，存储失败不提前消耗原终点或推进结算。
