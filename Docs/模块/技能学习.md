# 在线技能学习

目标为 S5A9 x86 客户端。完整字段及原码来源见[学习证据](../协议/技能学习.md)与[资源合同](../资源/技能学习与成长.md)。当前接入普通未转职 SP 学习、双树持久化及界面通知；正常经验来源、升级发点、TP学习和实际施放尚未完成，不能把隔离fixture的学习成功写成正常成长或Windows通过。

## 普通学习范围

C2S `(1,29)` 为 `context:u8,count:u8,count*(id:u16,decrease:u8,magnitude:u8),mode:u8`。支持context0/1、mode0/1、正向单阶decrease0/magnitude1、1..255个不同技能ID；批次按顺序检查前置，在一次事务中全成或全败。当前限定grow0、非job9/10、普通active/passive SP资源且无combo/feature业务。缺必要费用/门槛声明、其他模式、降级、特殊职业、TP与未闭合状态拒绝，不伪造通用成功。

Parser分别接受直接正文与实际发送前处理追加4B检查值的形状，模式字节不从检查尾读取；只因该合法尾部而关闭连接的长度误判已修正。真实skill190请求已用于[解析回归](../../Server/DfoServer/SelfTests/SkillLearningDisconnectTests.cs)，不据此认定该角色资源/等级资格或实机学习已通过。场景、等级、前置等业务拒绝的完整wire映射仍须闭合；学习资格与原owner/事务检查保持。

按匹配职业目录检查ID、角色等级、已学等级、前置、费用及SP。费用为资源fitness调整值；当前服务端没有额外减免状态，角色减免明确为零。primary上限允许的范围是已证明子集；达到primary边界后第二OR仍未闭合，返回Unsupported，不能将保守边界伪装成精通错误。

Lv1新角色两树SP/TP均为0。初始化只绑定原CHR已学技能，不扣或赠点；固有已精通技能缺升级range不妨碍绑定。普通最低空槽0..254为确定分配策略，升级保持原slot，FF不可作未分配值。空/未知/special角色保留原数据和原Player投影，不发送空NOTI19冒充初始化。

## 事务与通知

`SkillRequests → SkillHandler → GameSession/SkillLearning → CharacterRepository → SkillPackets`。Domain规划为只读快照，不写库。Repository在有效account generation内以角色id/account/revision作CAS，同事务写SP、技能等级、稳定slot及revision。GM保留不递增revision合同，因此提交前另比对当前level/grow/主技能及完整两树快照，旧计划不能覆盖工具已提交数据。context0同步既有character_skills；context1拥有独立等级，不覆盖主树。学习事务禁止增加SP、改变TP或经验。SQL失败不替换Selected。

[SkillLearning](../../Server/DfoServer/Game/Skills/SkillLearning.cs) 负责初始化与学习规则；[Session 协调](../../Server/DfoServer/Game/Session/GameSession.Skills.cs)捕获当前角色、选角 epoch 和阶段，锁外解析资源与规划，重新进入原 lease 后复查快照引用与状态，再提交并安装 Repository 返回的角色。初始化允许发生在入城投影前，保留已有经验，已初始化时不重复写库；在线学习要求 Ready/Town。规划期间换角、接管、GM 替换快照或另一笔提交使原计划失效，不自动重试或扣费。

成功结果携带 `SkillLearningReceipt`，绑定实际提交角色、generation 与选角 epoch。Handler 按回执构造 ACK，发送队列出队时再次核对当前角色快照；尚未发送的过期 ACK 跳过，数据库提交保留。同 revision 的 GM 更新也会使旧回执失效。已开始写入的帧仍可能与状态切换交叠，发送门禁不撤销在途数据。

提交后仅发完整ACK29：`01 ctx sp:u16 tp:u16 count items mode`；普通每项 `slot:u8 id:u16 targetLevel:u8 hasExtra=0`，总长 `8+5*n`，单项13B、两项18B。成功本身刷新该上下文等级、余额及界面，不重跑提交来补通知。已确认不存在技能/点不足的失败为 `00 1500` / `00 1600`，完整3B且后续同连接可继续。其他状态/前置/上限/SQL及身份错误没有已证错误域时关闭连接，日志记录原因，不猜D9或通用码。

选角顺序保持ACK4、1382、Actor、Player、可选完成任务表，随后对完整已初始化树发送NOTI19，再仓库/城镇通知及124。NOTI19为u32长度加protobuf，两tree按context0/1顺序；required零SP/TP也写tag与值，每个已学技能携带持久slot/id/level。Player同时分别投影两tree等级及完整u64经验，不把主树重复当作第二tree。完整字段见[证据](../协议/技能学习.md)。

请求magnitude是真实signed delta的绝对值，不是目标等级，正文没有稳定操作身份。相同报文可表示合法连续升级；每次到达按当前等级、余额与revision重新判定，不按报文哈希伪造幂等。服务器不因发送失败自动重跑费用。客户端主动重复发送仍可能是下一次合法增量，不能声称任意重复都不再扣费。

## 学习存档与初始化

技能点余额与稳定槽位绑定随[完整数据库基线](../开发/数据库.md)建立。技能、任务和角色 revision 由所属业务事务维护；首次合法初始化绑定作为独立事实递增 revision，只写零余额，不因数据库初始化补发经验或点数。

[学习Repository](../../Server/DfoServer/Persistence/CharacterRepository.Learning.cs)保留资产、金币及未参与任务。发送失败后重登/重启读取已提交余额与槽位。开发GM更改等级不发点、不写经验，不作为升级验收；已有绑定的技能等级覆盖同步两树但不改点数。工具加入未闭合资源仍须独立资格，不用GM绕过本业务。

C# [Domain测试](../../Server/DfoServer/SelfTests/SkillLearningTests.cs)、[独立包体读取](../../Server/DfoServer/SelfTests/SkillPacketsTests.cs)、[Repository测试](../../Server/DfoServer/SelfTests/SkillRepositoryTests.cs)、[发送失败](../../Server/DfoServer/SelfTests/SkillPublicationTests.cs)及[TCP](../../Server/DfoServer/SelfTests/Tcp/SkillProtocolTcpTests.cs)覆盖两树、费用、前置/等级、容量、短长包、SQL回滚、旧generation/revision、提交后发送失败、重登和重启。TCP中的较高等级、经验与余额为隔离fixture，依据匹配资源配置，不是生产正常成长事实。

Windows学习成功、正常发点、已学技能实际施放分别验收。[经验升级通知证据](../协议/经验升级通知.md)已闭合NOTI37自身完整直接读取布局，长度为91+8*bonusCount，并记录新对象附属状态初值及窄范围普通事件策略；合法经验来源、成长事务、完整发布包序和实机仍待接入。纯Builder或独立成长计划不能替代正式XP来源；不发截短升级包，不以零覆盖存量未知状态，不为按钮可点赠SP，不用初始技能表或测试成功宣称16职业主线已完成。成长接入前提见[角色成长](角色成长.md)，按[文档索引](../README.md)继续定位所属协议与资源。

已有双树的角色使用GM技能编辑时，只允许覆盖双方已有绑定等级；无完整资源/slot资格的新技能及删除最后绑定被明确拒绝。未初始化的旧角色保留原工具编辑合同。该守界防止工具产生canonical与双树不一致，随后学习事务静默删除工具数据；不通过清空余额重建来掩盖问题。
