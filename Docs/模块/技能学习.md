# 在线技能学习

目标为 S5A9 x86 客户端。当前实现 SP/TP 学习、多级购买、降级、整树重置、固定等级赠技、达人契约状态及账号获取、双树存档、手动换槽、技能指令保存，以及黑暗武士和缔造者的技能树与成长。字段见[技能协议](../协议/技能学习.md)，资源规则见[技能学习与成长](../资源/技能学习与成长.md)。双树切换、普通快捷槽整理与服务端技能施放仍未实现。

## 普通学习范围

C2S29 支持 context0/1、mode0/1、decrease0/1 与正数 magnitude；magnitude 是增减等级数量。批次包含 1–255 个不同 ID，按请求顺序检查资源、职业/觉醒上限、角色等级、前置和费用，整批提交或整批拒绝。job9/10沿匹配职业资源计算；combo根不作为可购买技能，feature单独使用TP，公会技能和未知资源保持拒绝。已有技能保持 slot，多级购买逐级计费；降级不低于免费基线，退到零删除绑定及该技能指令，并在 ACK 中返回零级变更。降级后仍保留的付费技能必须满足前置。

等级上限取 primary 与对应 secondary 的较大值，再受资源 maximum 限制。下一阶等级门槛为 required + 当前已学等级 × range；达人生效时角色等级资格增加匹配契约目录声明的技能等级数。费用采用匹配资源的 growtype fitness 百分比截断，角色额外减免当前为零。

通用技能沿各职业自己的SKL参与同一学习事务。required level及required level range缺省时均采用匹配客户端初始化值1；受身蹲伏不因缺少间隔标签而拒绝包含暴击、跃翔的混合批次。主动填可见快捷栏空位，被动使用基础组，已有绑定升级保持原槽；职业资源的零上限、等级门槛、SP费用与整批原子性继续生效，不按通用技能编号另设放行规则。

SP 使用 S4A21 的扣除模型：每树可用 SP = 累计等级表 SP + 独立额外 SP − 该树已学技能在免费基线以上的费用。初始、转职、累计觉醒赠技和固定等级技能属于免费基线。额外 SP 不因学习、退款、洗点、升级或重登被清零；两树费用分别计算，TP技能费用不扣SP。余额是这个结果的存档和协议镜像，不另存每次购买费用历史。

Lv1 新角色额外 SP 为零。已有完整两树只有在所有费用可核算、两树“余额加费用”一致且不低于等级表时才接管来源，差额保存为额外 SP；不一致或未知旧状态保留原值，不强行修复。未知来源仍可沿原余额进行普通正向学习，不允许退款或重置制造新来源。

初始主动优先使用整个可见快捷栏0–11，再使用150–197；初始被动从102分配。后续主动沿相同顺序，被动按资源分组使用12–53、54–101、102–137，避开12个快捷格；138–149留给特殊映射。满组整批拒绝。方向声明缺省为空，已声明 class0–3 的空方向被动属于转职组；class4 为基础组，class大于4沿参考端回退普通被动组。重复且未闭合的分组元数据保持未知，不影响已有绑定升级。

建角入口在绑定前调整前两个快捷技能的输入顺序，使Z技能直接绑定第一格，后跳及其余技能沿原槽位规则；原技能列表保持资源顺序，两棵技能树同事务保存。单快捷技能或前两项包含后跳时保持原顺序；通用初始化、槽位分配器、已有角色登录、学习及GM重置沿原规则。

新角色后续新学主动优先填最靠前的未使用主快捷槽0–5，再填扩展快捷槽6–11；两栏全满才进入普通主动区。手动移走主动后留下的空位也会优先复用。旧198–203绑定及误绑的被动不自动迁移，其历史绑定仍按占用计算；已有技能升级保持原槽。

## TP与特殊职业

TP同样采用累计来源减技能费用：匹配表的等级贡献累计至当前等级，加独立额外TP，再减该树feature技能免费基线以上的special purchase cost。费用逐级取值、超出声明项重复末项，不套SP的fitness折扣。TP学习检查资源上限、角色等级与前置，不使用达人加成。Lv49贡献0，Lv50贡献1，Lv60贡献11；正常升级按累计差增加双树余额。两树旧来源一致且能完整核算时才接管额外差额；未知旧状态保留原余额，不能退款或重置制造来源。

黑暗武士job9按CHR建立六个免费连招根；根占0–5，初始子技能保留独立等级并放150–197，后跳使用扩展空位。新学主动仍按整个12格快捷栏填空。C2S508保存指定树的六组连招，每组至多六个已学主动，跨组重复ID保留最后位置。子技能退款到0时从连招移除；登录通过NOTI447回放两树，学习或重置后同步当前连招。

C2S510是黑暗武士自动编排的前置：将快捷栏上的本职业连招候选移入150–197的空位，保持等级、指令、费用、根和后跳；提交后先回放变化绑定再发成功ACK，由客户端生成随后提交的508连招。它不实现普通快捷栏排序。缔造者job10沿本职业active/passive和前置计算；两种特殊职业允许first0的0x10/0x20觉醒资源资格，不授予转职或觉醒任务完成事实。技能200–211固定绑定138–149，不占普通空槽，也不能按普通换槽移动。

## 技能指令

C2S331按实收记录数读取ID和原始按键字节，编辑主树中已学且允许自定义的主动技能；没有context字段，双树切换仍未开放。单项“恢复默认”也可以通过331提交默认字节；零长度删除该技能自定义，C2S332清除主树全部自定义。保存不改点数、等级或槽位，相同状态免写入；提交后发成功ACK及完整NOTI19。

指令随技能绑定和完整学习快照同事务保存，升级保留，删除技能同步删除。NOTI19的skill field4是packed整数，按键大于127使用varint，不能套其他版本的裸字节编码；ACK29的hasExtra扩展仍按原始u8序列发送。登录先回放存档完整树，在地区23/24绑定后再次回放完整树并为空指令补充资源默认按键；玩家已有指令优先，每树独立处理。默认补充仅属于发送投影，不修改角色、revision或指令表。重选、重连和服务恢复采用相同包序，331/332成功回包也显式补默认，保证清空自定义后实际恢复默认按键。单独跳跃/攻击等不可通过field4安装的固有输入仍由客户端处理。编辑未学技能、施放指令验证及服务端施放效果尚未接入。

## 固定等级与达人契约

CHR 初始、转职和累计觉醒赠技按当前成长阶段加载；技能列表已删除的 CHR 编号不创建绑定。固定等级技能还检查职业/觉醒资格，等级为 (1 + (角色等级 − required) / interval) × add；适用达人时增加契约目录声明的技能等级数 / interval，最后受资源 maximum 限制。这些等级免费，不能手动购买。

登录、技能操作及正式经验成长同步免费基线，保留已有槽位。升级导致固定技能变化时，NOTI37 后补完整 NOTI19；通关成长沿同一规则。资源在 Catalog 装配时预读，成长的 SQLite writer 内只访问已缓存的定义。

账号达人契约保存绝对到期秒数。旧开发 GM `contract` 期限与[商城、礼包及遗留契约消费](背包与装备.md)的账号钱包类型27期限分别保存，有效期限取两个账号来源的较大值；`CharacterLearningState.ExpertContractExpiresAt` 只是读取镜像，不写角色期限表。GM清除自身来源不撤销仍有效的购买期限。钱包提交后当前角色立即安装实际有效期限，其他角色在选角时读取同一账号权益；学习事务继续核对完整学习快照，不能覆盖同revision的GM期限变化。

生效时按资源声明放宽SP学习资格，不放宽TP门槛。`SkillLearningCatalog.Load`显式接收契约目录的达人技能等级参数，生产与开发装配共用声明；缺少加成时使用零，不默认补五级。到期后的登录、成功技能操作或成长将超额等级回落普通资格，按减少的已学费用返还SP，固定等级同时回落；没有后台到期推送。保留到期记录供回落判定，不在列表过滤时删除账号账本。登录通过NOTI66 type2/effect27通知剩余秒数，过期记录发送零秒清除客户端状态；账号购买或使用提交后在NOTI1760之后发布同一有效期限的NOTI66。代码、资源与TCP回归不代替客户端技能界面及实际施放验收。

## 普通换槽

C2S28 按[换槽协议](../协议/技能学习.md#普通换槽)读取完整8B正文及可选4B检查尾。普通分支为 context0/1、额外上下文-1、mode0。[SkillLayout](../../Server/DfoServer/Game/Skills/SkillLayout.cs)交换两个绑定，目标为空时移动源绑定；不新增技能、不改等级、SP/TP、经验或当前树。

普通位置为0–203，排除138–149；0–11和旧198–203区域只接受明确active，两个方向均校验。主动可手动移到普通非快捷区域，未参与操作的旧绑定原样保留。同槽只确认原事实，不写库或递增revision。ACK28完整4B，不额外发NOTI19，重登按持久slot回放。

学习、降级、洗点和换槽要求选中角色且 Ready，允许地下城及结算阶段。操作不使用通用城镇门禁，也不修改副本 run、死亡事实或奖励账本。回执记录实际阶段，阶段切换会使未发送旧回执失效。

## 整树重置

C2S491 接入普通 context0/1、mode0/1，清除指定树的付费SP/TP等级、恢复免费基线，并从两种总来源派生余额；保留另一树、额外SP/TP、免费技能已有槽位及其指令，连招移除已删除的子技能。任一种来源未知时拒绝重置。重复重置无变化时免写库。提交后发3B ACK491，再发完整NOTI19，黑暗武士另同步NOTI447；其他版本的 ACK 宽度不适用。重置耗材、付费和决斗场模式未接入。

## 事务与通知

`SkillRequests → SkillHandler → GameSession/SkillLearning → CharacterRepository → SkillPackets`。Session 捕获角色、generation、选角 epoch、阶段与快照，锁外纯规划，重入原 owner 后复验，再提交原子 SQLite 事务。费用、两树余额/绑定、额外来源、context0 的 canonical 技能与 revision 同事务保存；SQL 失败不安装 Selected 或发送成功。单项GM进度编辑保留原revision合同，因此还比较完整学习快照，旧计划不能覆盖同revision的工具修改；GM等级/职业重置则完整重建双树并递增revision，见[开发GM](../开发/GM.md)。

成功回执绑定实际提交角色和阶段，发送队列出队再次校验。尚未发送的过期 ACK 跳过，提交不撤销、不重做。ACK29 完整体为 `01 ctx sp:u16 tp:u16 count items mode`，每项 `slot:u8 id:u16 level:u8 hasExtra`，自定义指令存在时追加数量及u8字节；同步自动技能或余额时才额外发送完整 NOTI19。请求没有操作 nonce，相同报文可以表示下一次合法增量，不能按正文哈希去重。

已确认业务失败码：不存在0015、SP不足0016、精通0012、等级/前置不满足00D9。TP不足采用S4A21的0002；匹配客户端公共失败尾可解除学习等待，没有该码专用文案。技能资源重复学习标签按[首段读取规则](../资源/技能学习与成长.md#费用前置与上限)处理，首段前置、费用和SP/TP资格仍参与正常校验与原子保存。有效但未支持的业务记录原因并保持连接，不猜成功或失败码；非法正文宽度、非法 decrease 和损坏存档仍按协议/存储错误处理。换槽与洗点的未知失败域不套用学习码。

选角继续以Actor/Player后的完整NOTI19回放两树；required零SP/TP也显式编码。初始化不重排旧槽位，不清空未知旧来源或奖励历史。数据库v12增加TP来源、技能指令与连招空表，见[数据库](../开发/数据库.md)。开发`sp`设置独立额外来源，`level`写目标等级起始经验并重建两树，均须重新选角刷新客户端；GM不代替正常升级验收。
