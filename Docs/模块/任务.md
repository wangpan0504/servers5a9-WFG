# 主线任务状态

当前实现任务资源读取、创建时初始主线槽、已完成任务/剧情等级的持久化及选角投影。正式3145的权威清图条件、完成请求及完整领奖事务支持job0–15和合法转职/觉醒；匹配任务声明job=all、grow type=-1，清图及领奖不再以job0/grow0作业务门禁。一般接取、父子任务聚合及其他任务仍未接入，3145剧情交付画面仍需集中客户端验收。

## 持久状态与投影

普通建角与角色/技能/初始装备同事务写入 `accepted_story_level=1`、第 0 槽 `quest_id=3145, condition_state=1`；其余 29 槽为空。3145 的单清图 Boolean 初始未达成为 1，达成为 0，不可把 0 作为初始化值或推广成所有任务的状态枚举。

ACK4 携带进行中任务，NOTI356 携带已完成表，NOTI1382 携带已接受剧情等级；三者不能替代。字节布局分别见[角色与入城](../协议/角色与入城.md)和[主线任务协议](../协议/主线任务.md)。选择、城镇移动、返回选角与重登保留进行中槽，诊断副本死亡不推进条件。

每个持久进行中槽携带独立 `AcceptanceId`。正式准入冻结此身份，迁移只为原接取补建身份、保留原条件，不依据scalar=0补造清图或奖励。重新接取须分配新身份，旧实例不能修改新接取。

任务表随[完整数据库基线](../开发/数据库.md)建立，包含已完成任务、进行中槽及 condition_state。新角色的剧情等级和初始任务由建角业务写入；数据库初始化不补发任务或修改已有进度。

## 请求和资源

C2S33仅支持已核验6B、3145/value0/reserved0形状，由独立 `QuestConditionHandler` 读取本次接取的持久权威清图事实，回复完整7B ACK33（success、quest、scalar0）。它不因客户端报告修改条件或发奖；未满足资格、未知字段或模式保持未处理，不猜造失败码。C2S34完成请求只接入已证10B、3145/rewardFFFF/multiplier1/reservedFFFF形状，由独立 `QuestCompletionHandler` 调用完整领奖用例。公共成功体143B使用资源清图类型3、实际提交EXP增量、item模式0和原序七项19B奖励；满包error4有专属提示，中立业务拒绝使用本服error19静默收尾并保持连接。未知请求不借用此范围；请求本身不证明通关或奖励资格。

匹配任务 3145 至 3149 及关联子任务的条件、前置、奖励和 maze 声明见[资源参考](../资源/新角色主线.md)。资源存在不证明 NPC 已生成、赛丽亚可见或剧情交付完成；ACK34 奖励消费、3146 聚合和 NPC 交付的缺口以[协议参考](../协议/主线任务.md)为准。

## 权威清图事务

正式3145当前只接受资源Dungeon3、Boss地图76126及本次接取身份。末次敌方可信死亡的Prepare候选携带实际BossMap、唯一死亡集合与结算epoch；成长Repository在同一SQL事务核对本实例全部已提交死亡，将条件1更新为0并保存唯一清图receipt，经验、等级、两树SP与角色revision同时提交。此条件推进与职业、转职无关，已达成不代表已领奖；S4A21和external同样从权威地图完成事实推进活动任务，再在领奖用例按职业资源筛选奖励。剧情同team actor保留身份，不要求死亡，不授予经验。诊断状态、C2S33、旧房/实例/接取、重复或篡改事实不能签发此资格。

清图失败整体回滚；已提交未返回的精确重放只读取同一成长和清图账本，不再次推进任务。清图达成仍保留活动槽，未发任务奖励、未清槽、未写完成表。`ReadClearedQuest`仅在有效Town或本实例Settlement下读取同接取持久事实，回执绑定账号generation、选角epoch、实际角色快照和可选实例身份，不能投递到重选或回城后的另一阶段。已有条件0但缺权威账本不能借查询变成已验收通关。

同次接取已达成且持久清图凭据有效时，全职业及合法转职/觉醒允许再次入场及结果页再挑战，沿用已有新attempt/instance/key预留；重复清图保留首个凭据，不再次推进条件或新增领奖资格。仅有条件0而没有真实清图账本的记录仍拒绝入场。

## 本服3145领奖规划

[QuestCompletionPlan](../../Server/DfoServer/Game/Quests/QuestCompletionPlan.cs)在锁外提供完整只读规划，捕获原角色、同接取的持久clear receipt、实际资源、共享grant整批背包计划、成长计划、七项原序目的槽/Core、清槽后的活动列表及保留历史项的完成表。它不持有在线状态、不写库，不能用客户端C2S34或条件0替代clear账本。存储提交仍须在原owner内复核generation、选角/实例身份、完整角色revision及原资产，将EXP、等级、两树SP、七项UID/槽/Core、清槽、完成位与唯一领奖receipt放在一个事务。

任务经验明确采用本服规则`local-3145-quest-parameter-exp-v1`，适用于全职业普通3145，完整匹配epic/difficulty1、clear map76126、Tobi1247交付、item奖励及七件原序，且未声明`not give exp quest`。按资源的直接index=`Quest.MinimumLevel`取EXP基础，使用difficulty原字符串键的值作为本服百分比，`floor(base * weight / 100)`；当前index1/base100/weight1780产生1780EXP。规则保存版本、资源路径、index、基础、原追加参数、difficulty键/值及额度，不读客户端或PVF文件哈希。此百分比组合仍是明确本服选择，不因复用S4A21或external的业务结构而宣称恢复V31原服普通任务经验算法；不借COD46%、额外bonus或其他任务的规则补量。

Gold遵循已证本任务没有item0奖励行的消费结果为0，不从Gold参数表补发72/101。固定物品沿`QuestFixedRewardDefinition.ForJob`保留资源原序，公共10165055、本职业武器及10403、12403、14403、16403、18403各一件；job0武器101010438、job14武器108000198、job15武器116000005，其余职业见[奖励资源表](../资源/新角色主线.md#普通初始装备与全部显式物品奖励)。转职或觉醒不改变本任务的基础职业奖励，不能向其他职业统一发job0武器。`QuestFixedRewardGrant.ReadRewards`统一校验七项固定合同，经验与物品规划共用它；金币为空不等于物品或EXP为空。物品使用统一grant创建满耐久/品质及完整合法Core，冻结规划时刻的期限；实际UID由提交分配，已有堆叠保留真实UID/Core并投影本次增量。

成长复用[CharacterGrowthPlan](../../Server/DfoServer/Game/Characters/CharacterGrowth.cs)，从实际累计经验自然确定等级并分别增加两树等级贡献，保留不同余额、TP、技能等级及稳定槽。旧未初始化成长、未知额外倍率、EXP上界或SP溢出拒绝完整计划，不先发物品或用EXP0完成。背包不能完整接纳七项时返回领域`InsufficientSpace`，不能发布已规划的前半奖励或清任务；它不是wire错误码，匹配满包ACK34 error4的消费者见[协议](../协议/主线任务.md#ack34-注册与公共失败包)。

成功增量ACK34只能针对原客户端仍拥有active对象的一次提交结果，随后再投影实际库存及成长快照。已安装、重选/重登后已恢复完整库存的重复请求不能重放旧143B成功体，以免重复增加本地堆叠；SQL已提交但返回丢失的恢复仅可核对原未安装pending及精确receipt。其他中立拒绝采用本服明确的静默error19，不把它宣称为原服“重复领奖”错误；不得因业务拒绝断网或伪成功。

生产路径为 `QuestRequests → QuestCompletionHandler → GameSession/QuestCompletionPlan → ICharacterRepository.CommitQuestCompletion → QuestPackets/GrowthPackets`。Session捕获Ready/Town或本实例Settlement的原快照与接取身份，锁外规划资源，重新进入原lease复查选角/phase/run和快照引用后提交。v13领奖事务复用既有资产写入事务与成长/双树写入：一次revision+1同时保存实际UID/Core/槽/数量、累计XP、目标等级、两树余额、删除原接取活动槽、写完成表和唯一receipt；不修改未参与的账号钱包、金币、TP、技能或历史任务。

SQL失败不安装Selected，原pending计划保留用于精确恢复；结果不明时先查询原接取账本，不能因为旧Selected的revision而重做资产。已提交重复只读返回当前持久角色，实际revision/职业/成长/两树/任务/七项完整资产仍与receipt相符，才允许原未安装请求的一次增量投影。普通重复或重登已加载完整背包的请求直接中立拒绝。pending期间不能用回城绕过未知结果，重选/断线使原计划失效，新会话从持久数据恢复。只有实际提交角色安装后更新Session完成任务集合。

成功包序为 ACK34本次真实增量 → NOTI14七槽完整Core绝对校准 → NOTI37绝对XP/等级/两树SP与已有附属owner；固定技能等级变化时沿既有SKILLINFO更新两树，再在实际升级时按[等级投影](角色属性.md)按实际阶段追加Player（Town/MapSelect仍为Actor→Player），使用提交前后实际等级判断，未升级不额外刷新；没有先发最终库存再重放增量，也没有写库前成功。成功/拒绝投影均绑定原账号generation、选角epoch、实际角色引用和可选结算实例身份，等待期间回城、重选、GM替换或接管不能向新角色发布旧结果。发送失败结束原连接，不撤销或重跑已提交奖励；客户端从下一次全量投影恢复。

[QuestCompletionPlanTests](../../Server/DfoServer/SelfTests/QuestCompletionPlanTests.cs)覆盖本服参数计算、规则范围、禁EXP/缺奖励拒绝、持久接取/clear前提，以及实际资源的整批七项、两树保留、自然升级、满包与未知成长。规划回归不代替SQL、TCP及集中实机的剧情交付与重登验证。

## 事务约束和验证

新增完成业务必须绑定持久接取身份、当前角色、实例与实际 maze/map。异步结果重验 lease/generation、选角及实例 epoch；条件、完成位、奖励、清槽和后继资格在同一事务提交。不能先 ACK 后补发奖，不能借开发 GM 或诊断客户端报告制造正式通关。

[正式Session回归](../../Server/DfoServer/SelfTests/FormalDungeonSessionTests.cs)补充同revision接取身份改变、末次清图SQL晚期回滚、条件和唯一receipt恢复，正式TCP源码核对剧情角色不要求死亡及隔离服务实际重启恢复。源码用例不等于已运行结果，也不替代客户端通关和NPC交付。

[角色创建测试](../../Server/DfoServer/SelfTests/CharacterCreationTests.cs)和[TCP角色回归](../../Server/DfoServer/SelfTests/Tcp/TownProtocolTcpTests.cs)覆盖初始槽、投影、重登及失败回滚。完整接取→通关→领奖流程尚未实机验收；执行命令见[贡献指南](../../CONTRIBUTING.md#验证)。
