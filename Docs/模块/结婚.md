# 结婚系统

本模块负责婚约、准备任务、婚礼及访客经济、婚戒与心意点、婚房家具、夫妻树、成长胶囊、伴侣传送和夫妻副本。字节合同见[结婚协议](../协议/结婚.md)，正式组队与战斗沿用[副本](副本.md)。

## 状态与所有权

`Game/Marriage`保存不可变关系快照与纯规则；`GameSession`持有选角身份、当前角色和临时入场身份；`IMarriageStore`是持久化边界。`MarriageCatalog`由Runtime从实际PVF装配一次，Handler、规则及投影共享该目录。

关系使用不可复用的GUID、非零u32上下文和递增revision。状态0为历史解除，1为订婚，2为已预约，4为已婚。婚礼有独立GUID、支付账本、预约频道及礼堂、邀请与礼金，以及待开场、成功、取消终态。有效成员索引保证角色同时只有一段有效关系；历史关系不阻止解除后的删角。

双方确认、预约和需要双方同步的提交，先确定参与者，再按账号固定顺序取得双方租约。角色库存、关系revision、有效成员、费用及邮件在同一个SQLite事务内保存。双方在线快照只安装实际提交结果；离线配偶的款项与物品走系统邮件托管，不直接重写其角色资产。

结婚物品组合计划保留实际消耗的源、材料及本次授予实体的最早有限期限，并沿用Runtime注入的同一时钟在原库存事务中复验。到期等号即拒绝，双方任一计划过期时金币、道具、关系及邮件整笔回滚；未消费的后续材料堆和无关仓库物品不成为本次截止。人工期限回归只证明该提交边界，不代表实际资源已声明有限期婚礼道具。

礼金及预约退款收件人受删角事务保护。任何未结清来宾礼金都会阻止删除该来宾；预检和实际删除均复核，避免预检后竞态丢失收件人。

## 婚约与准备

求婚、回应、退婚、协议离婚及强制离婚使用当前关系身份，拒绝不创建关系。对象不能是本人、同账号角色、已有有效关系角色或不符合资源资格的角色；待确认请求绑定原会话和选角版本。

准备任务20737、20738归当前关系。五次双人进度由正式共享副本冻结的婚约、双方名册和真实clear receipt证明；其他队友、另一段关系及重复事件不增加次数。退婚或离婚只清理结婚专属任务，不移除无关任务历史。

准备任务20737、20738省略难度声明时，遵循[任务经验](任务.md)的统一默认100%倍率，不设置婚约专用难度白名单。第一步仍复验本次接取的五次通关凭据；第二步仍要求完成第一步并足额持有资源声明的心意娃娃，交付时按原寻物事务扣除材料。两步均保留有效婚约及奖励库存容量检查，显式未知难度继续拒绝。奖励、经验、材料消耗与任务完成记录在同一事务内提交，重复交付不重复发放。

预约资格以双方已完成资源声明的准备任务为准；任务提交负责校验实际通关进度，预约不再额外要求婚约上的累计通关计数。计数不能代替未完成任务，也不会为预约回填或改写。

每日心意点在登录时按资源增加并钉住上限，重复登录不重复领取。婚后道具使用与商店购买分别扣费；婚戒只允许按资源顺序升级，不把商店售价再当作使用费用。

商城的`[cerashop restrict item]`按商品编号而非物品编号过滤，仅已婚角色可购买；提交时复验关系身份及婚姻阶段。申请订婚或已预约期间不能购买、启用或完成角色更名卡，已婚及无婚约角色不受此限制。更名资格在原消费／改名事务内再次复核，拒绝不扣道具、不丢失待更名资格。

## 婚礼与访客经济

婚礼选择窗口通过本人伴侣角色卡取得预约对象姓名。原生零目标查询返回本人有效关系中的真实伴侣资料；非零目标是被查看角色的编号，返回该角色的伴侣而非查看者自己的伴侣。未婚角色也可查看他人的婚姻信息；主体无有效关系时拒绝，不将任意目标解释为婚姻context。婚姻信息窗口的伴侣装扮空槽使用[统一角色默认外观](角色.md#默认外观)，同时匹配对方职业、转职分支及觉醒阶段；克隆装扮显示已保存的来源，无来源按空槽处理。未映射槽使用原生-1，不能用0抹去客户端默认。此处理仅用于显示，不写入库存，不改变本人外观路径。

双方确认预约后才一次扣金币或婚礼券，并保存预约日资格。礼堂按服务器、频道及资源区域8至37分配，当前频道没有空位时拒绝。到时由单一有界调度器检查双方是否仍在本场礼堂；成功才转为已婚并投影电影，缺席按账本取消退款。调度发包遇到某成员断线只记录诊断，已提交结算不回滚、不重新发奖。

邀请有效期为60秒，未决期间拒绝重复邀请，普通双人组队不影响预约。回应必须匹配原目标会话、发起人和操作类型；错误对象的回应不能消费有效邀请。合法回应失败或过期时，仍向回应人保留原操作回执，并通知原发起会话关闭等待窗口；不把通知发送给重登后的新会话。

同一地图区域上的角色按ceremonyId隔离同屏和普通聊天。入场事务重查当前婚礼revision、频道、时限、实际请帖及礼金。普通CMD36不能直接进入礼堂；来宾必须有请帖并实际送礼，且开场后不能补发邀请或收取新礼金。

来宾首次入场按`[ceremony gift]`领取礼炮及礼花。完整库存放置、入场位置和请帖领取凭据共用同一个事务，容量不足整笔拒绝；重进、重放或重登不重复赠送。此礼物与婚礼成功后的礼金分档回礼分开，期限遵循实际物品和每日清理配置，不根据说明文字推算期限。

礼炮使用按本版共享特效物品CMD251处理。`[chn random image percent]`五列保留结果序号、权重、奖励礼包及两条动画，成功消费一件后在当前城镇场景发布原生219特效，婚礼仍按ceremonyId隔离。正数奖励引用复用既有礼包奖池和发放事务，不将无名中间礼包塞入背包；无奖励行仅产生特效。源消费、随机产物、冷却及使用次数一次提交；容量、期限、旧库存版本或资源不支持时不消费。当前接入城镇路径，副本中客户端原生UDP共享特效不在此C2S入口处理。

礼金保存来宾身份、金额、祝福及结算标记，重复提交不扣第二次。成功按资源手续费和分账规则生成双方邮件、婚礼礼包和来宾回礼；取消退回实际托管本金和预约费用。每封交付有绑定婚礼及收件人的幂等标识，邮件失败回滚整笔事务。大额按既有邮件上限拆分。

婚礼化妆箱沿普通CMD160开箱。豪华化妆箱10002631的`[charactor]`按开启者的精确职业与等级范围筛选，本职业各独立池分别抽取，不限制转职或觉醒，也不发其它职业奖励。女圣职者的五项为结婚礼服礼包490700962、武器装扮415600000、100个心意通及两种婚戒升级券各一张。源消耗、全部普通道具和装扮详情沿既有开箱事务提交，容量或期限失败保留源盒；内层礼服礼包仍作为实际道具发放，按自己的入口再开箱。

婚服仅是临时显示，不修改真实装备。电影结束及大祭司离堂由客户端发送普通CMD36，来源为0/0、Movement5、PathKind0、TargetNpc0；服务端要求当前临时礼堂身份，目标地图实际有婚礼NPC20013，落点为该NPC坐标及Y加30，或本版原生离堂精确落点39/0/2165/180。原生离堂落点与MAP中的NPC摆放坐标不同，不能据此放开任意目标坐标。该原生坐标允许在普通步行矩形外，地区等级和任务权限仍须通过。正式旅行提交后解除婚服，重复离堂请求不再保存或发布。重连不恢复旧礼堂身份，先回合法普通地区，再按请帖入口进入。

## 婚房与后续玩法

已婚成员通过资源中赛丽亚房间左门进入101/0。场景按relationshipId共享，仅夫妻同屏。进图发布1011家具和树、1012共享保管箱；普通城镇也保留1011输入供客户端重算婚房权益。家具布置、收回、交换和删除使用一份共享存档，编辑锁绑定原Session、generation及选角epoch，离开、接管和重选后旧锁不能阻止新会话。

原生家具摆放、收回的目标编号是源家具编号回显，空目标也使用该值；共享背包内部拖动才校验目标原物品编号。跨容器仍验证实际来源、资源允许的位置、真实目标占用及完整数量，堆叠摆放一件、收回同物品合并、内部交换整堆的行为不变；资产与关系revision复用原事务提交。

家具移动按原生1048消费者区分关系资格、编辑占用、容量不足、不合法摆放和过期请求；已经收回的来源不能再次生成家具，也不能误报伴侣信息丢失。失败不改变共享资产及版本，不通过伪造成功或自定义弹窗绕过客户端分支，具体返回值见[结婚协议](../协议/结婚.md)。

婚房的资源出口-101不是普通城镇号。入口缓存本次来源房间，出口只接受回该来源的300/200及原生CMD36形状；普通街区Return不被婚房覆盖。来源缓存不跨连接，因此保存于婚房的角色重登先返回合法普通地区。在线离婚会保存并投影双方从婚房离场，清除家具、树、胶囊、戒指及心意点权益。

三类树按资源种子、期限、每日共用浇水次数、成长点和最后阶段成熟值处理。存档保存种子物品编号；客户端树通知和婚房完整通知统一映射为资源中的树index，带树重登、回访和重新入房不能直接发送种子编号。已有树的期限、成长及浇水次数继续保留，不通过清树或回档规避显示问题。收获先规划一次随机奖励，再将清树和实际物品奖励同事务提交；失败不消耗树，重复请求不重复发奖。到期不能收获，可移除后重新种植。

推荐副本真实通关按唯一clear事件增加本人胶囊能量，提交后1019立即更新进度。制作扣资源指定刻度；赠送在共享关系内减少本人持有并增加配偶待领，允许对方离线；领取同时减少待领、增加当日已领并生成真实物品。跨日只重置领取次数，保留持有量与待领量。

持续在线跨过现有业务日边界时，复用日切投影刷新本人胶囊领取次数；仍在婚房的成员同时刷新树的每日浇水次数。推送只更新显示，不提前写回余额或发放奖励，下一次实际操作仍在原事务内按当前业务日核算。

伴侣传送使用资源声明的原生动作和券。报价绑定当前夫妻关系revision、双方会话与角色快照、同频道、源槽及目标坐标；确认时对方移动、换角或关系改变均拒绝且不扣券。成功扣一张已有券并保存原生冷却，资源中的五枚材料是商店兑换价。目标不得是婚房、礼堂、赛丽亚房间、剧情私有场景或副本。

夫妻副本3541复用正式双人队伍实例，由婚礼NPC的专用菜单进入。只允许同一已婚关系的恰好两名成员，指定难度及资源三张门票逐人校验；关系和门票在双方入场事务内复核，一人不足全员不扣。保留真实地图、加载、怪物、掉落、拾取与退出；资源禁止普通怪物/通关经验、疲劳和普通翻牌奖励，不抹去本图专属掉落。

城镇指定副本直入沿共用队伍投影先发送42字节空NOTI27建立客户端scene2，再发送28/29；已处于选图上下文时不重复切换。此场景建立规则不绑定3541，也不替代入口、队长、资源和副本自身资格检查；所有成员仍须实际发送加载完成请求才释放战斗屏障。

已婚即拥有0级婚戒。服务器本地06:00复用现有物品日切事务，为每个有婚戒的角色补齐夫妻副本门票；模板和目标数量取该副本的实际入场材料，当前为10002609、3张。统计主背包含快捷栏的全部同编号堆叠，只补差额；已有3张或更多不截断数量、不改原实例，同一服务日使用后不再补发。资格、发放与已有角色补给日戳同事务提交，无需新增库表；满包保留待重试，不改发邮件。选角与持续在线均沿现有本地06:00调度，领取前失去婚姻资格不发放。

该DGN只声明1×1、BB及重合起终点。资源池仅装配反向归属3541、类型boss、greed为BB BB的唯一实际地图`map/chn_wedding_couple_dungeon/chn_wedding_couple_01.map`；按专用单房建立零出口拓扑，不给普通BB迷宫开放越界出口。

## 属性与验证边界

本人婚戒和婚房属性由本版客户端消费1003、1011后计算；服务端不再向基础Player永久属性叠加同一数值。PK私有角色和PK房间不开放本模块操作及初始化。跨窗口整合须继续核对PK模式入口，不能用普通城镇验收代替PK排除验收。

同屏Actor创建后通过1016补充远端关系、婚戒与装饰分；关系、戒指和家具变更复用当前场景成员刷新。装饰分只按已摆条目累计其模板材料标价数量，目录在Runtime装配时冻结，场景锁内不读PVF或数据库。

所有完整Actor投影在116字节头的+23／+24直接携带当前关系状态与婚戒等级；装备、装扮、宠物、技能、契约及其它外观刷新共用此Builder，不能将两字段清零。普通刷新不重新发送1003来修补，否则会清理客户端已缓存的伴侣预览。心意点、婚期、胶囊及家具仍由原所属通知更新，不因外观重建改写存档或重复发奖。

纯规则、Parser/Builder、数据库事务和实际网络回归分开运行。核心用例为`MarriageResourceTests`、`MarriageWeddingTests`、`MarriageCoupleTests`、`MarriagePersistenceTests`、`MarriagePreparationTests`、`MarriageLifecycleTests`及`MarriageDungeonTests`；资源回归使用实际目录。TCP组为`marriage`、`marriage-wedding`、`marriage-home`和`marriage-dungeon`。自动回归不等于客户端实机通过，婚服、动画、婚房拖放及客户端加成仍须匹配客户端验收。
