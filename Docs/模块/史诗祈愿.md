# 史诗祈愿

史诗祈愿使用匹配客户端原有五槽窗口。玩家选择、取消单槽或清空全部后，CMD1354提交完整清单；服务端检查装备目录和角色身份，先提交角色独立存档，再以NOTI1292更新客户端清单，最后回复专用成功应答。重新选角、重连与服务重启后回放已保存清单；无存档角色也发送空清单，清除上一角色残留。

原生窗口保存时读取全部五槽，空槽为0；清单保留槽位顺序和中间空位。每份清单至多五槽，非空装备不得重复。候选来自当前PVF的史诗图鉴名册，并检查装备类型、史诗稀有度和Lv70以上条件；不要求已经拥有装备，也不限定为当前职业。选择后的排序、搜索和分页由原生窗口负责。

清单只影响客户端展示与掉落特效，不消耗材料、不发装备、不改变掉率、随机次数或掉落候选。匹配客户端的地面物品分类、提示与掉落演出均读取同一祈愿清单；服务端不额外改写死亡包、拾取资产或组队掉落。原生消费者及字节见[史诗祈愿协议](../协议/史诗祈愿.md)。

持久化使用`character_epic_wishes`，角色删除时级联清理。账号租约下复核角色归属、资产revision及原清单，再同事务写入完整新清单；清单保存本身不递增资产revision。合法同值保存仍确认成功，但不申请writer。SQL失败不回复成功，发送失败不重跑已提交保存。发布结果复核原generation、选角epoch、阶段和角色引用，旧会话及旧角色结果不得覆盖新上下文。

`EpicWishTests`覆盖五槽空位、取消、非法请求、目录、角色隔离、重开恢复、外部writer下零变化、SQL回滚、旧快照、旧generation、旧epoch及迁移。`--selftest-tcp epic-wish`覆盖真实注册、选角回放、保存与拒绝、同账号角色隔离、SQL失败、重启和清空，资源候选从实际输入PVF选择。客户端窗口操作及掉落动画仍待QA实机验收。
