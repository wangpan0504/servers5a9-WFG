# 角色属性

角色属性来源属于 GameWorld；在线角色、等级、学习树、装备槽和 revision 仍由 Session 的实际 Selected 快照持有，不建立第二套在线属性状态。完整物品实例继续由[背包与装备](背包与装备.md)保存；经验、等级和两树 SP 的事务见[角色成长](角色成长.md)。

`CharacterCatalog.GetAttributeDefinition(job)` 装载 job0–15 的原始 CHR 属性声明。`CharacterAttributeDefinition` 分开 initial、各 growtype 及其 awakening，保留 float32 数值、负声明和缺项；资源编号本身不作为业务 GrowType 的映射。

独立的 [CharacterStatComputer](../../Server/DfoServer/Game/Characters/CharacterStatComputer.cs) 属于 Game 层，通过共享的 `CharacterCatalog` 读取资源；资源定义和目录只负责解析、保存声明与查询，不承担等级属性计算。`ComputeLevelBaseStats(job,growType,level)`提供全部16职业及目录内转职/两觉编码Lv1..95的正常CHR基础成长：每项先转换为原生十倍整数，初始值加未转职块乘`min(L,18)-1`，再加实际firstGrow块乘`max(L-18,0)`。正常模式基础沿匹配客户端原码，不把旧版50级觉醒分段或技能/永久修正合并进CHR。客户端另有永久/模式修正、装备效果应用和能力缓存重算，不能将服务端计算的装备总额直接叠进89B。当前目录没有提供强化、附魔、增幅、精通、被动的全部最终属性规则；因此正常升级和穿脱的面板、战斗属性一致性尚不能从服务端基础字节或装备列表推出。资源与wire的证据边界见[属性声明与消费](../资源/角色属性.md)。

`CharacterStatComputer.Compute(character)`从实际角色快照评估本人Player属性，统一判断CHR成长来源资格：job0–15、CHR目录内合法成长编码、实际Lv1..95、完整两树Learning和非空DungeonState。创建用例明确初始化这两个owner；计算CHR基础后，只叠加该角色已持久化的 `PermanentStats` 来源，不把装备或被动的派生贡献再加一次。缺少附属owner的存量角色保留原InitialStats基底，不补造永久来源或清未知字段。计算器无角色缓存或持久状态，只返回类型化 `CharacterStats`，不生成协议字节。发布仍使用原角色快照、Session当前选角epoch及提交回执资格，不另建带ID/revision的属性副本。

`ServerRuntime`显式创建一个计算器，供 `TownProjection`、`InventoryProjection`、`CharacterLevelProjection` 和 `PremiumContractProjection` 共享。各入口在锁外以各自实际角色快照计算属性，并按本次会话读取的账号冒险团等级交给 `TownPackets.Player(character, attributes, adventureLevel)`；Builder将基础属性交由 `CharacterStatsPackets.Build` 编为89B，不查询资源或重新计算基础属性。Player尾部的冒险团等级由客户端安装并重建常驻效果，见[冒险团](冒险团.md#本人等级同步)。同一构包还投影熟练等级与当前级经验的17字节头，供客户端安装熟练状态。计算器不读数据库、不发包，Projection继续负责包序和发布资格。重登、升级、转职、觉醒、换装及契约刷新均从同一快照的永久来源计算，不使用上次面板总值累计。当前实现不增加属性存档、数据库字段、接口转发或DI容器。

## 永久成长道具

[PermanentGrowthService](../../Server/DfoServer/Game/Characters/PermanentGrowthService.cs)接入CMD30原生SP书、TP书和八类属性石。当前这些STK没有数值效果标签，按真实LST的ID与规范脚本路径双重确认，再使用原生固定增量；不能根据中文说明、相似目录或复制脚本推断新编号也可使用。数值与回包种类见[CMD30永久成长](../协议/经验升级通知.md#永久成长cmd30)。

| 注册ID | 脚本 | 每件永久增量 |
|---|---|---|
| 1031 / 1038 | `book_skill1.stk` / `book_skill2.stk` | SP +5 / +20 |
| 1204 / 1205 | `book_fskill1.stk` / `book_fskill2.stk` | TP +1 / +5，遵守STK最低等级 |
| 1039 / 1040 | `stone_str.stk` / `stone_int.stk` | 力量 / 智力 +5 |
| 1041 / 1042 | `stone_helth.stk` / `stone_mind.stk` | 体力 / 精神 +5 |
| 1043 / 1044 | `stone_hp.stk` / `stone_mp.stk` | 最大HP / 最大MP +25 |
| 1045 / 1046 | `stone_speed.stk` / `stone_allr.stk` | 移动速度 / 所有属性抗性 +1 |

属性石来源独立保存于新表 `character_permanent_stats`，字段为最大HP、最大MP、力量、体力、智力、精神、移动速度和全抗增量，统一使用原生十倍定点。没有来源行表示额外值为0；查询和登录不创建来源、不推断历史奖励。SP／TP书复用已有 `character_skill_point_sources`、`character_tp_sources`，同次增加额外预算与两棵树各自的余额，不新建另一套点数总额；洗点及转职由既有技能账本保留来源。属性表不保存技能预算或派生面板总值。

源须为Main消耗品槽或快捷栏内的真实实例，校验数量、锁、期限、PVF职业/等级、城镇限制与冷却。资源解析和规划在owner锁外，提交前复核原generation、角色引用、选角epoch、细阶段、实例及revision；扣一件、额外来源、两树点数和库存审计共用同一写事务。属性增量须能在本职业全部合法转职及1/18/95级分段端点投影，点数须能在满级及洗点时表示；超出协议数值范围不消费。练习等免耗模式不豁免永久授予的道具成本，避免不消费却永久增长。

提交后先发消费ACK，再校准点数或属性；不重复删除源、不重建技能树、不改用户业务状态。发送失败不重做授予；提交结果不明时关闭原连接，重登以持久来源恢复。新库、增量迁移、SQL回滚、重开、删角、属性重算及两树预算由核心和 `permanent-growth` 定向TCP回归覆盖；实际能力面板、提示与客户端效果仍须实机验收。

所有本人Player全量刷新从同次角色快照的 `Inventory.StaminaUntil`、账号黑钻56期限和构包当前UTC时间，经既有 `StaminaRecoveryService.Percent` 投影真实虚弱百分比到89B的offset84；无期限、虚弱已到期或黑钻仍有效时为100，黑钻到期等号不保留豁免。构包接受可选UTC时间供确定性验证，不修改恢复期限、库存或基础HP/MP，也不追加恢复成功回执或依赖补发NOTI4纠正瞬时100。黑钻开通和选角对旧误罚期限的持久修复见[虚弱与魔王服务](背包与装备.md#魔王契约八项服务)。城镇、选图、副本及结算中的装备、升级和契约刷新共用这一入口，原包序和每包发布守卫不变。Actor的既有场景字段及宠物生命周期继续使用原合同；Actor更早的间接属性副作用及当前/最大血蓝、界面刷新效果仍需匹配客户端验收，不能仅由最终Player字节推断。

511精通在本地buff manager的最终能力buffer3阶段应用，174基础精通也修改最终buffer3攻击倍率分量；本人Player应继续提供完整装备Core和两树状态，以实际提交快照触发本地效果。服务端基础89B不再叠这些派生贡献。选角/重登及现有穿脱Actor→Player组使用计算器返回的实际等级基础。正式击杀、通关结算及任务领奖共用等级刷新入口，在完整N37和需要的N19之后、结算N35之前，实际升级时追加Player。普通副本/结算升级按S4A21仅发Player，城镇/选图升级保留Actor→Player。转职/觉醒另须在全部实际场景同步Actor的job/grow及Player，不受普通升级的Actor省略规则影响。通关用例在owner内返回真实调用前角色快照；重复已安装结算前后等级相同，不重复升级刷新。同等级XP增加不追加刷新。每帧仍核对原提交角色引用、generation、选角epoch及实例身份，发送失败不重复经验或奖励。普通模式HP和四个基础分量的完整getter/CHR安装桥仍需进一步证据，面板/战斗一致性仍待集中验收，不能由纯规则回归宣布全部属性功能完成。

[属性资源回归](../../Server/DfoServer/SelfTests/CharacterAttributeResourceTests.cs)的无资源入口核对全量Player真实虚弱10/19、同档反复刷新、临近到期、到期及无期限，独立检查89B基础字节和恢复期限不变；已有装备TCP覆盖已通知虚弱后的城镇脱装及穿装刷新。资源入口覆盖资源块与觉醒归属、float32位精度、负值、缺项和非法声明，并核对全部16职业及合法转职/两觉编码Lv1/2/18/19/49/50/74/75/95的等级基础属性。回归验证基础数学、来源资格与通知，不替代客户端面板和战斗验收。
