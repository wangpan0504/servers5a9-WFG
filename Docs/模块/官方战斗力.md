# 官方乘区战斗力（cp-official v1）

本服复刻原版「我的战斗力值」面板的乘区口径，由服务端按本人已提交穿戴快照计算，经 `CP_SCORE/2` 下发给客户端 CharacterScore 侧栏。实现：`Game/Characters/CombatPowerScore.cs`、`CombatPowerService.cs`、`GameWorld/Items/CharacterInvestmentMetadataCatalog.Combat.cs`；测试 `SelfTests/CombatPowerTests.cs`。

## 公开来源

- 17173 攻略（作者 金Auu）：战斗力 = 基础属性分 × 白字 × 黄字 × 爆伤 × 装备 五个乘区相乘，属强通过白字/基础分体现。
- 9upk 攻略示例：8764 × 1.69 × 1.4 × 2.5405 × 1.38 = 72696.81（v2 金样正文 `…|72697|8764|6900|4000|15405|3800|5|…` 即该例，段位为英杰）。
- 段位名（探索 开拓 无畏 征服 战绝 英杰 武炼 极尊 绝世 斗皇）来自上述攻略截图；**分数阈值为本服假设**：0/3500/9000/23000/40000/65000/85000/500000/750000/1200000。

## 公式

```text
战斗力 = 基础属性分 × (1+白字) × (1+黄字) × (1+爆伤) × (1+装备)
基础属性分 = (攻击+1) × (1+主属性/250) × (1.05+0.0045×最佳属强) × (1+0.5×暴击率) / 1.5
```

- 主属性 = max(力量, 智力)：CHR 等级成长/10 + 永久加成/10 + 装备 `[physical attack]/[magical attack]` 与增幅 type3/4。
- 攻击 = 装备物理/魔法/独立攻击取最大。暴击率 = clamp(3% + max(物暴, 魔暴), 0, 100%)。
- 最佳属强 = 全属强 + 单属强最大值。
- `[unique increase damage]`/白字首字段为整数选择器；白字模式 `%` 进入乘区，合法的 `+` 固定追加伤害不计入百分比白字。
- 白字 = Σ所有属性伤害% + Σ属性白字% × (1.05+0.0045×对应属强)。
- 黄字 = max(unique increase damage) + Σ add increase damage；爆伤同理（critical 变体）。
- 装备 = (1 + (Σ稀有度基点[0,50,100,150,250,150,200] + 强化每级10基点 + 激活套装档位×100基点)/10000 + Σ所有攻击力增加%) × Π(1+技能攻击力%) − 1。
- 普通根声明、`[stat]` 及非条件块伤害词条逐条按各自求和、unique 取最高或技攻连乘规则计算；仅同一来源同名属性的条件阶梯（`[stat by condition]` 及 `[if]/[then]/[else]/[condition]` 内词条）取最大。
- PVF 整数与有限浮点数保留小数参与计算，宽类型累加，输出整数/bp 时统一 AwayFromZero 取整并封顶 INT32_MAX。已识别词条结构、数值或属性标识无效时标 partial 并记来源 note；未知 stat 名忽略。

## 覆盖范围与未覆盖项

计入：穿戴装备栏中全部装备（含称号、辅助/魔法石/耳环）、宠物与宠物装备的静态词条，装备附魔卡，套装激活档位；稀有度/强化分只对装备类计。

未计入（导致结果偏低，面板说明行已注明「不含技能与BUFF」）：技能/被动、动态 BUFF、徽章、时装/装扮、收集箱、公会、随机词条称号、无视防御、最终伤害等。职业等级成长表缺失时 status=partial 并记 `level_stats_unavailable`；物品/附魔/套装读取失败记对应 note 并标 partial，不把缺失当 0 分。

### 恍惚之境套装资源结构

恍惚之境首饰（氤氲之息100300733、启明星的指引100312425、清泉流响100322294）归属套装12594。
当前已识别的 `equipment/character/partset2/set_item_12594.equ` 含没有对应起标签的 `[/module]`，
会使严格套装树解析失败并产生 `set:12594/unavailable`；穿满三件也会显示“部分装备未计入”。
这是套装资源结构问题，不按强化或增幅等级猜改分数、倍率或段位门槛。

[定向差量工具](../../Tools/PvfPatches/New-HazySetStructureDelta.ps1)只接受已核对的该条目或其已修正状态，
删除token22（原始偏移110～114）的5字节孤立闭合，其余字节及3件套、黄字/爆伤20%等声明保持不变。
工具只读PVF，在尚不存在的输出目录发布 `.raw` 和 `manifest.json`，不写包、不覆盖运行资源；
未知内容或不同字符串池偏移拒绝，不能把它当通用坏资源修复器。C#解析、诊断和评分模型均保持原样。

```powershell
./Tools/PvfPatches/New-HazySetStructureDelta.ps1 -PvfPath '<匹配Script.pvf>' `
  -PvfLibPath '<已有PvfLib.dll>' -OutputDirectory '<新的差量目录>'
./Tools/PvfPatches/Test-HazySetStructureDelta.ps1 -PvfPath '<匹配Script.pvf>' `
  -PvfLibPath '<已有PvfLib.dll>' -TemporaryDirectory '<新的测试目录>'
```

差量清单沿用 `replacements/path/raw_file/expected_before_sha256`，附修正后哈希；整条目哈希仅绑定这一份资源，
不计算或依赖整包PVF哈希。已修正输入输出相同raw、空replacements，已有目录拒绝覆盖。
差量须由资源发布流程另行应用到匹配服务端资源；生成与严格解析通过不等于已经部署，
也不证明截图中的角色分数、段位或其余未覆盖效果已实机验收。
