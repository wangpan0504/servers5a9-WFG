# 卢克团队模式

本模块用于95级末期的普通卢克团队攻坚。1–8人使用同一个`AntonRaidBattle`框架和同一套规则，按原分队共享正式Run；不按人数切换单人模式、缩放怪物数值或自动完成能源。普通5101–5106和困难/专属单人模式各自独立。

## 装配与开团

`ServerRuntime`在完整资源就绪时创建`LukeProductionPolicy`。策略以本版15个地下城、40条原规则为基础，只施加下述明确的本服差量。资源、奖励依赖或消费者不完整时保持失败，不以空脚本开放。显式注入的诊断及兼容策略继续保留，不能把其合成终结当作生产流程。

频道20/type32要求90–99级、完成2903及4872。开团每人消耗10159649一张；费用、位置、角色revision及同实例入场账本同一事务提交，任一成员失败全部回滚。重复666确认原实例，不再扣票。沿原`RaidRegistry`、`PartyService`及owner组建立1–2支普通分队，不另建在线角色或资产状态。

角色每周成功通关最多2次，账号每日入场最多10次；周清与账号入场分别计账。周锚沿本服周日06:00（UTC+8），账号日切沿既有统一日切。主动退出不额外扣周次数，已用门票不返还；五分钟重返不新增入场次数。购票沿原商店合同，开团不再重复扣精炼泰拉或数据芯片。当前10162065礼盒资源售价为精炼泰拉1、数据芯片10，开出10159649一张；与日服95末期公告2+10存在地区/资源差异，本实现保留当前客户端标价，不在服务端隐式加收。

## 路线与设施

原生选图支持CMD15正文0打开候选，以及CMD16携目标地下城和尾`FFFFFFFF`进入；兼容旧的非零15及尾0。15零值沿同一领域入口为当前分队建立MapSelect并发送ACK15、原成员状态及42字节空NOTI27，未选目标时不占图、不建立Run；重复打开、重选和入图拒绝均保留原选图场景，132可正常返回候战。非零15或直接16从城镇进图也在28/29之前发布原27场景边界，已在MapSelect不重复打开。16沿同一`LukeRaidDungeonService`复验队长、分队、阶段、路线和占用，失败释放本次选择。其它未知字段继续严格校验，不发送普通副本选图目录。

选图移出城镇时保留原分队Actor及P2P引用，只隐藏城镇实体，不以销毁队员再重发名册代替场景切换。该生命周期与安徒恩、普雷共用原投影；漩涡后续接入同类通知时沿用。

门票盒、四团共用费用就绪与个人通关列沿[背包](背包与装备.md#礼包开箱)和[副本模块](副本.md#当前行为)实现；原生面板字段足够，本路径不增加客户端自定义协议。开战前的通关横线保留原生显示条件。

P1为诞生、湮灭、蔓延各3次，共9次。`LukeSanctumRoute`从资源五组三元组等概率选一组，在本次Battle冻结；真实共享Run清图后才推进一步，失败重试不换组、不跳步。随机分布为明确本服策略。P1完成顺序继续影响P2分支。

静态设施证据由`PvfLib`读取精确ACT赋值动作，`GameWorld`登记房间/模板/资源序号，正式Run冻结绑定。117/118/119只接受当前已加载房间的合法对象报告；同对象跨成员重报、回房及旧map epoch不能重复累计。各圣所cap5，总15，按0–5、6–10、11–15结转能源控制室档位。放弃仅回退本次未完成Run的对应贡献，不抹除其它已完成图或其它分队成果。

本版全部地下城`PARTY MAX=1`，同图只能一队，异图可并行。保留原地图解锁和最终光王座→暗王座顺序，取消逐角色光暗路线锁，原`LOCKOUT TYPE`仅保留资源元数据。成员可以先后完成两路。

## 能源与王座

| 条件 | 行为 |
|---|---|
| 双圣殿完成 | 光王座与能源储藏室一同开放，选图等待不增长能源 |
| 首次真实进入任一王座或储藏室 | 启动储藏室600秒增长，初次进王座不要求先压能源 |
| 合法销毁储藏室能源对象 | 真实完成当前Run，全员各自提交清图事实；压制300秒后重新开放 |
| 能源控制室恢复 | 按原三档放宽为225/450/600秒，保留设施价值 |
| 主动退出王座 | 保留能源当前状态与剩余时钟；Boss未完成战斗状态不跨Run保存 |
| 光王座通关 | 暗王座按原前置开放，能源状态和剩余时间延续，不免费清零、不提前结束压制 |

## 阶段、返回和复活

P1总限45分钟，P2总限60分钟；同一单调时钟从真实提交开战/初始化阶段起算。清图已密封成功后不被慢SQL或退出延迟倒退为超时。截止真实写入失败阶段资格，再沿原退场路径回候战，不计周通关、不发成功奖励。

P1全部合法奖励和旧Run退出后进入最多600秒休息。团长可提前666；自动与手动共用全体当前成员同实例、候战32/4、加载完成及无在途Run/复活预约门禁，通过后保留3秒准备再初始化P2。P2不重复扣票。

已清单图通过原42或72结果菜单返回；图内战况返回为放弃。每名成员只退出自己的Run绑定，原普通分队保留；未清图、旧Run和伪造结果不获得清图/领奖资格。阶段转换等待全部成员退场，不能由队长代领或代提交个人事实。场景37及城镇同屏继续复用既有加载投影。

P1每共享Run8次、P2全团阶段20次复活额度。真实本人扣币提交才占一次额度；SQL失败撤销预约，同死亡重放不重复消耗。满能源安全返回不占额度。怪物血量、防御、攻击、屏障、连击破防及本地ACT沿当前资源；自然战斗、强制多人机关及各职业可完成性须由客户端实机确认。

## 奖励

`LukeResourceRewards`按实际资源奖池及权重展开所有可达随机容器，材料、货币、装备和卡片直接结算，不同时发箱和内容。随机在每个原角色的策略中冻结，阶段持久回执保存实际完整Grants与展示；重试和重连不重抽。

每次完整团队通关不渝之咏合计100，分P1的25和P2的75，避免原箱25+100重复。P1仅个人牌，P2个人及团队牌；网吧沿真实会话`PremiumPcRoom`资格；本版尚无可验证的独立特权资格来源，生产保持特权false，不把全员当特权。沿统一货币上限与重置，不单独改变其它团本。当前资源魔岩石实际13/14/15/30与旧箱名8个不同，采用实际资源内容；未沿旧文案减发。可达奖励无宿命之恒产物。

每项结果按卢克600的16字节物品行编码，按实际条数发送，资产提交后才发布结果与ACK660。满包走原永久邮件事务。演出最长65秒另加120秒选牌后，在线沿原Session发奖，离线只预约空闲账号并沿原持久资格发奖；不接管在线账号。结算回执确认后可收敛阶段，网络失败不重发资产。

原角色离团、账号停在选角或改玩另一角色后，由当前账号owner领取已冻结的原角色资格；有在途资产规划时等待下一次回调。提交只更新原角色背包，当前另一角色仅安装共享钱包的最新快照并刷新实际差量，不向其投影原团600/601。重放沿同一持久回执，不能因换角重新抽奖。

奖励合同携带`EnchantUpgrade`，并在实际物品core、邮件及结果中一致保存。95末期官方确认团本可能产出随机升级卡，但本地奖励箱和卡片表没有提供团本专属升级权重，现有实现不编造分布或强制满级；该部分不能称已还原原服随机升级规则。原箱兼容工厂与历史奖励的管理恢复继续保留，详见[副本模块](副本.md#卢克历史资格的管理恢复领取)。

## 五分钟重返

断线前按原Session/owner捕获实例、团key、分队及两个层次槽位；旧owner释放后才可通知。835仅向同账号、同角色、同频道且原Battle仍可恢复的连接发布，668复验全部身份与全团命令/owner门禁，绑定原Battle并返回候战，再投影当前名册、符号、战况及阶段。

原队仍存在时保留其ID和继任队长；原普通分队已消失时，由首位返回者重建原分队设置，其余返回者汇合。不重建攻坚实例、不复制资产、不回旧战斗房、不重播历史死亡/能源惩罚。全团离线仍保留原团至候选过期；第299秒可重返，满300秒拒绝并清理空团。重返后再次断线按本次离线重新计时。

候选与时钟有界，停机等待已启动回调收尾。进程重启只保留已提交阶段/奖励回执，不恢复活跃Battle或战斗房间。

## 验证边界

`luke-raid-production`使用默认Runtime，从666开始分别验证1/4/8人两阶段原规则自然前置流程；战斗报告为TCP夹具输入，不等于客户端自然战斗。`luke-raid-recovery`覆盖图中真实断线、835/668原团重返、在线及离线超时领奖；其它Luke专项覆盖能源、设施、路线、SQL回滚、复活、结果包与阶段超时。共享目录、时钟和结果返回同时回归安徒恩及普雷引导。

构建、领域/资源、TCP与客户端验收分别报告。窗口、动画、UDP、Boss机关和1/多人实际体验仍需QA；端口就绪或TCP通过不扩展为实机通过。
