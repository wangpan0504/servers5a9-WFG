# 副本选择与开发诊断

当前实现选图入口应答及显式开启的普通单人诊断。正式副本准入、费用、服务端权威战斗、任务通关、经验、掉落和奖励尚未实现。字段、消费者与未知边界见[副本协议](../协议/副本.md)，资源工具见[副本目录](../资源/副本目录.md)。

## 当前行为

[DungeonSelectionHandler](../../Server/DfoServer/Network/Handlers/DungeonSelectionHandler.cs)提供正式与诊断共用的 C2S15 选图界面入口。Ready 角色的 u32=0 时回复 ACK15 `01` 和 42B 空 NOTI27；非零只回复 ACK。宽度或会话状态错误关闭；失败样本 `00 01 00` 不用于这条成功路径。

`DevelopmentDungeonEntryProbe` 默认 `Disabled`。[ServerRuntime](../../Server/DfoServer/Infrastructure/ServerRuntime.cs)选择 [DungeonHandler](../../Server/DfoServer/Network/Handlers/DungeonHandler.cs)处理普通 C2S16：记录已知 25B 请求，不返回猜测的 ACK16 成功，也不装配诊断状态或注册诊断加载、死亡、过房、退出处理。

显式启用诊断时，Runtime 改为装配 [DungeonProbeModule](../../Server/DfoServer/Development/Dungeons/DungeonProbeModule.cs)，注册 16/37/39/42/45；它与正式选择模块互斥，命令表拒绝重复注册。禁用模式、缺少必需目录或怪物诊断缺少房间资源时不能构造诊断模块。启用诊断须使用独立开发实例和匹配 PVF，选角 epoch 内只允许一次初始化：

| 配置 | 诊断行为 |
|---|---|
| `Information` | 按已校验请求与资源计划发送 NOTI28 |
| `StartMap` | 发送 NOTI28/29；此阶段仍等待加载收尾 |
| `FinishLoading` | 同一有效上下文实收 8B 全零 C2S37 后，一次发送 ACK37 `01` → NOTI30 五个零 → NOTI3 本人 state1；空 C2S42 回复 ACK42 与原城镇位置 NOTI24 |
| `FinishLoadingMonsters` | 读取实际地图固定普通怪物，使用独立对象 key 投影；支持诊断死亡报告、相邻房间切换和各房间缓存 |

## 状态归属

[DungeonProbeState](../../Server/DfoServer/Development/Dungeons/DungeonProbeState.cs)由 Runtime 的工厂按连接创建，持有初始化计划、加载/返回标记及 [DungeonProbeRun](../../Server/DfoServer/Development/Dungeons/DungeonProbeRun.cs)。状态、运行对象和候选包体构造均属于 `Development/Dungeons`；正式 `Game` 层不引用诊断实现，共用的准入/怪物计划仍保留在 `Game/Dungeons`。

Run 保存实例 ID 和当前房间序号，并核对角色、选角 epoch 与角色 revision。加载后只接受本房间已宣布 key 的死亡报告；重复报告不重复通知，旧房 key 不进入新房。对象 key 在同一连接单调分配，重选不立即复用。返回选角/退出及连接关闭时通过活动生命周期结束旧 Run 并释放计划、房间状态；清理只影响本连接，并保留其对象 key 计数器。

全部已宣布怪物均收到诊断死亡报告后，才允许迷宫内真实曼哈顿邻格。先解析目标资源并构包，再发布房间状态，发送 ACK45 和 NOTI29，等待新的 C2S37；回到缓存房间不重生已报告死亡的怪物。未知生成条件和未支持 Boss 明确拒绝，不能用空房替代。

通用连接上下文只持有 [IGameConnectionActivity](../../Server/DfoServer/Network/Protocol/IGameConnectionActivity.cs) 门禁与清理合同，不携带诊断字段。城镇、技能、背包等处理器通过 `BlocksTownActions` 保留原有活动期间拒绝规则，不识别诊断模式。诊断期间阻止 35/631/36/1426 写城镇位置；退出成功或重新选角解除阻断，退出不恢复同 epoch 的再次初始化资格。诊断不修改正式 SessionPhase、持久落点或任务，发送失败关闭、不重试结算；客户端死亡报告不构成正式通关事实。

## 验证边界

`--selftest` 覆盖模式选择、缺少连接状态、重复注册、加载/返回、死亡、过房、revision 与 owner 冲突、旧状态清理。`--selftest-tcp "town,dungeon-probe"` 分别覆盖默认入口与显式诊断实例；诊断 TCP 验证真实 Runtime 装配、包序、城镇写入阻断、直接返回选角、对象 key 不复用和返回城镇后门禁解除。完整验证规则见[贡献指南](../../CONTRIBUTING.md#验证)，自动化不代替客户端验收。

匹配3145路线的六张地图76121–76126已逐房核对资源：前四房分别有4/5/7/5行固定普通怪物；76125共6行，其中第5行原值为`1 1 0 503 233 0 1 1 [fixed] [normal]`，第二整数1不符合当前计划要求的0，不能猜成固定Lv3。76126有`107000903 ... [fixed] [boss]`和模板107000906普通行，当前计划拒绝Boss品级；地图另声明`[basic action] Action/Map_76126.act`，相对同地图目录解析的资源含`[ON START MAP] → [ME] 0`及行为`[CINEMATIC] 1`。这些参数与触发的运行语义、Boss投影及后续收尾仍待恢复；不得省略不支持行、替换普通怪或用空房通过。

六张地图自己的`[greed]`文本依次为`BB BB / FF FF / GG GG / JJ JJ / FF FF / EE EE`，与迷宫各非零格对应，但地图文本的两个编码用途及`[pathgate pos]`八整数的消费合同仍须独立确认。负坐标也出现在真实门位置资源中，不能据此删除门或将其当作迷宫格坐标。

已有客户端确认诊断进图、移动、攻击、返回城镇、固定哥布林显示/受击及地图精灵效果。NOTI3 state1 后已收到过房请求。死亡通知完整收尾与诊断房间切换仍需匹配客户端确认，不据此宣称正式战斗或主线完成。具体读宽、原码身份、已知变体与自动化入口见[副本协议](../协议/副本.md)。
