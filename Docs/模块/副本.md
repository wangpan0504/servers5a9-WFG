# 副本选择与开发诊断

当前默认接入普通单人3145的正式入场、加载、原生本地HP统计死亡核验、经验/两树SP事务、冻结掉落拾取、清房过房、Boss确认、通关经验和退出；显式诊断继续独立装配。入场不限制职业或转职类型；成长仍仅支持已初始化普通双树的未转职角色，黑暗武士、缔造者及转职角色的成长拒绝尚待单独处理。翻牌道具、金币和费用暂时为空，任务推进及领奖未接入。当前路线的普通/控制技能击杀、Boss通关与空翻牌结算已获Windows客户端实机确认；其他路线和完整任务链仍需接入并分别验收。字段与边界见[副本协议](../协议/副本.md)，资源工具见[副本目录](../资源/副本目录.md)。

## 当前行为

清房使用资源声明的阵营与阻塞属性，不按模板ID、NPC名字或对象种类排除。地图`[monster team]`按生成行索引对应，0为友方、不阻塞；未声明的项保持阻塞。友方对象仍生成并保留场景key，但不提供敌对击杀、经验或掉落资格。终点通关将房间全清与最后敌对Boss死亡分开判定，不为残余普通对象伪造奖励。后续APC生成与战斗接入时应沿用同一Run的阻塞和Boss资格，不另外建立一套清图或奖励状态；APC协议当前尚未实现。

3145的76126房间中，107000903的team为100，107000906的team为0。后者脚本名为托比，是任务友方；任务声明为`[clear map] 76126`，完成NPC为1247，不能要求击杀托比才能结算。任务剧情用途与正式任务完成、领奖事务分别保留。

[DungeonSelectionHandler](../../Server/DfoServer/Network/Handlers/DungeonSelectionHandler.cs)提供正式与诊断共用的 C2S15 选图界面入口。Ready 角色先回复 ACK15 `01`，随后发送本人 NOTI3 `state=1` 同步客户端选图状态；u32=0 时再发42B空NOTI27，非零不重发选图列表。宽度或会话状态错误关闭；失败样本 `00 01 00` 不用于这条成功路径。

入口通过 [GameSession.DungeonSelection](../../Server/DfoServer/Game/Session/GameSession.DungeonSelection.cs)进入 `MapSelect`，保存本次选择身份、原城镇位置与安全返回点，并清除本人旧视图、移出城镇同屏。[TownCatalog](../../Server/DfoServer/GameWorld/Towns/TownCatalog.cs)保留当前阶段地图中目标为 `-1/-1` 的副本入口；从入口左右边界外8像素的候选中选取距入口中心最近的可走落点，避开其他入口，只调整X，保留原Y、城镇、区域和方向。该间距不等于客户端碰撞宽度，也不引入时间冷却；没有入口的场景保留原位置，原Y没有合法横向安全点则拒绝本次入口。重复 C2S15 保留首次返回点；活动已接管场景时不重新打开选图。选图期间沿阶段门禁拒绝城镇移动/切图、背包、技能及邮件资产操作，不修改存档。

空 C2S132 `BACK_2_VILLAGE` 只消费当前选择上下文；安全点与原位置不同时先通过现有位置保存提交，再恢复 Town。提交失败保留原选择阶段与快照，不发送成功。由 [TownProjection](../../Server/DfoServer/Network/Projection/TownProjection.cs)使用实际提交快照发送 ACK132 → 本人状态0 → 返回点所在城镇区域与场景，房间另补返回地区，完成后重建双向同屏。重复返回、无选择上下文静默拒绝；非空正文或活动副本场景保持未实现，不猜造错误码。返回只调整必要的位置及revision，保留资产、进度和房间返回信息；返回点与原位置一致时不写库，不执行出生传送或资产重载，也不重发初次入城124。

发布回执绑定 generation、选角 epoch、本次选择身份和实际角色快照；每帧出队复验。换角或下一次选择让旧回执失效，同阶段 GM/资产替换快照使旧投影按连接错误收尾。返回选角、退出和断线清除选择上下文。发送失败不重跑回城业务，重连由持久存档恢复。包体与验证边界见[选择界面返回城镇](../协议/副本.md#选择界面返回城镇)。

`DevelopmentDungeonEntryProbe`默认`Disabled`。[ServerRuntime](../../Server/DfoServer/Infrastructure/ServerRuntime.cs)装配正式[DungeonHandler](../../Server/DfoServer/Network/Handlers/DungeonHandler.cs)，注册16/37/39/42/43/45，另由[DungeonSettlementHandler](../../Server/DfoServer/Network/Handlers/DungeonSettlementHandler.cs)注册117/46/69/70/71/72；资源目录与成长规则显式注入。正式实例和原生统计权威归GameSession私有状态，按Town→Loading→Dungeon→Settlement→Town推进，返回选角/断线时失效；不分配诊断状态。

正式入口接匹配25B请求、当前38/2的Ready角色、3145未达成任务槽及持久副本owner，不以职业、转职类型或双技能树初始化状态阻止入场。解析完整但模式或准入不支持时发送静默失败ACK16，保留原选图阶段和返回上下文；不自动回城。未选角、未就绪、活动已接管或正文宽度不符不套用该拒绝合同。拒绝发送前复验账号owner、选角epoch、阶段、选择身份与角色快照，迟到拒绝不能影响新选择或新副本。

## 状态归属

[DungeonProbeState](../../Server/DfoServer/Development/Dungeons/DungeonProbeState.cs)由 Runtime 的工厂按连接创建，持有初始化计划、加载/返回标记及 [DungeonProbeRun](../../Server/DfoServer/Development/Dungeons/DungeonProbeRun.cs)。状态、运行对象和候选包体构造均属于 `Development/Dungeons`；正式 `Game` 层不引用诊断实现，共用的准入/怪物计划仍保留在 `Game/Dungeons`。

Run 保存实例 ID 和当前房间序号，并核对角色、选角 epoch 与角色 revision。加载后只接受本房间已宣布 key 的死亡报告；重复报告不重复通知，旧房 key 不进入新房。对象 key 在同一连接单调分配，重选不立即复用。返回选角/退出及连接关闭时通过活动生命周期结束旧 Run 并释放计划、房间状态；清理只影响本连接，并保留其对象 key 计数器。

全部已宣布怪物均收到诊断死亡报告后，才允许迷宫内真实曼哈顿邻格。先解析目标资源并构包，再发布房间状态，发送 ACK45 和 NOTI29，等待新的 C2S37；回到缓存房间不重生已报告死亡的怪物。未知生成条件和品级明确拒绝，不能用空房替代。

通用连接上下文只持有 [IGameConnectionActivity](../../Server/DfoServer/Network/Protocol/IGameConnectionActivity.cs) 门禁与清理合同，不携带诊断字段。城镇、技能、背包等处理器通过 `BlocksTownActions` 保留原有活动期间拒绝规则，不识别诊断模式。诊断期间阻止 35/631/36/1426 写城镇位置；退出成功或重新选角解除阻断，退出不恢复同 epoch 的再次初始化资格。诊断不进入正式 Loading/Dungeon/Settlement 阶段、不修改持久落点或任务；共用入口的 MapSelect 在诊断 C2S42 成功退出后结束、恢复 Town 并重新加入同屏。原诊断包序与同 epoch 使用记录保留，发送失败关闭、不重试结算；客户端死亡报告不构成正式通关事实。

## 正常战斗闪退的证据边界

匹配客户端正常战斗仍可发生 `C000041D` 用户回调包装异常。WOW64转储必须分别解释x86应用与native64异常结构；异常stream中的低32位地址不能直接当作故障代码。完整应用内存转储恢复了64位包装record、CONTEXT和LONGJUMP jumpbuffer，经同启动周期映像身份、事故保存Ldr/模块地址及匹配Microsoft符号交叉核验，真实包装继续点为 `ntdll!KiUserCallbackDispatcherContinue`，跳转目标为 `wow64!Wow64KiUserCallbackDispatcher`。`whNtCallbackReturn`恢复record保存 `C0000028`（`STATUS_BAD_STACK`），其LONGJUMP是WOW64回调恢复机制，不能据此认定用户组件主动longjmp。

应用调用链包含 `WM_IME_STARTCOMPOSITION → ImmSetCompositionWindow`，随后有IMM/MSCTF、输入法及UIAutomationCore回调；部分第三方帧有解栈警告，只能证明保存时的调用链。已核实native/x86栈指针位于各自边界内；native CONTEXT保留的x86 frame不能按native栈范围直接判坏。完整WOW64应用转储仍缺少4GB以上native代码页，保存上下文处于致命回调展开路径，尚未恢复首个不合法frame或最初BAD_STACK检查，不能归责输入法、UIA或特定服务端包。

部分转储对应的较早正常战斗样本仅实收14B技能使用包，没有C2S39或NOTI38；另一完整转储样本已实收C2S39并发送9B NOTI38，之后还有技能请求再发生回调异常。两种包序分别保留，不能沿用“所有闪退均无死亡包”结论，也不能以后一轮的时间邻近证明死亡通知导致崩溃。根因与修复仍需首次异常上下文及明确控制变量的有界验证。

两次CDB创建调试进程均在启动阶段遇到 `std::bad_alloc`，32位地址空间近耗尽；其中 `-hd` 已取消堆调试检查，仍沿相同路径失败。随后不带CDB的普通启动实际到达名册及选角后的赛丽亚房间，私有内存约1.2–1.3GiB；普通名册进程只读样本确认BeingDebugged与NtGlobalFlag均0，技能发送原码片段与历史匹配。因此两次调试启动失败不能视为普通客户端必然失败；两种创建配置不同，保护/解包行为与分配循环的因果仍未恢复。普通选角可用不证明正常战斗或原 `C000041D` 已修复。后续采集按各方式实测内存、新服务端需求及至少1GiB余量预算；完整调试创建曾占约4GiB，不沿用普通启动占用估计，也不通过系统设置或客户端补丁绕过。
