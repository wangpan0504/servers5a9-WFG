# 副本选择与开发诊断

当前默认接入任务显式路线的普通单人正式入场、加载、原生本地HP统计死亡核验、经验/两树SP事务、冻结掉落拾取、清房过房、Boss确认、通关经验和退出；显式诊断继续独立装配。入场与普通成长支持job0–15及合法转职/觉醒，成长仍要求已有合法双树来源。通用清图及资源职业筛选领奖、同实例中的普通怪物猎杀已接入[任务系统](任务.md)。普通免费翻牌已接入金币、物品和满背包永久邮件；普通金币付费、黑钻额外免费奖励及黄金牌每日免费次数已接入；额外活动牌未开放。当前路线的普通/控制技能击杀、Boss通关与空翻牌结算已有Windows实机证据；其他路线、猎杀UI和完整任务链仍需分别验收。字段与边界见[副本协议](../协议/副本.md)，资源工具见[副本目录](../资源/副本目录.md)。

## 角色死亡与复活币

正式单人副本加载完成后接收 `DIE_CHARACTER(40)` 的两个 u16 坐标，普通角色另带一个保留原值的 u16 上下文字段，由当前 Session 的角色 key 发布 `DIE_STATE(32)`。普通死亡为state0；有效[神圣祝福药水](背包与装备.md#持续效果与特殊药剂)先在原库存事务内消费单次资格，再依次发布死亡state0和药剂复活state2，不走复活币请求、不扣币，也不启动死亡回城计时。死亡同时按资源维护位清理消耗品持续状态。死亡资格保存在当前正式实例内；已死亡时的重复报告不重复提交或发布，返回城镇、换角或新实例不会继承旧资格。死亡期间不能过房，仍可按原放弃流程返回城镇。

`USE_COIN(41)` 只处理当前死亡角色的本人 key。普通副本每次成功复活从角色钱包扣除一枚复活币，复用原库存事务及 revision 校验；提交后安装实际角色快照，再依次发送完整 ACK41、32 的复活状态和 Main 槽1的绝对剩余余额14。普通副本零余额返回失败；修炼场免费复活并同步原余额。活角色、错误 key 或失效实例不扣币。数据库异常沿现有连接错误处理，事务回滚且不发布成功。发送失败不撤销已经提交的扣币，重复41不会再次消费。

复活保持原 Run、房间、怪物、掉落及结算身份；同事务产生的寻物任务条件变化按既有通知发布。普通死亡按 external 的 `dungeon_death_return.go` 启动10秒回城计时；已经死亡时的重放不延长计时。到期复验账号 generation、选角 epoch、实例和本次死亡序号，再沿原回城流程发布24及任务刷新；没有ACK40或ACK42。计时不绑定角色快照或房间 epoch，因此购买换快照或残留攻击不会丢失计时；成功复活、主动回城、换角及断线使旧回调失效，每个连接的任务在断线时取消并等待退出。

死亡窗口的现场购买使用普通商城CMD64及真实PVF商品：`100004`为100点券购买1枚复活币。费用与发币沿原商城库存事务提交，完整ACK64后刷新14及53；购买成功仅增加余额，随后仍由客户端发41使用，不重置死亡计时。购买或复活失败保留当前死亡与计时。入口资格及价格来源见[背包与装备](背包与装备.md#npc-商店买卖与限购)。

字段来源及本版 ACK41 与 external 的差异见[角色死亡与复活协议](../协议/副本.md#角色死亡与复活币)。自动回归覆盖正式Session、请求codec和 `--selftest-tcp dungeon-revive,formal-dungeon,cash-shop,dungeon-settlement`。直接使用复活币、死亡窗口现场购买及10秒自动回城均已通过匹配客户端实机验收。

## 副本练习模式

普通选图的 C2S16 在 offset8=1、FFFF token、任务号0且其余模式字段为0时进入练习；5000修炼场、7142职业体验及非零任务号的1459授权回放仍独立处理。练习沿正式副本Run、账号owner、选角epoch及user状态推进，不维护另一套在线实例。仍验证城镇入口、等级、难度、地图与原生战斗对象；`[prohibit practice]` 非零或声明形状未知时拒绝，未声明或显式0允许。只从无任务连接的普通maze抽取，不根据活动主线改走剧情路线。

练习不要求持有、不校验或扣除入场门票、材料、金币和疲劳，也不校验、占用每日或其它玩法入场次数；重复入场和再练习没有玩法次数上限。练习与普通/传奇深渊、随机密门及强袭付费入场互斥；原副本maze含深渊声明不影响练习，但只使用普通地图，不扣深渊票、不安装深渊波次或奖励。深渊及普通正式入场继续沿各自原收费与次数规则，不能将“普通图支持练习”解释为普通模式免费。

练习死亡只确认本次内存事实，不产生击杀经验、普通/任务/被动物件掉落、任务进度、宠物经验、幸运星或翻牌奖励。普通练习、修炼场和职业体验统一通过`HasFreeCombatConsumption`免扣普通客户端效果道具、技能及装备脚本材料、复活币，但仍验证源物品、数量、冷却和实际死亡状态；晶之契约不扣周期材料，宠物不进入战斗饱食消耗。免消耗不免除主动购买、丢弃、契约或礼包等独立资产业务，也不把普通副本的禁止翻牌标记当作免扣资格。道具大类与扣除合同见[背包与装备](背包与装备.md#普通恢复药)。入场沿既有存档预留尝试号和对象key，用于实例身份及防重放，不作为玩法次数限制；不新增练习库表或奖励账本。

NOTI28安装客户端练习模式，加载、过房及回访复用正式场景合同。可信Boss清图后只发送本版NOTI255打开练习结果，不借普通评分、经验或翻牌流程；再练习保留模式并预留新身份，选择其他地下城不自动继续主线，回城解除Run且不新增虚弱。换角、断线和旧owner收尾仍按原实例身份执行。`--selftest-tcp dungeon-practice`覆盖实收副本1000请求、零疲劳、逐房回访、免消耗、无奖励、重放、再练习及回城；客户端画面与交互仍需实机确认。字节依据见[练习模式协议](../协议/副本.md#副本练习模式)。

悲叹之塔资源由 `GriefTowerCatalog` 按 `etc/towerofgrief.etc` 读取最低等级、顶层、楼层/副本对应、抗魔与分层奖励组；计数及冒险团加成保留为资源声明。楼层映射必须完整、唯一，抗魔与奖励必须覆盖各层，重复或缺失字段不填默认值。仅在读取悲叹资源时装载专表，与其它副本共享原PVF归档。当前资源含100层、副本5115–5214，1–49/51–99层使用普通奖励组、50/100层使用特殊组；编号取专表，不在业务中用楼层加常量生成。

专表的 `[use allow item list in dungeon]` 是物品编号及单次挑战使用上限：客户端 `0255FA79` 同时保存初始与剩余次数，`0255DF80` 对负数上限始终放行、非负上限要求剩余大于0，`0255E010` 使用后减一，`0255E080` 恢复初始次数。`GriefTowerItemUse` 据此拒绝表外物品和用尽额度，负数不限次；正式会话在普通药剂、宠物食品、经验/疲劳/永久成长/状态道具、契约、礼包及允许副本使用的515动作、修理道具、任务/升级券的实际提交入口复验源物品，只在提交成功后推进本次实例计数。失败和重复恢复不扣次数，新实例独立初始化；普通商店操作及技能材料消耗不套用主动使用物品的计数。悲叹实例的复活币请求及普通祝福药剂自动复活均被禁止。这些限制归本次正式实例，不能跨角色或跨次挑战继承。

`GriefTowerRewardTable`解析`etc/itemdropinfo_togclearreward.etc`的具名卡槽表，保留同槽多候选、原始数值及数量，并验证每层引用的奖励组存在。`GriefTowerRewardPolicy`采用本服推定规则`grief-pvf-independent-slots-inferred-v1`：每个已配置槽独立抽一次，槽内原顺序累计到10000，同槽候选互斥，剩余区间为空奖，不归一化、不补缺省槽。普通层card3–9各有28.5%获得一份千年一步，card10为28%千年一步、5%隐藏罐、67%空奖；50/100层card9为28.5%千年一步、5%隐藏罐、66.5%空奖，card10固定一份千年岁月。各层组名由专表决定，调用者不能替换。

以上精确概率及独立性是推定实现，不是原版执行代码的已验证结论。依据为当前PVF的2850/2800/500/10000原值，以及官方[初版奖励说明](https://arad.nexon.co.jp/campaign/201705/tower_of_grief.aspx)和[后续隐藏罐更新](https://arad.nexon.co.jp/update/season6_act4/4_2/)。初版说明最多7个千年一步，而当前普通组card3–10有8个材料候选；本实现以当前资源为准，可得到0–8份，不私删第八槽或截断第八份。公开资料没有证明当前版本的准确分布，不能将该差异写成官方已变更上限。匹配客户端配置分支`0255F95E..0255FA79`读取起止楼层和临时组名后释放临时数据，结算回调`01FCB980`消费服务器结果；这两条路径也不证明随机算法。抽取结果在真实清图后的正式结算中冻结并持久发放。

悲叹地图按该层DGN、无值 `[tower of grief]`、1×1 BB、同格唯一起终点及MAP反向归属确定。无显式图、连接或叠层时，必须唯一匹配悲叹目录内的normal或boss型BB BB地图（本版57、58层为boss）；生成单房无邻接拓扑，保留原始BB与全部演员。拓扑继续核对资源池确认的实际MAP，不能仅凭模式标记替换房间。首层5115对应100247及敌对Boss APC470。所有声明为悲叹或位于悲叹目录的副本均受专用准入约束，后续楼层不能绕入普通流程。

本服采用账号日限次规则：`GriefTowerEntryPolicy`按专表最低等级、账号基础额度及冒险团区间作纯准入判断，复用UTC+8的06:00游戏日边界。原角色当天失败后必须使用10161065悲叹邀请函，不再占账号基础额度；换角色不能继承重试资格，已通关当天拒绝再次进入。`enterable count`不作为付费重试上限。`CommitDungeonEntry`支持悲叹准入规划：账号游戏日/已用次数、角色楼层/本次挑战、入场回执与门票、角色revision、尝试号在同一事务提交；提交时复核原次数、角色挑战及冒险团等级，失败整笔回滚。重开从账本恢复，删除角色只清理其挑战及入场回执，账号日次数保留。正式会话尚未调用这项存储合同，不能据纯策略Accepted发送成功；正式准入仍保留未支持保护，独立奖励抽取与通关通知完成前不开放收费。结构及升级见[数据库](../开发/数据库.md)。

`GriefTowerClearReward`在账号锁外冻结各槽选择、完整物品核心、期限及入包/溢出邮件归属；同一Run只接受原冻结对象。悲叹结算由原`CommitDungeonSettlement`事务共同保存经验、库存、永久溢出邮件、楼层推进、当天已通关及`character_grief_tower_clears`回执，末段失败全部回滚。重试核对原实例、报告和奖励后读取持久结果，不重抽、不重复发奖、不再扣账号次数。冒险团经验可能在同一事务升级，因此通关只复核原挑战，不把旧冒险团等级当成清图前提。空奖也正常记通关；删除角色先清除通关回执，再清理准入及邮件依赖，账号额度保留。100层完成后账本记为101的已完成状态，循环重置尚未还原，不擅自设为1层。

### 入场票与准入原因

#510/#511：选图准入失败时，`LastFormalDungeonRejection`与`formal_dungeon_entry`日志的`RejectReason`按顺序给出具体原因：`selection-area-missing`、`selection-area-without-world-map`、`selection-world-map-missing:<世界地图>`、`selection-world-map-invalid:<世界地图>`、`selection-dungeon-not-listed:<副本>`、`selection-quest-required:<任务>`（`[is clear quest]`未完成）、`selection-quest-in-progress-required:<任务>`（`[in progress]`未接取）、`selection-gate-unavailable`。同一副本有多个条目时任一满足即放行，都不满足时报第一个条目的任务。判定与原合并条件相同，客户端回包仍为SelectionRejected `[0,9,0,0]`，不新增错误码。例：代号希望8523未完成6170报`selection-quest-required:6170`，泰波尔斯291100320/291100322未完成6116报`selection-quest-required:6116`。

普通入场的副本若声明唯一一段`[required item]`且恰为一行“物品 1 1”，`DungeonEntryPlan.EntryItem`冻结该票。准入时按当前背包规划，不够报`entry-item-required:<物品>`，无物品目录报`entry-item-catalog-unavailable`，都不写库。入场提交时按最新背包重算，与[入场一次性疲劳](单人副本实例.md#普通图疲劳owner)、尝试号预留同一写事务扣除；票已不够则入场作废。成功后发NOTI14背包增量，并写`dungeon_entry_item_consumed`日志。重复请求或提交失败不会只扣一半。普通安徒恩同时具备anton dungeon和raid normal dungeon标记时，唯一消耗行的正数量也完整执行。其他形状（多行、其它副本数量不为1、第三列不为1、多段）不当作入场票，保持原行为，日志`EntryCostNote=required-item-shape-unsupported`。深渊派对、强袭（自有材料消耗）、练习、比赛、回放、修炼场、职业体验和任务路线不扣这张票，所以耀眼之塔、强袭、深渊派对的原有规则不变。第三列的非零消耗/零持有由匹配客户端018E6EDC提示分支确认；当前入场仅消费已接入的第三列1。

## 剧情房间推进

普通与剧情房间共用特殊父对象和控制子怪规划。子怪等级为0或负数时使用副本基础等级，正数保持资源指定等级；子怪退场沿场景对象处理，不授予普通击杀经验。剧情暂停请求191按本人场景回复170，同步暂停状态及类型，不修改角色存档。已加载的Dungeon或Settlement场景收到state=1恢复请求后，按170→3补发本人角色状态，使演出隐藏的角色重新激活；三个type共用此流程。Loading阶段仅同步170，后续真实加载确认仍发送初始角色状态；重复恢复只重发状态投影，不重建Actor、加载、任务或结算。

同坐标叠层仍有后续资源层时，先按资源顺序推进，不能提前走向普通邻格；末层结束后恢复正常过房，返回同坐标时恢复实际来源基础房间或剧情阶段及其状态。任务maze的Boss坐标重复时，将对应地图行按资源顺序建立独立剧情阶段，保留普通起始房间；一行多个地图编号保持为同一阶段的候选列表，剧情使用资源首项。每阶段使用独立房间状态和对象key，沿原加载流程切换，最后阶段才产生终点清图事实。

任务单地图清图目标明确等于唯一Boss坐标的基础地图时，即使迷宫的对应行使用`map`标记，入场计划也将该行投影为基础Boss图；同坐标叠层目标沿用相同规则。投影只改变本次计划的房间种类，保留地图编号、路径、坐标、候选、全部真实演员及原接取身份，不改共享资源定义。普通无目标路线、非清图任务、非Boss坐标目标和歧义路线不能借此放行，通关仍经正式Run、真实死亡与原成长事务确认。

C2S45的同坐标kind1在末层没有后继且已清房时，同样表示返回来源基础房间。恢复使用NOTI29的operation2/mode0缓存正文，保留基础房间的原怪物key、死亡集合、种子和任务接取，不重新创建Actor；随后真实加载确认仍沿原流程执行。返回后的最后一个同坐标kind1仅消费本次收尾标记，不发送ACK或地图、重置加载或再次进入首层。其他坐标、旧实例和已消费标记不能充当该确认，普通清怪及邻房门禁保持。

实际Boss房间的死亡提交产生ClearFact时，若本实例接取集合中只有一个尚未达成的被动物件猎杀目标，且它是当前maze关联父任务的无奖励子任务，则同一死亡事务推进该目标。父任务、接取身份、地下城、难度及实际清图事实均复用现有任务合同；重复死亡或SQL失败不会多计进度。

普通`map/boss`行的多个地图编号为随机候选，按编号去重后在本次入场资源规划时选择并固定；重复进房沿房间缓存，不重新抽选。剧情阶段行首项保持原阶段顺序，同行其余编号与该坐标其他基础候选合并，排除该坐标全部阶段首项后选普通基础图；没有额外候选时回退首阶段模板，并使用独立基础身份。入场基础图不自动推进阶段，基础与阶段各自规划怪物、对象key和物件事件缓存，最后阶段才产生终点清图事实。`layered`行的多个编号是有序层列表，保持原始顺序，重复模板也有独立层身份。回放复用同一资源解析入口；条件传送的替换地图使用本次已经选定的基础模板，阶段切换时不覆盖对应剧情阶段，普通自动地图池排除剧情及叠层的全部声明编号。只装载本次使用的地图，选中资源不可用时返回入场失败，不临时替换路线。

## 剧情电梯

电梯按地图内容识别：四个`event monster position`坐标、滚动对象1111、控制对象1113，以及特殊父对象1112声明的控制怪56716。不绑定任务、职业或地图编号。剧情入场同样预留并下发父对象与控制子怪的独立key；父子关联沿用当前客户端的特殊actor合同，不将控制怪加入普通清房阻塞或击杀奖励。

加载确认和角色状态通知后启动本连接的电梯计时，每15秒发送一次254，计数1至4、状态0。计时结束不代替控制怪退场。当前房间控制怪的真实退场先发送254结束状态，再回复空掉落38：计数不大于3时状态1，否则状态2。完成后旧计时不再发布，换图沿原资源连接和清房规则执行；未结束的电梯不能提前换图。

状态保存在当前Run房间中，计时器不占用账号锁等待，也不写数据库。每次推进和出队复验账号代次、选角epoch、副本实例、地图及电梯状态；同角色的普通revision变化不重置计时。每连接最多一个计时任务，换电梯取消旧任务，断线先取消并等待计时退出，再结束会话。

## 状态归属

[DungeonProbeState](../../Server/DfoServer/Development/Dungeons/DungeonProbeState.cs)由 Runtime 的工厂按连接创建，持有初始化计划、加载/返回标记及 [DungeonProbeRun](../../Server/DfoServer/Development/Dungeons/DungeonProbeRun.cs)。状态、运行对象和候选包体构造均属于 `Development/Dungeons`；正式 `Game` 层不引用诊断实现，共用的准入/怪物计划仍保留在 `Game/Dungeons`。

诊断Run 保存实例 ID 和当前房间序号，并核对角色、选角 epoch 与角色 revision。加载后只接受本房间已宣布 key 的死亡报告；诊断重复报告不重复通知，旧房 key 不进入新房。对象 key 在同一连接单调分配，重选不立即复用。返回选角/退出及连接关闭时通过活动生命周期结束旧 Run 并释放计划、房间状态；清理只影响本连接，并保留其对象 key 计数器。

全部已宣布怪物均收到诊断死亡报告后，才允许迷宫内真实曼哈顿邻格。先解析目标资源并构包，再发布房间状态，发送 ACK45 和 NOTI29，等待新的 C2S37；回到缓存房间不重生已报告死亡的怪物。未知生成条件和品级明确拒绝，不能用空房替代。

通用连接上下文只持有 [IGameConnectionActivity](../../Server/DfoServer/Network/Protocol/IGameConnectionActivity.cs) 门禁与清理合同，不携带诊断字段。城镇、技能、背包等处理器通过 `BlocksTownActions` 保留原有活动期间拒绝规则，不识别诊断模式。诊断期间阻止 35/631/36/1426 写城镇位置；退出成功或重新选角解除阻断，退出不恢复同 epoch 的再次初始化资格。诊断不进入正式 Loading/Dungeon/Settlement 阶段、不修改持久落点或任务；共用入口的 MapSelect 在诊断 C2S42 成功退出后结束、恢复 Town 并重新加入同屏。原诊断包序与同 epoch 使用记录保留，发送失败关闭、不重试结算；客户端死亡报告不构成正式通关事实。

## 验证边界

副本重复声明的`difficulty level`只有五个整数标志的类型、值和顺序完全相同时才共用同一难度表；冲突、残缺或未知声明仍拒绝。剧情`difficulty size`和指定难度继续独立校验。英雄冢的任务3240沿其真实八房路线进入，定向`--selftest-tcp hero-tomb-entry`覆盖接取、入场、加载、重复加载、拒绝后继续请求、回城重进及重连保持任务。

有完整`story mode`块的任务路线只按块内唯一`difficulty size`校验故事难度，不受块外普通路线的`designate dungeon difficulty`或`difficulty level`覆盖。多个故事块必须各自完整闭合、具有合法难度及唯一非空纯整数`quest list`，任务归属不能重叠；使用最终所选maze的连接任务定位唯一故事块，不能借用请求中的零任务号或父接取身份。单块的完整、无重复正整数`quest list`只约束名册内任务；最终所选maze的连接任务明确不在名册时，沿块外普通难度表及指定难度校验。缺失、引用token、重复或不完整名册不能作为扩大难度的证据，保留原单块兼容范围。显式任务、普通选图匹配的任务路线及回放沿同一规则；未声明故事块时沿原指定难度与普通难度表。嵌套、未闭合、任务归属不明及未知难度声明仍拒绝，普通路线的难度范围和原始资源声明保持。真实夜之摩天楼6206、6214分支在`dungeon-entry-plan`定向检查原五房路线、完整演员及零难度边界；这些领域检查不代替Session/TCP和客户端验收。

沿普通死亡清图合同、没有真实Boss的终点若包含普通、精英或超精英敌对APC，加载和前房死亡不能提前产生清图事实，必须等本房所有可报告的敌对APC真实死亡提交。APC仍不加入普通门阻挡集，友方退场不形成战斗或奖励事实；有真实Boss的房间保持原Boss通关合同，显式迷宫清图条件继续使用其独立规则。结算许可115引用当前终点真实已死亡、未清场且可报告的对象key，包括非Boss敌对APC，随后发送31，不补造瓦格纳这类友方演出演员的死亡。7930的真实D152四房路线覆盖两种入口及0/1/2难度、46/34与重连；同类11副本14任务只验证资源难度归属，不宣称其它准入或客户端演出均已验收。

## 正常战斗闪退的证据边界

匹配客户端正常战斗仍可发生 `C000041D` 用户回调包装异常。WOW64转储必须分别解释x86应用与native64异常结构；异常stream中的低32位地址不能直接当作故障代码。完整应用内存转储恢复了64位包装record、CONTEXT和LONGJUMP jumpbuffer，经同启动周期映像身份、事故保存Ldr/模块地址及匹配Microsoft符号交叉核验，真实包装继续点为 `ntdll!KiUserCallbackDispatcherContinue`，跳转目标为 `wow64!Wow64KiUserCallbackDispatcher`。`whNtCallbackReturn`恢复record保存 `C0000028`（`STATUS_BAD_STACK`），其LONGJUMP是WOW64回调恢复机制，不能据此认定用户组件主动longjmp。

应用调用链包含 `WM_IME_STARTCOMPOSITION → ImmSetCompositionWindow`，随后有IMM/MSCTF、输入法及UIAutomationCore回调；部分第三方帧有解栈警告，只能证明保存时的调用链。已核实native/x86栈指针位于各自边界内；native CONTEXT保留的x86 frame不能按native栈范围直接判坏。完整WOW64应用转储仍缺少4GB以上native代码页，保存上下文处于致命回调展开路径，尚未恢复首个不合法frame或最初BAD_STACK检查，不能归责输入法、UIA或特定服务端包。

部分转储对应的较早正常战斗样本仅实收14B技能使用包，没有C2S39或NOTI38；另一完整转储样本已实收C2S39并发送9B NOTI38，之后还有技能请求再发生回调异常。两种包序分别保留，不能沿用“所有闪退均无死亡包”结论，也不能以后一轮的时间邻近证明死亡通知导致崩溃。根因与修复仍需首次异常上下文及明确控制变量的有界验证。

两次CDB创建调试进程均在启动阶段遇到 `std::bad_alloc`，32位地址空间近耗尽；其中 `-hd` 已取消堆调试检查，仍沿相同路径失败。随后不带CDB的普通启动实际到达名册及选角后的赛丽亚房间，私有内存约1.2–1.3GiB；普通名册进程只读样本确认BeingDebugged与NtGlobalFlag均0，技能发送原码片段与历史匹配。因此两次调试启动失败不能视为普通客户端必然失败；两种创建配置不同，保护/解包行为与分配循环的因果仍未恢复。普通选角可用不证明正常战斗或原 `C000041D` 已修复。后续采集按各方式实测内存、新服务端需求及至少1GiB余量预算；完整调试创建曾占约4GiB，不沿用普通启动占用估计，也不通过系统设置或客户端补丁绕过。

普通、星空和超星空的异形碎片与天空之愿均逐个生成地面物品，每个数量1、各自拥有地面key，分别拾取后沿背包规则合堆；例如15个异形碎片生成15个物品，不生成一份数量15的地面物品。总数量及领取资格沿上述规则，拆分后的完整对象数在入图准备时计入500容量限制，超限明确拒绝，不截断或合并规避。黎明裂缝的材料仍沿原堆叠规则。

可选环境变量 `DFO_HARLEM_MATERIAL_RULES` 是业务规则JSON，启动时读取一次；未设置使用上述默认值。允许部分覆盖，未知字段、非五档数量、非正数或超出1至10000的数量、超出0至1000的概率均拒绝启动，不自动修正。`SkyWishes` 可配置五档天空之愿数量，`CosmoMaterialMultiplier` 默认2、范围1至10，倍乘结果不得超过10000。`DawnPurgedPermille` 为千分比，0只掉碎片，1000只掉净化结晶；`Enabled:false` 关闭这组本服材料奖励。配置不会改变PVF翻牌概率、门票和次数。

```powershell
$env:DFO_HARLEM_MATERIAL_RULES='{"Enabled":true,"NormalFragments":[9,10,12,13,15],"LegendFragments":15,"DawnFragments":200,"DawnPurgedCrystallines":120,"DawnPurgedPermille":50}'
```

### 深渊概率奖励本服补全

`harlem-abyss-bonus-local-v1` 默认启用。官方95专题及当前PVF道具说明能证明奖励种类，但尚未找到三种深渊完整的非零掉率；下表概率均为明确制定的本服参数，不是官方或PVF原值。该规则独立于史诗装备命中、稀有度、末波装备骰数及稀有怪额外史诗开关。

| 奖励 | 哈林普通深渊 | 星空裂缝 | 超星空裂缝 |
|---|---|---|---|
| 3330深渊派对邀请函 | 0／1／2张各1/3 | 同普通 | 同普通 |
| 10158124史诗灵魂 | 1%掉1个 | 同普通 | 同普通 |
| 10305940哈林深渊晶石 | 0.1%掉1个 | 同普通 | 同普通 |
| 10305616苍穹碎片 | 不追加 | 10%掉2／3／4／4／5个，按五档难度 | 10%，命中数量为星空两倍；固定难度4为10个 |
| 10307527星空深渊灵石礼袋 | 不追加 | 0.5%掉1个 | 0.5%掉1个 |

各项独立判定，可以同次掉落。邀请函用2/3命中率及命中后1至2张等概率数量实现0／1／2各1/3；不可用两个独立的一半概率替代。邀请函和苍穹碎片逐个落地，每个数量1；苍穹碎片先判一次概率，再生成完整份数，不按每个碎片分别判定。超星空只翻倍苍穹碎片数量，不翻倍本表其它奖励数量或概率。史诗灵魂先生成可拾取地面物品，拾取后沿既有物品奖励合同计入账号史诗灵魂余额。晶石与礼袋各作为一个物品落地，不直接发放其开盒内容；PVF中晶石可开500张邀请函，10307527礼袋可开20个10305821灵石，10307537的50灵石升级礼袋不用于此奖励。

普通及星空只在末波实际最后一只怪死亡时生成一次，超星空仅合法真实最终领主死亡时生成。每个演员的无末杀计划不含这组奖励，不能提前击杀一个演员后再在末杀重复发放。所有新奖励随原死亡冻结、事务、地面账本和拾取提交；死亡故障重试复用随机结果，重复死亡、拾取、回城及新挑战不能再次消费旧奖励。普通地图、其它地区、练习、任务路线、前波、友方及脚本dummy不适用。不改写PVF原独立掉落、史诗或翻牌表，也不删除已有通用奖励。

可选环境变量 `DFO_HARLEM_ABYSS_BONUS_RULES` 在启动时读取一次严格JSON，允许部分覆盖；未知字段、null、非法概率及数量拒绝启动。`Enabled:false` 关闭整组；各概率设0可分别关闭，关闭项不增加随机抽样。邀请函概率使用 `InvitationNumerator`／`InvitationDenominator`（默认2／3，分母1至1000000，分子0至分母），命中数量1至 `InvitationMaximumCount` 等概率（默认2，范围1至500）。其余四项分别为 `SoulPermille`、`CrystalPermille`、`SkyFragmentPermille`、`StoneBagPermille`，范围0至1000，默认10／1／100／5。`SkyFragments` 为五档正数量，默认[2,3,4,4,5]，`CosmoSkyFragmentMultiplier` 默认2、范围1至10；单次完整数量及总掉落对象数不得超过500，容量与原奖励合并校验，不截断或重新合堆。

### 深渊出口

当前深渊房间加载完成，普通阻挡怪与所有波次都已沿正式死亡流程移除后，发送无正文NOTI789。它只更新客户端深渊完成状态，不签发Boss清图、通关经验或翻牌。此后C2S15正文u32=0可结束旧实例并直接进入选图，依次发布ACK15、状态3和NOTI27；不增加撤退虚弱，旧Run和地面对象沿原退场边界回收。未清房、普通副本或非零指定副本请求不能借此绕过流程；继续当前副本的过房与Boss结算保持原规则。静态通知合同和合成Handler回归不能代替上方传送门的实机验收。

随机密门仍为独立实验：`DFO_SEAL_DOOR=1` 才按既有rate%推断尝试普通深渊，不扣票、不查深渊任务，失败回退普通入场。玩家不能借offset8选择深渊档位，它还承担练习、训练和授权回放。当前正式Run仅支持单人，不扩展组队规则。

## 副本进入次数（DungeonIncountInfo）

数据全部取自 `Etc/DungeonEtc/DungeonIncountInfo.etc` 与 dgn，不写死副本或次数。实现见 [DungeonIncountCatalog](../../Server/DfoServer/GameWorld/Dungeons/DungeonIncountCatalog.cs)、[DungeonIncountPolicy](../../Server/DfoServer/Game/Dungeons/DungeonIncountPolicy.cs)、[GameSession.DungeonIncount](../../Server/DfoServer/Game/Session/GameSession.DungeonIncount.cs)，断言在 [FiendwarChannelTests](../../Server/DfoServer/SelfTests/FiendwarChannelTests.cs)。

已证（ARAD 7560188d 静态）：

- `[dungeon incount info]` 每行为“重置类型 数量n 副本×n 上限 标志 第二值”（解析器 03FEFB50）。世界地图 018EC180 的“每日进入次数 %d/%d”（48010）分母读上限（03FB9D50，节点 +0x30）。018EC6BD 的“每周入场次数 %d/%d”（67086）分母读第二值（03FB9DC0，节点 +0x38），所以第二值是每周上限。第二值 <=0 时 018EC6C6 不显示每周，即没有周上限。
- 剩余次数只由 NOTI 550 写入：u32 副本，u8 日剩余写 +0x6C68，u8 周剩余写 +0x6C7C（023A0200）。每日显示取 min(+0x6C68,+0x6C7C)。没有周上限的行，第二个字节回填日剩余。两个字段在角色对象上，因此角色表按角色计数。
- dgn `[required item]` 第三列非 0 时提示“消耗%d个”（47702），为 0 时提示“持有%d个”（47703），见 018E6EDC。

服务端行为：

- 角色表 18 个副本在任意城镇、非练习的普通入场（含任务与再挑战）提交时扣 1 次日次数和 1 次周次数，次数为 0 时拒绝（`dungeon-incount-exhausted`）。不扣次的入场：新手训练、修炼场、职业体验、强袭、深渊派对、练习。同一行的多个副本共用一份次数，以行首副本为键。入城时为全部 18 个副本下发 NOTI 550，入场扣次后为该行全部副本重发。
- 账号表 `[account dungeon incount info]`（72 条，每条为“重置键 副本 上限 标志”）按账号计数。入场时同时给 `[enter add incount dungeon index]` 的连带副本记次，连带副本只记次、不拦截。连带表 424 对里只有 6013 不在账号表，它没有上限，所以不记次。次数用满时拒绝（`dungeon-account-incount-exhausted`）。账号次数不下发：客户端没有读者，也没有已知的下发包。
- `[sub incount on clear dungeon]`（95 PVF 只有 7184）列出的副本入场时只核对、不扣次，通关结算提交后才记次。7184 不在角色表，`dungeon.lst` 里也没有它。
- 只在频道专属城镇消耗 `[required item]` 第三列非 0 的物品。其它城镇暂不核对 dgn `[required item]`。
- 存储：v83 `character_dungeon_incount`（角色日/周），v84 `account_dungeon_incount`（账号周期）；这两张表曾有五种非主线编号（合并前本地构建 v62/v63、主线 v67 之前合并分支 v67/v68、主线 v68 之前合并分支 v68/v69、主线 v69–v73 之前合并分支 v69/v70、主线 v74–v82 之前合并分支 v74/v75），升级时按表与列结构判定后分别从 v61、v66、v67、v68、v73 重跑其后的主线迁移，两张表原数据保留。跨周期读出时视为 0。

假设（客户端无读者，未证明）：

- 日界为 UTC+8 06:00，依据本服统一业务日和客户端文本 33348、42796（“每日凌晨6点初始化”）。
- 默认周界为周四 06:00，依据文本 68076、68109（“每周四凌晨6点初始化”）。
- `[special weekly reset day]` 的星期按 0=周日编码，所以 8523 的周界为周一 06:00。
- 账号表重置键查 `[reset info]`：值 -1 为每日，0..6 为每周该星期（PVF 0→-1、1→4）。
- 同一行多个副本共用次数：依据是客户端为 n>1 的行分配组号，但这个组号没有读者。
