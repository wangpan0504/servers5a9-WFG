# 角色创建与选择

目标为 S5A9 x86 客户端，按[开发环境](../开发/环境与配置.md)规定的固定目录读取 PVF。当前源码接入 job0–15 的 Lv1 普通创建、角色列表、选角及城镇投影；五件 CHR 初始装备与角色同事务创建并投影；在线转职、升级、战斗及特殊职业玩法仍未实现。自动化通过与匹配客户端实机通过分别记录，不能混用。

## 请求与资源身份

创建请求使用匹配 `character/character.lst` 的 job0–15，姓名以 CP936 编码，限制 1–12 字节及 ASCII 字母、数字、下划线和可编码的常用汉字。Parser 保留完整尾部，只接受[角色协议](../协议/角色与入城.md#角色请求)中已知形状，未知字段不根据职业猜填。

job0/15 已有同版本实收请求；其他职业依公共布局和匹配 PVF 接入，逐职业实际请求与特殊流程仍需验收。自有 TCP 构造帧不作为客户端字段证据。

## 名称重复检查

创建界面中姓名旁的重复检查按钮发送 C2S `(1,692)`，body为姓名DSTR。可用名回复 `01`；重名回复 `00 18 00`，由匹配客户端错误码24分支显示“名称重复。”。匹配客户端 的20/24同分支，当前选择24，字段为 u16。错误码2只进入致命错误日志，不能用于重名提示，消费者及原码验证见[协议](../协议/角色与入城.md#角色名重复检查的客户端消费)。检查为只读操作，保持连接，允许重复检查、修改姓名、创建或选角；实际创建仍由数据库唯一约束完成最终重名校验。

## 事务与投影

`Parser → Handler → GameSession/CharacterCreation → ICharacterRepository → Builder`：Catalog 提供职业与初始化定义，[CharacterCreation](../../Server/DfoServer/Game/Characters/CharacterCreation.cs) 负责初始任务、技能与穿戴的只读规划。Session 在原 owner 内确认尚未选角并捕获选角 epoch，释放锁后生成 NewCharacter；重新进入原 lease 后复查仍未选角且 epoch 未变，再提交。规划期间发生选角、返回列表或接管时，拒绝原计划，不自动重跑创建。

Repository 将角色、槽位、Lv1/未转职默认状态、共享房间/返回地区、初始任务/技能与穿戴实例放在同一个事务中提交；任一部分失败全部回滚，成功后才发 ACK5 → roster。角色名唯一性及槽位容量以提交时的数据库为准。发送失败不回滚或重跑创建。无资源的[会话规划测试](../../Server/DfoServer/SelfTests/SessionPlanningTests.cs)覆盖规划与选角、接管竞争，资源集成继续检查各职业初始内容。

未知 job、未知尾部、重名或满槽仍关闭当前连接，不猜造通用失败 ACK。重名按钮是独立只读用例，其业务拒绝保持连接。旧 generation 不得创建或释放新 owner，位置写入继续检查账号与 expected revision。

初始任务见[任务模块](任务.md)，物品创建与保存见[背包与装备](背包与装备.md#创建发放与空间预检)。重开已有角色不补创建奖励，普通创建不改变离线 Lv95 实验角色的数据；较新 schema 的库拒绝打开。

roster 与 Actor 使用同一个角色 job；选角 ACK 的初始城镇取已提交的 Position.Town。Catalog 输出类型化 CharacterStats，89B 排列与字段依据见[角色协议](../协议/角色与入城.md#角色属性块)，不在业务模型存 wire blob。

枪剑士的 HP/MP 为1700/1500，physical attack/defense 为70/70，magical attack/defense 为50/50，inventory limit 为450000，attack/cast speed 为9000/8000。未声明抗性发0是当前初始化合同，不宣称还原了引擎继承或成长规则。等级成长公式尚未实现，离线 Lv95 剑影仍沿用男鬼剑初始属性。

选角由 [CharacterSelection](../../Server/DfoServer/Game/Characters/CharacterSelection.cs)准备房间出生、到期物品清理和金币携带上限，成功后 Session 安装实际角色并推进选角 epoch；准备顺序与失败恢复见[NPC与出生](NPC与出生.md#2-出生点返回地区和提交)。随后发送[角色与入城](../协议/角色与入城.md#连接与角色选择)的条件包序；普通 Lv1 不发送完成任务表。ACK4 的 tutorial 字段不按职业猜改；特殊职业流程仍需独立实机确认。

## 名册与完整角色读取

[ICharacterRepository](../../Server/DfoServer/Game/Characters/ICharacterRepository.cs) 区分三种查询：`ListRoster` 返回 [CharacterRosterEntry](../../Server/DfoServer/Game/Characters/CharacterRosterEntry.cs)，只包含角色身份、职业、等级和穿戴外观；`LoadCharacter` 按当前账号与槽位读取一个完整角色；`List` 明确读取账号下全部完整角色。登录和创建后的名册使用第一种，选角使用第二种，开发 GM 的详细查询使用第三种。名册不是可写的角色快照，不能用于保存资产或推进任务。

[查询实现](../../Server/DfoServer/Persistence/CharacterRepository.Queries.cs) 在延迟只读事务中读取一致快照；名册以账号为单位查询穿戴，不加载背包、仓库、任务、技能和钱包。完整列表在本次查询内只读取一次账号钱包、仓库、碎片及账号限购，再与各角色的数据组合；不跨请求缓存这些资产。单角色加载仍完整校验该角色及账号共享资产，其他角色的非穿戴资产异常不阻止读取名册或选择正常角色。

所有查询继续通过当前 owner 的 generation 门禁；选角后的房间归一、到期物品清理、提交与发布流程保持一致。

## 验证

验证命令见[贡献指南](../../CONTRIBUTING.md#验证)。

[CharacterReadTests](../../Server/DfoServer/SelfTests/CharacterReadTests.cs) 使用独立 SQLite 验证名册包体等价、按槽加载、账号隔离、共享快照复用、外部 writer 下读取已提交状态、下一次查询可见新提交、异常资产隔离及旧 generation 拒绝，纳入无资源基础测试。

[CharacterCreationTests](../../Server/DfoServer/SelfTests/CharacterCreationTests.cs) 覆盖16个职业的解析、创建同事务写入3145、235B ACK4、技能、重开库、任务与技能失败回滚、重名、过期 generation/revision 和基线建库。初始装备、完整属性、UID、重开保留及物品失败回滚另见[背包自测](../../Server/DfoServer/SelfTests/Inventory/InventorySelfTests.cs)。C# TCP 职业用例使用独立库，覆盖创建、含1382且不含356的选角包序、ACK4 第0槽、移动、重名失败与重登。任务栏与重登画面仍需逐职业实机确认。

## 初始 SP 与学习技能边界

匹配 PVF 的 `etc/sptable.etc` 中 `[sp table]` 起始条目为 `1 0 2 30 3 30`，Lv1 条目明确为 0。job0 的 CHR 初始技能是 `179:7,174:1,169:1,5:1,46:1,511:1`，没有另一个初始 SP 字段。因此新建 Lv1 显示零可用 SP 本身不证明出错，不能为通过界面验收随意补点。更高等级的累计贡献和等级差已由[成长资源](../资源/角色成长.md)定义；累计贡献不等于扣点后的剩余余额。

当前角色保存双树SP/TP余额、稳定slot与技能等级，普通SP学习及C2S29 `BUY_SKILL` 已接入，见[在线技能学习](技能学习.md)。正常升级发点和合法经验来源尚未接入，开发GM改等级不发点。鬼斩脚本 `skill/swordman/hardattack.skl` 声明 purchase cost 15、required level 1、required level range 2，初始已学等级为 1；下一等级还受自身等级条件约束。

双树投影、普通学习请求、扣点与等级同事务及已确认错误回复由技能模块维护；TP 学习、特殊分支及正常经验来源仍未接入。纯成长计划和 NOTI37 Builder 的边界见[角色成长](角色成长.md)，不能由界面显示推定实际施放或正常升级完成。
