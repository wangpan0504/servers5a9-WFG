# 角色创建与选择

目标为 S5A9 x86 客户端，按[开发环境](../开发/环境与配置.md)规定的固定目录读取 PVF。当前源码接入 job0–15 的 Lv1 普通创建、角色列表、选角及城镇投影；五件 CHR 初始装备与角色同事务创建并投影。升级、任务转职及技能学习分别见[角色成长](角色成长.md)、[任务](任务.md)和[技能学习](技能学习.md)；普通创建不证明完整战斗及特殊职业玩法。自动化通过与匹配客户端实机通过分别记录，不能混用。

## 请求与资源身份

协议支持 job0–15，实际可创建职业来自 `character/character.lst`，不要求名册必须包含全部16项。姓名以 CP936 编码，限制 1–12 字节及 ASCII 字母、数字、下划线和可编码的常用汉字。Parser 保留完整尾部，只接受[角色协议](../协议/角色与入城.md#角色请求)中已知形状，未知字段不根据职业猜填。

普通建角允许尾部 `tail[8]` 携带界面选中的分支展示索引 0–5，各基础职业共用此布局。该值只保留在解析结果中，不用于设置角色转职、等级、技能或装备；实际创建始终按请求的基础 job 初始化为 Lv1、`grow_type=0`。界面选择鬼泣、阿修罗等分支后仍建立未转职基础角色。

job0/15 已有同版本实收请求；其他职业依公共布局和匹配 PVF 接入，逐职业实际请求与特殊流程仍需验收。自有 TCP 构造帧不作为客户端字段证据。

## 默认外观

`CharacterCatalog.DefaultAppearance`统一查询普通角色各职业、转职分支及觉醒阶段的默认显示编号。`GetEquipment`读取单槽，`Resolve`返回不可变槽位映射；只用于显示，不创建物品、UID或穿戴状态。已有`CharacterProfile.DefaultAvatarEquipment`仍是旧`characteretc`基础资源声明，不包含完整的新职业及觉醒选择，不能作为完整预览默认值使用。

普通基础值以匹配ARAD的`02B61730`为准。当前PVF没有魔枪士、女圣职者及枪剑士的对应`characteretc/*.etc`，不能因此回传0或借用其它职业的装扮。觉醒表从`character/chn_1stawaken_defaultavatarinfo.chr`装配一次；当前格式为13个显示槽、80行职业／分支，逐行跳过武器装扮槽10，保留12个编号。资源格式归`PvfLib.CharacterEquipmentFile`，显示选择归`CharacterDefaultAppearance`。

选择规则与原生`01E26BF0→02B61730`一致：`growType&15`为转职分支，`(growType>>4)&7`非零且觉醒外观开关开启时，只在槽0–9查询该分支的觉醒行；条目为-1或没有匹配行时回基础，显式0保留。二觉不另造第二份装扮表，武器装扮及真实武器不由觉醒表接管。未映射的槽保持-1，交由客户端原生默认路径处理。男鬼剑第五分支的基础皮肤还受客户端选项1控制；调用方不知道该选项时保留-1，不猜测客户端设置。

当前婚姻角色卡使用此入口解析对方默认装扮；真实装扮及克隆来源优先，不改变本人Actor／Player发包。匹配客户端的实际预览仍须实机验收。

## 专用决斗角色

`PvpPrivateCharacterService` 使用共享 CHR、技能、成长、物品和城镇目录在账号锁外生成完整85级规划。C2S872只检查当前账号普通角色等级、相同职业分支唯一性和删角冷却，并绑定当前未选角会话；C2S5必须匹配这次许可，最终建角事务再次验证。重选、账号接管或成功创建使许可失效；明确回滚可按原许可重试。原初装、普通双树初值、身份及冷却一起提交，不允许半建角色。

当前58份原分支定义中54份可生成完整规划。守护者原`character/knight/knight.chr`的job12/grow3、4缺少重建惩罚时，按已确认本服规则使用30天；资源原值仍保留缺失，明确配置不覆盖，其它职业、分支和替代CHR不继承。装备、职业、等级、账号资格及原子提交校验保持不变。枪剑士四分支引用了魔枪士武器，仍拒绝而不改职业掩码；未注册且不含专用装备标志的枪剑士善斗者武器不能直接替代客户端原初装。初装flag解释与流转保护见[任务](任务.md)。基础grow保留0–5，不因85级擅自增加觉醒位。

专用身份保存在账号建角账本，并投影到名册及入城Actor。当前专用角色只允许决斗频道选角，直接进入10/0；不能通过普通城镇旅行、传送或正式PVE入口离开决斗区域。专用任务原经验仍归角色，但共同经验事务不计入账号冒险团，名册和每周出战名册也排除该身份；普通角色贡献保持原规则。专用转普通的1275转换条件及1237计数含义尚未闭合，不返回假成功，也不据此清除身份。

## 名称重复检查

创建界面中姓名旁的重复检查按钮发送 C2S `(1,692)`，body为姓名DSTR。可用名回复 `01`；重名回复 `00 18 00`，由匹配客户端错误码24分支显示“名称重复。”。匹配客户端 的20/24同分支，当前选择24，字段为 u16。错误码2只进入致命错误日志，不能用于重名提示，消费者及原码验证见[协议](../协议/角色与入城.md#角色名重复检查的客户端消费)。检查为只读操作，保持连接，允许重复检查、修改姓名、创建或选角；实际创建仍由数据库唯一约束完成最终重名校验。

## 角色更名卡

角色更名卡通过 C2S509 指定 Main 槽位，按共享消耗品规则核对真实实例、锁定、期限、职业等级、冷却与使用地点。正式资源2660698声明 `[character name change]`，允许城镇及赛丽亚房间，禁止强袭；`[need material]` 是兑换价格，不作为额外使用费。扣一张卡和写入 `character_rename_pending` 资格在同一库存事务提交，已有资格不再扣卡。成功后沿既有小退流程退出同屏与组队，并回放带资格的选角名册。

待改名角色不能直接选角。C2S135只在未选角时接受最近已发布名册的行索引、匹配的旧名及原因1，不把行索引当角色ID或持久槽位。新名称沿创建姓名规则与全局不区分ASCII大小写的唯一约束；非法名、重名、旧名不符及重复请求不消耗资格。改名、拍卖卖家名称快照和清资格同一事务提交，保持角色ID、槽位和资产。成功推进选角epoch，发送确认及新名册；发送失败不回滚或重复扣卡，重连从持久资格恢复。

该入口实现用卡更名，不推测其它更名原因及历史角色的90/180天限制。协议与匹配消费者见[角色更名卡协议](../协议/角色与入城.md#角色更名卡)，资格迁移见[数据库](../开发/数据库.md#角色更名卡资格)。自动化验证不替代匹配客户端弹窗、小退及最终姓名显示的实机验收。

## 角色曾用名

角色面板的曾用名窗口以CMD8模式5查询当前在线目标，按真实改名历史倒序显示旧名和改名日期。GM与更名卡两种改名入口均在原名称事务内保存旧名、提交前revision及Unix时间；历史保存失败时整笔改名回滚。失败、重复请求或原名未改变不制造历史。存量角色不补造过去的记录；当前展示最近255次，完整记录仍保留在角色历史表，删角同事务清理。

查询在目标自己的owner内读取，只按目标角色与账号筛选历史，不装载其它角色资产；发送时复核请求者选角与目标快照，旧会话不得发布。NOTI736在窗口已打开后发送，空历史发送零行以清理旧内容；不在登录时提前推送。字节与原生入口见[角色协议](../协议/角色与入城.md#角色曾用名)。

团本频道的跨频道角色菜单以C2S821模式1查询在线目标，复用同一历史来源并核对真实服务器、频道和角色，返回专用NOTI761。空历史清空窗口；定位过期或目标不可用时不伪造记录。其它尚未恢复的模式不返回通用成功，也不借历史查询建立邀请或改变攻坚名册。

## 被拉黑计分

`Character.BlacklistCount`保存角色被其他玩家拉黑后的有效计分，对应`characters.blacklist_count`，不是本人黑名单的长度，也不是装备称号ID。新旧角色默认0，范围0至2147483647；完整列表与按槽加载读取同一持久字段，普通位置、库存及称号穿脱不改写它。Actor向本人和同屏角色投影该值，客户端按100/200/300选择GradeB/C/D惩罚动画，具体字节与消费者见[角色协议](../协议/角色与入城.md#被拉黑计分与惩罚称号)。

当前只接入有效计分的持久化、加载和投影，未实现黑名单增删、累计计分、抵消及按时间衰减，不把角色ID、称号ID或未知客户端通知当作增分依据；也不补造历史拉黑记录。完整黑名单业务接入时须维护此字段与真实关系来源及当前角色快照的一致性。

## 事务与投影

`Parser → Handler → GameSession/CharacterCreation → ICharacterRepository → Builder`：Catalog 提供职业与初始化定义，[CharacterCreation](../../Server/DfoServer/Game/Characters/CharacterCreation.cs) 负责初始任务、技能与穿戴的只读规划。Session 在原 owner 内确认尚未选角并捕获选角 epoch，释放锁后生成 NewCharacter；重新进入原 lease 后复查仍未选角且 epoch 未变，再提交。规划期间发生选角、删除、返回列表或接管时，拒绝原计划，不自动重跑创建。成功建角推进 epoch，返回实际创建身份与提交名册；ACK5与名册投影绑定该回执的 generation/epoch，不在发送器内查询数据库。

Repository 将角色、槽位、Lv1/未转职默认状态、共享房间/返回地区、初始任务/技能与穿戴实例放在同一个事务中提交；任一部分失败全部回滚，成功后才发 ACK5 → roster。角色名唯一性及槽位容量以提交时的数据库为准，选择0–31中最小空槽，保留其他角色原槽位。发送失败不回滚或重跑创建。无资源的[会话规划测试](../../Server/DfoServer/SelfTests/SessionPlanningTests.cs)覆盖规划与选角、删除和接管竞争，资源集成继续检查各职业初始内容。

未知 job、未知尾部、重名或满槽仍关闭当前连接，不猜造通用失败 ACK。重名按钮是独立只读用例，其业务拒绝保持连接。旧 generation 不得创建或释放新 owner，位置写入继续检查账号与 expected revision。

初始任务见[任务模块](任务.md)，物品创建与保存见[背包与装备](背包与装备.md#创建发放与空间预检)。重开已有角色不补创建奖励，普通创建不改变离线 Lv95 实验角色的数据；较新 schema 的库拒绝打开。

roster 与 Actor 使用同一个角色 job；选角 ACK 的初始城镇取已提交的 Position.Town。Catalog 输出类型化 CharacterStats，89B 排列与字段依据见[角色协议](../协议/角色与入城.md#角色属性块)，不在业务模型存 wire blob。

枪剑士的 Lv1 HP/MP 为1700/1500，physical attack/defense 为70/70，magical attack/defense 为50/50，inventory limit 为450000，attack/cast speed 为9000/8000。未声明抗性发0是当前初始化合同。等级与转职后的89B基础属性由 `CharacterStatComputer` 按对应 CHR 计算，入城及升级投影使用实际角色状态；计算规则与装备/技能边界见[角色属性](角色属性.md)。

选角由 [CharacterSelection](../../Server/DfoServer/Game/Characters/CharacterSelection.cs)准备普通选角的房间出生、到期物品清理和金币携带上限；原生换频道保留已提交城镇位置。成功后 Session 安装实际角色并推进选角 epoch；准备顺序与失败恢复见[NPC与出生](NPC与出生.md#2-出生点返回地区和提交)。随后发送[角色与入城](../协议/角色与入城.md#连接与角色选择)的条件包序；普通 Lv1 不发送完成任务表。ACK4 的 tutorial 字段不按职业猜改；特殊职业流程仍需独立实机确认。

## 名册与完整角色读取

选角左上角的塔次数由账号专用通知提供，角色框悬停则按已发布名册行索引查询当前角色。两者共用`SelectionContentsRules`和轻量只读`ReadSelectionContents`，从现有绝望入场/通关、悲叹账号/角色、通用日周次数、攻坚通关和眩惑绑定账本投影，不加载所有角色资产或写入日切重置。账号上限取对应PVF及冒险团等级加成，绝望账号计数按当天实际挑战的不同角色数计算，失败重试不重复占名额。

角色基础额度在首次入场后耗尽，付费重试次数不叠加扣显示额度；当前层来自持久进度。查询与发送绑定账号generation、选角epoch及原发布名册对象，换位、删建、重连和返回选角后只使用新映射，跨06:00的旧查询不能发布。已选角的迟到悬停请求只回原生失败。客户端负责悬停显示及移开消隐；数据协议见[选角次数](../协议/角色与入城.md#选角冒险团与角色悬停次数)。

[ICharacterRepository](../../Server/DfoServer/Game/Characters/ICharacterRepository.cs) 区分三种查询：`ListRoster` 返回 [CharacterRosterEntry](../../Server/DfoServer/Game/Characters/CharacterRosterEntry.cs)，只包含角色身份、职业、等级和穿戴外观；`LoadCharacter` 按当前账号与槽位读取一个完整角色；`List` 明确读取账号下全部完整角色。登录和创建后的名册使用第一种，选角使用第二种，开发 GM 的详细查询使用第三种。名册不是可写的角色快照，不能用于保存资产或推进任务。

名册每行启用原生光环预览，普通光环、克隆来源和光环幻化槽仍由真实穿戴外观提供，不补造光环物品。首次登录、创建后刷新、返回选角及重连使用同一构包入口；使能位与槽位、染色和克隆孔位扩展不能相互替代。字段与客户端消费者见[名册光环预览](../协议/角色与入城.md#名册光环预览)。

选角武器按已选幻化、武器装扮（含克隆来源）、真实武器的优先级显示。已解析的替代外观只投影到名册武器槽，不重复输出武器装扮槽，以免客户端跳过武器特效安装；染色来自所选外观，强化等级与增幅标志来自实际穿戴武器，无实际武器时为零。这仅是选角视图，轻量查询中的原始穿戴、持久库存和城镇 Actor 保持各自原有信息。自动化核验构包与回放，最终外观仍须实机验收。

[查询实现](../../Server/DfoServer/Persistence/CharacterRepository.Queries.cs) 在延迟只读事务中读取一致快照；名册以账号为单位查询穿戴，不加载背包、仓库、任务、技能和钱包。完整列表在本次查询内只读取一次账号钱包、仓库、碎片及账号限购，再与各角色的数据组合；不跨请求缓存这些资产。单角色加载仍完整校验该角色及账号共享资产，其他角色的非穿戴资产异常不阻止读取名册或选择正常角色。

所有查询继续通过当前 owner 的 generation 门禁；选角后的房间归一、到期物品清理、提交与发布流程保持一致。

## 删除存档与连续建角

[删除用例](../../Server/DfoServer/Game/Session/GameSession.CharacterDeletion.cs)只接受尚未选角的当前 owner，按请求的当前名册行索引核对确认姓名，再读取真实持久槽位、ID和 revision，经[仓储](../../Server/DfoServer/Persistence/CharacterRepository.Deletion.cs)在同一事务复验后删除。提交成功才递增 SelectionEpoch，返回实际删除身份和提交后名册；ACK6及名册绑定该回执的 generation/epoch。失败保持存档及会话原状，已选角、确认名失配或缺行回复已确认的静默收尾并保持连接。删除前开始的锁外建角规划因旧 epoch 拒绝，新建角可以立即复用空槽及姓名。角色和物品UID沿用 AUTOINCREMENT，不回绕或清理 sqlite_sequence，旧持久删除身份不能覆盖重建同槽角色。

当前格斗家终图还含未能在本封包 LST 解析到父脚本的历史 `[hellparty]` 特殊元数据；只在明确训练路径保留其原声明，不臆造怪物或奖励，普通副本的缺资源拒绝不变。该机关、逐职业电影、按键教学和完整Windows客户端流程仍需验收。参考项目中的旧死亡包、带零字节的NOTI31、完成角色快速退场路径及未经本版确认的自动教学升级请求未移植。协议与原码证据见[训练协议](../协议/角色与入城.md#训练模式)。

## 名册与完整角色读取

[ICharacterRepository](../../Server/DfoServer/Game/Characters/ICharacterRepository.cs) 区分三种查询：`ListRoster` 返回 [CharacterRosterEntry](../../Server/DfoServer/Game/Characters/CharacterRosterEntry.cs)，只包含角色身份、职业、等级和穿戴外观；`LoadCharacter` 按当前账号与槽位读取一个完整角色；`List` 明确读取账号下全部完整角色。登录和创建后的名册使用第一种，选角使用第二种，开发 GM 的详细查询使用第三种。名册不是可写的角色快照，不能用于保存资产或推进任务。

[查询实现](../../Server/DfoServer/Persistence/CharacterRepository.Queries.cs) 在延迟只读事务中读取一致快照；名册以账号为单位查询穿戴，不加载背包、仓库、任务、技能和钱包。完整列表在本次查询内只读取一次账号钱包、仓库、碎片及账号限购，再与各角色的数据组合；不跨请求缓存这些资产。单角色加载仍完整校验该角色及账号共享资产，其他角色的非穿戴资产异常不阻止读取名册或选择正常角色。

所有查询继续通过当前 owner 的 generation 门禁；普通选角的房间归一，以及到期物品清理、提交与发布流程保持一致。

当前角色保存双树SP/TP余额、稳定slot与技能等级，普通SP学习及C2S29 `BUY_SKILL` 已接入，见[在线技能学习](技能学习.md)。正常升级发点和合法经验来源尚未接入，开发GM改等级不发点。鬼斩脚本 `skill/swordman/hardattack.skl` 声明 purchase cost 15、required level 1、required level range 2，初始已学等级为 1；下一等级还受自身等级条件约束。

## GM实验性角色复制

开发GM命令 `account <账号> character-copy <原名字> <原角色编号> <原revision> <新名字>` 仅在整个账号离线且未被其它owner占用时执行；禁止接管在线账号。新名沿现有姓名规则且全局唯一，账号须有空槽，专用决斗角色受职业唯一约束而拒绝复制。

`ICharacterCopyStore` 由角色仓储实现。一笔写事务重验来源身份和revision、插入新角色、为所有个人容器物品分配新UID，并重映射时装/宠物核心、克隆来源、装扮预设、切装与进行中任务接取GUID。角色属性、技能、任务、限购和入场次数保留；账号仓库、账号货币和账号任务仍共享。冒险团贡献以复制时位置作为新基线，不重算旧等级贡献。出生点来自当前PVF正常房间，不带入婚房、公会或副本位置。

关联表按显式字段策略复制；阶段任务仅携带继续领奖必需的来源收据和最小因果祖先，GUID与JSON依据同步重映射。婚姻、公会、邮件、拍卖和在途战斗身份不转移。未知角色字段/关联表拒绝，不能猜写。提交前完整加载和验证新角色；任意晚失败整笔回滚，源角色和账号共享资产不写。溢出及损坏JSON转换为明确GM拒绝，不能使监听任务异常终止。

核心入口 `CharacterCopyTests.Run` 覆盖身份/私有物品隔离、共享资产不变、真实婚姻公会来源、满槽/同名/过时修订、专用决斗、回滚与并发；`--selftest-tcp character-copy` 使用所选PVF验证真实任务延期/后续领奖/已领取再复制与GM在线门禁。自动化不能代替玩家存档备份和客户端验收。
