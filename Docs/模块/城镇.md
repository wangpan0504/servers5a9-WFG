# 全城镇通行

本页定义当前匹配PVF的城镇准入、码头与房间传送阵合同。wire格式及发包顺序见[城镇切图](../协议/城镇切图.md)，会话/持久化规则见[服务端业务开发规范](../规范/服务端架构.md)。

选角、普通切图、出房及副本回城统一从本次角色快照投影转职特效显示位，各职业沿用同一合同。开启和关闭均保留角色设置，不因换区清零，也不额外重发完整入城或设置通知。

## 1. 资源和实现入口

服务端启动从 `Data/Pvf/Script.pvf` 读取实际城镇、区域与默认/阶段地图，不限制到最初房间区域，也不依赖预导出JSON。既有资源样本包含65个城镇、343个区域、去重352份地图，这些数量不作为启动校验条件。

| 资源标识（PVF内部） | 当前用途 | 实现 |
| --- | --- | --- |
| town/town.lst、town/*.twn | 全城镇区域、权限、出生gate、阶段 | [TownCatalog](../../Server/DfoServer/GameWorld/Towns/TownCatalog.cs) |
| map脚本及import | 可走几何、有向出边、动画门、NPC、房间识别 | 同上 |
| etc/dock/docksysteminfo.etc | 码头站点、开放任务与等级、阶段替换 | [TownDock](../../Server/DfoServer/GameWorld/Towns/TownDock.cs) |

匹配资源改变时，先确认区域、阶段和缺项，再更新预期数据与测试；不可用其他版本编号或坐标替换。

## 2. 准入与位置

C2S36固定16B，完整保留targetNpc:u32、pathKind:u8、x/y:u16。Parser要求movement=5，pathKind允许0–255；“能解析所有字节值”不等于“所有特殊玩法已实现”。

`GameSession.Travel` 在当前 owner 内检查就绪阶段；[TownTravel](../../Server/DfoServer/Game/Town/TownTravel.cs) 从角色快照、请求和完成任务集合规划移动、切图与无坐标出房。它核对 previousTown/previousArea 等于原 Position，再由 TownCatalog.Admission 按以下顺序判断：

1. 目的地区域存在且当前阶段地图可用，目标等级、need quest全部完成、need quest or至少一项、except quest均不命中。
2. targetNpc非零时验证来源NPC的显式传送关系与目标地图NPC身份。
3. 房间右侧菜单验证配置目的地及菜单等级/任务；已观测kind5走菜单，其他kind在目的地确实属于菜单时也按同一配置判断。
4. 普通房间出口必须匹配持久返回地区。例外：共享房间38/1所在城镇以外的房间式区域（如艾尔丁纪念馆67/0）自己的地图写有通往本城非房间区域的门时，这扇门按第6条普通通路判断。
5. 非房间来源的码头间传送验证当前开放阶段与两端权限。
6. 其他普通通路必须存在PVF有向出边；要求相关任务完成，非空check condition目前返回route-state-required。

所有C2S36成功落点直接采用请求x/y，不裁剪、不替换固定门口、不检查NPC+30、码头portal area、XUI矩形或源坐标到门的距离。位置和返回地区在一次revision事务中保存，提交后发送23→24；目标是房间时追加1379。拒绝或事务失败不修改Selected、数据库和revision。

35/631普通走路独立校验当前阶段PVF可走矩形及非零实际出口矩形。C2S36可提交矩形外坐标；后续步行仍受自己的矩形合同约束。选角和空body1426没有坐标，使用服务端解析的房间出生/地区门口，见[NPC传送与选角出生](NPC与出生.md)。

## 3. 地图继承、阶段和返回地区

map import递归读取，局部几何区块替代父区块，显式空区块也替代。普通town movable area与动画move town共同形成有向出口；负数town/area标记不转换成普通byte城镇。几何行的quest condition约束任务，check condition保留为未接入实例条件。

阶段只使用completed quest，按最后满足的phase shift选择map；活动驱动阶段仍使用PVF默认图，不伪造活动开启状态。例如黑市完成5936使用Before阶段、完成6045使用Liberation阶段。

黑市的正式街道及小地图区域为54/1，54/0只引用固定Before地图，不作为房间返回地区。旧存档的位置或返回点为54/0时，正常重新选角沿已有返回地区解析，在等级与任务准入通过后使用54/1的当前阶段门口；不批量改库、不跳过5936等前置，也不改写正在进行的换频道场景快照。

通过Common/Gate_Seria.map及其(r)版本继承识别房间。共享房间38/1记住最后可用地区，街道返回点也保留；进入无房间的NPC特殊区保持此前地区。普通频道（`channel.txt` type 22）的共享房间出口只认持久返回地区，频道分组不改变出门城镇，在哪个城镇下线就回哪个城镇；只有特殊区域与团队频道按频道落点出门，见[帧与频道](../协议/帧与频道.md)。只经频道进入的城镇（ChannelAreaLanding.IsChannelBoundTown，如艾尔丁纪念馆67）与频道起始城镇安徒恩战舰19（ChannelAreaLanding.PreservesRoomReturn）内切图保持进入前的返回地区，战舰街区不写入共享房间的返回地区；旧存档若已把战舰19/1记成返回地区，普通频道选角与频道重连按共享房间初始地区修复，位置不变。进入房间时保存来源地区门口，选角统一出生450,234，空body1426返回对应地区门口。默认艾尔文防线返回622,196，不能使用离线站立坐标代替。

## 6. 药剂与光环个人传送

`TeleportHandler` 接入237药剂、469玩家位置预检查、470光环个人传送及434单成员队伍的组队光环传送。规则由 [TeleportService](../../Server/DfoServer/Game/Town/Teleport.cs)规划，Session独占当前角色及选角epoch，提交后沿TownProjection的23→24场景切换，不重发124。普通36继续检查来源、有向通路和原路线权限。

个人光环传送成功后，379阶段1在本人旧场景清理前播放出发特效，阶段2在目标23/24及成员入场后播放到达特效，再同步378剩余冷却；`[none]`光环同样按此顺序切图，只是378没有能力行。旧场景可见者按“出发特效→删除旧actor”接收，新场景可见者按“actor/状态/区域/位置→到达特效”接收；仅本次提交生效，不重复保存或启动冷却。药剂237、普通36/1426切图、失败请求及重新选角不触发该特效。广播复用[城镇同屏](城镇同屏.md)的频道、PVF阶段、房间及成员身份隔离，不向其他频道或私有房间外投递。

药剂只允许本角色Main中的实际源槽与模板匹配、未过期、未加装备锁的`[teleport potion] 0`，等级和10秒等冷却取实际脚本。`int data`的地下城选择地图编号只用于有`[dungeon gate]`的区域，不作为town编号；本服默认（`--teleport-potion-gates Open`）不按该白名单拒绝，全部地下城入口可达（资源白名单停留在1–31，未含哈林49、代号:希望77等后期地图），`Pvf`模式恢复白名单。客户端`0234CC40`对237失败只在码23时显示36288，其余码静默关窗。旧事件期限及NPC专用药的费用/协议未接入时拒绝；`[need material]`是商店兑换价，不作为药剂使用门禁或额外费用。成功扣一件，保留原UID/Core；扣药、位置、返回地区、冷却和审计在同一SQLite事务保存，业务revision增加一次。

光环必须真实穿戴于Equipment9、详情有效且未过期。PvfLib按装备继承读取`[aura ability]`的标签及整数，GameWorld区分下列能力，不把客户端枚举值作为服务端领域编号：

| PVF声明 | 当前业务 | 匹配ARAD类型 |
| --- | --- | --- |
| `[none]`或显式空块 | 有光环但无传送能力：470仍只切图，不写冷却 | 1 |
| `[party teleport] seconds` | 已创建的单成员队伍沿434传送；多人确认未接入 | 0 |
| `[solo teleport] seconds` | 普通个人传送 | 2 |
| `[upgrade solo teleport] seconds` | 升级个人传送，沿相同470入口处理 | 3 |

资源时间单位为秒，0表示无冷却，300/420/600分别按原值使用。普通与升级个人传送按ARAD的两个计时器独立保存，同类型换光环、重选或重启不能清除冷却；不因另一类型仍在冷却就拒绝当前能力。个人传送入口由客户端城镇地图决定：实机`[none]`光环同样发送470，服务端不再按光环能力拒绝，`[none]`或未穿戴光环只切图、不写计时器也不刷新378；组队光环的地图入口已分流到434，不能借470绕过队伍上下文；皮肤槽、背包中的光环不当作已穿戴能力。点选城镇的个人传送两个标识都是-1，落点用请求坐标。NPC目标必须存在于当前阶段目的地图；玩家目标只取同频道公开城镇的现有成员，排除本人、私有房间、离线与过期owner。玩家传送重验原成员身份并使用实际位置，不采用客户端预检查后的旧坐标。

组队传送只接受来源1的光环请求，要求Session实际持有[单成员队伍](队伍.md)，本人是唯一成员及队长，并穿戴有效的组队光环。按旧端流程，队长已自动同意；仅一人时无需等待435。锁外规划前后复核原队伍对象、版本、角色快照及选角epoch，退队重建不能沿用旧授权。目的地权限与可走坐标继续检查，不能从同屏名单推定队伍，不借个人470或公会来源取得资格。当前未接入多人邀请、跨账号队伍或435成员确认；未来扩展多人必须有真实共享owner、冻结成员及同意上下文，不能只移动队长后声称整队成功。

单成员成功后发送434 ACK、379准备阶段3、377已同意状态，再沿出发阶段1、23/24及到达阶段2完成传送，最后378同步type0冷却。同场景可见者的阶段3、阶段1及旧Actor删除绑定同一有界离场消息，旧源owner、旧目标视图及未知Actor均不接收迟到特效。组队冷却取PVF秒数，与药剂及两类个人冷却独立持久化；退队、换光环、重选或重启不清除。无队伍或资格不足按9B失败正文回复19，冷却中回复22，保留目标城镇、实际剩余秒数及来源以结束等待，不改位置或延长冷却。小地图图标通知不充当传送成功或关窗包，不能靠空558通知绕过业务。

两类传送仍检查目的地等级、AND/OR/排除任务及阶段资源，专用传送不要求普通邻接路径。普通地图点选、玩家目标和药剂校验可走落点；NPC目标在核对当前阶段地图中确有该NPC后，保留客户端导航提供的固定坐标，不再以通用步行矩形拒绝。ARAD的NPC导航数据与步行区域边界不等价，例如赫顿玛尔NPC18请求1125/175，低于街道步行区域的Y=176；不能因此阻止合法传送或把坐标强行夹回地面。同区域合法传送也可执行。失败不扣物品、不写位置或推进冷却，并按本版失败ACK收尾。库存刷新与场景通知绑定同一实际提交角色、generation和epoch；旧选角不发布结果，保存或网络异常由连接生命周期关闭，重连只恢复实际存档。

任务接取/放弃/条件、交付、物件或跳过事务尚待恢复时，步行、普通切图、房间返回和专用传送共用提交门禁，避免改写原操作的角色和场景快照。药剂、光环传送及玩家目标预检查另外保护已冻结的连图或任务回放入口，不将该场景限制扩大为普通行走的取消规则。仅准备而尚未提交的手册、任务券及已提交回答缓存不额外阻止城镇移动或传送，按原规则随快照变化失效；原事务明确恢复后重新允许操作。

角色私有`character_teleport_cooldowns`用UTC毫秒保存药剂和两类个人传送截止时刻；v78在原表追加`upgrade_aura_until`，缺省0，保留原药剂与普通光环冷却，不改旧资产或补发历史效果。删角在原事务清理该表。光环剩余时间用378的type2/type3秒数恢复，可在同一通知中带两行，完整资产初始化后发送；详情见[数据库](../开发/数据库.md)。

无资源规则、原生字段、SQL末段回滚、重复、重选和接管检查见 [TeleportTests](../../Server/DfoServer/SelfTests/TeleportTests.cs)，迁移覆盖真实v77升级、旧值保留及失败整笔回滚；TCP入口为`--selftest-tcp teleport`，覆盖完整ACK、绝对库存、23/24、两类个人冷却、真实300/600秒高级光环、真实`[none]`光环只切图且无冷却、组队光环拒绝、失败后继续操作及玩家同屏目标。匹配客户端的实际画面、药剂数量与后续操作另行验收，TCP不代替实机结果。

## 状态与拒绝语义

旅行规则只返回目标位置、返回地区和拒绝原因，不写库或修改 Session。[会话协调](../../Server/DfoServer/Game/Session/GameSession.Town.cs)在原 lease 内调用规则与提交，`CharacterRepository.Save` 用 `id + account + expected revision` 更新位置和返回地区，恰好影响一行后提交，revision 加1。Session 安装实际返回角色，并给调用方 `TownTravelReceipt`（角色、generation、选角 epoch）。步行位置（含朝向）未变不重复保存，速度不参与位置值；旅行普通拒绝无成功回执，不修改存档、不增加 revision、不关闭连接。

投影使用本次回执中的位置构造 23/24/可选1379，不在清场等待后重新读取另一份 Selected。清场前、每帧发送前和加入新场景前重新核对原会话与角色；另一选角 epoch 的旧结果跳过，不能移除或加入新角色成员。同次选角中快照被 GM 或其他提交替换时，关闭原连接，让重登恢复已提交位置，不能丢掉必要切图通知后继续处理请求。发送失败不回滚旅行、不重跑保存。已经开始的网络写入仍可能与状态变化交叠，门禁不能撤回在途帧。结构错误、过期 owner 或 SQL 异常也由连接生命周期记录后关闭。

无资源的[规则与选角测试](../../Server/DfoServer/SelfTests/TownSelectionTests.cs)覆盖全部 kind 字节、权限/阶段、NPC 优先级、坐标、事务与回执边界；[旅行发布测试](../../Server/DfoServer/SelfTests/TownTravelPublicationTests.cs)使用真实 Handler/发送队列，覆盖清场等待与首帧写入期间的重选、同 revision GM 更新和实际包序。测试入口见[贡献指南](../../CONTRIBUTING.md#验证)。

同区域36返回 `same-area`；未知NPC、无PVF出边、任务/等级不满足、需要实例状态等都有独立Reason。未恢复的错误ACK不由服务端猜造。新业务若客户端会进入等待状态，必须先恢复匹配版本的失败收尾合同，再接入请求。

区域通知顺序和Loading见[城镇切图Loading](../协议/城镇切图.md)；NPC及选角出生见[NPC传送与选角出生](NPC与出生.md)。
