# 共同地图几何

服务端从数据目录`DisplayCompat.world.json`读取schema1的world覆盖；缺文件保持实际PVF几何，非法文件拒绝启动。此配置由维护者与客户端配套发布，不能放入玩家visual覆盖目录。改变后需重启服务端，不在在线会话锁内热解析。

`MapGeometryConfig`以资源路径、段名、出现次数和整段端点守卫派生资源，不写PVF。三个显示比例必须得到相同目标，可使用严格的`{"all":[...]}`共同端点；连接目标、NPC身份、朝向与条件不得随坐标变化。未知类型、重叠段、未匹配或非法形状拒绝。配置上限为32MiB、32768条规则、8192个别名和32Mi个JSON值；单段最多16384个token。值数量与客户端world解析器一致，字节、规则及别名门限保持独立约束。

| 适配器 | 标签 | 已核实的变换边界 |
|---|---|---|
| `town_gate` | `[town movable area]` | 六字段矩形记录，目标镇区身份保持 |
| `walk_area` | `[virtual movable area]` | 四字段矩形记录，宽高为正 |
| `npc_position` | `[npc]` | 五字段记录，NPC身份、朝向及条件保持 |
| `gate_points8` | `[pathgate pos]` | 唯一首段八个整数，允许零和负坐标，数值限于±1048576；不猜补历史四整数形状 |
| `gate_recognize8` | `[pathgate recognize range]` | 唯一首段八个整数，允许零和负值，同样限于±1048576；不能套用正矩形尺寸约束 |
| `tile_pass14` | `[pass type]` | 仅声明的私有TIL别名，唯一首段、每行14个byte整数；原始及目标行数相同，保留合法非0/2值 |
| `dungeon_tiles` | `[tile]` | 唯一首段，四个字符串变为五个；前三个引用原样保留，末两项均绑定本配置的受守卫TIL别名 |
| `dungeon_tiles3` | `[tile]` | 唯一首段，三个字符串变为五个；前两项保持，末三项均为受守卫私有TIL别名，且每个别名的实际源必须等于原第三项 |
| `dungeon_ext_tilefiles` | `[tile files]` | 完整ID/路径对列表，保留原始全部前缀，只追加唯一非负ID及受守卫别名 |
| `dungeon_ext_tilemap` | `[tile map]` | 每行四格变为五格，前三格保持；原末格非空时，末两格均使用本次新增的别名ID，原末格为`-1`时末两格都保持`-1` |
| `dungeon_ext_tilemap3` | `[tile map]` | 每行三格变为五格，前两格保持；原末格为`-1`时末三格全`-1`，否则末三格均为本次新增ID，且每个ID指向的别名源必须等于该行原末ID对应TIL |

扩展文件与矩阵适配器必须与同一MAP的主地板方案共同声明；四列矩阵只绑定`dungeon_tiles`，三列矩阵只绑定`dungeon_tiles3`。源及目标矩阵的非空ID均须存在于对应文件列表；三列方案同样复用`dungeon_ext_tilefiles`完整前缀追加合同。应用时还核对已有完整`[extended tile]`容器。不能借此创建任意标签、修改原ID或选择多个同名段之一。

`dungeon_movable_xywh3`只同步终端插列的`[dungeon movable area]`元数据：唯一完整闭合段恰有三组XYWH整数，宽高为正，X>=672时左边界增加224，跨越672时宽度增加224，右边界恰为672保持；Y、高度和其他字段保持。它使用既有DCG2字段；此元数据与实际原生通行的虚拟活动区不同，不作为行走矩形改写器，也不替代TIL和门触达核查。

`dungeon_virtual_xywh1`单独处理实际虚拟活动区，唯一完整闭合段只能有一组XYWH四整数，并绑定同图`dungeon_tiles`四到五列方案。按x672插224映射左边界和跨缝宽度，Y/高度保持；原生使用脚底点的半开矩形包含测试，配方同步移动原第四地板及锚点，保留每个方向原有门触达状态。该段已纳入DCG2，不能把其他条件嵌套段或多矩形记录套入单矩形适配器。

`dungeon_virtual_xywh4_append`只接三到五列等待室的四矩形记录：唯一完整闭合段恰有16整数，每组宽度增加448，X/Y/高度保持，必须绑定同图`dungeon_tiles3`。四矩形按原生逐条OR的通行合同扩大右侧，不改原town六字段或门哨兵，也不改变原有不可触门状态。

终端前插列另支持七个严格锚点适配器：`dungeon_animation5`（两字符串、三整数，X索引2）、`dungeon_passive4`（四整数，X索引1）、`dungeon_monster10_fixed_normal`（八整数及`[fixed]`/`[normal]`，X索引3）、`dungeon_ai8`（四整数、两字符串、两整数，X索引1）、`dungeon_event_xyz3`（三整数，X索引0）、`dungeon_special11_single_child`（五整数、`[trap]`、`[monster]`或`[item]`及五整数，头childcount=1，X索引1）。每段多条记录完整消耗，只允许`X>=672`增加224，其余身份、Y、动作参数、字符串和子记录逐token保持；未知尾、重复段或缺闭合拒绝。此合同只开放已核实子集，不把怪物token5猜作第三坐标。

`dungeon_animation5_append`为纯ANI地板提供独立的末端追加合同：唯一完整闭合`[animation]`段中，原有全部五字段记录逐token保持，末端恰追加一条两字符串/三整数记录；原列表必须已有X=784的相同ANI、层、Y/Z记录，新增X严格为1008，其余四字段相同。所有整数限制为±1048576。它必须绑定同一MAP的`dungeon_tiles`四到五列根，不能单独扩大视觉或绑定三列根；三个比例共享同一追加目标，窄视口按正常相机裁切第五块。它沿用现有DCG3完整动画锚点签名，未扩展DCG1/DCG2/DCT1字节格式；普通visual仍不能绕过共同几何许可修改该段。

`dungeon_ext_tilefiles_repair`为缺失扩展块提供窄适配器：完整旧定义前缀中只替换一个路径到私有空图别名，原ID/顺序及其他路径保持；后续追加及四到五列矩阵仍受原合同约束。别名pass必须至少10行、全2且from/to不变；能力快照装配另确认旧源实际不存在，空源只有空IMAGE/frame0和全2通行段。匹配原生空IMAGE不会生成绘制，扩展块缺行原返回2，这一替代保持原绘制与碰撞。以后补回真实旧源，或空源出现图像/额外元数据时拒绝旧配置，不能继续用替代物遮蔽新资源。

终端前插列另支持七个严格锚点适配器：`dungeon_animation5`（两字符串、三整数，X索引2）、`dungeon_passive4`（四整数，X索引1）、`dungeon_monster10_fixed_normal`（八整数及`[fixed]`/`[normal]`，X索引3）、`dungeon_ai8`（四整数、两字符串、两整数，X索引1）、`dungeon_event_xyz3`（三整数，X索引0）、`dungeon_special11_single_child`（五整数、`[trap]`、`[monster]`或`[item]`及五整数，头childcount=1，X索引1）。每段多条记录完整消耗，只允许`X>=672`增加224，其余身份、Y、动作参数、字符串和子记录逐token保持；未知尾、重复段或缺闭合拒绝。此合同只开放已核实子集，不把怪物token5猜作第三坐标。

`dungeon_ext_tilefiles_repair`为缺失扩展块提供窄适配器：完整旧定义前缀中只替换一个路径到私有空图别名，原ID/顺序及其他路径保持；后续追加及四到五列矩阵仍受原合同约束。别名pass必须至少10行、全2且from/to不变；能力快照装配另确认旧源实际不存在，空源只有空IMAGE/frame0和全2通行段。匹配原生空IMAGE不会生成绘制，扩展块缺行原返回2，这一替代保持原绘制与碰撞。以后补回真实旧源，或空源出现图像/额外元数据时拒绝旧配置，不能继续用替代物遮蔽新资源。

可选`aliases`对象把新的`map/.../displaycompat/*.til`映射到实际已有、非`displaycompat`命名空间的`map/*.til`源。别名不允许链或覆盖归档已有路径，每个别名必须有本配置的`[pass type]`首段完整守卫。读取别名时先读取原始源，再以别名路径应用规则。MAP内新增TIL引用必须相对当前MAP目录；允许安全的`..`，但不能越出`map/`根，不能写`map/...`绝对样式，因为原生加载器会直接拼接目录。

新增路径字符串使用配置解析时冻结的负ID表；归档字符串池不变。派生token的消费者通过`MapGeometryConfig.ResolveString(id, originalResolver)`解析这些引用，不能直接把负ID送入PVF字符串池。`ReadText`也使用同一别名源和完整token守卫。

Application在装配TownCatalog前读配置；城镇递归import和DungeonRoomCatalog读取MAP时采用同一不可变实例，Runtime显式传递，不另建目录或更改Session。城镇Walk、路线、入口和NPC继续使用派生后的现有目录消费者。副本房间连接、清怪、层状态和队伍判定继续沿原业务；`MOVE_MAP`未知字段不解释为世界坐标。服务端不把TIL派生误称为新增了完整角色行走碰撞模拟，正常副本出生/门触发仍沿匹配客户端的实际MAP/TIL消费者。

Runtime在启动时通过`MapGeometryCapabilities.Build`规范化城镇及导入MAP、world指定资源的生效几何，形成只读签名快照。每个副本根递归读取完整原生及私有TIL、扩展层文件和MAP import闭包，每图限制32768节点及512层；缺失、循环、越出map根或资源类型冲突拒绝。import按相对当前目录、map根及区域`(r)`顺序回退。每图预算不作为整库快照条数上限。

公开HTTP`GET /client/displaycompat-world?map=map/...map`保留原32字节签名合同；`GET /client/displaycompat-world/version`返回32字节快照版本，`POST /client/displaycompat-world/batch`每批核对至多64个规范路径及请求版本，再按请求顺序返回签名。快照及版本在装配时固定，查询不需要GM凭据、不解析PVF、不读取角色，也不获取在线角色锁。客户端在发布父MAP前以本地完整依赖的expected集合与此快照核对，缓存重入也读取真实版本；失败和换代清除许可。它与客户端`WorldEndpoint`使用同一公开HTTP监听；端口按实际服务端配置决定。

DCG1采用UTF-8长度前缀文本和小端32位整数，包含规范路径、按标签及出现次序排序的完整`[town movable area]`、`[virtual movable area]`、`[npc]`语义块。块内条件保留；标签忽略大小写，池字符串ID不入签名，字符串值和几何身份保留。客户端在受影响地图派生及缓存重入时比较同一生效内容，包括已加载的MAP导入依赖。只比较相关几何，不计算或限制整份PVF身份。

旧城镇`Canonical/Compute`的DCG1字节合同保持不变。副本采用独立的`CanonicalDungeon/ComputeDungeon`（DCG2）：并入旧三种完整闭合块，同时签入`[pathgate pos]`、`[pathgate recognize range]`、`[dungeon movable area]`、`[dungeon start area]`、`[tile]`、`[extended tile]`、`[tile files]`、`[tile map]`、`[import script]`、`[force map width]`、`[ignore movable rect]`与`[camera edge exception]`。新字段按下一个kind3标签或EOF终止，不要求资源中不存在的闭合标签；旧三种块仍包含条件子标签并要求完整闭合。TIL采用`CanonicalTile/ComputeTile`（DCT1），签入唯一`[pass type]`标量段，每14个整数构成一行。

DCG2/DCT1沿同一确定性壳：四个原始ASCII魔数字节、规范资源路径的UTF-8字节数`i32`及内容、字段数`i32`；字段按小写标签及出现序号排序，逐字段写标签长度与内容、出现序号`i32`、token数`i32`，再逐token写kind`u32`及整数`i32`或已解析字符串的长度与内容。标签字符串小写，普通字符串保留值，所有整数小端；DCT1行数由token数除14得到，不额外写行数。`SignatureKind`按TIL路径选择DCT1、按副本专用规则选择DCG2，其余选择DCG1。MAP绑定签名与其实际TIL通行签名必须一同覆盖，单个MAP门签名不能证明依赖图的全部碰撞一致。

声明六类锚点规则的MAP选择独立DCG3，以相同确定性壳签入DCG2字段和六类完整闭合锚点段。普通副本的DCG2及旧城镇DCG1保持原字节合同，不能因为插列图需要锚点校验而限制其他地图的合法visual。黄金文件使用DGG2头、资源数及每份资源的签名类型（2=DCG2、3=DCG3、4=DCT1），便于同一候选跨C#/C++精确核对；向量仍不进入玩家资源包。

`MapGeometryTests`覆盖解析、整段守卫、目标身份、比例一致、幂等、别名、追加列及拒绝，并保留DCG1/DCG2/DCT1逐字节黄金。`MapGeometryHttpTests`覆盖实际只读监听和返回边界。`--selftest-map-geometry-golden <world> <PVF> <向量文件>`输出完整副本依赖的path/tokens/signature向量，不改变旧城镇30图向量入口。`--selftest-map-geometry-interop <world> <PVF> <客户端自测EXE> <向量文件>`装配同一快照，绑定隔离的127.0.0.1随机端口，运行C++真实HTTP校验后回收；这两个入口在数据库与正式监听初始化前执行。跨C++/C#黄金夹具与实际资源输入保存在包外。测试通过不代表真实游戏中门可达、美术位置或三比例显示已验收。

`dungeon_ai10_npc_monster_boss`只处理已核实的NPC型AI：四整数、`[monster]`、`[NPC]`、NPC关联整数、`[boss]`及两整数，共十个token；X索引1按相同插列映射，其它字段逐token保持，不能拆成普通八字段AI。特殊父对象的`[item]`子记录仍保留全部五整数，只映射父X，不改变掉落或互动规则。
